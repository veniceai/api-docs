如果省略 `type` 查询参数，响应仅包含文本模型。传入 `type=all` 可返回完整的模型目录。

## 解读模型条目 {#reading-a-model-entry}

将模型的 `id` 作为 `model` 参数发送。你筛选所用的大部分字段都位于 `model_spec` 下：

| 字段 | 含义 |
| --- | --- |
| `type` | 模型对应的端点：`text` 表示 chat completions，或 `image`、`video`、`tts`、`asr`、`embedding` 等 |
| `model_spec.capabilities` | 文本模型支持的功能，例如 `supportsFunctionCalling`、`supportsVision`、`supportsReasoning`、`supportsResponseSchema`、`supportsWebSearch` 和 `supportsE2EE` |
| `model_spec.availableContextTokens` | 上下文窗口，以 token 计 |
| `model_spec.pricing` | 以 USD 和 DIEM 计的价格：文本模型按每 1M tokens 计，媒体模型按单位计 |
| `model_spec.privacy` | `private` 或 `anonymized`。E2EE 和 TEE 模型为 `private`，并设置 `supportsE2EE` 或 `supportsTeeAttestation` |
| `model_spec.constraints` | 模型接受的参数值，例如宽高比、视频时长和质量等级 |
| `model_spec.traits` | 模型承担的角色，例如 `default` 或 `fastest` |
| `model_spec.deprecation` | 模型即将停用时出现，包含移除日期以及（如有）其 `replacementModelId` |

要按角色而非 ID 选择模型，请调用 [`GET /models/traits`](/zh/api-reference/endpoint/models/traits)。要浏览和比较模型，请参阅[模型](/zh/models/overview)页面。

## 质量等级定价

对于接受可选 `quality` 参数的图像模型，响应在 `model_spec.pricing.quality` 下提供按质量划分的价格矩阵。每个顶级键是一个分辨率等级（`1K`、`2K`、`4K`），每个嵌套键是一个质量等级（`low`、`medium`、`high`），各自带有自己的 `usd` 和 `diem` 价格：

```json
"pricing": {
  "resolutions": {
    "1K": { "usd": 0.27, "diem": 0.27 },
    "2K": { "usd": 0.51, "diem": 0.51 },
    "4K": { "usd": 0.84, "diem": 0.84 }
  },
  "quality": {
    "1K": {
      "low":    { "usd": 0.02, "diem": 0.02 },
      "medium": { "usd": 0.07, "diem": 0.07 },
      "high":   { "usd": 0.26, "diem": 0.26 }
    },
    "2K": {
      "low":    { "usd": 0.03, "diem": 0.03 },
      "medium": { "usd": 0.13, "diem": 0.13 },
      "high":   { "usd": 0.50, "diem": 0.50 }
    },
    "4K": {
      "low":    { "usd": 0.05, "diem": 0.05 },
      "medium": { "usd": 0.21, "diem": 0.21 },
      "high":   { "usd": 0.83, "diem": 0.83 }
    }
  }
}
```

`pricing.resolutions` 是为向后兼容而保留的旧版按图像价格表。`pricing.quality` 是按（分辨率，质量）组合的矩阵，每当 `quality` 参数被支持时即适用。两个字段都会保留在响应中，以便客户端检测质量支持并在自己的 UI 中展示该矩阵。

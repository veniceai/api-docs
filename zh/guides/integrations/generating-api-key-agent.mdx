控制 Base 上钱包的 AI agent 可以在无需人类参与的情况下铸造自己的 Venice 推理 API 密钥。agent 获取 VVV、质押它、为其钱包请求一个短期密钥请求、签署该请求的可读消息，然后将签名回传以获得绑定到质押钱包的全新 API 密钥。当钱包签署的消息注明密钥类型为 ADMIN 时，同一流程也可以铸造 ADMIN 密钥。

本指南从端到端介绍整个流程，并涵盖密钥铸造后用于实际支付推理的资金选项。

## 前置条件 {#prerequisites}

* agent 控制的 Base 上的 EVM 钱包（私钥保存在环境变量或密钥管理器中）。
* Base 上少量 ETH 用于 gas（质押需要两笔交易：`approve` 然后 `stake`）。
* 任意非零数量的 VVV 用于质押。铸造端点仅要求钱包具备非零 sVVV 余额，因此 1 VVV 足以铸造密钥。请参阅[为推理付费](#paying-for-inference)了解实际调用付费端点需要什么。

<Tip>
  使用专用的 agent 钱包，而不是金库钱包。该钱包的私钥会签署每个 Venice token 请求，因此其影响范围应保持最小。
</Tip>

## 步骤 {#steps}

<Steps>
  <Step title="获取 VVV">
    将 VVV 发送到 agent 的钱包，或让 agent 在 DEX（如 [Aerodrome](https://aerodrome.finance/swap?from=eth\&to=0xacfe6019ed1a7dc6f7b508c02d1b04ec88cc21bf\&chain0=8453\&chain1=8453) 或 [Uniswap](https://app.uniswap.org/swap?chain=base\&inputCurrency=NATIVE\&outputCurrency=0xacfe6019ed1a7dc6f7b508c02d1b04ec88cc21bf)）上兑换。

    Base 上的 VVV 代币合约：`0xacfE6019Ed1A7Dc6f7B508C02d1b04ec88cC21bf`
  </Step>

  <Step title="向 Venice 质押 VVV">
    将 VVV 质押到 [Venice 质押智能合约](https://basescan.org/address/0x321b7ff75154472b18edb199033ff4d116f340ff#code) `0x321b7ff75154472B18EDb199033fF4D116F340Ff`。这需要两笔交易：

    1. 在 VVV 代币上调用 `approve(spender, amount)`，其中 `spender` 是质押合约。
    2. 在质押合约上调用 `stake(amount)`。

    <Frame as="div">
      <img src="/images/guides/SC-Stake.png" alt="Smart Contract Staking" />
    </Frame>

    当第二笔交易确认时，钱包的 VVV 余额减少，其 sVVV 余额相应增加。铸造端点读取 sVVV 余额以确认钱包已质押。
  </Step>

  <Step title="为钱包请求密钥请求">
    使用质押钱包的地址调用 `GET /api/v1/api_keys/generate_web3_key`。此端点无需身份验证。

    ```bash
    curl --request GET \
      --url 'https://api.venice.ai/api/v1/api_keys/generate_web3_key?address=<wallet address>'
    ```

    可选查询参数 `apiKeyType` 设置钱包授权的密钥类型：`INFERENCE`（默认）或 `ADMIN`。该类型固定在 token 中并在消息中注明，因此请请求你要铸造的类型。参见[铸造 ADMIN 密钥](#minting-an-admin-key)。

    响应包含两个字段：

    - `token`，由 Venice 签名并绑定到该钱包的 token。它在签发 15 分钟后过期，因此请尽早签名并提交。
    - `message`，钱包要签署的可读文本。它列出钱包、密钥类型（`INFERENCE`，除非你请求了 `ADMIN`）、签发方、链、一次性 nonce 以及签发和过期时间：

    ```text
    Venice API key request

    Sign this only if you are creating a Venice inference API key for this wallet. The key spends from this wallet's Venice account.

    Wallet: <wallet address>
    Key type: INFERENCE
    Issued by: api.venice.ai
    Chain ID: 8453
    Nonce: <random hex>
    Issued At: <ISO 8601 time>
    Expiration Time: <ISO 8601 time>
    ```
  </Step>

  <Step title="用质押钱包签署消息">
    用持有质押 VVV 的钱包签署完全相同的 `message` 字符串。这是标准的 `personal_sign`（EIP-191）。`ethers.Wallet.signMessage(message)` 和 `viem` 的 `account.signMessage({ message })` 都能生成正确的签名。不要修改消息：Venice 会根据 token 重建它，签名必须与之完全匹配。
  </Step>

  <Step title="铸造 API 密钥">
    将地址、签名和 token `POST` 到同一端点。

    ```bash
    curl --request POST \
      --url https://api.venice.ai/api/v1/api_keys/generate_web3_key \
      --header 'Content-Type: application/json' \
      --data '{
        "address": "<wallet address>",
        "signature": "<signature of message>",
        "token": "<token>",
        "apiKeyType": "INFERENCE",
        "description": "Agent key minted on <date>"
      }'
    ```

    必填字段：`address`、`signature`、`token`、`apiKeyType`。`apiKeyType` 必须与签名消息中注明的密钥类型一致：未带 `apiKeyType` 请求的 token 用 `INFERENCE`，带 `apiKeyType=ADMIN` 请求的 token 用 `ADMIN`。

    可选字段：

    - `description`、`expiresAt`
    - `consumptionLimit` — 此密钥的支出上限，以 `usd` 或 `diem` 计（`vcu` 已弃用，请改用 `diem`）
    - `limitPeriod` — 上限的计量周期：`EPOCH`（每个 UTC 日重置）、`MONTH`（每个 UTC 月的 1 日重置）或 `LIFETIME`（永不重置，上限即为永久上限）
    - `modelPrivacy` — 该密钥可调用哪些模型，按隐私层级划分：`ALL`、`PRIVATE_TEXT` 或 `PRIVATE_ONLY`
    - `ipAllowlist` — 允许使用该密钥的 IPv4 或 IPv6 地址及 CIDR 子网（最多 100 个条目）；空列表表示允许任何 IP 地址

    <Warning>
    `limitPeriod` 省略时默认为 `EPOCH`，这意味着上限会**每天重置**，而不是终身总额。使用 `consumptionLimit: {"usd": 50}` 且未设置 `limitPeriod` 创建的密钥每天可以花费 $50。对于无人值守的代理密钥，请显式设置 `limitPeriod: "LIFETIME"`，使该限制成为永久上限。
    </Warning>

    成功时响应包含铸造的 `apiKey` 字符串。将其存储在 agent 的密钥存储中，并作为正常的 Bearer token（`Authorization: Bearer <key>`）使用。
  </Step>
</Steps>

## 端到端示例 {#end-to-end-example}

下面的示例使用来自环境变量的真实钱包，而不是随机生成的钱包。随机钱包没有质押的 VVV，铸造将被 `Wallet 0x… has no staked VVV on Base` 错误拒绝。

```typescript
import { ethers } from "ethers"

const wallet = new ethers.Wallet(process.env.WALLET_PRIVATE_KEY!)
const address = wallet.address

const tokenResponse = await fetch(
  `https://api.venice.ai/api/v1/api_keys/generate_web3_key?address=${address}`,
)
const { data: { token, message } } = await tokenResponse.json()

const signature = await wallet.signMessage(message)

const mintResponse = await fetch("https://api.venice.ai/api/v1/api_keys/generate_web3_key", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({
    address,
    signature,
    token,
    apiKeyType: "INFERENCE",
    description: "Agent key",
    // 永久的 $50 上限。如果没有 limitPeriod，此上限将每天重置。
    consumptionLimit: { usd: 50 },
    limitPeriod: "LIFETIME",
  }),
})

const result = await mintResponse.json()
if (!mintResponse.ok) {
  throw new Error(`Mint failed: ${result.error}`)
}

console.log("Minted key:", result.data.apiKey)
```

## 铸造 ADMIN 密钥 {#minting-an-admin-key}

ADMIN 密钥可以创建和删除其他 API 密钥、读取钱包 Venice 账户的账单，并从该账户扣费。要铸造 ADMIN 密钥，请用 `apiKeyType=ADMIN` 请求 token，签署其消息，然后以 `apiKeyType: "ADMIN"` 发送 `POST`：

```bash
curl --request GET \
  --url 'https://api.venice.ai/api/v1/api_keys/generate_web3_key?address=<wallet address>&apiKeyType=ADMIN'
```

返回的 `message` 说明它会创建 ADMIN 密钥以及该密钥的权限：

```text
Venice API key request

Sign this only if you are creating a Venice ADMIN API key for this wallet. An ADMIN key can create and delete other API keys and read billing for this wallet's Venice account, and it spends from this wallet's Venice account.

Wallet: <wallet address>
Key type: ADMIN
Issued by: api.venice.ai
Chain ID: 8453
Nonce: <random hex>
Issued At: <ISO 8601 time>
Expiration Time: <ISO 8601 time>
```

按上述步骤签名并提交，在 `POST` 请求体中使用 `"apiKeyType": "ADMIN"`。token 的密钥类型无法更改：`INFERENCE` token 不能铸造 ADMIN 密钥，`ADMIN` token 也不能铸造 INFERENCE 密钥。ADMIN 密钥需要可读消息，因此[旧版 token](#legacy-tokens) 无法铸造它们。

<Warning>
  仅在 agent 需要管理密钥或读取账单时，才让钱包签署 ADMIN 消息。任何持有 ADMIN 密钥的人都可以为该账户创建新密钥，因此请至少像保管钱包私钥一样谨慎地保管它。
</Warning>

## 错误参考 {#error-reference}

端点返回具体、可操作的错误消息。在 agent 中映射这些错误，以便它可以决定是重试、请求新 token 还是停止。

| 状态 | 错误消息包含 | 含义 | 应对方式 |
| --- | --- | --- | --- |
| `400` | `Invalid wallet address` | `address` 查询参数或字段不是有效的 EVM 地址。 | 修正地址并重新提交。 |
| `400` | `Invalid "apiKeyType"` | `apiKeyType` 查询参数既不是 `INFERENCE` 也不是 `ADMIN`。 | 使用 `INFERENCE` 或 `ADMIN`。 |
| `400` | `ADMIN keys require a readable key request` | `GET` 请求了 `apiKeyType=ADMIN` 但未带 `?address=`。 | 同时带上 `address` 和 `apiKeyType=ADMIN` 请求 token。 |
| `400` | `This token was issued for an` | `POST` 请求体中的 `apiKeyType` 与签名消息中注明的密钥类型不一致。 | 发送该 token 签发时对应的类型，或用你需要的 `apiKeyType` 请求新 token。错误信息会给出正确的 `GET`。 |
| `400` | `ADMIN keys cannot be created with a token that has no wallet address` | 旧版 token（未带 `?address=` 请求）与 `apiKeyType: "ADMIN"` 一起使用。 | 用 `?address=<wallet>&apiKeyType=ADMIN` 请求 token 并签署其 `message`。 |
| `400` | `issued for a different wallet` | 请求 token 时使用的 `address` 与 `POST` 请求体中的不同。 | 请求 token 时将 `?address=` 设为签名钱包。 |
| `400` | `JWT has expired` | 验证 token 在您签名并提交之前已过期。 | 请求新 token，签名并立即提交。 |
| `400` | `JWT signature is invalid` | 该 token 不是由 Venice 签发的（可能被篡改或伪造）。 | 始终使用 `GET` 端点返回的新鲜 token。 |
| `400` | `JWT claims are invalid` | token 的签发者或受众与 Venice 期望的不匹配。 | 使用 `GET` 端点返回的未修改 token。 |
| `400` | `JWT is malformed` | 提交的 `token` 不是 JWT。 | 确保发送 `GET` 端点返回的确切 `token` 字符串。 |
| `400` | `Wallet signature does not match` | `signature` 不是 `address` 钱包对该 token 的 `message` 的签名。 | 用拥有 `address` 的钱包签署随 token 返回的完全相同的 `message`。 |
| `400` | `Tokens without a wallet address are no longer accepted` | 请求 token 时未提供 `?address=`。这些旧版 token 自 2026 年 12 月 26 日起失效。 | 使用 `?address=` 请求 token 并签署其 `message`。 |
| `400` | `Could not verify wallet signature` | 验证签名的 RPC 调用失败（瞬态）。 | 退避后重试。 |
| `400` | `has no staked VVV` | 钱包的 sVVV 余额为零。完整消息为 `Wallet 0x… has no staked VVV on Base`，其中 `0x…` 会替换为您的钱包地址，后面还附有一个链接，因此请匹配 `has no staked VVV`，而不是完整文本。 | 先质押 VVV，然后重试。 |

## 旧版 token {#legacy-tokens}

2026 年 11 月之前，该端点签发不带钱包地址的 token，钱包签署原始 token 字符串。这些 token 在 **2026 年 12 月 26 日 00:00 UTC** 之前仍可铸造 INFERENCE 密钥，其响应带有 `Deprecation`、`Sunset` 和 `Link` 标头。该日期之后，`POST` 会拒绝它们。请在此之前改用 `?address=` 并签署 `message`。

## 为推理付费 {#paying-for-inference}

铸造密钥与能够用它调用付费端点是两回事。新铸造的密钥可以正确认证，但在钱包的账户具有可花费余额之前，无法调用付费端点（如 `/chat/completions`）。

铸造的密钥可以按以下优先顺序从用户账户花费：DIEM，然后是赚取的额度，然后是捆绑额度，然后是 USD。

| 资金来源 | 自主？ | 方法 |
| --- | --- | --- |
| **来自 VVV 质押的 DIEM** | 是 | 钱包的每日 DIEM 分配与其在质押池中的份额成比例。账户需要至少 0.1 个质押 DIEM 才能让任何 DIEM 可花费。质押越多，按比例获得更多每日 DIEM，每个 epoch（00:00 UTC）刷新。 |
| **通过 Stripe 的 USD** | 否（浏览器） | 使用相同的钱包登录 venice.ai（Sign-In-With-Ethereum）。仪表板会找到现有的用户记录。在 Settings、API 中添加额度。 |
| **Coinbase 加密订阅** | 否（浏览器） | 相同的钱包登录，然后通过仪表板订阅。流程会重定向到 Coinbase Commerce 进行实际付款，因此无法通过脚本驱动。 |
| **Coinbase onramp** | 否（浏览器） | 相同的钱包登录，然后在仪表板中使用 onramp 小部件。托管在 Coinbase 的 UI 上。 |

如果 agent 需要完全 crypto 原生、无头的资金路径，最干净的选项是：

1. **质押更多 VVV**，使每日 DIEM 分配覆盖 agent 的支出。铸造的密钥会自动接入。
2. **使用 [x402 钱包流程](/zh/guides/integrations/x402-venice-api) 代替 API 密钥。** 通过 x402，agent 每个请求签署一个 Sign-In-With-X 消息，通过 `POST /api/v1/x402/top-up` 在 Base 或 Solana 上直接用 USDC 充值，并按请求付费。x402 USDC 余额绑定到钱包，而非用户，因此它不会以余额形式出现在铸造的 Bearer 密钥下，但它确实让同一钱包以编程方式为推理付费。

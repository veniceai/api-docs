Se ometti il parametro di query `type`, la risposta include solo i modelli di testo. Passa `type=all` per restituire il catalogo completo dei modelli.

## Leggere una voce di modello {#reading-a-model-entry}

Invia l'`id` di un modello come parametro `model`. La maggior parte di ciò su cui filtri si trova in `model_spec`:

| Campo | Cosa indica |
| --- | --- |
| `type` | Quale endpoint serve il modello: `text` per le chat completions, oppure `image`, `video`, `tts`, `asr`, `embedding` e così via |
| `model_spec.capabilities` | Cosa supporta un modello di testo, ad esempio `supportsFunctionCalling`, `supportsVision`, `supportsReasoning`, `supportsResponseSchema`, `supportsWebSearch` e `supportsE2EE` |
| `model_spec.availableContextTokens` | La finestra di contesto, in token |
| `model_spec.pricing` | Prezzi in USD e DIEM: per 1M token per i modelli di testo, per unità per i modelli multimediali |
| `model_spec.privacy` | `private` o `anonymized`. I modelli E2EE e TEE sono `private` e impostano `supportsE2EE` o `supportsTeeAttestation` |
| `model_spec.constraints` | I valori dei parametri accettati dal modello, come proporzioni, durate dei video e livelli di qualità |
| `model_spec.traits` | Ruoli ricoperti dal modello, come `default` o `fastest` |
| `model_spec.deprecation` | Presente quando il modello è in ritiro, con la data di rimozione e, se esiste, il suo `replacementModelId` |

Per scegliere un modello in base al ruolo anziché all'ID, chiama [`GET /models/traits`](/it/api-reference/endpoint/models/traits). Per sfogliare e confrontare i modelli, consulta le pagine [Modelli](/it/models/overview).

## Prezzi per livello di qualità

Per i modelli di immagine che accettano il parametro opzionale `quality`, la risposta espone una matrice di prezzi per qualità sotto `model_spec.pricing.quality`. Ogni chiave di primo livello è un livello di risoluzione (`1K`, `2K`, `4K`) e ogni chiave annidata è un livello di qualità (`low`, `medium`, `high`) con il proprio prezzo `usd` e `diem`:

```json
"pricing": {
  "resolutions": {
    "1K": { "usd": 0.27, "diem": 0.27 },
    "2K": { "usd": 0.51, "diem": 0.51 },
    "4K": { "usd": 0.84, "diem": 0.84 }
  },
  "quality": {
    "1K": {
      "low":    { "usd": 0.02, "diem": 0.02 },
      "medium": { "usd": 0.07, "diem": 0.07 },
      "high":   { "usd": 0.26, "diem": 0.26 }
    },
    "2K": {
      "low":    { "usd": 0.03, "diem": 0.03 },
      "medium": { "usd": 0.13, "diem": 0.13 },
      "high":   { "usd": 0.50, "diem": 0.50 }
    },
    "4K": {
      "low":    { "usd": 0.05, "diem": 0.05 },
      "medium": { "usd": 0.21, "diem": 0.21 },
      "high":   { "usd": 0.83, "diem": 0.83 }
    }
  }
}
```

`pricing.resolutions` è lo schema legacy per immagine mantenuto per retrocompatibilità. `pricing.quality` è la matrice per (risoluzione, qualità) che si applica ogni volta che il parametro `quality` è supportato. Entrambi i campi vengono mantenuti nella risposta in modo che i client possano rilevare il supporto della qualità e mostrare la matrice nelle proprie UI.

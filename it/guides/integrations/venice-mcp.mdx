Il [Venice MCP Server](https://github.com/veniceai/venice-mcp-server) è il server ufficiale [Model Context Protocol](https://modelcontextprotocol.io/) per Venice. Espone l'API Venice (chat, image, video, audio, music, embeddings, web augment, characters, RPC crypto e attestazione TEE) più le operazioni sull'account (fatturazione e chiavi API) come **45 tool** che qualsiasi agente compatibile con MCP può chiamare.

## Avvio rapido

<Steps>
  <Step title="Ottieni una API key Venice">
    Generane una da [venice.ai/settings/api](https://venice.ai/settings/api?utm_source=venice-api-documentation). Consulta la [guida alle API key](/guides/getting-started/generating-api-key) per la procedura passo passo.
  </Step>

  <Step title="Aggiungi Venice alla configurazione del tuo host MCP">
    Incolla questo blocco nel file di configurazione del tuo host MCP:

    ```json
    {
      "mcpServers": {
        "venice": {
          "command": "npx",
          "args": ["-y", "@veniceai/mcp-server@0.3.0"],
          "env": { "VENICE_API_KEY": "<your-venice-api-key>" }
        }
      }
    }
    ```

    Percorsi di configurazione comuni:

    | Host | Percorso |
    |---|---|
    | Claude Desktop (macOS) | `~/Library/Application Support/Claude/claude_desktop_config.json` |
    | Claude Desktop (Windows) | `%APPDATA%\Claude\claude_desktop_config.json` |
    | Cursor | `~/.cursor/mcp.json` |
    | LM Studio | `mcp.json` (dalle impostazioni MCP dell'app) |
  </Step>

  <Step title="Riavvia il tuo host MCP">
    Il tuo agente ora ha a disposizione chat, image, video, musica, TTS, ASR, fatturazione, chiavi API e altri 39 tool Venice.
  </Step>
</Steps>

<Note>
La maggior parte degli host MCP passa solo le variabili d'ambiente **elencate esplicitamente** nel blocco `env`. Le variabili di sistema non vengono ereditate. Se vedi errori 402 con una API key impostata, verifica che `VENICE_API_KEY` sia dentro `env` nella tua configurazione.
</Note>

## Cosa ottieni

**45 tool** che coprono ogni modalità Venice più le operazioni sull'account, **3 risorse** (`venice://models`, `venice://styles`, `venice://voices`) e **3 template di prompt** (ricerca senza censura, scrittura creativa NSFW, esploratore di stili immagine).

Ogni tool dichiara annotazioni esplicite `readOnlyHint`, `destructiveHint`, `idempotentHint` e `openWorldHint`: gli host possono eseguire le lookup senza chiedere conferma e chiederla prima di qualsiasi azione distruttiva, come la pulizia dei media o un relay crypto.

### Chat ed embeddings

| Tool | Descrizione |
|---|---|
| `venice_chat` | Chat completion compatibile OpenAI sull'intero catalogo LLM di Venice, con blocchi testo/immagine/audio/video/file, output strutturati, function tool, prompt caching e controllo del reasoning. Le chiamate sono in chiaro e senza streaming. |
| `venice_responses` | API Responses alpha e stateless, compatibile OpenAI, con input testo/immagine e controllo del reasoning. I modelli E2EE e i campi dei tool non sono supportati. |
| `venice_embeddings` | Calcola embeddings per input testuale. |
| `venice_chat_with_character` | Chatta con un character Venice tramite slug. |

### Image

| Tool | Descrizione |
|---|---|
| `venice_image_generate` | Genera un'immagine (Flux 2, Lustify SDXL, Anime/WAI, Qwen Image, GPT Image, Nano Banana Pro e altri), con aspect ratio o larghezza/altezza, livelli di qualità, prompt enhancement, style reference, web search e varianti. |
| `venice_image_edit` | Modifica un'immagine con un prompt. |
| `venice_image_multi_edit` | Modifica fino a 8 immagini insieme con un solo prompt (composizione / outpainting). |
| `venice_image_upscale` | Ingrandisce un'immagine da 2 a 4×, con controllo `creativity`. |
| `venice_image_remove_bg` | Rimuove lo sfondo di un'immagine. |
| `venice_image_styles` | Elenca i preset di stile immagine. |

### Video

| Tool | Descrizione |
|---|---|
| `venice_video_generate` | Accoda una generazione video (Sora 2, Veo 3.1, Kling, Wan, LTX 2, Seedance, Runway Gen-4 e altri) con input immagine, video, audio, reference ed elementi. |
| `venice_video_status` | Controlla lo stato di un job video (`POST /video/retrieve`). |
| `venice_video_complete` | Segna un video completato come scaricato; elimina i media lato server solo quando Venice lo conferma. |
| `venice_video_quote` | Ottieni un preventivo prima di accodare. |

### Audio (TTS / ASR)

| Tool | Descrizione |
|---|---|
| `venice_tts` | Text-to-speech con voci clonate, temperature e tag di emozione. Lo streaming viene bufferizzato in un unico risultato audio completo. |
| `venice_asr` | Trascrive audio da un URL, con timestamp opzionali per parola/carattere. Le trascrizioni grandi vengono paginate tramite un handle di sessione. |
| `venice_voice_clone` | Elenca le voci live per modello, oppure clona una voce da un URL di esempio (restituisce un handle `vv_<id>` per `venice_tts`). |
| `venice_audio_quote` | Ottieni un preventivo per la generazione musicale. |

### Musica

| Tool | Descrizione |
|---|---|
| `venice_music_generate` | Accoda una generazione musicale (`ace-step-15`, `elevenlabs-music`, `minimax-music-v2/v25/v26`, `stable-audio-25`, `mmaudio-v2-text-to-audio`, `elevenlabs-sound-effects-v2`) con controlli su testo, strumentale, loop, voce, lingua, velocità e durata. |
| `venice_music_status` | Controlla lo stato di un job musicale. |
| `venice_music_complete` | Segna un job musicale completato come scaricato. |

### Web augment

| Tool | Descrizione |
|---|---|
| `venice_web_search` | Cerca sul web con Brave (predefinito, Zero Data Retention) o Google (proxato e anonimizzato da Venice). |
| `venice_web_scrape` | Esegue lo scraping di un URL in markdown. |
| `venice_text_parser` | Estrae testo da PDF/DOCX/EPUB/PPTX/XLSX. |

### Catalogo e character

| Tool | Descrizione |
|---|---|
| `venice_list_models` | Sfoglia il catalogo modelli live di ogni tipo, con riepiloghi compatti, prezzi e flag di capacità. |
| `venice_model_details` | Ottieni la riga completa di un modello esatto: vincoli `model_spec`, capacità e prezzi. |
| `venice_model_traits` | Mappa i nomi dei trait (`default`, `most_uncensored`, …) agli ID modello attuali. |
| `venice_model_compatibility_mapping` | Mappa i nomi modello compatibili agli ID modello Venice. |
| `venice_list_characters` | Elenca i character pubblici di Venice con filtri di ricerca, tag, modello e ordinamento. **Solo API key.** |
| `venice_get_character` | Ottieni un character pubblico tramite slug. **Solo API key.** |
| `venice_character_reviews` | Elenca le recensioni pubbliche di un character, paginate. **Solo API key.** |

### Attestazione TEE

| Tool | Descrizione |
|---|---|
| `venice_tee_attestation` | Ottieni le prove di attestazione hardware (quote Intel TDX, prove NVIDIA opzionali, chiave di firma) per un modello testuale TEE, usando un tuo nonce di 32 byte. |
| `venice_tee_signature` | Ottieni il payload di firma dell'enclave per l'ID di una richiesta chat TEE completata. |

<Warning>
Entrambi i tool TEE restituiscono solo le prove del provider: non le verificano e non cifrano la chat. Verifica tu il nonce restituito, lo stato di debug e il binding della chiave di firma prima di fidarti di un modello TEE, e usa `venice_chat` (mai `venice_responses`) per i modelli TEE. Questo server rifiuta `enable_e2ee`.
</Warning>

### Crypto

| Tool | Descrizione |
|---|---|
| `venice_crypto_networks` | Elenca gli slug di rete live accettati dal proxy RPC. |
| `venice_crypto_rpc` | Inoltra una richiesta JSON-RPC, o un batch fino a 100, verso Ethereum, Base, Arbitrum, Optimism, Polygon, Solana, Starknet, zkSync, Linea, BSC, Avalanche, Blast e altri. |

Le broadcast di transazioni (`eth_sendRawTransaction`, `eth_sendUserOperation`, `sendTransaction` di Solana, scritture Starknet) devono essere inviate come richieste singole con `idempotency_key`, riusando la stessa chiave in caso di retry.

### Fatturazione (chiavi admin)

| Tool | Descrizione |
|---|---|
| `venice_billing_balance` | Disponibilità attuale di USD, DIEM e crediti inclusi. |
| `venice_billing_usage_analytics` | Utilizzo aggregato in beta per data, modello e chiave API (lookback o intervallo personalizzato). |
| `venice_billing_usage_history` | Utilizzo dettagliato con paginazione a cursore e output JSON o CSV. |

<Note>
I tool di fatturazione richiedono una API key **ADMIN**. Le chiavi di inferenza non possono chiamare questi endpoint e il server fallisce localmente invece di ricorrere a un token wallet. La route deprecata `/billing/usage` non è coperta.
</Note>

### Chiavi API

| Tool | Descrizione |
|---|---|
| `venice_list_api_keys` | Elenca i metadati delle chiavi attive, includendo solo gli ultimi sei caratteri. Solo chiave admin. |
| `venice_get_api_key` | Ottieni metadati, utilizzo, saldi e rate limit di una chiave tramite ID. Solo chiave admin. |
| `venice_api_key_rate_limits` | Saldi correnti, stato di accesso, tier, scadenza e rate limit per modello. Chiave di inferenza o admin. |
| `venice_api_key_rate_limit_logs` | Gli ultimi 50 eventi di rate limit superati (sperimentale). Solo chiave admin. |

### Helper wallet x402

Rilevanti solo se ti autentichi con un wallet via [x402](/guides/integrations/x402-venice-api) invece che con una API key.

| Tool | Descrizione |
|---|---|
| `venice_x402_balance` | Controlla il saldo di credito x402 prepagato di un indirizzo wallet EVM o Solana. |
| `venice_x402_top_up_info` | Ottieni i requisiti di ricarica (rete, token USDC, destinatario, importo minimo). Non accetta argomenti. |
| `venice_x402_transactions` | Elenca le ricariche e gli addebiti x402 recenti di un indirizzo wallet EVM o Solana. |

## Configurazione

Il server è configurato interamente tramite variabili d'ambiente.

### Modelli e richieste

| Variabile | Default | Note |
|---|---|---|
| `VENICE_API_KEY` | _(nessuna)_ | La tua API key Venice. La configurazione più semplice. |
| `VENICE_DEFAULT_CHAT_MODEL` | `deepseek-v4-flash-0731` | |
| `VENICE_DEFAULT_IMAGE_MODEL` | `flux-2-pro` | |
| `VENICE_DEFAULT_TTS_MODEL` | `tts-kokoro` | |
| `VENICE_DEFAULT_ASR_MODEL` | `openai/whisper-large-v3` | |
| `VENICE_DISABLE_NSFW` | `0` | Imposta `1` per rimuovere le note sulla capacità NSFW dalle descrizioni dei tool. |
| `VENICE_HTTP_TIMEOUT_MS` | `60000` | |
| `VENICE_SIWX_TOKEN` | _(nessuno)_ | Token di autenticazione in modalità wallet x402. Consulta [x402 più sotto](#modalità-wallet-x402). |

Se sono impostati sia `VENICE_API_KEY` che `VENICE_SIWX_TOKEN`, vince la API key.

### Limiti di dimensione delle risposte

I media generati vengono bufferizzati e incorporati in base64 nel risultato MCP, quindi ogni modalità ha un tetto in byte.

| Variabile | Default | Si applica a |
|---|---|---|
| `VENICE_MAX_IMAGE_RESPONSE_BYTES` | `33554432` (32 MiB) | `venice_image_generate`, `venice_image_edit`, `venice_image_multi_edit`, `venice_image_upscale`, `venice_image_remove_bg` |
| `VENICE_MAX_VIDEO_RESPONSE_BYTES` | `26214400` (25 MiB) | `venice_video_status` |
| `VENICE_MAX_AUDIO_RESPONSE_BYTES` | `33554432` (32 MiB) | `venice_tts`, `venice_music_status` |

Un risultato immagine o TTS troppo grande viene scartato con un errore. Un video o una musica troppo grandi restano in coda, quindi puoi richiamare il tool di stato con lo stesso queue ID dopo aver alzato il limite.

### Server HTTP

Rilevante solo nel [deployment Streamable HTTP](#self-hosting-streamable-http).

| Variabile | Default | Note |
|---|---|---|
| `PORT` | `3333` | Porta del listener HTTP. |
| `VENICE_MCP_HOST` | `127.0.0.1` | Indirizzo di bind. Imposta `0.0.0.0` per esporre su LAN o container. |
| `VENICE_MCP_AUTH_TOKEN` | _(nessuno)_ | Token bearer richiesto da `/mcp` quando il bind è fuori dal loopback. |
| `VENICE_MCP_ALLOW_UNAUTHENTICATED_HTTP` | `0` | Via di fuga per HTTP esposto senza autenticazione. Usala solo dietro un proxy autenticato fidato. |
| `VENICE_MCP_MAX_SESSIONS` | `100` | Numero massimo di sessioni Streamable HTTP attive. |
| `VENICE_MCP_SESSION_TTL_MS` | `1800000` | Durata di una sessione inattiva prima della pulizia. |

## Comportamento della generazione media

- **I media completati possono essere byte o un URL.** I job video e musicali restituiscono risorse MP4/audio incorporate, oppure JSON con una `download_url` restituita come resource link. Scarica prima quel link, poi chiama `venice_video_complete` o `venice_music_complete`; la pulizia dei media non viene mai applicata a un risultato `download_url`, perché il link smette di funzionare una volta eliminato il file.
- **Alcuni modelli restituiscono l'URL solo all'accodamento.** Per i modelli VPS e Grok Imagine Private, conserva la `download_url` restituita da `venice_video_generate` e passala a `venice_video_status`; un retrieve `COMPLETED` senza URL inline fornisce comunque un link utilizzabile.
- **Il prompt enhancement viene restituito.** Quando `enhance_prompt` è applicato, i risultati di generate, edit e multi-edit delle immagini includono il prompt URL-decodificato restituito da Venice.
- **La paginazione ASR viene addebitata una sola volta.** Le trascrizioni con timestamp o superiori a 8000 caratteri restituiscono un `result_handle` con la prima pagina. Richiedi le pagine successive con quell'handle. Gli handle vivono in memoria per sessione MCP per 10 minuti e solo i 16 più recenti vengono conservati.
- **Il consenso Seedance non è un bypass delle policy.** Gli attuali modelli Seedance pubblici possono rifiutare del tutto media con persone riconoscibili. Quando viene restituita una risposta `needs_consent`, i tre flag `consents.seedance` sono attestazioni legali: impostali a `true` solo dopo che l'utente ha confermato esplicitamente ogni dichiarazione.

## Modalità wallet x402

Venice supporta l'autenticazione con un [token wallet Sign-In-With-X](/guides/integrations/x402-venice-api) garantito da credito USDC prepagato su Base o Solana, oltre al normale flusso con API key. Nessuna email, telefono o KYC: il tuo wallet è l'unica identità.

```json
{
  "mcpServers": {
    "venice": {
      "command": "npx",
      "args": ["-y", "@veniceai/mcp-server@0.3.0"],
      "env": { "VENICE_SIWX_TOKEN": "<base64 Sign-In-With-X payload>" }
    }
  }
}
```

Il server MCP inoltra `VENICE_SIWX_TOKEN` nell'header `SIGN-IN-WITH-X` a ogni chiamata dell'API Venice. Il server non vede mai la tua chiave privata. La firma del wallet e le autorizzazioni di ricarica USDC avvengono nel tuo wallet.

| Flusso | Cosa succede |
|---|---|
| **Setup iniziale** | Firmi un messaggio Sign-In-With-X nel tuo wallet → produce un token SIWX (JSON in base64). |
| **Ricarica** | `POST /api/v1/x402/top-up` restituisce 402 + i requisiti di pagamento. Firma un pagamento USDC per una delle opzioni Base o Solana restituite, invia di nuovo e Venice accredita il saldo. |
| **Ogni chiamata di inferenza** | Il server MCP invia `SIGN-IN-WITH-X: <SIWX>`; Venice addebita il saldo prepagato. |

La ricarica minima è **\$5 USD**. Il saldo minimo per chiamare l'inferenza è **\$0.10**. Una volta ricaricato, le chiamate richiedono meno di 100 ms perché il regolamento avviene off-chain su un conto di credito veloce.

<Tip>
I wallet collegati a un account Venice con DIEM in staking consumano dal saldo di staking invece che dai crediti USDC, quindi non serve alcuna ricarica.
</Tip>

Venice non accetta header di pagamento sulle route di inferenza, quindi questo server non ne invia mai. `PAYMENT-SIGNATURE` appartiene solo a `/x402/top-up`, e l'helper di ricarica scopre i requisiti senza inviare alcun pagamento.

### Copertura delle modalità di auth

Alcuni endpoint accettano una sola modalità di auth:

| Tool | API key | x402 |
|---|---|---|
| Inferenza, media, web augment, RPC crypto, chat con character | ✓ | ✓ |
| `venice_list_characters`, `venice_get_character`, `venice_character_reviews` | ✓ | ✗ |
| `venice_billing_*`, `venice_list_api_keys`, `venice_get_api_key`, `venice_api_key_rate_limit_logs` | ✓ (admin) | ✗ |
| `venice_api_key_rate_limits` | ✓ (qualsiasi chiave) | ✗ |
| `venice_x402_balance`, `venice_x402_transactions` | ✗ | ✓ |
| `venice_x402_top_up_info` | ✓ | ✓ |

Se imposti entrambe le credenziali, la API key vince su ogni chiamata: gli helper riservati a SIWX (`venice_x402_balance`, `venice_x402_transactions`) funzionano quindi solo quando il token wallet è la tua unica credenziale.

## Self-hosting (Streamable HTTP)

Per deployment di team o workspace, esegui il server MCP su HTTP invece che su stdio:

```bash
docker run -p 3333:3333 \
  -e VENICE_API_KEY=<your-venice-api-key> \
  -e VENICE_MCP_AUTH_TOKEN=<choose-a-long-random-token> \
  ghcr.io/veniceai/venice-mcp-server:latest
```

Il server è ora disponibile su `http://localhost:3333/mcp`. I client HTTP devono inviare `Authorization: Bearer <VENICE_MCP_AUTH_TOKEN>` e creare nuove sessioni senza header `mcp-session-id`, poi riutilizzare l'ID di sessione emesso dal server.

<Warning>
`/mcp` è un endpoint di esecuzione di tool basato su credenziali: chi chiama può spendere la API key Venice configurata o il saldo x402. Quando la modalità HTTP si lega fuori dal loopback, l'avvio fallisce a meno che `VENICE_MCP_AUTH_TOKEN` non sia impostato, o che `VENICE_MCP_ALLOW_UNAUTHENTICATED_HTTP=1` sia configurato dietro un proxy autenticato fidato. In produzione, fissa esplicitamente la versione del pacchetto npm invece di affidarti a `latest`.
</Warning>

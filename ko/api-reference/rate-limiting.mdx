## 기본 제한

### 텍스트 및 임베딩 모델

텍스트 및 임베딩 모델은 네 가지 크기로 그룹화됩니다. 모든 임베딩 모델은 XS입니다.

| 크기 | 요청/분 | 토큰/분 | 파트너 요청/분 | 파트너 토큰/분 |
|:-----|-------------:|-----------:|---------------------:|-------------------:|
| XS | 500 | 5,000,000 | 500 | 10,000,000 |
| S | 150 | 3,000,000 | 300 | 6,000,000 |
| M | 100 | 2,000,000 | 200 | 4,000,000 |
| L | 100 | 2,000,000 | 150 | 3,000,000 |

<Note>
  일부 모델은 전용 인프라 또는 서드파티 인프라에서 실행되며, 이 네 가지 크기에 해당하지 않는 제한을 가집니다. 사용 중인 키에 대한 모델별 공식 제한은 [`GET /api_keys/rate_limits`](/ko/api-reference/endpoint/api_keys/rate_limits)를 호출하세요.
</Note>

### 이미지 및 오디오 모델

| 유형 | 요청/분 | 파트너 요청/분 |
|:-----|-------------:|---------------------:|
| 이미지, 업스케일, 인페인트 | 20 | 60 |
| 음성 및 전사 | 60 | 120 |

### 비디오 및 음악 모델

비디오, 음악, 보이스 체인저의 대기열 등록 및 조회 요청에는 계정별 요청 제한이 적용됩니다. `429` 응답은 백오프로 처리하고, 조회 엔드포인트는 짧은 루프로 반복하지 말고 적당한 간격으로 폴링하세요. 작업은 크레딧 잔액에서 생성 건당 청구되므로, 먼저 [`POST /video/quote`](/ko/api-reference/endpoint/video/quote), [`POST /audio/quote`](/ko/api-reference/endpoint/audio/quote) 또는 [`POST /audio/voice-changer/quote`](/ko/api-reference/endpoint/audio/voice-changer/quote)로 작업 비용을 산정하세요.

## 오류 처리

실패한 요청(500, 503, 429)은 지수 백오프로 재시도해야 합니다.

추론 엔드포인트에서 429 오류가 발생한 경우, `x-ratelimit-reset-requests` 헤더는 요청 윈도우가 완전히 비워지는 가장 늦은 시점을 밀리초 단위 Unix 타임스탬프로 알려줍니다. 그때까지 기다리면 항상 안전하며, 그보다 일찍 재시도해도 성공할 수 있습니다.

```javascript
const reset = Number(response.headers.get('x-ratelimit-reset-requests'));
const waitMs = Math.max(0, reset - Date.now());
await new Promise((resolve) => setTimeout(resolve, waitMs));
```

### 오류 버짓

벽에 부딪히면서도 계속 재시도하는 클라이언트로부터 API를 보호하기 위해 두 가지 추가 제한이 있습니다. 둘 다 API 키별, 모델별로 집계되며, 둘 다 `429`를 반환합니다. 실패한 요청은 고정된 30초 윈도우 단위로 집계됩니다:

| 버짓 | 임계값 | 적용 대상 |
|:-------|----------:|:-----------|
| 실패한 요청 | 30초당 50 | 모든 엔드포인트 |
| 지원되지 않는 기능 요청 | 30초당 200 | `/chat/completions`, `/responses` |

두 번째 버짓은 모델이 지원하지 않는 기능을 요청하는 경우를 집계합니다. 예를 들어 해당 기능이 없는 모델에 비전이나 도구 호출을 요청하는 경우입니다. 두 버짓 중 하나라도 초과하면 [속도 제한 로그](/ko/api-reference/endpoint/api_keys/rate_limit_logs)에 `FAILED_REQUESTS` 또는 `UNSUPPORTED_FEATURE_REQUESTS`로 표시됩니다.

응답 본문의 `error` 필드에 초과된 임계값이 명시됩니다. 실패한 요청 버짓의 경우 다음과 같습니다:

```
Too many failed attempts (> 50) resulting in a non-success status code. Please wait 30 seconds and try again. See https://docs.venice.ai/api-reference/rate-limiting for more information.
```

## 응답 헤더

추론 응답(chat completions, responses, 이미지, 오디오, 임베딩)에는 다음 헤더가 포함됩니다. 이 헤더는 모델, API 키, 결제 또는 x402 경로에서는 전송되지 않으며, `x-venice-balance-*` 헤더도 마찬가지입니다.

| Header | Description |
|:-------|:------------|
| `x-ratelimit-limit-requests` | 현재 윈도우에서 허용된 최대 요청 |
| `x-ratelimit-remaining-requests` | 현재 윈도우에서 남은 요청 |
| `x-ratelimit-reset-requests` | 현재 윈도우가 완전히 비워지는 시점의 Unix 타임스탬프(밀리초) (사용량과 관계없이 요청 시각에 전체 윈도우 길이를 더한 값) |
| `x-ratelimit-limit-tokens` | 분당 허용된 최대 토큰 |
| `x-ratelimit-remaining-tokens` | 현재 분에 남은 토큰 |
| `x-ratelimit-reset-tokens` | 토큰 제한이 재설정되는 Unix 타임스탬프(밀리초) |

실패한 요청 버짓에는 별도의 헤더가 있으며, `401` 응답을 포함하여 API 키로 보낸 요청에 대한 모든 응답에 전송됩니다:

| Header | Description |
|:-------|:------------|
| `x-ratelimit-remaining` | 현재 30초 윈도우에서 남은 실패한 요청 수 |
| `x-ratelimit-resets` | 현재 30초 윈도우가 재설정되는 Unix 타임스탬프(밀리초) |

`/crypto/rpc/{network}` 엔드포인트는 자체 제한과 자체 `X-RateLimit-Limit`, `X-RateLimit-Remaining`, `X-RateLimit-Reset` 헤더를 사용하며, 이 헤더들은 429 응답에서만 설정됩니다. 위의 밀리초 단위 헤더와 달리 `X-RateLimit-Reset`은 초 단위 Unix 타임스탬프입니다. 자세한 내용은 [Crypto RPC](/ko/api-reference/endpoint/crypto/rpc)를 참조하세요.

## 파트너 등급

파트너 제한은 위 표에서 기본 제한과 함께 나열되어 있습니다.

지속적으로 속도 제한에 도달하고 사용 패턴이 **시간 경과에 따른 지속적인 수요**를 보이는 경우, 파트너 액세스를 논의하기 위해 연락하세요: [support@venice.ai](mailto:support@venice.ai).

파트너 등급 제한은 특정 요구 사항에 따라 조정할 수 있습니다.

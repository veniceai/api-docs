[모델 카탈로그](/ko/models/overview)는 [`GET /models`](/ko/api-reference/endpoint/models/list)를 기반으로 매시간 생성됩니다. 이 페이지에서는 카탈로그의 수치가 어떻게 산출되는지 설명하므로, 직접 재현해 보고 각 수치가 무엇을 의미하고 무엇을 의미하지 않는지 파악할 수 있습니다.

## 패밀리와 변형 {#families-and-variants}

여러 모델 ID가 실제로는 같은 모델을 다른 방식으로 제공하는 경우가 많습니다. 카탈로그는 이들을 하나의 패밀리 페이지로 묶습니다.

| 변형 유형 | 예시 | 별도로 구분하는 이유 |
|---|---|---|
| 속도 | `claude-opus-5-5` 및 `claude-opus-5-5-fast` | 더 높은 가격으로 더 빠르게 제공됩니다 |
| 모드 | `kling-v3-pro-text-to-video`, `-image-to-video`, `-motion-control` | 입력과 가격이 다릅니다 |
| 작업 | `nano-banana-pro` 및 `nano-banana-pro-edit` | 생성 엔드포인트와 편집 엔드포인트 |

모든 변형은 고유한 모델 ID, 가격, 프라이버시 등급을 유지합니다. 변형의 ID를 `model`로 전달하세요. `deepseek-v4-flash-0731`과 같은 날짜별 스냅샷은 별도 패밀리로 유지되며 **다른 버전** 아래에 표시됩니다.

`z-ai-glm-5-3`에 대한 `e2ee-glm-5-3-p`처럼 E2EE 빌드는 변형이 아니라 별도의 페이지를 가집니다. 호출하려면 E2EE 핸드셰이크가 필요하고 제한과 가격이 다르기 때문입니다. 해당 페이지의 이름은 모델 이름에 E2EE를 붙인 것이고, URL은 모델 URL에 `-e2ee`를 붙인 것이며, 두 페이지는 서로 링크됩니다.

## 정규화된 가격 {#normalized-prices}

각 모달리티는 고유한 단위로 과금됩니다. 카탈로그는 기본 단위와 하나의 참조 가격을 함께 표시하므로 모델을 정렬하고 비교할 수 있습니다.

| 모달리티 | 기본 단위 | 참조 가격 |
|---|---|---|
| 텍스트 | 입력 및 출력 토큰 100만 개당 | **혼합 가격**: `(3 × input + output) / 4`, Artificial Analysis가 사용하는 3:1 비율입니다. 캐시된 입력 할인율은 `1 − cached ÷ input`입니다. |
| 이미지 | 이미지당, 해상도 등급별 | 선택한 등급(1K, 2K 또는 4K)에서의 이미지당 가격. 편집은 추가 입력에 대해 이미지당 할증료가 붙습니다. |
| 비디오 | 클립당, 해상도·길이·오디오별 | 전체 견적 매트릭스(아래 참조)에서 산출한, 선택한 설정의 초당 및 클립당 가격. |
| 텍스트 음성 변환 | 100만 자당 | 분당 150단어(약 825자) 기준 음성 1분당 가격. |
| 음성 텍스트 변환 | 오디오 1초당 | 오디오 1시간당 및 1,000분당 가격. |
| 음악 및 효과음 | 트랙당, 초당 또는 길이 구간별 | 모델이 허용하는 경우 오디오 1분당, 그렇지 않으면 트랙당 가격. |
| 임베딩 | 입력 토큰 100만 개당 | 변경 없음. |

<Note>
추론 모델은 같은 작업에서 비추론 모델보다 훨씬 많은 출력 토큰을 사용할 수 있으므로, 혼합 가격은 실제 비용을 과소평가합니다. 벤치마크 실행으로 측정한 작업당 비용이 계획되어 있습니다. [벤치마크](#benchmarks)를 참조하세요.
</Note>

### 비디오 가격 {#video-pricing}

비디오 모델은 `GET /models`에 가격을 공개하지 않습니다. 빌드 시 Venice는 각 모델이 지원하는 모든 해상도 × 길이 × 오디오 조합에 대해, 첫 번째로 나열된 화면 비율로 [`POST /video/quote`](/ko/api-reference/endpoint/video/quote)를 호출합니다(화면 비율은 가격에 영향을 주지 않습니다). 카탈로그는 전체 매트릭스를 저장하고 다음 값을 산출합니다.

- **초당 가격**: 특정 해상도와 오디오 설정에서 여러 길이에 걸친 `price ÷ seconds`의 중앙값입니다. 거의 모든 모델에서 가격은 길이에 비례합니다.
- **초안 클립**: 5초, 720p, 무음.
- **프로덕션 클립**: 10초, 1080p, 오디오 포함.

모델이 요청한 설정을 제공하지 않으면, 카탈로그는 지원되는 가장 가까운 설정을 사용하고 해당 가격에 표시를 남깁니다. 편집, 모션 컨트롤, 업스케일 모드는 원본 비디오 길이에 따라 과금되므로 가격 대신 **원본 기준**이 표시됩니다. 정확한 금액을 알려면 대기열에 넣기 전에 항상 `POST /video/quote`를 호출하세요.

## 프라이버시 등급 {#privacy-tiers}

| 등급 | 의미 |
|---|---|
| **E2EE** | 프롬프트는 사용자의 기기에서 암호화되며, 증명된 하드웨어 엔클레이브 내부에서만 복호화됩니다. [TEE 및 E2EE 모델](/ko/guides/features/tee-e2ee-models)을 참조하세요. |
| **TEE** | 추론이 암호학적 증명(attestation)을 갖춘 하드웨어 엔클레이브에서 실행됩니다. |
| **비공개** | Venice가 관리하는 인프라에서 제공되며 데이터를 전혀 보존하지 않습니다. |
| **익명화** | 사용자의 신원 없이 상위 연구소로 프록시됩니다. 연구소는 프롬프트를 보존할 수 있습니다. |

패밀리에는 그 변형들이 제공하는 모든 등급이 나열됩니다. 특정 등급으로 필터링하면 해당 등급의 변형이 고유한 가격과 함께 표시됩니다.

## 참조 프롬프트 세트 {#reference-prompt-suite}

이미지 및 비디오 모델은 고정된 프롬프트 세트로 기본 설정에서 렌더링되며, 같은 모달리티의 모든 모델에 동일한 프롬프트가 사용됩니다. 덕분에 탐색기의 갤러리를 모델 간에 비교할 수 있습니다.

| 모달리티 | 프롬프트 |
|---|---|
| 이미지 | 이미지 내 텍스트, 사실적 표현, 지시 이행, 일러스트레이션 스타일 |
| 이미지 편집 | 원본 사진 한 장을 세 가지 방식으로 편집: 부분 변경, 스타일 변경, 텍스트 추가 |
| 업스케일링 | 512px 사진을 2배 업스케일한 결과와 같은 부분을 바이큐빅으로 확대한 결과를 나란히 비교 |
| 비디오 | 시네마틱 풍경, 끊김 없는 루프, 도시 시네마틱 |
| 비디오 편집 | 원본 클립 하나를 스타일 변경하거나 연장 |
| 비디오 업스케일링 | 480p 클립을 2배 업스케일한 결과와 같은 부분을 바이큐빅으로 확대한 결과를 나란히 비교 |

대부분의 렌더링은 venice.ai의 모델 페이지에서 가져옵니다. venice.ai에 렌더링이 없는 경우 문서에서 Venice API로 같은 세트를 렌더링하며, 클립을 가볍게 유지하기 위해 비디오 모델은 시네마틱 풍경 프롬프트만 사용합니다.

렌더링이 없는 모델은 **아직 참조 렌더링 없음** 아래에 표시됩니다.

## 성능 {#performance}

텍스트 모델 페이지에는 API, venice.ai, 앱에서 발생한 Venice 트래픽으로 측정한 최근 24시간의 첫 토큰까지의 시간, 출력 속도, 가동률이 표시됩니다. 이 수치는 요청의 횟수와 소요 시간이며, 요청의 프롬프트나 출력은 절대 포함하지 않습니다. 수치는 매시간 갱신되며, 6시간이 지나면 페이지에 더 이상 표시되지 않습니다.

| 수치 | 측정 방법 |
|---|---|
| 첫 토큰까지의 시간 | 추론 시작부터 첫 번째 추론 또는 출력 토큰까지의 중앙값으로, 페일오버를 포함합니다. 90번째 백분위수는 agent brief와 데이터 파일에 있습니다. 스트리밍 Chat Completions만 해당합니다. |
| 출력 속도 | 추론을 포함한 출력 토큰 수의 중앙값을 첫 번째 출력 토큰부터 스트림 종료까지의 시간으로 나눈 값입니다. 10토큰 이상의 성공한 스트리밍 Chat Completions가 대상이며, venice.ai와 앱은 이를 기록하지 않으므로 API만 해당합니다. |
| 가동률 | 성공한 요청과 실패한 요청 중 성공한 요청의 비율로, 내림 처리합니다. 요청이 1,000건 미만이면 정수 백분율, 그 이상이면 소수점 첫째 자리까지 표시합니다. 5xx 오류, 타임아웃, 도중에 끊긴 스트림, 401·402·404 응답은 실패로 집계됩니다. 다른 제공업체로 페일오버되어 성공한 요청은 성공으로 집계됩니다. 속도 제한(429), 지역 차단(403), 잘못된 형식으로 거부된 요청(400, 413, 422)은 어느 쪽에도 집계되지 않습니다. |

첫 토큰까지의 시간과 출력 속도는 요청 20건, 가동률은 요청 100건이 필요합니다. 그보다 적으면 해당 카드가 생략되며, 수치가 하나도 없는 모델에는 성능 카드가 표시되지 않습니다.

첫 토큰까지의 시간과 출력 속도 차트는 24시간을 15분, 1시간, 3시간, 6시간 또는 하루 전체의 동일한 구간으로 나눕니다. 요청이 있는 모든 구간이 그날 수치에 필요한 만큼의 요청을 갖는 가장 짧은 길이를 사용합니다. 따라서 모든 점은 충분한 트래픽에 기반한 실제 수치이며, 트래픽이 적은 모델은 몇 개의 긴 구간이나 일일 수치에서 평평한 선 하나로 표시됩니다. 새 모델의 첫 요청 이전처럼 요청이 없는 구간은 선에 빈틈으로 남습니다. 구간이 1시간보다 긴 모델은 선 대신 다른 텍스트 모델들 사이에서 해당 수치가 어디에 위치하는지를 보여 주며, 오른쪽일수록 좋습니다. 차트는 중앙값 구간을 중간 높이에 두고 중앙값의 두 배를 넘는 값은 맨 위에 그리며, 마우스를 올리거나 드래그하면 각 구간의 수치를 볼 수 있습니다.

가동률 차트는 하루의 15분 단위 구간마다 얇은 막대 두 개를 표시합니다. 정상일 때는 녹색, 성능 저하(95% 미만)일 때는 경고 색상, 중단(80% 미만)일 때는 빨간색, 새 모델의 첫 요청 이전처럼 요청이 없을 때는 회색입니다. 요청이 100건 미만이면 95% Wilson 구간의 낙관적인 끝값조차 기준선 아래일 때만 성능 저하나 중단으로 표시되므로, 적은 요청 중 한 번의 실패는 녹색으로 남습니다. 마우스를 올리거나 드래그하면 각 15분 구간의 가동률을 볼 수 있습니다. 요청이 100건 미만이면 실패가 있는 15분 구간은 가동률 대신 상태를 표시합니다. 가동률로 요청 수를 추정할 수 있기 때문입니다. 요청이 없는 15분 구간이 하루의 8분의 1보다 넓게 흩어져 있는 모델에서는 이 구간들이 얇은 선으로 줄어듭니다.

각 수치 아래에는 첫 토큰까지의 시간과 출력 속도가 다른 텍스트 모델 중 몇 위인지, 가동률은 중단되거나 성능이 저하된 시간이 얼마나 되는지 표시됩니다. 페이지의 Compare 표는 유사한 모델의 첫 토큰까지의 시간과 출력 속도를 제공합니다.

### 예정 {#planned}

<Info>
아직 공개되지 않았습니다. 여기서는 카탈로그에 표시될 내용을 설명합니다.
</Info>

Venice는 고객 프롬프트가 아닌 합성 프로브만으로 나머지 모달리티를 측정하고 다음 항목을 공개할 예정입니다.

| 모달리티 | 지표 |
|---|---|
| 이미지 | 가동률, 1K 이미지 1장 생성 시간(p50 및 p95), 성공률 |
| 비디오 | 가동률, 5초 720p 클립의 대기열 시간 및 생성 시간(별도 보고), 성공률 |
| 오디오 | 가동률, 첫 오디오까지의 시간, 속도 배율, 성공률 |
| 임베딩 | 가동률, 1K 토큰 입력의 지연 시간, 성공률 |

텍스트 모델에는 500토큰 응답까지의 시간과 캐시 적중률도 추가됩니다. 캐시 적중률은 전체 트래픽에 대한 `cache_read ÷ (input + cache_read + cache_write)`입니다.

## 벤치마크 {#benchmarks}

텍스트 모델 페이지에는 GPQA Diamond가 표시됩니다. 생물학, 화학, 물리학 분야의 대학원 수준 문제 198개로, 각 문제에 보기 4개가 있으며, Venice가 제공하는 그대로의 각 모델에 대해 Venice가 API를 통해 실행합니다.

- **점수.** 모델의 점수는 기본 추론 설정에서의 실행 결과이며, 그 결과가 생기기 전까지는 최고 실행 결과를 사용합니다. 순위는 점수가 있는 모든 텍스트 모델을 기준으로 합니다. 다른 설정으로 실행한 결과는 Artificial Analysis가 구성을 명명하는 방식처럼 이름에 설정을 표시합니다: *Kimi K3 (off)*.
- **가격.** 각 차트는 점수가 있는 모든 텍스트 모델을 Venice에서의 혼합 가격(출력 토큰 1개당 입력 토큰 3개 기준)과 함께 표시합니다. 음영 처리된 모서리에는 더 적은 비용으로 더 높은 점수를 내는 모델이 있으며, 비어 있으면 Venice에서 두 측면 모두에서 이 모델보다 나은 모델이 없다는 뜻입니다.
- **신뢰도.** 각 점수에는 95% 신뢰 구간이 있으며, 점수에 마우스를 올리면 표시되고 데이터에도 공개됩니다. 따라서 몇 점 차이인 모델은 사실상 동률입니다.
- **잘못된 실행.** 무작위 수준인 25%보다 낮은 점수를 낸 실행은 잘못된 설정을 측정한 것이므로 제외됩니다.

벤치마크는 최첨단 모델을 기준으로 선정됩니다. 즉, 최상위권에서도 여전히 변별력이 있고, 오염에 강하며, Venice가 제공하는 그대로의 모델에 대해 실행할 수 있어야 합니다. 모든 점수에는 하나의 출처 라벨이 붙으며, 서로 평균을 내지 않습니다.

- **Venice 검증**: 페이지에 표시된 Venice 엔드포인트에서 실행.
- **독립 측정**: 제3자가 실행하며, 보통 연구소 자체 API에서 실행.
- **연구소 보고**: 모델 제작사가 공개.

각 점수에는 벤치마크 및 하니스 버전, 추론 강도, 테스트 날짜, 신뢰 구간도 함께 표시됩니다. 90일이 지났거나 새 벤치마크 버전으로 대체된 점수는 오래된 것으로 표시됩니다.

| 모달리티 | 계획된 대표 벤치마크 세트 |
|---|---|
| 텍스트 | Artificial Analysis Intelligence Index, 그리고 Humanity's Last Exam, Terminal-Bench, τ³-bench, AA-LCR, IFBench, AA-Omniscience 및 Venice Openness Score |
| 이미지 | Artificial Analysis 및 LMArena 아레나의 인간 선호도 Elo, GenEval 2, 과잉 거부율 |
| 비디오 | Artificial Analysis 텍스트-비디오(오디오 포함 및 미포함) 및 이미지-비디오 Elo, LMArena 텍스트-비디오 |
| 텍스트 음성 변환 | Artificial Analysis Speech Arena Elo, 단어 오류율, 첫 오디오까지의 시간 |
| 음성 텍스트 변환 | Artificial Analysis 단어 오류율, Open ASR Leaderboard, 속도 배율 |
| 음악 | Artificial Analysis Music Arena(연주곡 및 보컬) |
| 임베딩 | MTEB Multilingual, RTEB 및 Venice 비공개 검색 평가 세트 |

이 세트는 분기마다 검토됩니다. 최첨단 모델이 포화 상태에 이르거나 오염 감사를 통과하지 못한 벤치마크는 대표 지표에서 제외되어 최저 기준 점검용으로 전환됩니다.

## 기계 판독 가능한 데이터 {#machine-readable-data}

이 페이지들의 기반이 되는 카탈로그는 [`/data/model-catalog.json`](https://docs.venice.ai/data/model-catalog.json)에 JSON으로 공개되며, 매시간 동기화할 때마다 다시 빌드됩니다. 비교, 분석, 에이전트에 적합합니다. 런타임에 모델을 선택하려면 [`GET /models`](/ko/api-reference/endpoint/models/list)를 호출하세요.

| 필드 | 내용 |
|---|---|
| `version` | 스키마 버전, 현재 `1` |
| `generatedAt` | 데이터를 변경한 마지막 빌드의 ISO 8601 시각 |
| `counts` | 전체 및 모달리티별 모델과 패밀리 총계 |
| `providers` | slug를 키로 하는 모델 제작사 목록, `name`과 `logo` 포함 |
| `families` | 패밀리 배열: `slug`, `name`, `modality`, `task`, `provider`, `description`, `primary`(기본 변형의 ID), `variants`(모델 ID), `created` 및 `updated`(Unix 초), `privacy`(제공되는 모든 등급), `counterpart`(모델의 E2EE 빌드 slug 또는 E2EE 빌드의 원래 모델 slug), `uncensored`, `openWeights` |
| `models` | 모델 ID를 키로 하는 객체: `name`, `type`(`GET /models`와 동일), `modality`, `task`, `variant`, `provider`, `family`(소속 패밀리의 slug), `privacy`, 모달리티 이름을 딴 제한 및 기능 블록 하나(`text`, `image`, `video`, `audio` 또는 `embedding`), 기본 단위의 `pricing`, `headline`(위의 참조 가격), `media`(참조 렌더링), `benchmarks`(아래 벤치마크 점수에서 텍스트 모델의 항목) |
| `benchmarks` | ID를 키로 하는 벤치마크 정의로, 각각 `name`과 `source`를 포함합니다. `venice`는 Venice가 API를 통해 직접 실행한 결과입니다 |
| `mediaSuite` | 모달리티별 참조 프롬프트 세트 |

값이 없는 필드는 생략됩니다. 가격은 USD 기준입니다.

[성능 수치](#performance)는 별도 파일인 [`/data/model-performance.json`](https://docs.venice.ai/data/model-performance.json)에 있으며, 이 파일도 매시간 동기화할 때마다 갱신됩니다.

| 필드 | 내용 |
|---|---|
| `version` | 스키마 버전, 현재 `1` |
| `source` | 수치를 복사해 온 출처 |
| `generatedAt` | Venice가 수치를 계산한 ISO 8601 시각 |
| `window` | 24시간의 `start` 및 `end` |
| `models` | 모델 ID를 키로 하는 객체: `uptime`(24시간 가동률, 내림 처리: 요청이 1,000건 미만이면 정수 백분율, 그 이상이면 소수점 첫째 자리), `ttftMs`(첫 토큰까지의 시간(밀리초), `1h`, `4h`, `24h`별 `p50` 및 `p90`), `tokensPerSecond`(같은 기간의 초당 토큰 기준 출력 속도 중앙값), 첫 토큰까지의 시간과 출력 속도 차트가 그리는 내용인 `periods`: `ttftMs`, `tokensPerSecond`, `uptime` 각각에 구간 길이인 `minutes`와 구간별 수치 하나씩을 오래된 순으로 담은 `values`(요청이 없는 구간은 null)가 있으며, 가동률 차트가 그리는 내용인 `uptimeStatus`는 기간의 15분 단위 구간을 하나의 문자로, 오래된 순으로 나타냅니다: `u` 정상, `d` 성능 저하(95% 미만), `x` 중단(80% 미만), `-` 요청 없음. `uptimeQuarters`는 15분 단위 구간별 가동률을 정수 백분율로, 오래된 순으로 나타냅니다. 요청이 100건 미만이면 실패가 없을 때만 100으로 표시되고, 그렇지 않으면 null입니다. 요청이 충분하지 않은 수치는 생략됩니다. |

Venice 자체 벤치마크 점수도 별도 파일인 [`/data/model-benchmarks.json`](https://docs.venice.ai/data/model-benchmarks.json)에 있으며, 새 실행 결과가 나오면 매시간 동기화 때 갱신됩니다.

| 필드 | 내용 |
|---|---|
| `version` | 스키마 버전, 현재 `1` |
| `source` | 점수를 복사해 온 출처 |
| `generatedAt` | Venice가 점수를 공개한 ISO 8601 시각 |
| `benchmarks` | 카탈로그와 같은 벤치마크 정의 |
| `results` | 모델 ID, 그다음 벤치마크 ID를 키로 하는 객체: 추론 설정마다 실행 하나씩이며, 순서는 `off`, `default`, 그다음 가장 낮은 강도부터 가장 높은 강도입니다. 각 실행에는 `reasoning`(`off`, 실행이 추론 매개변수를 보내지 않은 경우 `default`, 또는 설정한 `reasoning_effort`), `accuracy`(정답을 맞힌 샘플의 백분율), `ci95`(95% 신뢰 구간 폭의 절반, 포인트 단위), `samples`, `outputTokens` 및 `reasoningTokens`(샘플당, 실행에서 집계하지 않은 경우 `null`), `measuredOn`(실행의 UTC 날짜), `harness`(실행한 하네스의 버전)가 있습니다. |

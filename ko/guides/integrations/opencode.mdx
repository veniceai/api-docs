[OpenCode](https://opencode.ai/)는 터미널용 AI 코딩 에이전트입니다. OpenCode에는 이미 Venice AI 제공자가 포함되어 있으므로 명령 한 번으로 연결하고 전체 Venice 카탈로그에서 모델을 고를 수 있습니다. 구성 파일은 필요하지 않습니다.

<Note>
  이 가이드는 표준 설치 프로그램이 설치하는 OpenCode 1을 기준으로 합니다. OpenCode 2에도 Venice AI가 포함되어 있으며 일부 레이블만 다릅니다. [OpenCode 2](#opencode-2)를 참조하세요.
</Note>

## 사전 요구 사항 {#prerequisites}

- [venice.ai/settings/api](https://venice.ai/settings/api?utm_source=venice-api-documentation)에서 받은 Venice API 키
- 설치되어 작동 중인 OpenCode

---

## 설정 {#setup}

<Steps>
  <Step title="Venice AI 연결">
    OpenCode를 실행하고 연결 명령을 실행하세요:

    ```txt
    /connect
    ```

    **Venice AI**를 검색해 선택하세요.

    <Frame as="div">
      <img
        src="/images/guides/opencode/connect-venice.png"
        alt="Venice AI로 필터링된 OpenCode의 /connect 팔레트"
      />
    </Frame>
  </Step>

  <Step title="Venice API 키 붙여넣기">
    **API key** 필드에 키를 붙여넣고 Enter를 누르세요.

    OpenCode는 자격 증명을 `~/.local/share/opencode/auth.json`에 저장하므로 모든 프로젝트에서 계속 사용할 수 있습니다.
  </Step>

  <Step title="모델 선택">
    모델 명령을 실행하고 Venice 모델을 선택하세요:

    ```txt
    /models
    ```

    `z-ai-glm-5-3-flash`는 코딩용 기본 모델로 적합합니다. 빠르고 저렴하며 1M 토큰 컨텍스트 창을 제공합니다. 다른 옵션은 [모델 ID](#model-ids)를 참고하세요.

    OpenCode는 자체 호스팅 무료 티어도 비슷한 이름으로 표시합니다. 예를 들어 **OpenCode**의 **GLM-5.3-Flash Free**가 **Venice AI**의 **GLM 5.3 Flash** 옆에 표시됩니다. 오른쪽 열의 제공자 이름으로 둘을 구분할 수 있으며, Venice AI 행이 사용자의 키와 크레딧을 사용합니다.
  </Step>
</Steps>

전체 흐름을 확인하려면 작은 작업을 보내 보세요. 예를 들면 다음과 같습니다:

```txt
Review the current file and suggest one safe improvement.
```

## 기본 모델 고정 {#pin-a-default-model}

연결 후 OpenCode는 새 세션을 Claude Sonnet 4.6 같은 라우팅 모델로 시작할 수 있으며, 이 모델은 [모델 ID](#model-ids)의 모델보다 비쌉니다. OpenCode가 시작할 때 사용할 모델을 정하려면 프로젝트 루트의 `opencode.json`(또는 전역 기본값의 경우 `~/.config/opencode/opencode.json`)에 추가하세요:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "model": "venice/z-ai-glm-5-3-flash",
  "small_model": "venice/z-ai-glm-5-3-flash"
}
```

모델 참조는 `venice/<model-id>` 형식을 사용하며, `small_model`은 백그라운드 작업에 쓸 더 저렴한 모델을 지정합니다.

## `/connect` 없이 연결 {#connect-without-/connect}

번들 제공자는 환경에서 `VENICE_API_KEY`도 읽습니다. OpenCode를 실행하기 전에 내보내면 `/connect`를 실행하지 않아도 Venice AI 모델이 `/models`에 표시됩니다:

```bash
export VENICE_API_KEY="your-api-key"
```

번들 제공자가 포함되기 전의 OpenCode 빌드이거나 OpenCode가 표시하는 모델 목록을 고정하려면 `opencode.json`에서 Venice를 OpenAI 호환 제공자로 구성하세요. `VENICE_API_KEY`는 계속 내보낸 상태로 두세요:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "model": "venice/z-ai-glm-5-3-flash",
  "small_model": "venice/z-ai-glm-5-3-flash",
  "provider": {
    "venice": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Venice AI",
      "options": {
        "baseURL": "https://api.venice.ai/api/v1",
        "apiKey": "{env:VENICE_API_KEY}"
      },
      "models": {
        "z-ai-glm-5-3-flash": {
          "name": "GLM 5.3 Flash"
        },
        "kimi-k2-6": {
          "name": "Kimi K2.6"
        },
        "minimax-m25": {
          "name": "MiniMax M2.5"
        }
      }
    }
  }
}
```

원하는 모델을 `models` 안에 나열하세요. OpenCode는 이 제공자에 대해 여기에 선언된 항목만 표시합니다. 번들 제공자가 포함된 빌드에서는 환경 변수만으로도 전체 카탈로그를 사용할 수 있습니다.

## OpenCode 2 {#opencode-2}

OpenCode 2는 자체 설치 프로그램이 있는 별도의 릴리스 라인입니다.

```bash
curl -fsSL https://opencode.ai/v2/install | bash
```

OpenCode 2에는 네이티브 Venice AI 제공자가 포함되어 있으며, 위 설정은 몇 가지 차이점을 제외하고 그대로 작동합니다.

- `/connect` 대화 상자의 제목은 **Connect an integration**입니다. **Services**에서 **Venice AI**를 검색한 다음 **Connect Venice AI** 대화 상자에 키를 붙여 넣으세요.
- 실행 전에 `VENICE_API_KEY`를 내보내면 `/connect` 없이도 제공자가 활성화됩니다.
- 고정된 모델이 없으면 OpenCode 2는 Claude Fable 5.2 같은 라우팅 모델로 시작할 수도 있습니다.
- OpenCode 2는 여전히 OpenCode 1 구성 형식을 읽으므로 이 페이지의 `opencode.json` 예제는 계속 작동합니다. OpenCode 2 네이티브 구성에서는 `small_model` 대신 `agents.title.model`로 백그라운드 모델을 설정하세요. 나머지 네이티브 형식은 OpenCode의 [마이그레이션 가이드](https://opencode.ai/docs/migrate-v1)를 참조하세요.

## 모델 ID {#model-ids}

코딩 에이전트에서 잘 작동하는 몇 가지 Venice 모델입니다. 카탈로그는 바뀌므로 최신 목록은 [`GET /models?type=text`](/ko/api-reference/endpoint/models/list)로 확인하세요.

| 모델 | Venice ID |
|-------|-----------|
| GLM 5.3 Flash | `z-ai-glm-5-3-flash` |
| GLM 5.3 | `z-ai-glm-5-3` |
| Kimi K2.6 | `kimi-k2-6` |
| MiniMax M2.5 | `minimax-m25` |
| DeepSeek V4.1 Flash | `deepseek-v4-1-flash` |

이와 같은 오픈 웨이트 모델은 완전히 프라이빗하게 실행됩니다. Anthropic, OpenAI, Google의 라우팅 모델은 익명화되어 실행되므로 업스트림 연구소는 사용자의 신원을 알 수 없습니다.

## 구성 참고 사항 {#config-notes}

- 수동 제공자 블록에서는 `baseURL`을 `https://api.venice.ai/api/v1`로 유지하세요. 번들 제공자는 이미 이 주소를 가리킵니다.
- 제공자 ID는 `venice`이므로 두 방식 모두에서 모델 참조는 `venice/<model-id>` 형식을 사용합니다.
- 저장된 Venice 키를 바꾸려면 언제든지 `/connect`를 다시 실행하세요.
- 모델이 지원하면 컨텍스트를 넓히세요. 여러 Venice 모델이 1M 토큰을 지원합니다.

## 문제 해결 {#troubleshooting}

<AccordionGroup>
  <Accordion title="/connect에 Venice AI가 없음">
    `opencode upgrade`로 OpenCode를 최신 1.x 릴리스로 업데이트하세요. Venice AI 제공자는 현재 빌드에 포함되어 있으므로, 오래된 설치에서는 위의 수동 구성 방법만 사용할 수 있습니다.
  </Accordion>
  <Accordion title="잘못된 API 키 또는 401">
    키가 [venice.ai/settings/api](https://venice.ai/settings/api?utm_source=venice-api-documentation)에서 발급된 것인지 확인한 뒤 `/connect`를 실행하고 **Venice AI**를 선택해 다시 붙여넣으세요. 저장된 키가 만료되면 OpenCode는 Venice에 연결하지 않고 인증 실패를 보고합니다.
  </Accordion>
  <Accordion title="모델을 사용할 수 없음">
    [모델 ID](#model-ids), [텍스트 모델 카탈로그](/ko/models/text) 또는 `GET /models`에서 ID를 정확히 복사하고, Venice 계정에 해당 모델에 대한 액세스 권한이 있는지 확인하세요.
  </Accordion>
  <Accordion title="여전히 해결되지 않나요? 에이전트가 보내는 내용을 확인하세요">
    OpenCode와 Venice 사이에 [로컬 디버깅 프록시](/ko/learn/local-debug-proxy)를 실행해 모든 요청과 응답을 기록하세요. 에이전트가 실제로 보낸 모델 ID, 도구, 오류 본문과 사용한 키의 마지막 네 글자까지 확인할 수 있습니다.
  </Accordion>
</AccordionGroup>

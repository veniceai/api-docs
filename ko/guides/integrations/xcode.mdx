[Xcode](https://developer.apple.com/xcode/)에는 프로젝트에 대한 질문에 답하고, 코드를 작성 및 리팩터링하고, 오류를 수정할 수 있는 코딩 어시스턴트가 포함되어 있습니다. Xcode는 기본 제공 프로바이더 외에도 Chat Completions API를 지원하는 모든 채팅 프로바이더를 허용하므로, Xcode의 Intelligence 설정에서 Venice를 추가하고 코딩 어시스턴트 대화에서 Venice 모델을 사용할 수 있습니다.

## 사전 요구 사항

- [venice.ai/settings/api](https://venice.ai/settings/api?utm_source=venice-api-documentation)에서 받은 Venice API 키
- [Xcode](https://developer.apple.com/xcode/) 26.3 이상 (이전 Xcode 26 릴리스에서는 Xcode를 다시 실행할 때 사용자 지정 채팅 프로바이더가 사라질 수 있습니다)
- macOS Tahoe 26 이상 (Xcode 27은 macOS Tahoe 26.6 이상과 Apple silicon Mac이 필요합니다)

## 설정

<Steps>
  <Step title="Venice API 키 발급">
    [venice.ai/settings/api](https://venice.ai/settings/api?utm_source=venice-api-documentation)에서 키를 생성하세요. Xcode에는 **Inference Only** 키면 충분합니다.

    **Epoch Consumption Limit**이 설정된 전용 키를 만드는 것을 고려하세요. 이렇게 하면 Xcode의 지출 한도를 정할 수 있고, 다른 앱에 영향을 주지 않고 키를 폐기할 수 있습니다. [API 키 생성](/ko/guides/getting-started/generating-api-key)을 참조하세요.
  </Step>

  <Step title="Intelligence 설정 열기">
    Xcode에서 **Xcode > Settings**를 선택하고 사이드바에서 **Intelligence**를 선택하세요.
  </Step>

  <Step title="Venice를 채팅 프로바이더로 추가">
    **Chat** 아래에서 **Add a Chat Provider**를 클릭하고 **Internet Hosted**를 선택하세요. 일부 Xcode 26 릴리스에서는 이 버튼의 이름이 **Add a Model Provider**입니다.

    다음 값을 입력한 후 **Add**를 클릭하세요:

    | 필드 | 값 |
    | --- | --- |
    | URL | `https://api.venice.ai/api` |
    | API Key | `Bearer your-venice-api-key` |
    | API Key Header | `Authorization` |
    | Description | `Venice` |

    URL은 `/v1`이나 후행 슬래시 없이 표시된 그대로 입력하세요. Xcode는 여기에 `/v1/models`와 `/v1/chat/completions`를 덧붙이며, 그 결과 `https://api.venice.ai/api/v1` 아래의 Venice 표준 엔드포인트가 만들어집니다.

    Xcode는 **API Key** 필드를 `Authorization` 헤더의 전체 값으로 전송합니다. `your-venice-api-key`를 실제 키로 바꾸고 `Bearer ` 접두사는 그대로 유지하세요.
  </Step>

  <Step title="모델 선택">
    **Chat** 아래에서 Venice 프로바이더를 선택하세요. Xcode가 Venice에서 모델 목록을 가져옵니다. 사용하려는 모델을 켜고, 가장 자주 사용하는 모델에 별표를 표시하면 모델 메뉴 상단에 나타납니다.

    목록에는 모든 Venice 텍스트 모델이 포함되지만, 코딩 어시스턴트는 도구 호출(tool calling)을 지원하는 모델에서만 작동합니다. 선택하기 전에 [모델 요구 사항](#모델-요구-사항)을 확인하거나, `z-ai-glm-5-3-flash`로 시작하세요.
  </Step>

  <Step title="대화 시작">
    프로젝트를 연 다음 **Coding Assistant** 버튼을 클릭하거나 **Command-0**을 누르세요. **New Conversation**을 클릭하고 **Chat** 아래에서 Venice 모델을 선택하세요. 메시지 필드의 자리 표시자 텍스트에 대화에서 사용하는 모델이 표시됩니다.

    연결을 테스트하려면 짧은 프롬프트를 보내세요:

    ```txt
    Summarize what this project does in three bullet points.
    ```
  </Step>
</Steps>

## 설정 확인

테스트 프롬프트를 보내는 것이 실제 확인 방법입니다. Venice의 `GET /models` 엔드포인트는 유효한 키 유무와 관계없이 카탈로그를 반환하므로, Xcode에 전체 모델 목록이 표시된다고 해서 키가 작동한다는 의미는 아닙니다. Venice는 메시지를 보낼 때만 키를 확인합니다.

프롬프트가 실패하면 Xcode 외부에서 API 키를 확인하세요:

```bash
curl https://api.venice.ai/api/v1/api_keys/rate_limits \
  -H "Authorization: Bearer $VENICE_API_KEY"
```

이 엔드포인트는 유효한 키가 필요하므로, 여기서 `401`이 반환되면 Xcode 구성이 아니라 키에 문제가 있는 것입니다. 키가 작동한다면 프로바이더 설정을 [문제 해결](#문제-해결)과 비교해 보세요.

## 모델 요구 사항

<Warning>
**모델이 도구 호출을 지원해야 합니다.** 채팅 대화에서 Xcode는 프로젝트를 검색하고 편집하기 위한 도구를 모델에 제공하므로, 도구 호출을 지원하지 않는 모델은 코딩 어시스턴트의 요청을 처리할 수 없습니다.
</Warning>

[텍스트 모델 카탈로그](/ko/models/text)에서는 이 기능을 **Function Calling**으로 표시하며, 대부분의 Venice 텍스트 모델이 이를 지원합니다.

이상적으로는 모델의 컨텍스트 윈도우가 200K 토큰 이상이어야 합니다. Xcode에는 채팅 프로바이더용 컨텍스트 윈도우 설정이 없으며, **Project Context**가 켜져 있으면 요청에 Xcode의 도구 정의 외에도 많은 양의 프로젝트 코드가 포함될 수 있습니다.

두 요구 사항을 모두 충족하는 Venice 모델을 나열하려면:

```bash
curl -s https://api.venice.ai/api/v1/models \
  | jq -r '.data[] | select(.model_spec.capabilities.supportsFunctionCalling and .model_spec.availableContextTokens >= 200000) | .id'
```

## 모델 선택

다음 모델은 두 요구 사항을 모두 충족합니다:

| 사용 사례 | 예시 모델 ID |
| --- | --- |
| 코딩 | `deepseek-v4-pro-0813` |
| 저비용 | `z-ai-glm-5-3-flash` |
| 가장 어려운 작업 | `grok-4-7` |
| **Upload files**를 사용한 스크린샷 및 목업 | `qwen-3-8-27b` |

다른 모델을 비교할 때:

- [`GET /models/traits?type=text`](/ko/api-reference/endpoint/models/traits)는 코딩용 `default_code` 등 Venice의 현재 추천 모델을 반환합니다.
- **Project Context**는 요청을 크게 만들므로 입력 토큰 가격이 평소보다 더 중요합니다. [텍스트 모델 카탈로그](/ko/models/text)에서 가격을 비교하세요.

Venice는 정기적으로 모델을 지원 종료하고 교체합니다. 모델이 작동을 멈추면 [지원 중단](/ko/overview/deprecations)을 확인하고 현재 모델로 전환하세요.

## 에이전트

채팅 프로바이더는 채팅 대화에만 사용됩니다. Claude Agent 및 Codex와 같은 Xcode의 기본 제공 에이전트와 Agent Client Protocol(ACP)을 통해 추가한 에이전트는 별도로 구성되며 채팅 프로바이더를 통해 요청을 보내지 않습니다. 또한 에이전트는 앱 빌드 및 테스트 등 채팅보다 더 많은 Xcode 기능을 사용할 수 있습니다.

Xcode 프로젝트에 접근할 수 있는 에이전트를 Venice 모델로 실행하려면, 터미널 에이전트를 Venice용으로 구성하고 Xcode 26.3 이상에서 제공하는 Model Context Protocol(MCP) 서버에 연결하세요:

<Steps>
  <Step title="외부 에이전트 허용">
    Xcode의 Intelligence 설정에서 **Model Context Protocol** 아래의 **Allow external agents to use Xcode tools**를 켜세요.
  </Step>

  <Step title="Venice로 에이전트 설정">
    [Codex CLI](/ko/guides/integrations/codex-cli) 또는 [Claude Code](/ko/guides/integrations/claude-code) 가이드를 따르세요.
  </Step>

  <Step title="에이전트를 Xcode에 연결">
    Xcode의 MCP 서버를 에이전트에 등록하세요:

    <CodeGroup>
    ```bash Codex CLI
    codex mcp add xcode -- xcrun mcpbridge
    ```

    ```bash Claude Code
    claude mcp add --transport stdio xcode -- xcrun mcpbridge
    ```
    </CodeGroup>
  </Step>

  <Step title="에이전트에 프롬프트 보내기">
    먼저 Xcode에서 프로젝트를 연 다음, 터미널에서 에이전트에 프롬프트를 보내세요. 에이전트가 연결되면 Xcode가 알림을 표시합니다.
  </Step>
</Steps>

## 프라이버시

Xcode는 Mac에서 Venice로 채팅 요청을 직접 전송합니다. 채팅 대화에서는 **Project Context**가 기본적으로 켜져 있으므로, Xcode는 각 요청에 프로젝트의 관련 코드와 기타 컨텍스트를 포함합니다. Xcode가 전송하는 내용을 제한하려면 메시지 필드에서 **Project Context**를 끄고 `@`를 사용해 파일과 심볼을 명시적으로 참조하세요.

Venice는 프록시에서 프롬프트 및 응답 내용을 저장하거나 기록하지 않습니다. 선택한 모델에 따라 런타임 프라이버시 등급이 결정됩니다:

- **Private** 모델은 데이터 무보존(zero-data-retention) 인프라를 사용합니다.
- **Anonymized** 모델은 업스트림 프로바이더로부터 사용자의 신원을 숨기지만, 해당 프로바이더가 코드를 처리할 수 있습니다.
- `e2ee-` 모델 ID를 가진 **TEE** 모델은 하드웨어 엔클레이브 내부에서 실행됩니다. Xcode는 Mac에서 프롬프트를 암호화할 수 없으므로, Xcode에서 이 모델을 사용할 때는 종단 간 암호화 모드가 아닌 TEE 모드로 실행됩니다.

독점 코드를 보내기 전에 [텍스트 모델 카탈로그](/ko/models/text)에서 각 모델의 프라이버시 레이블을 확인하고 [Venice 프라이버시](/ko/overview/privacy)를 읽어보세요.

## 문제 해결

<AccordionGroup>
  <Accordion title="401 또는 인증 오류">
    **API Key**가 `Bearer ` 뒤에 [venice.ai/settings/api](https://venice.ai/settings/api?utm_source=venice-api-documentation)에서 받은 Venice 키가 추가 공백 없이 이어지는 형태인지 확인하세요. 모델 목록은 공개되어 있으므로 Xcode는 잘못된 키로도 모델 목록을 불러오며, 인증 오류는 메시지를 보낼 때만 나타납니다. [설정 확인](#설정-확인)의 명령으로 키를 테스트하세요.
  </Accordion>
  <Accordion title="Xcode가 모델을 불러오지 못하거나 프로바이더를 거부하는 경우">
    URL이 정확히 `https://api.venice.ai/api`인지 확인하세요. URL이 `/v1`로 끝나면 Xcode가 `/api/v1/v1/models`를 요청하고, 후행 슬래시가 있으면 `/api//v1/models`가 됩니다. Venice는 두 경우 모두 `404`를 반환합니다. 수정된 URL로 프로바이더를 다시 추가하세요.
  </Accordion>
  <Accordion title="메시지를 보낼 때 엔드포인트 오류가 발생하는 경우">
    대화에서 도구 호출을 지원하고, 이상적으로는 컨텍스트 윈도우가 200K 토큰 이상인 모델을 사용하는지 확인하세요. Xcode는 각 요청에 도구 정의와 프로젝트 컨텍스트를 함께 보냅니다. 도구 호출을 지원하지 않는 모델은 이를 처리할 수 없으며, 큰 프로젝트는 작은 컨텍스트 윈도우를 초과할 수 있습니다. [모델 요구 사항](#모델-요구-사항)을 충족하는 모델을 켠 다음 해당 모델로 새 대화를 시작하세요.
  </Accordion>
  <Accordion title="402 또는 결제 필요 오류">
    Venice는 두 가지 경우에 `402`를 반환합니다:

    - 요청이 `Authorization` 헤더 없이 Venice에 도달한 경우. Venice는 `x-api-key` 같은 다른 헤더를 무시하고 x402 결제 챌린지로 응답합니다. **API Key Header**를 `Authorization`으로 설정하세요.
    - 키가 지출 한도에 도달했거나 잔액이 소진된 경우. [지출 한도 오류 문제 해결](/ko/guides/getting-started/generating-api-key#지출-한도-오류-해결하기)을 참조하세요.
  </Accordion>
  <Accordion title="모델을 찾을 수 없는 경우">
    Venice가 해당 모델을 지원 종료했을 수 있습니다. [지원 중단](/ko/overview/deprecations)을 확인하고, 프로바이더의 모델 목록에서 현재 모델을 선택한 다음 새 대화를 시작하세요.
  </Accordion>
</AccordionGroup>

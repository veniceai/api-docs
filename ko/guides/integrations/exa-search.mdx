[Exa](https://exa.ai)는 AI 에이전트를 위해 만들어진 웹 검색 엔진입니다. Venice의 [웹 검색 엔드포인트](/ko/api-reference/endpoint/augment/search)는 쿼리를 Exa에서 실행할 수 있습니다. `search_provider`를 `"exa"`로 설정하면 Venice가 Zero Data Retention 조건으로 Exa에서 검색을 실행합니다. 인증은 Venice API 키로 하고, 검색 요금은 Venice가 청구하므로 Exa 계정이 필요하지 않습니다.

결과는 모든 제공자에서 동일한 형식으로 반환되므로, Venice의 기본 Brave 검색으로 구축한 어떤 시스템에도 Exa를 그대로 끼워 넣을 수 있으며 제공자 전환은 필드 하나만 바꾸면 됩니다. 이 가이드에서는 엔드포인트 호출, Venice 모델에 Exa 검색을 도구로 제공하는 방법, Exa 결과로 프롬프트를 직접 그라운딩하는 방법, 그리고 대신 Exa 자체 API를 호출해야 하는 경우를 다룹니다.

## 사전 요구 사항

- [Venice API 키](/ko/guides/getting-started/generating-api-key)
- Python 3.10 이상 또는 Node.js 22 이상
- 에이전트 예제의 경우 [함수 호출](/ko/guides/features/function-calling)을 지원하는 Venice 모델. 예제에서는 `z-ai-glm-5-3-flash`를 사용합니다.

## 설정

OpenAI SDK를 설치하고, Python의 경우 `requests`도 설치하세요. Node.js에는 `fetch`가 내장되어 있습니다:


## Exa로 검색하기

`search_provider`를 `"exa"`로 설정하여 `/augment/search`로 쿼리를 보내세요:

<CodeGroup>
```python Python
import os

import requests

response = requests.post(
    "https://api.venice.ai/api/v1/augment/search",
    headers={"Authorization": f"Bearer {os.environ['VENICE_API_KEY']}"},
    json={
        "query": "open-source alternatives to vector databases",
        "limit": 5,
        "search_provider": "exa",
    },
    timeout=60,
)
response.raise_for_status()

for result in response.json()["results"]:
    print(result["title"], result["url"])
```

```javascript Node.js
const response = await fetch("https://api.venice.ai/api/v1/augment/search", {
  method: "POST",
  headers: {
    Authorization: `Bearer ${process.env.VENICE_API_KEY}`,

for (const result of (await response.json()).results) {
  console.log(result.title, result.url);
}
```

```bash cURL
  -H "Authorization: Bearer $VENICE_API_KEY" \
```

</CodeGroup>

응답에는 쿼리와 결과 목록이 포함되며, 각 결과에는 네 개의 필드가 있습니다:

```json
{
  "query": "open-source alternatives to vector databases",
  "results": [
    {
      "title": "Page title",
      "url": "https://example.com/article",
      "content": "Page text, up to about 10,000 characters",
      "date": "Publication date, or an empty string"
    }
  ]
}
```

`limit`의 기본값은 10이며 1에서 20까지 허용되고, `query`는 1자에서 400자까지 허용됩니다. 이 범위를 벗어난 값은 범위 내로 조정되지 않고 `400`을 반환합니다. 많은 페이지가 날짜를 게시하지 않으므로 `date`는 선택 사항으로 취급하세요.

## Venice 모델에 Exa 검색 제공하기

모델이 언제 무엇을 검색할지 결정하게 하려면, 채팅 요청의 `tools` 배열에 `web_search` 함수를 기술하고 모델이 이를 호출할 때마다 직접 검색을 실행하세요. 이 프로그램은 위의 요청을 검색 헬퍼로 감싸고, 결과를 `tool` 메시지로 모델에 반환하며, 모델이 텍스트로 답할 때까지 반복합니다:

<CodeGroup>
```python Python
import json
import os

import requests
from openai import OpenAI

BASE_URL = "https://api.venice.ai/api/v1"
VENICE_API_KEY = os.environ["VENICE_API_KEY"]
MODEL = "z-ai-glm-5-3-flash"

venice = OpenAI(api_key=VENICE_API_KEY, base_url=BASE_URL)

SYSTEM_PROMPT = "Search the web for recent or specific facts. Cite the URL of each source."
TOOLS = [
    {
        "type": "function",
        "function": {
            "name": "web_search",
            "description": "Search the web with Exa. Describe the pages to find in natural language.",
            "parameters": {
                "type": "object",
                "properties": {"query": {"type": "string"}},
                "required": ["query"],
            },
        },
    }
]


def exa_search(query: str, limit: int = 5) -> list[dict]:
    response = requests.post(
        f"{BASE_URL}/augment/search",
        headers={"Authorization": f"Bearer {VENICE_API_KEY}"},
        json={"query": query, "limit": limit, "search_provider": "exa"},
        timeout=60,
    )
    response.raise_for_status()
    return response.json()["results"]


def run_search(call) -> str:
    try:
        query = json.loads(call.function.arguments)["query"]
        return json.dumps(exa_search(query[:400]))
    except Exception as error:
        return f"Error: {error}"


def ask(question: str, max_rounds: int = 6) -> str:
    messages = [
        {"role": "system", "content": SYSTEM_PROMPT},
        {"role": "user", "content": question},
    ]
    for _ in range(max_rounds):
        completion = venice.chat.completions.create(
            model=MODEL,
            messages=messages,
            tools=TOOLS,
            extra_body={"venice_parameters": {"include_venice_system_prompt": False}},
        )
        message = completion.choices[0].message
        if not message.tool_calls:
            return message.content
        messages.append(message)
        for call in message.tool_calls:
            messages.append({"role": "tool", "tool_call_id": call.id, "content": run_search(call)})
    raise RuntimeError(f"No answer after {max_rounds} rounds")


print(ask("What changed in the latest stable release of Python?"))
```

```javascript Node.js
import OpenAI from "openai";

const BASE_URL = "https://api.venice.ai/api/v1";
const MODEL = "z-ai-glm-5-3-flash";

const venice = new OpenAI({ apiKey: process.env.VENICE_API_KEY, baseURL: BASE_URL });

const SYSTEM_PROMPT = "Search the web for recent or specific facts. Cite the URL of each source.";
const tools = [
  {
    type: "function",
    function: {
      name: "web_search",
      description: "Search the web with Exa. Describe the pages to find in natural language.",
      parameters: {
        type: "object",
        properties: { query: { type: "string" } },
        required: ["query"],
      },
    },
  },
];

async function exaSearch(query, limit = 5) {
  const response = await fetch(`${BASE_URL}/augment/search`, {
    method: "POST",
    headers: {
      Authorization: `Bearer ${process.env.VENICE_API_KEY}`,
      "Content-Type": "application/json",
    },
    body: JSON.stringify({ query, limit, search_provider: "exa" }),
  });
  if (!response.ok) throw new Error(`${response.status}: ${await response.text()}`);
  return (await response.json()).results;
}

async function runSearch(call) {
  try {
    const { query } = JSON.parse(call.function.arguments);
    return JSON.stringify(await exaSearch(query.slice(0, 400)));
  } catch (error) {
    return `Error: ${error.message}`;
  }
}

async function ask(question, maxRounds = 6) {
  const messages = [
    { role: "system", content: SYSTEM_PROMPT },
    { role: "user", content: question },
  ];
  for (let round = 0; round < maxRounds; round++) {
    const completion = await venice.chat.completions.create({
      model: MODEL,
      messages,
      tools,
      venice_parameters: { include_venice_system_prompt: false },
    });
    const message = completion.choices[0].message;
    if (!message.tool_calls?.length) return message.content;
    messages.push(message);
    for (const call of message.tool_calls) {
      messages.push({ role: "tool", tool_call_id: call.id, content: await runSearch(call) });
    }
  }
  throw new Error(`No answer after ${maxRounds} rounds`);
}

console.log(await ask("What changed in the latest stable release of Python?"));
```
</CodeGroup>

모델은 쿼리만 작성합니다. 제공자, 결과 수, 검색 실패 시 처리 방식 등 나머지는 모두 코드가 결정합니다. 루프를 수정할 때 유지할 만한 세 가지 세부 사항이 있습니다:

- **모델이 작성한 쿼리를 잘라내세요.** 엔드포인트는 400자를 초과하는 쿼리를 줄이지 않고 거부하며, 모델은 때때로 긴 쿼리를 작성합니다.
- **오류를 도구 결과로 반환하세요.** 실패한 검색은 `Error:`로 시작하는 도구 메시지가 되므로, 루프가 중단되는 대신 모델이 다른 쿼리를 시도하거나 실패를 설명할 수 있습니다.
- **도구 결과보다 어시스턴트 메시지를 먼저 추가하세요.** 모든 `tool` 메시지는 이를 요청한 어시스턴트 턴 뒤에 와야 합니다. 메시지 객체 자체를 추가하면 GLM 5.3 Flash 같은 추론 모델이 반환하는 `reasoning_content`도 유지되므로, 모델이 라운드 간에 추론을 이어갈 수 있습니다.

각 결과의 `content`는 최대 약 10,000자의 페이지 텍스트이므로, 모델은 대개 검색 결과만으로 답변할 수 있습니다. 전체 페이지가 필요한 경우 페이지를 Markdown으로 반환하는 [`/augment/scrape`](/ko/api-reference/endpoint/augment/scrape)를 호출하는 두 번째 도구를 추가하세요.

## 먼저 검색한 후 생성하기

함수 호출을 사용하면 모델이 언제 무엇을 검색할지 결정합니다. 코드가 이미 무엇을 검색할지 알고 있다면 도구 루프를 생략할 수 있습니다. Exa 검색을 한 번 실행하고, 결과에 번호를 매긴 뒤, Venice에 그 결과를 바탕으로 답변하도록 요청하세요. 이 방식은 모든 Venice 텍스트 모델에서 동작하며, 프롬프트에 들어간 소스 목록을 직접 보관하므로 답변의 모든 인용이 URL로 연결됩니다.

이전 예제의 검색 헬퍼, 클라이언트, 모델을 사용합니다:

<CodeGroup>
```python Python
question = "What are the main techniques for reducing LLM inference latency?"

results = exa_search(question, limit=8)
sources = "\n\n".join(
    f"[{i}] {result['title']}\n{result['url']}\n{result['content']}"
    for i, result in enumerate(results, start=1)
)

completion = venice.chat.completions.create(
    model=MODEL,
    messages=[
        {
            "role": "system",
            "content": "Answer only from the numbered sources. Cite each claim by number, like [2].",
        },
        {"role": "user", "content": f"Question: {question}\n\nSources:\n\n{sources}"},
    ],
    extra_body={"venice_parameters": {"include_venice_system_prompt": False}},
)

print(completion.choices[0].message.content)
for i, result in enumerate(results, start=1):
    print(f"[{i}] {result['url']}")
```

```javascript Node.js
const question = "What are the main techniques for reducing LLM inference latency?";

const results = await exaSearch(question, 8);
const sources = results
  .map((r, i) => `[${i + 1}] ${r.title}\n${r.url}\n${r.content}`)
  .join("\n\n");

const completion = await venice.chat.completions.create({
  model: MODEL,
  messages: [
    {
      role: "system",
      content: "Answer only from the numbered sources. Cite each claim by number, like [2].",
    },
    { role: "user", content: `Question: ${question}\n\nSources:\n\n${sources}` },
  ],
  venice_parameters: { include_venice_system_prompt: false },
});

console.log(completion.choices[0].message.content);
results.forEach((r, i) => console.log(`[${i + 1}] ${r.url}`));
```
</CodeGroup>

[웹 검색으로 인용 답변 만들기](/ko/guides/tools/cited-web-answers)는 이 패턴을 소스 선택, 페이지 스크래핑, 로드에 실패한 페이지 처리로 확장합니다. 해당 검색 헬퍼는 제공자 인수를 받으므로 `"exa"`를 전달하면 Exa에서 실행됩니다.

## Exa API 직접 사용하기

Venice의 검색 엔드포인트는 쿼리와 결과 수를 받습니다. Exa 자체 API는 더 많은 제어 기능을 제공합니다. 뉴스, 연구 논문, 기업, 인물, 재무 보고서 카테고리, 도메인 및 날짜 필터, 쿼리 중심 하이라이트와 전체 페이지 텍스트, 심층 다단계 검색 등이 있습니다. 이를 사용하려면 [Exa 대시보드](https://dashboard.exa.ai/api-keys)에서 발급한 API 키로 Exa를 직접 호출하세요. 이러한 요청은 애플리케이션에서 Exa로 직접 전송되며, Venice가 아닌 Exa의 약관이 적용되고 Exa 계정으로 요금이 청구됩니다. Exa는 Enterprise 플랜에서 [Zero Data Retention](https://exa.ai/docs/admin/security/zero-data-retention)을 제공합니다.

Exa SDK인 `exa-py`와 `exa-js` 2.24.0 이상에는 위의 루프에 바로 넣을 수 있는 Chat Completions 형식의 도구가 포함되어 있습니다. 도구 목록을 Exa의 도구로 교체하세요:

<CodeGroup>
```python Python
from exa_py import Exa

exa = Exa()  # reads EXA_API_KEY
TOOLS = [
    exa.openai.web_search(),
    exa.openai.get_contents(text={"max_characters": 10000}),
]
```

```javascript Node.js
import Exa from "exa-js";

const exa = new Exa(); // reads EXA_API_KEY
const tools = [
  exa.openai.webSearch(),
  exa.openai.getContents({ text: { maxCharacters: 10000 } }),
];
```
</CodeGroup>

그런 다음 직접 만든 도구 실행기 대신 각 도구 호출 메시지를 SDK에 전달하세요. Python에서는 `messages += exa.openai.handle_tool_calls(message)`, Node.js에서는 `messages.push(...(await exa.openai.handleToolCalls(message)))`를 사용합니다. SDK는 각 Exa 호출을 실행하고 대응하는 `tool` 메시지를 반환하며, 실패는 `Error:` 결과로 보고됩니다. `exa-js`는 제한이 없으면 전체 페이지를 반환하므로 페이지 텍스트 제한은 유지하세요. `category`, `include_domains`, `start_published_date` 같은 키워드 인수는 Exa 검색으로 그대로 전달됩니다. 모든 옵션은 Exa의 [도구 호출 가이드](https://exa.ai/docs/integrations/tool-calling/openai)를 참조하세요.

## 권장 모델

| 사용 사례 | 모델 | 이유 |
| --- | --- | --- |
| 리서치 에이전트 | `z-ai-glm-5-3-flash` | 함수 호출을 지원하는 빠르고 저렴한 프라이빗 모델 |
| 도구 사용 기본값 | `zai-org-glm-5-2` | Venice의 현재 `function_calling_default` |
| 무검열 리서치 | `venice-uncensored-1-2` | 콘텐츠 필터링 없는 함수 호출 |

모델 ID는 변경될 수 있습니다. 런타임에 [`GET /models/traits`](/ko/api-reference/endpoint/models/traits)로 현재 함수 호출 기본 모델을 확인하거나, 함수 호출을 지원하는 다른 모델은 [텍스트 모델](/ko/models/text)에서 찾아보세요.

## 개인정보 보호

`search_provider: "exa"`를 사용하면 애플리케이션은 Venice와만 통신하며, Venice는 Zero Data Retention 조건으로 Exa에서 각 검색을 실행합니다. Venice는 프롬프트나 응답 내용을 저장하지 않으며, 추론 계층에서의 처리는 모델의 [개인정보 보호 등급](/ko/overview/privacy)에 따라 결정됩니다. 프라이빗 모델은 데이터를 보존하지 않는 인프라에서 실행됩니다.

놓치기 쉬운 부분은 모델이 대화 내용을 바탕으로 검색 쿼리를 작성하므로, 프롬프트의 세부 정보가 Exa로 전송되는 쿼리에 포함될 수 있다는 점입니다. 프롬프트에 개인 정보나 기밀 정보가 포함될 수 있다면, 시스템 프롬프트에서 해당 정보를 검색에 포함하지 않도록 모델에 지시하거나, [먼저 검색하는 패턴](#먼저-검색한-후-생성하기)을 사용해 모든 쿼리를 코드가 직접 작성하도록 하세요.

[Exa API를 직접 호출](#exa-api-직접-사용하기)하는 경우, 해당 요청은 Exa의 약관에 따라 Exa로 전송됩니다.

## 비용

검색 1회당 비용은 $0.01(1,000회당 $10)로 Brave 또는 Google 검색과 같습니다. Venice는 채팅 요청에 사용된 토큰과 함께 Venice 계정으로 청구하므로 별도의 Exa 청구서는 없습니다. 오류로 실패한 검색은 청구되지 않지만, 결과가 비어 있는 검색은 청구됩니다. 검색 결과는 다음 라운드에서 모델의 입력으로 다시 전달되며, 페이지 텍스트를 포함하므로 결과 5개짜리 검색은 흔히 5,000~10,000개의 입력 토큰을 추가합니다. 다음 습관으로 두 비용을 모두 줄일 수 있습니다:

- 소수의 소스로 충분하다면 `limit`을 낮추세요. 검색 비용은 `limit`과 관계없이 같지만, 결과가 적을수록 다음 라운드의 입력 토큰이 줄어듭니다.
- `max_rounds`를 낮게 유지하세요. 라운드가 늘어날 때마다 토큰뿐 아니라 검색도 추가될 수 있습니다.
- 코드가 무엇을 검색할지 알고 있다면 먼저 검색하는 패턴을 사용하세요. 정확히 한 번의 검색과 한 번의 채팅 요청만 실행합니다.

<Tip>
암호화폐 지갑이 있는 에이전트는 API 키 없이 사용할 수 있습니다. `/augment/search`와 `/chat/completions`는 모두 [x402 지갑 인증](/ko/guides/integrations/x402-venice-api)을 지원하므로, 에이전트는 하나의 선불 USDC 잔액으로 Exa 검색과 추론 비용을 모두 지불할 수 있습니다.
</Tip>

## 문제 해결

<AccordionGroup>
  <Accordion title="401 Unauthorized 또는 자격 증명 누락">
    코드를 실행하는 프로세스에 `VENICE_API_KEY`가 설정되어 있는지 확인하세요. 설정되지 않은 경우 Python은 `KeyError: 'VENICE_API_KEY'`를 발생시키고, Node.js OpenAI SDK는 `OPENAI_API_KEY`로 대체합니다. 그것도 설정되지 않았다면 `Missing credentials` 오류가 발생합니다. 설정되어 있다면 SDK가 OpenAI 키를 Venice로 보내고, Venice는 `401`로 거부합니다. `VENICE_API_KEY`가 설정된 상태에서 `401`이 발생한다면 Venice가 키 자체를 거부한 것이므로, 오타가 없는지 확인하거나 [새 키를 생성](/ko/guides/getting-started/generating-api-key)하세요.
  </Accordion>

  <Accordion title="검색 엔드포인트의 400 오류">
    `query`는 1자에서 400자, `limit`은 1에서 20 사이여야 하며, `search_provider`는 `brave`, `google`, `exa` 중 하나여야 합니다. 이 범위를 벗어난 값은 범위 내로 조정되지 않고 거부됩니다. 도구 루프에서는 거부된 검색이 예외를 발생시키는 대신 `Error:` 도구 결과로 모델에 전달됩니다.
  </Accordion>

  <Accordion title="402 Payment Required">
    Venice 잔액이 요청 비용을 충당하지 못합니다. API 키로 보낸 요청은 `INSUFFICIENT_BALANCE`를 반환하므로 Venice 잔액을 충전하세요. x402 지갑 인증으로 보낸 요청은 응답에 충전 안내를 반환합니다.
  </Accordion>

  <Accordion title="도구 라운드 이후 Venice의 400 오류">
    Claude 및 GPT 모델을 포함한 일부 모델은 도구 호출 뒤에 해당 `tool_call_id`를 가진 `tool` 메시지가 오지 않으면 `400`을 반환합니다. GLM 모델은 이런 대화도 그대로 받아들이므로, 이 오류는 모델을 전환할 때 처음 나타날 수 있습니다. 루프는 모든 호출에 대해 이를 요청한 어시스턴트 메시지 바로 뒤에서 응답하므로, 도구를 추가할 때도 이 구조를 유지하세요.
  </Accordion>

  <Accordion title="모델이 검색하지 않고 답변하는 경우">
    모델이 함수 호출을 지원하는지 확인하고, 시스템 프롬프트에서 언제 검색해야 하는지 명시하세요. 최신 정보나 구체적인 사실을 검색하라고 지시하지 않으면, 모델은 기억만으로 답할 수 있다고 판단할 때 도구를 건너뛰는 경우가 많습니다.
  </Accordion>
</AccordionGroup>

Venice의 이미지 편집은 동기 방식입니다. 원본 이미지를 `/image/edit` 또는 `/image/multi-edit`로 보내면 편집된 결과가 같은 응답에 이미지 파일로 돌아옵니다. 누끼 작업에는 `/image/background-remove`가 투명한 PNG를 반환합니다.

<Warning>
이미지 편집 endpoint는 실험적이며 모델별 동작은 시간이 지남에 따라 변경될 수 있습니다.
</Warning>

## Endpoint

| Endpoint | Purpose | Best for |
|---|---|---|
| `POST /image/edit` | prompt로 단일 이미지 편집 | 일반 편집과 prompt 기반 inpainting |
| `POST /image/multi-edit` | 여러 장의 참조 이미지로 편집(상한은 모델별로 다름) | 합성 및 다중 참조 편집 |
| `POST /image/background-remove` | 이미지에서 배경 제거 | 제품, 인물, 자산을 위한 투명 컷아웃 |

<Note>
Venice에는 OpenAI 호환 `/images/edits` 엔드포인트가 없으므로 `client.images.edit()` 같은 OpenAI SDK 호출은 `404`를 반환합니다. 대신 `/image/edit`로 편집 요청을 보내세요.
</Note>

## 어떤 endpoint를 언제 사용하나요

- 원본 이미지가 하나이고 prompt로 일부를 변경, 제거, 재스타일링하고 싶다면 `/image/edit`를 사용하세요.
- 추가 참조 이미지를 기반으로 편집을 조정해야 하면 `/image/multi-edit`를 사용하세요.
- 깔끔한 전경 피사체와 투명도만 원한다면 `/image/background-remove`를 사용하세요.

<Note>
Inpainting에는 `/image/edit` 또는 `/image/multi-edit`를 사용하세요. `/image/generate`의 기존 `inpaint` 파라미터는 deprecated입니다.
</Note>

<Tip>
편집 endpoint에서 `enhance_prompt: true`로 설정하면, 비전 인식 enhancer가 입력 이미지 하나 또는 여러 개를 분석해 편집 전에 지시를 다시 작성합니다. 동작 방식, 가격, 응답 헤더 관련 세부 정보는 [Prompt Enhancement](/ko/guides/media/prompt-enhancement)를 참조하세요.
</Tip>

## 1단계: 단일 이미지 편집

단일 이미지 편집은 가장 단순한 inpainting 흐름입니다. 이미지 한 장과 "remove the sign", "change the sky to sunrise", "replace the background with a studio backdrop" 같은 짧은 prompt를 함께 보내세요.

**요청:**
```bash
POST https://api.venice.ai/api/v1/image/edit
Authorization: Bearer $VENICE_API_KEY
Content-Type: application/json

{
  "model": "firered-image-edit",
  "prompt": "Replace the cloudy sky with a warm sunrise while preserving the buildings and canal",
  "image": "https://example.com/venice-canal.jpg"
}
```

**응답(200):**
응답 본문은 raw 이미지 바이너리 데이터입니다. 그대로 파일에 저장하세요. 포맷은 1K 편집에서는 PNG, 2K 및 4K 편집에서는 JPEG이며, `transparent_background`가 `true`이면 해상도와 관계없이 PNG입니다. 포맷을 명시적으로 선택하려면 `output_format`을 `jpeg`, `png`, `webp` 중 하나로 설정하세요.

편집 엔드포인트에는 `response_format` 파라미터가 없으므로 이미지를 base64 JSON으로 반환할 수 없습니다. base64가 필요하면 응답 바이트를 직접 인코딩하세요.

<CodeGroup>
```python Python
import base64
import os
import requests

with open("input.jpg", "rb") as f:
    image_base64 = base64.b64encode(f.read()).decode("utf-8")

response = requests.post(
    "https://api.venice.ai/api/v1/image/edit",
    headers={
        "Authorization": f"Bearer {os.environ['VENICE_API_KEY']}",
        "Content-Type": "application/json",
    },
    json={
        "model": "firered-image-edit",
        "prompt": "Remove the tourist crowd from the square and keep the architecture intact",
        "image": image_base64,
    },
)

with open("edited.png", "wb") as f:
    f.write(response.content)
```

```javascript Node.js
import fs from "fs";

const imageBase64 = fs.readFileSync("input.jpg").toString("base64");

const response = await fetch("https://api.venice.ai/api/v1/image/edit", {
  method: "POST",
  headers: {
    Authorization: `Bearer ${process.env.VENICE_API_KEY}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    model: "firered-image-edit",
    prompt: "Remove the tourist crowd from the square and keep the architecture intact",
    image: imageBase64,
  }),
});

const editedImage = Buffer.from(await response.arrayBuffer());
fs.writeFileSync("edited.png", editedImage);
```

```bash cURL
curl https://api.venice.ai/api/v1/image/edit \
  -H "Authorization: Bearer $VENICE_API_KEY" \
  -H "Content-Type: application/json" \
  -o edited.png \
  -d '{
    "model": "firered-image-edit",
    "prompt": "Colorize this black and white portrait naturally",
    "image": "https://example.com/portrait-bw.jpg"
  }'
```
</CodeGroup>

## 2단계: 참조 이미지와 함께 multi-edit 사용

`/image/multi-edit`는 여러 장의 이미지를 받으며, 상한은 모델별로 다릅니다. `GET /models?type=inpaint`의 `model_spec.constraints.maxInputImages`를 읽어 특정 모델의 상한을 확인하세요. 이 필드가 없으면 상한은 3이며, `combineImages`가 `false`이면 1입니다.

첫 번째 이미지가 base 이미지입니다. 나머지 이미지는 편집을 조건화하는 추가 참조입니다.

<Note>
공개 엔드포인트에는 마스크 채널이 없습니다. 추가 이미지는 영역 맵이 아니라 이미지 전체에 걸친 참조로 작동합니다. `mask` 파라미터는 존재하지 않으며, 전송하면 `400`이 반환됩니다. 편집이 적용될 위치를 제한하려면 prompt를 정밀하게 작성하세요.
</Note>

다음과 같은 경우에 더 나은 선택입니다:

- 기존 구도에 추가 참조 이미지를 결합하고 싶을 때
- 적용할 스타일, 객체, 텍스처의 예시를 모델에 제공하고 싶을 때
- 단일 이미지 prompt가 할 수 있는 것보다 더 엄격하게 편집을 제약하고 싶을 때

**JSON 요청:**
```json
{
  "modelId": "firered-image-edit",
  "prompt": "Replace the blank billboard area with a glowing Venice film festival poster while preserving lighting and perspective",
  "images": [
    "https://example.com/street-scene.png",
    "https://example.com/billboard-reference.png"
  ]
}
```

**Multipart 요청:**
```bash
curl https://api.venice.ai/api/v1/image/multi-edit \
  -H "Authorization: Bearer $VENICE_API_KEY" \
  -F "modelId=firered-image-edit" \
  -F "prompt=Replace the blank billboard area with a glowing Venice film festival poster while preserving lighting and perspective" \
  -F "images=@street-scene.png" \
  -F "images=@billboard-reference.png" \
  -o multi-edited.png
```

`/image/edit`와 마찬가지로 응답 본문은 raw 이미지 데이터이며, 출력 포맷도 같은 규칙을 따릅니다.

<Note>
`/image/multi-edit`는 현재 요청 스키마에서 `model`이 아닌 `modelId` 필드를 사용합니다.
</Note>

## Inpainting 팁

Prompt 기반 inpainting은 지시가 짧고 국소적일 때 가장 잘 동작합니다:

- `remove the tree`
- `change the sky to sunset`
- `replace the logo with a blank sign`
- `restore the torn corner of the photo`

더 넓은 장면 변경의 경우, 유지되어야 할 부분을 함께 설명하세요:

```text
Replace the background with a modern photo studio backdrop while preserving the subject pose, facial features, and clothing.
```

편집이 계속 잘못된 영역에 영향을 준다면 `/image/edit`에서 `/image/multi-edit`로 전환해 원하는 결과를 보여주는 추가 참조 이미지를 제공한 다음, prompt에서 의도한 변경 사항을 정밀하게 설명하세요.

## 3단계: 배경 제거

전경 피사체를 투명 배경에 격리하고 싶다면 `/image/background-remove`를 사용하세요. 이 endpoint는 알파 투명도가 있는 PNG를 반환합니다.

**이미지 URL 사용:**
```bash
curl https://api.venice.ai/api/v1/image/background-remove \
  -H "Authorization: Bearer $VENICE_API_KEY" \
  -H "Content-Type: application/json" \
  -o cutout.png \
  -d '{
    "image_url": "https://example.com/product-photo.jpg"
  }'
```

**로컬 파일 업로드 사용:**
```bash
curl https://api.venice.ai/api/v1/image/background-remove \
  -H "Authorization: Bearer $VENICE_API_KEY" \
  -F "image=@product-photo.jpg" \
  -o cutout.png
```

배경 제거의 활용처:

- 이커머스 제품 사진
- 프로필 사진 및 인물 사진
- 새 배경 위에 배치할 자산

어차피 이미지를 생성하거나 편집할 예정이라면 이 두 번째 호출을 생략할 수 있습니다. `/image/generate`, `/image/edit`, `/image/multi-edit`는 지원 모델에서 `transparent_background: true`를 받아 알파 채널을 바로 반환합니다. 비교 내용은 [투명 배경 이미지](/ko/guides/media/transparent-backgrounds)를 참조하세요.

## 요청 파라미터

### `/image/edit`

| Parameter | Type | Required | Default | Description |
|---|---|---|---|---|
| `image` | 파일, base64 문자열, 또는 URL | 예 | - | 편집할 원본 이미지 |
| `prompt` | string | 예 | - | 편집을 위한 텍스트 지시 |
| `model` | string | 아니오 | `firered-image-edit` | 편집 모델 ID |
| `aspect_ratio` | string | 아니오 | 모델 기본값 | 지원 모델의 출력 비율 |
| `resolution` | string | 아니오 | `1K` | 출력 이미지의 해상도 등급(예: `1K`, `2K`, `4K`). 지원 값은 모델마다 다름 |
| `output_format` | string | 아니오 | 추론됨 | `jpeg`, `png`, `webp`. 생략하면 1K 편집은 PNG, 2K 및 4K 편집은 JPEG이며, `transparent_background`가 `true`이면 해상도와 관계없이 PNG |
| `enhance_prompt` | boolean | 아니오 | `false` | 입력 이미지를 분석하고 추론 전에 편집 지시를 다시 작성 |
| `disable_prompt_optimization_thinking` | boolean | 아니오 | 모델 기본값 | 더 빠른 생성을 위해 모델의 프롬프트 최적화 thinking 단계를 건너뜀. `supportsOptimizePromptThinking`이 있는 모델에서만 지원되며, 다른 모델은 무시 |
| `safe_mode` | boolean | 아니오 | `true` | 편집된 결과에서 성인 콘텐츠를 흐리게 처리합니다. `false`로 설정하면 흐림이 비활성화됩니다 |
| `transparent_background` | boolean | 아니오 | `false` | 실제 알파 채널이 포함된 편집 결과를 반환합니다. `supportsTransparentBackground: true`인 모델과 `png` 또는 `webp` `output_format`이 필요합니다(생략 시 PNG로 추론). [투명 배경 이미지](/ko/guides/media/transparent-backgrounds) 참조 |
| `modelId` | string | Deprecated | - | `model`의 deprecated 별칭 |

### `/image/multi-edit`

| Parameter | Type | Required | Default | Description |
|---|---|---|---|---|
| `images` | 파일, base64 문자열, 또는 URL 배열 | 예 | - | 첫 이미지는 base 이미지, 나머지는 추가 참조. 최대 개수는 모델별로 다름 — `model_spec.constraints.maxInputImages` 참조 |
| `prompt` | string | 예 | - | 이미지를 결합하거나 편집하는 방법에 대한 텍스트 지시 |
| `modelId` | string | 아니오 | `firered-image-edit` | 편집 모델 ID |
| `resolution` | string | 아니오 | `1K` | 출력 이미지의 해상도 등급(예: `1K`, `2K`, `4K`). 지원 값은 모델마다 다름 |
| `quality` | string | 아니오 | 모델 기본값 | `model_spec.constraints`에 `qualities`가 나열된 모델에서 `low`, `medium`, `high`. 값이 높을수록 요청 요금이 증가할 수 있음 |
| `output_format` | string | 아니오 | 추론됨 | `jpeg`, `png`, `webp`. 추론 규칙은 `/image/edit`와 동일 |
| `enhance_prompt` | boolean | 아니오 | `false` | 입력 이미지들을 분석하고 추론 전에 편집 지시를 다시 작성 |
| `disable_prompt_optimization_thinking` | boolean | 아니오 | 모델 기본값 | 더 빠른 생성을 위해 모델의 프롬프트 최적화 thinking 단계를 건너뜀. `supportsOptimizePromptThinking`이 있는 모델에서만 지원되며, 다른 모델은 무시 |
| `safe_mode` | boolean | 아니오 | `true` | 편집된 결과에서 성인 콘텐츠를 흐리게 처리합니다. `false`로 설정하면 흐림이 비활성화됩니다 |
| `transparent_background` | boolean | 아니오 | `false` | 실제 알파 채널이 포함된 합성 결과를 반환합니다. 모델 및 포맷 규칙은 `/image/edit`와 동일 |

### `/image/background-remove`

| Parameter | Type | Required | Description |
|---|---|---|---|
| `image` | 파일 또는 base64 문자열 | `image`나 `image_url` 중 하나 | 잘라낼 원본 이미지 |
| `image_url` | string | `image`나 `image_url` 중 하나 | 잘라낼 공개 이미지 URL |

<Note>
`/image/background-remove`는 고정된 내부 모델을 사용합니다. `model` 필드를 받지 않습니다. 필드를 함께 보내면(예: `"model": "bria-bg-remover"`) `model`이 인식되지 않는 필드이므로 `400`이 반환됩니다.
</Note>

### 성인 콘텐츠 및 safe mode

`/image/edit`와 `/image/multi-edit` 모두 `safe_mode`를 받습니다(기본값: `true`). 활성화되면 편집된 output의 성인 콘텐츠가 블러 처리됩니다. 블러 처리되지 않은 output을 받으려면 `safe_mode: false`로 설정하세요:

```json
{
  "model": "qwen-edit-uncensored",
  "prompt": "…",
  "image": "…",
  "safe_mode": false
}
```

블러 처리되지 않은 성인(NSFW) output은 모든 API 사용자가 이용할 수 있습니다. Pro 구독이 필요하지 않으며, Venice 앱의 성인 콘텐츠 필터 설정은 API를 통한 이미지 요청에 영향을 주지 않습니다.

콘텐츠 정책은 편집 모델에 따라 다르며 `safe_mode`와 무관하게 적용됩니다. 무검열 편집을 원한다면 `qwen-edit-uncensored`를 사용하세요.

Endpoint 간 모더레이션 이름 차이는 사람들을 헷갈리게 만드는 지점입니다:

| Endpoint | Field to disable blur |
|---|---|
| `POST /image/edit`, `POST /image/multi-edit` | `safe_mode: false` |
| `POST /image/generate` (네이티브 생성) | `safe_mode: false` |
| `POST /images/generations` (OpenAI 호환 생성) | `moderation: "low"` |

`/images/generations`에 `safe_mode`를 전달하면 `Unrecognized key(s) in object: 'safe_mode'`와 함께 `400`이 반환됩니다.

## 지원 input 포맷

| Endpoint | JSON input | Multipart input | Output |
|---|---|---|---|
| `/image/edit` | Base64 문자열 또는 URL | 파일 업로드 | `image/png`, `image/jpeg`, 또는 `image/webp` |
| `/image/multi-edit` | Base64 문자열 또는 URL | 파일 업로드 | `image/png`, `image/jpeg`, 또는 `image/webp` |
| `/image/background-remove` | Base64 문자열 또는 URL | 파일 업로드 | `image/png` |

편집 endpoint의 경우 이미지는 최소 256×256 픽셀이어야 하며, 총 픽셀 수는 33,177,600(8K 해상도)을 넘을 수 없습니다. 업로드 파일은 `25MB` 미만이어야 합니다.

## 모델 및 가격

기본 편집 모델은 `firered-image-edit`이며 **편집당 $0.04** 입니다. 편집 가능한 다른 모델은 가격과 제약이 다를 수 있습니다. Prompt enhancement는 편집 가격에 **적용된 재작성당 $0.04**를 추가합니다.

- [이미지 가격](/ko/overview/pricing)

## 에러

| Status | Meaning | Action |
|---|---|---|
| `400` | 잘못된 요청 파라미터 | 이미지 수, 필드 이름, 입력 포맷 확인 |
| `401` | 인증 실패 | API 키 확인 |
| `402` | 잔액 부족 | [venice.ai/settings/api](https://venice.ai/settings/api?utm_source=venice-api-documentation)에서 크레딧 추가 |
| `413` | 파일이 너무 큼 | 업로드 파일을 25 MB 미만으로 유지 |
| `415` | 잘못된 content type(`/image/multi-edit`만 해당, 다른 endpoint는 `400` 반환) | JSON 또는 multipart form-data를 올바르게 사용 |
| `422` | 콘텐츠 정책 위반 또는 입력 이미지가 너무 큼 | prompt를 조정하거나 이미지 크기를 줄이기 |
| `429` | Rate limit 초과 또는 모델 과부하 | 백오프와 함께 재시도, `Retry-After` 헤더 확인 |
| `500` | 추론 처리 실패 | 요청 재시도 |
| `503` | 모델 용량 초과 | 잠시 후 재시도 |

<Note>
일부 편집 모델은 이미지 생성 모델보다 엄격한 콘텐츠 정책을 가집니다. 선택한 모델의 정책을 위반하는 요청은 `422`로 거부됩니다.
</Note>

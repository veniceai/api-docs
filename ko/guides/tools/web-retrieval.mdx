Venice는 웹 페이지 탐색과 콘텐츠 추출을 위한 별도의 API를 제공합니다:

- **Web Search**는 제목, URL, 스니펫, 날짜가 포함된 구조화된 결과를 반환합니다.
- **Web Scrape**는 선택된 공개 페이지를 Markdown으로 변환합니다.

애플리케이션이 추론 전에 최신의 검증 가능한 소스 자료를 필요로 할 때 두 API를 함께 사용하세요.

## 웹 검색

Search API로 쿼리를 전송하세요:

```bash
curl https://api.venice.ai/api/v1/augment/search \
  -H "Authorization: Bearer $VENICE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"query":"latest developments in decentralized AI"}'
```

Brave가 기본 제공자이며 Zero Data Retention을 제공합니다. Google도 사용 가능하며, 쿼리는 익명화되어 Venice를 통해 프록시되며, [Exa](/ko/guides/integrations/exa-search)도 Zero Data Retention과 함께 사용할 수 있습니다. 제공자 선택 방법과 전체 응답 스키마는 [Web Search API 참조](/api-reference/endpoint/augment/search)를 확인하세요.

## 제공자 선택하기 {#choosing-a-provider}

모든 제공자는 같은 요청을 받고 검색당 비용도 같으므로, 제공자를 바꾸려면 필드 하나만 변경하면 됩니다. 차이는 반환되는 내용에 있습니다.

| 제공자 | 결과 | 적합한 용도 |
|---|---|---|
| `brave` (기본값) | 쿼리에 맞춘 짧은 발췌문 | 뉴스와 일상적인 조회, 선택한 페이지를 스크래핑하는 파이프라인 |
| `google` | 결과 5개. 대부분 페이지 상단부터의 전체 텍스트이며, 사이트가 스크래핑을 차단하면 스니펫만 반환 | 별도 스크래핑 없이 페이지 텍스트 읽기 |
| `exa` | 쿼리에 맞춘 짧은 발췌문. 벤치마크에서 가장 관련성 높은 결과 | 코딩 및 리서치 질문, 프롬프트에 바로 넣는 결과 |

결과를 모델에 전달하면 긴 결과는 입력 토큰이 되므로 비용이 더 들고 처리 시간도 길어집니다. 결과를 프롬프트에 바로 넣는다면 포함할 결과 수와 각 결과가 차지하는 텍스트 양을 제한하세요. `google`을 사용할 때는 각 결과의 앞부분 대신 쿼리와 일치하는 구절을 남기세요. 앞부분은 내비게이션이나 쿠키 배너인 경우가 많습니다.

관련성, 답변 정확도, 지연 시간, 토큰 비용 측면에서 제공자를 비교하려면 [웹 검색 제공자 벤치마크](/ko/learn/search-provider-benchmark)를 읽어 보세요. 벤치마크 하네스 링크가 있으므로 직접 준비한 질문으로 비교를 다시 실행할 수 있습니다.

## 페이지 스크래핑

결과를 선택한 후 해당 공개 URL을 Scrape API로 전송하세요:

```bash
curl https://api.venice.ai/api/v1/augment/scrape \
  -H "Authorization: Bearer $VENICE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"url":"https://example.com/article"}'
```

엔드포인트는 페이지 콘텐츠를 Markdown으로 반환합니다. 사이트의 네이티브 Markdown 표현이 있으면 먼저 이를 요청하고, 그렇지 않은 경우에는 브라우저 기반 추출을 사용합니다.

## 검색-스크래핑 워크플로

<Steps>
  <Step title="검색">
    집중된 쿼리를 제출하고 구조화된 결과를 수집하세요.
  </Step>
  <Step title="소스 선택">
    페이지 콘텐츠를 가져오기 전에 결과를 관련성, 도메인, 날짜로 필터링하세요.
  </Step>
  <Step title="스크래핑">
    애플리케이션에서 실제로 사용할 페이지에서만 Markdown을 추출하세요.
  </Step>
  <Step title="콘텐츠 사용 또는 저장">
    Markdown을 프롬프트에 포함하거나, 임베딩을 생성하거나, 캐시하거나, 인용을 위해 소스 URL을 보존하세요.
  </Step>
</Steps>

Web Search와 Web Scrape에는 각각 계정당 분당 요청 제한이 있습니다. 제한을 초과한 요청은 `429`를 반환하므로 지수 백오프로 재시도하고, 병렬 스크래핑은 작은 풀로 유지하세요.

## 독립형 검색과 모델 웹 검색 중 어느 것을 사용해야 할까?

애플리케이션이 소스 선택을 제어해야 하거나 검색된 콘텐츠를 재사용하려는 경우 독립형 API를 사용하세요. Venice가 단일 추론 요청의 일부로 검색을 처리하도록 하려면 모델 요청에서 웹 검색을 활성화하세요.

| 필요 사항 | 접근 방식 |
|---|---|
| 추론 전에 결과를 검사하거나 필터링 | 독립형 Web Search |
| 알려진 특정 URL 추출 | 독립형 Web Scrape |
| 검색된 콘텐츠 캐시 또는 재사용 | 독립형 API |
| 모델이 최신 컨텍스트를 자동으로 검색하도록 함 | 모델 웹 검색 |

<Warning>
Web Search와 Web Scrape는 실험적 API입니다. 요청 및 응답 형식은 사전 통지 없이 변경될 수 있습니다. Web Scrape는 공개적으로 접근 가능한 페이지만 허용하며, 자동화된 접근을 차단하는 사이트는 거부될 수 있습니다.
</Warning>

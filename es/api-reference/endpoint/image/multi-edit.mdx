## Límites de imágenes de entrada

El número máximo de imágenes de entrada depende del modelo. Consulta `model_spec.constraints.maxInputImages` en [`GET /models?type=inpaint`](/es/api-reference/endpoint/models/list). Cuando el campo no está presente, el límite es 3, o 1 cuando `combineImages` es `false`.

## Niveles de calidad

Algunos modelos de edición múltiple aceptan un parámetro opcional `quality` (`low`, `medium`, `high`) que intercambia fidelidad visual por coste. Los modelos que incluyen `qualities` en `model_spec.constraints` de [`GET /models?type=inpaint`](/es/api-reference/endpoint/models/list) solo aceptan esos valores, y algunos solo admiten un subconjunto, como `low` y `medium`. Otros modelos ignoran el parámetro.

```json
{
  "modelId": "gpt-image-2-edit",
  "images": ["iVBORw0KGgo...", "iVBORw0KGgo..."],
  "prompt": "blend the two scenes into one cinematic frame",
  "resolution": "2K",
  "quality": "medium"
}
```

Cuando omites `quality`, el modelo utiliza su nivel predeterminado (`high` para `gpt-image-2-edit`). Los precios por nivel (1K/2K/4K × low/medium/high) están en `model_spec.pricing.quality` en el [endpoint de Models](/es/api-reference/endpoint/models/list) y se listan en la [vista general de precios](/es/overview/pricing).

<Info>
La facturación según la calidad es la predeterminada para todos los llamadores de la API y del SDK: no se requiere ninguna cabecera de activación. Las solicitudes que omiten `quality` se facturan al nivel predeterminado del modelo (`high` para `gpt-image-2-edit`).
</Info>

Si omites el parámetro de consulta `type`, la respuesta incluye solo modelos de texto. Pasa `type=all` para devolver el catálogo completo de modelos.

## Leer una entrada de modelo {#reading-a-model-entry}

Envía el `id` de un modelo como parámetro `model`. La mayor parte de lo que filtras está en `model_spec`:

| Campo | Qué te indica |
| --- | --- |
| `type` | Qué endpoint sirve el modelo: `text` para chat completions, o `image`, `video`, `tts`, `asr`, `embedding`, etc. |
| `model_spec.capabilities` | Lo que admite un modelo de texto, como `supportsFunctionCalling`, `supportsVision`, `supportsReasoning`, `supportsResponseSchema`, `supportsWebSearch` y `supportsE2EE` |
| `model_spec.availableContextTokens` | La ventana de contexto, en tokens |
| `model_spec.pricing` | Precios en USD y DIEM: por 1M tokens para modelos de texto, por unidad para modelos multimedia |
| `model_spec.privacy` | `private` o `anonymized`. Los modelos E2EE y TEE son `private` y establecen `supportsE2EE` o `supportsTeeAttestation` |
| `model_spec.constraints` | Los valores de parámetros que acepta el modelo, como relaciones de aspecto, duraciones de video y niveles de calidad |
| `model_spec.traits` | Roles que tiene el modelo, como `default` o `fastest` |
| `model_spec.deprecation` | Presente cuando el modelo se va a retirar, con su fecha de eliminación y, si existe, su `replacementModelId` |

Para elegir un modelo por rol en lugar de por ID, llama a [`GET /models/traits`](/es/api-reference/endpoint/models/traits). Para explorar y comparar modelos, consulta las páginas de [Modelos](/es/models/overview).

## Precios por nivel de calidad

Para los modelos de imagen que aceptan el parámetro opcional `quality`, la respuesta expone una matriz de precios por calidad en `model_spec.pricing.quality`. Cada clave de nivel superior es un nivel de resolución (`1K`, `2K`, `4K`) y cada clave anidada es un nivel de calidad (`low`, `medium`, `high`) con su propio precio `usd` y `diem`:

```json
"pricing": {
  "resolutions": {
    "1K": { "usd": 0.27, "diem": 0.27 },
    "2K": { "usd": 0.51, "diem": 0.51 },
    "4K": { "usd": 0.84, "diem": 0.84 }
  },
  "quality": {
    "1K": {
      "low":    { "usd": 0.02, "diem": 0.02 },
      "medium": { "usd": 0.07, "diem": 0.07 },
      "high":   { "usd": 0.26, "diem": 0.26 }
    },
    "2K": {
      "low":    { "usd": 0.03, "diem": 0.03 },
      "medium": { "usd": 0.13, "diem": 0.13 },
      "high":   { "usd": 0.50, "diem": 0.50 }
    },
    "4K": {
      "low":    { "usd": 0.05, "diem": 0.05 },
      "medium": { "usd": 0.21, "diem": 0.21 },
      "high":   { "usd": 0.83, "diem": 0.83 }
    }
  }
}
```

`pricing.resolutions` es el esquema heredado por imagen que se mantiene por compatibilidad. `pricing.quality` es la matriz por (resolución, calidad) que se aplica siempre que el parámetro `quality` esté admitido. Ambos campos se mantienen en la respuesta para que los clientes puedan detectar el soporte de calidad y mostrar la matriz en sus propias interfaces.

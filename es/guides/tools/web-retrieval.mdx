Venice ofrece APIs independientes para descubrir páginas web y extraer su contenido:

- **Web Search** devuelve resultados estructurados con títulos, URL, fragmentos y fechas.
- **Web Scrape** convierte una página pública seleccionada en Markdown.

Úsalas juntas cuando tu aplicación necesite material fuente actual y verificable antes de la inferencia.

## Busca en la web

Envía una consulta a la API de Search:

```bash
curl https://api.venice.ai/api/v1/augment/search \
  -H "Authorization: Bearer $VENICE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"query":"latest developments in decentralized AI"}'
```

Brave es el proveedor predeterminado y ofrece Zero Data Retention. Google también está disponible con consultas anonimizadas enviadas mediante proxy a través de Venice, y [Exa](/es/guides/integrations/exa-search) está disponible con Zero Data Retention. Consulta la [referencia de la API Web Search](/api-reference/endpoint/augment/search) para la selección del proveedor y el esquema completo de la respuesta.

## Elige un proveedor {#choosing-a-provider}

Todos los proveedores aceptan la misma solicitud y cuestan lo mismo por búsqueda, así que cambiar de proveedor es cuestión de modificar un campo. La diferencia está en lo que devuelven:

| Proveedor | Resultados | Buen uso |
|---|---|---|
| `brave` (predeterminado) | Extractos cortos ajustados a la consulta | Noticias y búsquedas cotidianas, y pipelines que extraen las páginas que seleccionan |
| `google` | 5 resultados, en su mayoría el texto completo de la página desde su inicio, o solo el fragmento cuando un sitio bloquea la extracción | Leer el texto de la página sin una extracción aparte |
| `exa` | Extractos cortos ajustados a la consulta, y los resultados más relevantes de nuestro benchmark | Preguntas de programación e investigación, y resultados que van directamente a un prompt |

Los resultados más largos se convierten en tokens de entrada cuando los pasas a un modelo, así que cuestan más y tardan más en procesarse. Si los resultados van directamente a un prompt, limita cuántos incluyes y cuánto texto aporta cada uno. Con `google`, conserva los pasajes que coinciden con la consulta en lugar del inicio de cada resultado, que suele ser navegación o un banner de cookies.

Para ver cómo se comparan los proveedores en relevancia, precisión de las respuestas, latencia y coste en tokens, lee [Benchmark de proveedores de búsqueda web](/es/learn/search-provider-benchmark). Enlaza al harness del benchmark, así que puedes repetir la comparación con tus propias preguntas.

## Extrae una página

Después de seleccionar un resultado, envía su URL pública a la API de Scrape:

```bash
curl https://api.venice.ai/api/v1/augment/scrape \
  -H "Authorization: Bearer $VENICE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"url":"https://example.com/article"}'
```

El endpoint devuelve el contenido de la página como Markdown. Primero solicita la representación Markdown nativa del sitio cuando esté disponible y, en caso contrario, utiliza extracción basada en navegador.

## Flujo de búsqueda y extracción

<Steps>
  <Step title="Busca">
    Envía una consulta específica y recopila los resultados estructurados.
  </Step>
  <Step title="Selecciona las fuentes">
    Filtra los resultados por relevancia, dominio y fecha antes de obtener el contenido de las páginas.
  </Step>
  <Step title="Extrae">
    Extrae Markdown solo de las páginas que tu aplicación tenga previsto utilizar.
  </Step>
  <Step title="Usa o almacena el contenido">
    Incluye el Markdown en un prompt, crea embeddings, guárdalo en caché o conserva las URL de origen para las citas.
  </Step>
</Steps>

Web Search y Web Scrape tienen cada uno un límite de solicitudes por minuto por cuenta. Las solicitudes que superan el límite devuelven `429`; reinténtalas con backoff exponencial y limita el scraping en paralelo a un pool pequeño.

## ¿Búsqueda independiente o búsqueda web del modelo?

Utiliza las APIs independientes cuando tu aplicación necesite controlar la selección de fuentes o quiera reutilizar el contenido recuperado. Habilita la búsqueda web en una solicitud al modelo cuando quieras que Venice se encargue de la recuperación como parte de una única solicitud de inferencia.

| Necesidad | Enfoque |
|---|---|
| Inspeccionar o filtrar resultados antes de la inferencia | Web Search independiente |
| Extraer una URL específica conocida | Web Scrape independiente |
| Almacenar en caché o reutilizar el contenido recuperado | APIs independientes |
| Permitir que el modelo recupere contexto actual automáticamente | Búsqueda web del modelo |

<Warning>
Web Search y Web Scrape son APIs experimentales. El formato de sus solicitudes y respuestas puede cambiar sin previo aviso. Web Scrape solo acepta páginas de acceso público, y los sitios que bloquean el acceso automatizado pueden ser rechazados.
</Warning>

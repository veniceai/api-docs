Las solicitudes a la API de Venice se autentican con claves de API tipo Bearer. Esta guía muestra cómo crear una clave desde el panel de Venice, almacenarla de forma segura y verificar que funciona.

<Note>
  Si estás construyendo un agente autónomo que necesita generar su propia clave con una wallet, utiliza en su lugar la guía [Creación de claves de API para agentes autónomos](/guides/integrations/generating-api-key-agent).
</Note>

## Antes de comenzar {#before-you-start}

* Inicia sesión en tu cuenta de Venice.
* Asegúrate de que la cuenta tenga un saldo disponible antes de llamar a endpoints de pago. Puedes crear una clave antes de financiar la cuenta, pero las solicitudes a los modelos no se completarán hasta que la cuenta pueda consumir DIEM, créditos incluidos o USD.

<Steps>
  <Step title="Abrir la configuración de la API">
    Visita [https://venice.ai/settings/api](https://venice.ai/settings/api?utm_source=venice-api-documentation). También puedes abrir esta página desde la aplicación de Venice seleccionando **API** en tu configuración.

    El panel de configuración de la API muestra tus saldos, el nivel de la API, el uso y las claves de API existentes.
  </Step>

  <Step title="Iniciar una nueva clave">
    Selecciona **Generate New API Key** y luego configura la clave:

    * **Description:** Usa un nombre corto que identifique la aplicación, el entorno o la integración que utilizará esta clave.
    * **API Key Type:** Usa **Inference Only** para solicitudes normales a los modelos. Usa **Admin** solo cuando la clave deba gestionar claves de API de forma programática.
    * **Expires at:** Opcionalmente, establece una fecha de expiración. Si lo dejas en blanco, la clave no expirará automáticamente.
    * **Epoch Consumption Limits:** Opcionalmente, limita cuánto DIEM o USD puede gastar esta clave durante un epoch de 24 horas. Si lo dejas en blanco, la clave podrá usar el saldo disponible de la cuenta sujeto a los límites de tu cuenta.
  </Step>

  <Step title="Generar y copiar la clave">
    Haz clic en **Generate**. Venice mostrará la clave de API completa una sola vez.

    <Warning>
      Copia la clave de inmediato y guárdala en un lugar seguro. Después de cerrar el cuadro de diálogo, Venice solo mostrará metadatos identificativos como la descripción de la clave y los últimos caracteres. Si pierdes el valor secreto, elimina la clave y crea una nueva.
    </Warning>

    Pega la clave exactamente como se emitió. Usa el botón de copiar del cuadro de diálogo en lugar de seleccionar el texto a mano, para no recortar el primer o el último carácter ni arrastrar un salto de línea final. Cuando una herramienta te pida la clave en un campo de formulario, introduce solo la clave: sin el prefijo `Bearer`, sin comillas alrededor y sin espacios al principio o al final. Como el panel solo muestra los últimos caracteres una vez cerrado el cuadro de diálogo, nunca intentes reconstruir una clave perdida volviendo a escribir ese valor enmascarado.

    Añade la clave a tu entorno local o gestor de secretos:

    ```bash
    export VENICE_API_KEY=your-api-key-here
    ```
  </Step>

  <Step title="Verificar la clave">
    Realiza una solicitud de bajo riesgo para confirmar que la autenticación funciona. [Obtener límites de tasa y saldos de la clave de API](/es/api-reference/endpoint/api_keys/rate_limits) no tiene coste y acepta cualquier tipo de clave. Úsalo en lugar de `GET /models`, que devuelve el catálogo de modelos con o sin clave y, por tanto, funciona incluso cuando tu clave es incorrecta:

    ```bash
    curl --request GET \
      --url https://api.venice.ai/api/v1/api_keys/rate_limits \
      --header "Authorization: Bearer $VENICE_API_KEY"
    ```

    Una respuesta exitosa devuelve tu nivel de API, tus saldos y tus límites de tasa, y `data.accessPermitted` indica si la clave puede consumir los endpoints de inferencia.

    Un `401` con `AUTHENTICATION_FAILED` significa que la propia clave fue rechazada. Imprime el valor almacenado y compáralo con los últimos caracteres que se muestran en el panel: las causas habituales son una copia parcial, un prefijo `Bearer` o comillas incluidos en el propio valor, o un espacio o salto de línea sobrante en cualquiera de los extremos. Confirma también que el encabezado sea `Bearer`, un espacio y luego la propia clave, por ejemplo `Authorization: Bearer $VENICE_API_KEY` en una shell.
  </Step>
</Steps>

<Warning>
  Deshabilitar el gasto en USD al crear una clave API en la aplicación de Venice establece tu límite de gasto en USD en cero para esa clave API. Las llamadas a la API pueden fallar con un error de saldo insuficiente cuando tu DIEM disponible o los créditos agrupados no puedan cubrir la solicitud, incluso si tu cuenta tiene saldo en USD.
</Warning>

## Formato de la clave {#key-format}

Las claves nuevas empiezan con un prefijo de tipo seguido de 42 caracteres seguros para URL:

| Prefijo | Tipo de clave |
| --- | --- |
| `VENICE_INFERENCE_KEY_` | Inference Only |
| `VENICE_ADMIN_KEY_` | Admin |

Las claves antiguas siguen funcionando tal como se emitieron: algunas usan guiones en el prefijo (`VENICE-INFERENCE-KEY-`, `VENICE-ADMIN-KEY-`) y las más antiguas no tienen prefijo.

Usa la clave exactamente como se emitió. La API comprueba la cadena completa, así que una clave que una herramienta haya pasado a minúsculas, cuya puntuación haya cambiado, a la que haya quitado el prefijo o puesto otro prefijo falla con `401` y `Authentication failed`. Algunas páginas de la comunidad dicen que las claves de Venice empiezan con `vapi_`. No es así, y añadir `vapi_` a una clave la invalida.

El prefijo identifica el tipo de clave. Una clave Admin también funciona en los endpoints de modelos, porque es el tipo más amplio. Una clave Inference Only en un endpoint de administración, como listar o crear claves o consultar el saldo, falla con `401` y `Admin API key required`. `GET /api_keys/rate_limits` acepta cualquiera de los dos tipos.

## Solución de errores de límite de gasto {#troubleshooting-spend-limit-errors}

Los límites de gasto por clave son independientes del saldo de tu cuenta. Una clave puede quedar bloqueada para gastar incluso cuando tu cuenta todavía tiene créditos en USD financiados, DIEM o créditos incluidos. Si una solicitud devuelve un 402 con uno de estos códigos, la causa es el propio límite de la clave y no el saldo de tu cuenta:

* `API_KEY_USD_SPEND_LIMIT_EXCEEDED` — el límite de gasto en USD de la clave está establecido en cero (el gasto en USD se deshabilitó al crearla) o el epoch actual ha alcanzado su tope en USD.
* `API_KEY_DIEM_SPEND_LIMIT_EXCEEDED` — la clave ha alcanzado su tope de DIEM para el epoch actual de 24 horas.

Para confirmar el estado actual de una clave, llama a [Obtener límites de tasa y saldos de la clave de API](/es/api-reference/endpoint/api_keys/rate_limits) e inspecciona `data.accessPermitted` y `data.balances`. Para ver los límites configurados de la clave, llama a [Obtener clave de API](/es/api-reference/endpoint/api_keys/get) con una clave Admin y lee `consumptionLimits`.

Para resolver el error, aumenta o elimina los Epoch Consumption Limits de la clave en [venice.ai/settings/api](https://venice.ai/settings/api?utm_source=venice-api-documentation), o llama a [Actualizar clave de API](/es/api-reference/endpoint/api_keys/update) con un nuevo objeto `consumptionLimit`. El campo de la solicitud es singular, aunque las respuestas de claves de API devuelvan `consumptionLimits`. Los saldos a nivel de cuenta (USD, DIEM y créditos incluidos) son fuentes de pago independientes y se consumen automáticamente según estén disponibles; no es necesario elegir una en el momento de la solicitud.

Consulta [Códigos de error](/api-reference/error-codes) para ver la lista completa de respuestas relacionadas con la facturación.

## Buenas prácticas {#best-practices}

* Crea claves separadas para desarrollo, staging y producción.
* Prefiere claves **Inference Only** para aplicaciones que solo llaman a endpoints de modelos.
* Mantén las claves **Admin** como excepcionales, con un alcance estricto y almacenadas únicamente en entornos confiables del lado del servidor.
* Nunca subas claves de API al control de versiones ni las expongas en código del lado del cliente.
* Establece fechas de expiración y límites de consumo para claves usadas en entornos temporales, compartidos o de mayor riesgo.
* Elimina las claves que no uses y rota cualquier clave que pueda haber sido expuesta.

## Llamadas desde un navegador {#calling-from-a-browser}

La API envía `access-control-allow-origin: *`, así que un navegador puede llamarla directamente. Pero entonces la clave queda en tu bundle y es pública. Pon un pequeño proxy delante y mantén la clave en el servidor.

Un proxy por sí solo no basta. `access-control-allow-origin` no autentica nada: `curl` y otros servidores ignoran CORS por completo, y el hostname del Worker es público. Un proxy que solo inyecta la clave es un grifo abierto a tu saldo. Quien llama también tiene que identificarse.

Hay dos niveles, y importa cuál estás construyendo:

- **Un secreto compartido** controla el gasto. Todos los visitantes tienen el mismo valor, así que impide el uso anónimo de tu Worker, pero no que un visitante lo reenvíe. Adecuado para un prototipo.
- **Un token por usuario** identifica a quien llama. El navegador se autentica en tu propio backend, que emite un token de corta duración, y el Worker lo valida. Este es el esquema para producción.

Los dos ejemplos siguientes mantienen la clave de Venice en el servidor. Una tercera regla se aplica a ambos: **usa una clave inference-only**, porque una clave admin enrutada a través de un proxy público puede hacer `POST /api_keys` y leer el nuevo secreto directamente en la respuesta del proxy.

### Nivel 1: un secreto compartido {#level-1-a-shared-secret}

El Worker guarda la clave de Venice y un secreto, y rechaza todo lo que no incluya el secreto. Mantén el secreto fuera del navegador: haz que tu backend lo añada cuando llame al Worker, para que el navegador solo hable con tu backend.

```js index.js
// Only the paths you need. Add deliberately: an inference key still reads
// balances through GET /api_keys/rate_limits.
const ALLOWED = new Set(['/chat/completions', '/image/generate']);

export default {
  async fetch(request, env) {
    if (request.method === 'OPTIONS') {
      return new Response(null, { headers: cors() });
    }
    if (!ALLOWED.has(new URL(request.url).pathname)) {
      return json(404, { error: 'Not found' });
    }
    if (request.method !== 'POST') {
      return json(405, { error: 'Method not allowed' });
    }
    if (request.headers.get('x-proxy-key') !== env.PROXY_SECRET) {
      return json(401, { error: 'Proxy secret required' });
    }
    return forward(request, env);
  },
};

async function forward(request, env) {
  const path = new URL(request.url).pathname;
  const upstream = await fetch(`${env.VENICE_BASE_URL}/api/v1${path}`, {
    method: 'POST',
    headers: { 'content-type': 'application/json', authorization: `Bearer ${env.VENICE_API_KEY}` },
    body: await request.text(),
  });
  return new Response(upstream.body, {
    status: upstream.status,
    headers: { ...cors(), 'content-type': upstream.headers.get('content-type') ?? 'application/json' },
  });
}

const cors = () => ({
  'access-control-allow-origin': 'https://your-site.example',
  'access-control-allow-headers': 'content-type,x-proxy-key',
  'access-control-allow-methods': 'POST,OPTIONS',
});

const json = (status, body) =>
  new Response(JSON.stringify(body), { status, headers: { ...cors(), 'content-type': 'application/json' } });
```

```bash Deploy
npx wrangler deploy index.js --name venice-proxy
npx wrangler secret put VENICE_API_KEY      # an inference-only key
npx wrangler secret put PROXY_SECRET        # any long random value
npx wrangler secret put VENICE_BASE_URL     # https://api.venice.ai
```

Llámalo desde tu backend, donde se queda el secreto:

```js Server
await fetch('https://venice-proxy.<account>.workers.dev/chat/completions', {
  method: 'POST',
  headers: { 'content-type': 'application/json', 'x-proxy-key': process.env.PROXY_SECRET },
  body: JSON.stringify({ model: 'venice-uncensored-1-2', messages: [{ role: 'user', content: 'Hi' }] }),
});
```

Las rutas se añaden directamente, así que `/chat/completions` llega a `/api/v1/chat/completions` en el upstream. No incluyas `/v1` en la URL base de ningún cliente de OpenAI que apuntes aquí.

Un secreto compartido sigue siendo una credencial compartida: limita la tasa de la ruta con las reglas de rate limiting de Cloudflare antes de que reciba tráfico público.

### Nivel 2: un token por usuario {#level-2-a-per-user-token}

Cuando el navegador deba llamar al Worker directamente, pon tu propia autenticación delante. Tu backend verifica la sesión que ya tiene y firma un token de corta duración, y el Worker comprueba ese token en lugar de un valor compartido. Reutiliza `ALLOWED`, `forward`, `cors` y `json` del Worker del Nivel 1:

```js index.js
export default {
  async fetch(request, env) {
    if (request.method === 'OPTIONS') {
      return new Response(null, { headers: cors() });
    }
    if (!ALLOWED.has(new URL(request.url).pathname) || request.method !== 'POST') {
      return json(404, { error: 'Not found' });
    }
    if (!(await validToken(request.headers.get('authorization')?.replace(/^Bearer /, ''), env))) {
      return json(401, { error: 'Token required' });
    }
    return forward(request, env);
  },
};

// Verify a token issued by your backend: its signature, expiry and subject.
// Any HMAC over `sub.exp` works; this is the shape, not a full implementation.
async function validToken(token, env) {
  if (!token) return false;
  // The payload itself contains a dot, so split on the last one only.
  const cut = token.lastIndexOf('.');
  if (cut < 1) return false;
  const payload = token.slice(0, cut);
  const key = await crypto.subtle.importKey(
    'raw', new TextEncoder().encode(env.PROXY_SIGNING_KEY),
    { name: 'HMAC', hash: 'SHA-256' }, false, ['verify'],
  );
  const ok = await crypto.subtle.verify('HMAC', key, hexToBytes(token.slice(cut + 1)), new TextEncoder().encode(payload));
  return ok && Number(payload.slice(payload.lastIndexOf('.') + 1)) > Date.now();
}

const hexToBytes = (hex) => new Uint8Array(hex.match(/../g).map((b) => parseInt(b, 16)));
```

Emite el token en el backend después de tu propia comprobación de sesión, para que el Worker nunca guarde estado de usuario. Eso te da límites de tasa por usuario, revocación y una factura atribuible.

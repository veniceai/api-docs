Two endpoints bring the live web into your app. Web Search finds pages for a query, and Web Scrape reads one page as Markdown. Each costs $0.01 per successful call. To skip both, turn on web search in a chat request and let the model search, read and cite for you.

## Search the web

You need an API key in `VENICE_API_KEY` ([create one](/getting-started/quick-start)).

<CodeGroup>
```bash cURL
curl https://api.venice.ai/api/v1/augment/search \
  -H "Authorization: Bearer $VENICE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "query": "how to generate video with the venice api",
    "limit": 5,
    "search_provider": "exa"
  }'
```

```python Python
import os

import requests

response = requests.post(
    "https://api.venice.ai/api/v1/augment/search",
    headers={"Authorization": f"Bearer {os.environ['VENICE_API_KEY']}"},
    json={"query": "how to generate video with the venice api", "limit": 5, "search_provider": "exa"},
)
response.raise_for_status()

for result in response.json()["results"]:
    print(result["title"], result["url"])
```

```typescript TypeScript
const response = await fetch("https://api.venice.ai/api/v1/augment/search", {
  method: "POST",
  headers: {
    Authorization: `Bearer ${process.env.VENICE_API_KEY}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({ query: "how to generate video with the venice api", limit: 5, search_provider: "exa" }),
});
if (!response.ok) throw new Error(await response.text());

const { results } = await response.json();
for (const result of results) console.log(result.title, result.url);
```
</CodeGroup>

Each result has a title, a URL, text from the page and a date:

```json
{
  "query": "how to generate video with the venice api",
  "results": [
    {
      "title": "Video Generation | Venice API Docs",
      "url": "https://docs.venice.ai/guides/media/video-generation",
      "content": "A video takes longer than a request should wait, so it runs as a job…",
      "date": "2026-11-20"
    }
  ]
}
```

`query` takes 1 to 400 characters, and longer queries are rejected rather than cut. `limit` takes 1 to 20 and defaults to 10. Results without any text are dropped, so you can get fewer than you asked for. A search that finds nothing returns an empty `results` array and is still charged. `date` is whatever the provider reports, and can be an empty string.

## Choose a provider

Every provider takes the same request at the same price, so switching is a one-field change. What differs is what comes back:

| `search_provider` | Results | `content` holds | Privacy | Good for |
|---|---|---|---|---|
| `brave`, the default | Up to 10 | Short extracts that match the query | Zero data retention | News, everyday lookups, and pipelines that scrape the pages they pick |
| `google` | Up to 5 | Text from the top of each page, or only the snippet when a site blocks reading | Anonymized through Venice | Reading page text without a separate scrape |
| `exa` | Up to 20 | Highlights that match the query, up to 10,000 characters each | Zero data retention | Coding and research questions, and results that go straight into a prompt |

Exa returned the most relevant results in [Benchmarking web search providers](/learn/search-provider-benchmark), which also compares answer accuracy, speed and token cost, and links the harness so you can rerun it on your own questions.

Longer results become input tokens when you pass them to a model, so they cost more and take longer. Cap how many results a prompt includes and how much text each contributes. With `google`, keep the passages that match the query rather than the start of each page, which is often navigation or a cookie banner.

## Read a page

Send a public URL to Web Scrape and get the page back as Markdown:

<CodeGroup>
```bash cURL
curl https://api.venice.ai/api/v1/augment/scrape \
  -H "Authorization: Bearer $VENICE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"url": "https://docs.venice.ai/guides/media/video-generation"}'
```

```python Python
import os

import requests

response = requests.post(
    "https://api.venice.ai/api/v1/augment/scrape",
    headers={"Authorization": f"Bearer {os.environ['VENICE_API_KEY']}"},
    json={"url": "https://docs.venice.ai/guides/media/video-generation"},
)
response.raise_for_status()
print(response.json()["content"][:500])
```
</CodeGroup>

```json
{
  "url": "https://docs.venice.ai/guides/media/video-generation",
  "content": "# Video Generation\n\nA video takes longer than a request should wait…",
  "format": "markdown"
}
```

Sites that publish Markdown are returned as they are, and other pages are fetched and converted. Some pages come back partial, so check the length of `content` before you rely on it.

- **X, Twitter and Reddit** are refused with `400`. Search them from a chat request instead, with [web search](#or-let-the-model-search) or `enable_x_search`.
- **Private and internal addresses**, such as `localhost`, private IP ranges and cloud metadata hosts, are refused with `400`, and so are URLs with credentials in them. A public address that redirects to one fails with `500`.
- **Unreachable pages**, timeouts and pages with no text return `500`, and aren't charged.

## Search, read, then answer

The two endpoints combine into a research step: search, scrape the best few results, and give the text to a model with its sources.

```python
import os

import requests

API = "https://api.venice.ai/api/v1"
HEADERS = {"Authorization": f"Bearer {os.environ['VENICE_API_KEY']}"}
question = "How do I generate a video with the Venice API?"

search = requests.post(f"{API}/augment/search", headers=HEADERS, json={"query": question, "limit": 5, "search_provider": "exa"})
search.raise_for_status()

sources = []
for result in search.json()["results"][:3]:
    page = requests.post(f"{API}/augment/scrape", headers=HEADERS, json={"url": result["url"]})
    if page.ok:
        sources.append(f"Source: {result['url']}\n\n{page.json()['content'][:6000]}")

answer = requests.post(f"{API}/chat/completions", headers=HEADERS, json={
    "model": "zai-org-glm-5",
    "messages": [
        {"role": "system", "content": "Answer only from the sources, and cite the URL each claim comes from."},
        {"role": "user", "content": "\n\n---\n\n".join(sources) + f"\n\nQuestion: {question}"},
    ],
})
answer.raise_for_status()
print(answer.json()["choices"][0]["message"]["content"])
```

A scrape can fail on any page, so the loop keeps the ones that worked. [Cited answers with web search](/guides/tools/cited-web-answers) builds this out, with source selection and answers where every claim resolves to a URL.

## Or let the model search

Set `enable_web_search` in `venice_parameters` and the model searches as part of its answer. `"on"` always searches, and `"auto"` searches when the question needs it. `enable_web_citations` adds markers such as `^1^` that point to the sources:

```bash
curl https://api.venice.ai/api/v1/chat/completions \
  -H "Authorization: Bearer $VENICE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "zai-org-glm-5",
    "messages": [{ "role": "user", "content": "What changed in the Venice API this week?" }],
    "venice_parameters": { "enable_web_search": "on", "enable_web_citations": true }
  }'
```

The sources come back in `venice_parameters.web_search_citations`, each with a `url`, `title`, `content` and `date`.

| You want to | Use |
|---|---|
| Inspect or filter results before the model sees them | Web Search |
| Read one known page | Web Scrape |
| Cache or reuse what you retrieve | Web Search and Web Scrape |
| Answer with current information in a single request | Web search in the chat request |

## Limits

- **$0.01** per successful search or scrape. The balance is checked first, and failed calls aren't charged.
- **60 requests a minute** per account for each endpoint. Requests that fail validation count too. Beyond the limit you get `429`, so retry with exponential backoff and keep parallel scrapes to a small pool.
- **Experimental**: both endpoints may change their request and response shapes.

## Errors

| Status | Meaning | What to do |
|---|---|---|
| `400` | An invalid or blocked URL, an empty or over-long query, or a `limit` outside 1 to 20 | Fix the request. `details` in the body names the field. |
| `401` | The API key is missing or invalid | Check the `Authorization: Bearer` header. |
| `402` | Not enough balance, or the key reached its spend limit | Add credits at [venice.ai/settings/api](https://venice.ai/settings/api?utm_source=venice-api-documentation). |
| `429` | More than 60 requests a minute | Back off with jitter, then retry. |
| `500` | The page couldn't be read, or the search provider failed | Not charged, and safe to retry. |

## Your first image

You need an API key in `VENICE_API_KEY` ([create one](/getting-started/quick-start)). Each example asks Z-Image Turbo, Venice's default image model, for a portrait and saves it as `fisherman.webp`.

<CodeGroup>
```bash cURL
curl https://api.venice.ai/api/v1/image/generate \
  -H "Authorization: Bearer $VENICE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "z-image-turbo",
    "prompt": "Photorealistic close-up portrait of a weathered fisherman at golden hour, 85mm lens, shallow depth of field, natural skin texture",
    "return_binary": true
  }' \
  --output fisherman.webp
```

```python Python
import base64
import os

import requests

response = requests.post(
    "https://api.venice.ai/api/v1/image/generate",
    headers={"Authorization": f"Bearer {os.environ['VENICE_API_KEY']}"},
    json={
        "model": "z-image-turbo",
        "prompt": "Photorealistic close-up portrait of a weathered fisherman at golden hour, 85mm lens, shallow depth of field, natural skin texture",
    },
)
response.raise_for_status()

with open("fisherman.webp", "wb") as f:
    f.write(base64.b64decode(response.json()["images"][0]))
```

```typescript TypeScript
import { writeFile } from "node:fs/promises";

const response = await fetch("https://api.venice.ai/api/v1/image/generate", {
  method: "POST",
  headers: {
    Authorization: `Bearer ${process.env.VENICE_API_KEY}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    model: "z-image-turbo",
    prompt: "Photorealistic close-up portrait of a weathered fisherman at golden hour, 85mm lens, shallow depth of field, natural skin texture",
  }),
});
if (!response.ok) throw new Error(await response.text());

const { images } = await response.json();
await writeFile("fisherman.webp", Buffer.from(images[0], "base64"));
```
</CodeGroup>

Unless you set `return_binary`, as the cURL example does, the response is JSON:

```json
{
  "id": "generate-image-1234567890",
  "images": ["UklGRiIAAABXRUJQVlA4IBYAAAAwAQCdASoQABAAPm..."],
  "timing": { "inferenceDuration": 1840, "inferencePreprocessingTime": 22, "inferenceQueueTime": 31, "total": 1893 }
}
```

Each entry in `images` is a base64-encoded image, WebP unless you set `format` to `png` or `jpeg`. The `timing` values are milliseconds. With `return_binary: true`, the body is the image itself and `Content-Type` says which format.

## Shape the image

### Size

Each model sizes its images one way. Its model page says which, and so does `model_spec.constraints` in [`GET /models?type=image`](/api-reference/endpoint/models/list):

{/* image-sizing:start */}
| The model sizes by | Send | For example |
|---|---|---|
| Pixels | `width` and `height`, up to 1280 each | `lustify-v8`, `chroma`, `z-image-turbo` |
| Aspect ratio | `aspect_ratio` | `nano-banana-2-lite`, `luma-uni-1-max`, `qwen-image-2-pro` |
| Aspect ratio and resolution | `aspect_ratio`, and `resolution` of `1K`, `2K` or `4K` | `seedream-v5-5`, `flux-3-image`, `gpt-image-2-5-flare` |
{/* image-sizing:end */}

      "width": 1280,

  </Tab>
  <Tab title="Aspect ratio">

    {
      "model": "qwen-image-2",
      "prompt": "A gondola passing through a narrow Venice canal at blue hour",

    ```json
    {
      "model": "gpt-image-2-6-flare",

      "aspect_ratio": "16:9",
      "resolution": "2K"
    }
    ```
  </Tab>
</Tabs>

Send only values the model lists. A `resolution` it doesn't list returns `400`, but `aspect_ratio` isn't checked, so an unlisted ratio usually falls back to the model's default without an error. Models that size by aspect ratio ignore `width` and `height`, except `qwen-image`, `qwen-image-3`, `qwen-image-3-pro`, `qwen-image-2-1-turbo` and `qwen-image-2-1-pro`, which reject them with `400`.

### Quality

Models priced by quality, such as GPT Image, Ideogram V4.5 and Grok Imagine 2.0, take `quality` as `low`, `medium` or `high`. The price depends on resolution and quality together. Leaving `quality` out uses the model's default, which is `high` for GPT Image and Ideogram, and a level the model doesn't list returns `400`.

```json
{
  "model": "gpt-image-2-6-flare",
  "prompt": "Editorial product photo of a luxury watch on black marble, dramatic studio lighting",
  "aspect_ratio": "3:2",
  "resolution": "2K",
  "quality": "medium"
}
```

### Seed and variants

`seed` makes a result repeatable: on models that honor it, the same model, prompt, seed and settings return the same image. It takes any whole number from −999,999,999 to 999,999,999, and `0` is a seed like any other. Leave it out for a random one. GPT Image, Nano Banana Pro, Grok Imagine and a few others ignore it.

`variants` returns up to four images in one call. Only the first uses your `seed`, each one is billed as an image, and variants need the JSON response, so they don't combine with `return_binary`.

```json
{
  "model": "z-image-turbo",
  "prompt": "Cozy watercolor illustration of a hillside village in autumn",
  "seed": 42,
  "variants": 4
}
```

### Style

Two fields set a look without rewriting the prompt:

- **`style_preset`** applies a named style, on models that support presets. [`GET /image/styles`](/api-reference/endpoint/image/styles) lists the names in its `data` array, such as `Cinematic`, `Anime` and `Analog Film`, and needs no API key. Names are case-sensitive, and anything not on the list returns `400`.
- **`style_references`** passes images whose look the output should match, while the prompt describes the subject. Each entry is an `image` (a URL, base64 or a data URI, under 8 MB and not SVG) with an optional `strength` from `0.1` to `1`, which defaults to `0.5`. Only models with `supportsStyleReferences: true`, such as Krea V2 and Luma Uni-1, accept them, up to their `maxStyleReferences`. Other models return `400`, and Krea V2 adds a fee for each image it returns with references.

<CodeGroup>
```json Preset
{
  "model": "qwen-image-2",
  "prompt": "A futuristic Venice skyline at sunrise",
  "style_preset": "Cinematic"
}
```

```json References
{
  "model": "krea-v2-large",
  "prompt": "A quiet Venetian courtyard at golden hour",
  "style_references": [
    { "image": "https://example.com/reference-painting.png", "strength": 0.7 }
  ]
}
```
</CodeGroup>

### Negative prompt

`negative_prompt` names what to keep out of the image, such as `"blurry, text, watermark"`, and shares the prompt's length limit. Only some models read it, including `venice-sd35`, the Lustify models, `qwen-image-2` and `qwen-image-3`. The rest drop it without an error.

### More controls

| Field | What it does |
|---|---|
| `enhance_prompt` | Rewrites the prompt with more visual detail before generating. It adds up to 30 seconds, and $0.04 when it produces a rewrite. See [Prompt enhancement](/guides/media/prompt-enhancement). |
| `transparent_background` | Returns a PNG or WebP with a real alpha channel, on models with `supportsTransparentBackground: true`. See [Transparent backgrounds](/guides/media/transparent-backgrounds). |
| `cfg_scale` | How closely to follow the prompt, from just above `0` to `20`. Higher follows it more literally. |
| `steps` | Inference steps, on the few models that use them, such as `venice-sd35` and the Lustify models. Other models ignore it. |
| `lora_strength` | How strongly a model's built-in LoRAs apply, from `0` to `100`. The API doesn't accept custom LoRAs. |
| `enable_web_search` | Lets models with `supportsWebSearch: true`, such as Nano Banana Pro, look up current information first. |
| `hide_watermark` | Removes the watermark from Venice's flat-priced models, such as `z-image-turbo` and `chroma`. Other models never add one. |
| `embed_exif_metadata` | Writes the prompt into the image's EXIF data. |

### Adult content

`safe_mode` is on by default and blurs images classified as adult. Send `safe_mode: false` to get them unblurred. That's available to every API user, with no Pro plan needed, and the mature-content setting in the Venice app doesn't apply to API requests. Some models are built for adult images, such as the Lustify models. A third-party app shows blurred images unless it sends `safe_mode: false`.

## Read the response

These headers come back with the image:

| Header | Meaning |
|---|---|
| `x-venice-is-content-violation` | `true` when the image was blocked. The request still returns `200` with a blacked-out image, or a placeholder PNG with `return_binary`, and you aren't charged. |
| `x-venice-is-blurred` | `true` when `safe_mode` blurred the image. |
| `x-venice-content-violation-count` | How many variants a provider's content policy removed. |
| `x-venice-enhanced-prompt` | The rewritten prompt, URL-encoded, when `enhance_prompt` produced one. |
| `x-venice-model-deprecation-warning` | Present when the model is scheduled for retirement, with the date in `x-venice-model-deprecation-date`. |

With `variants` above one, a provider can reject some images and return the rest. You get fewer images than you asked for, and the body's `content_policy_violation_count` says how many are missing. If every variant is rejected, the request fails with `422`. Compare the length of `images` with `variants` rather than assuming they match.

## Use the OpenAI SDK

Already on OpenAI's image API? Point the SDK at Venice and `images.generate` calls `POST /images/generations`:

<CodeGroup>
```python Python
import base64
import os

from openai import OpenAI

client = OpenAI(api_key=os.environ["VENICE_API_KEY"], base_url="https://api.venice.ai/api/v1")

result = client.images.generate(
    model="z-image-turbo",
    prompt="A clean isometric illustration of an AI control room",
    size="1024x1024",
    response_format="b64_json",
)

with open("control-room.png", "wb") as f:
    f.write(base64.b64decode(result.data[0].b64_json))
```

```typescript TypeScript
import { writeFile } from "node:fs/promises";
import OpenAI from "openai";

const client = new OpenAI({ apiKey: process.env.VENICE_API_KEY, baseURL: "https://api.venice.ai/api/v1" });

const result = await client.images.generate({
  model: "z-image-turbo",
  prompt: "A clean isometric illustration of an AI control room",
  size: "1024x1024",
  response_format: "b64_json",
});

const image = result.data?.[0]?.b64_json;
if (!image) throw new Error("No image returned");
await writeFile("control-room.png", Buffer.from(image, "base64"));
```
</CodeGroup>

The compatible endpoint trades control for familiarity:

- `size` only reaches models that size by pixels. The rest use their default aspect ratio.
- `n` must be `1`, prompts stop at 1,500 characters, and output is PNG unless you set `output_format`.
- `moderation: "low"` replaces `safe_mode: false`, and `background: "transparent"` replaces `transparent_background`. Sending `safe_mode` here returns `400`.
- `quality`, `style`, `output_compression` and `user` are accepted and ignored, so models priced by quality bill at their default.
- `response_format: "url"` returns a data URL, not a hosted link.
- An unknown model ID, such as `dall-e-3`, falls back to `z-image-turbo` instead of failing.

Switch to `/image/generate` when you need `aspect_ratio`, `resolution`, `quality`, `seed`, `variants`, styles or binary output.

## Errors

| Status | Meaning | What to do |
|---|---|---|
| `400` | A field is missing, unknown, or not supported by this model | Check the model's constraints. The body is strict, so unknown fields fail too. |
| `401` | The API key is missing or invalid | Check the `Authorization: Bearer` header. |
| `402` | Not enough balance, or the key reached its spend limit | Add credits at [venice.ai/settings/api](https://venice.ai/settings/api?utm_source=venice-api-documentation). |
| `403` | The key's privacy setting excludes this model, or the model isn't available in your region | Use a private model, or a key that allows this one. |
| `404` | The model doesn't exist or was retired | The message names the replacement when there is one. |
| `422` | The provider rejected the prompt or a reference image | Rephrase it or switch models. The body may include `suggested_prompt` and `recommended_model`. |
| `429` | Rate limited, or the model is overloaded | Retry after the `Retry-After` header, with backoff. |
| `500`, `503` | Generation failed, or the model is at capacity | Retry with jitter. |

[Error codes](/api-reference/error-codes) has the body shapes and a retry strategy.

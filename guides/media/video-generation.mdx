## How a job runs

<div className="vg">
<ol className="vg-flow">
  <li><b>Quote</b><code>POST /video/quote</code><span>Optional. Prices the job in USD, free and with no API key.</span></li>
  <li><b>Queue</b><code>POST /video/queue</code><span>Checks the request, charges it, and returns a <code>queue_id</code>.</span></li>
  <li><b>Retrieve</b><code>POST /video/retrieve</code><span>Reports progress until the job is done, then returns the MP4.</span></li>
  <li><b>Complete</b><code>POST /video/complete</code><span>Optional. Deletes Venice's copy once you've saved yours.</span></li>

## Your first video

You need an API key in `VENICE_API_KEY` ([create one](/getting-started/quick-start)).

{/* video-first:start */}
Each example queues a 5-second clip from [MiniMax H3 Max](/models/minimax-h3-max), a private model, which costs $0.36. It polls every 10 seconds until the MP4 is ready, then saves it as `tokyo.mp4` and deletes Venice's copy.

<CodeGroup>
```python Python
import os
import time

import requests

API = "https://api.venice.ai/api/v1"
HEADERS = {"Authorization": f"Bearer {os.environ['VENICE_API_KEY']}"}

queued = requests.post(f"{API}/video/queue", headers=HEADERS, json={
    "model": "minimax-h3-max-text-to-video",
    "prompt": "A slow tracking shot through a rain-soaked Tokyo street at night, neon reflecting in puddles, steam rising from a food cart",
    "duration": "5s",
    "resolution": "768P",
    "aspect_ratio": "16:9"
})
queued.raise_for_status()
job = queued.json()

while True:
    result = requests.post(f"{API}/video/retrieve", headers=HEADERS, json={
        "model": job["model"],
        "queue_id": job["queue_id"],
        "delete_media_on_completion": True,
    })
    result.raise_for_status()
    if result.headers["Content-Type"].startswith("video/"):
        with open("tokyo.mp4", "wb") as f:
            f.write(result.content)
        break
    time.sleep(10)
```

```typescript TypeScript
import { writeFile } from "node:fs/promises";

const API = "https://api.venice.ai/api/v1";
const headers = {
  Authorization: `Bearer ${process.env.VENICE_API_KEY}`,
  "Content-Type": "application/json",
};

const queued = await fetch(`${API}/video/queue`, {
  method: "POST",
  headers,
  body: JSON.stringify({
    model: "minimax-h3-max-text-to-video",
    prompt: "A slow tracking shot through a rain-soaked Tokyo street at night, neon reflecting in puddles, steam rising from a food cart",
    duration: "5s",
    resolution: "768P",
    aspect_ratio: "16:9",
  }),
});
if (!queued.ok) throw new Error(await queued.text());
const job = await queued.json();

while (true) {
  const result = await fetch(`${API}/video/retrieve`, {
    method: "POST",
    headers,
    body: JSON.stringify({ model: job.model, queue_id: job.queue_id, delete_media_on_completion: true }),
  });
  if (!result.ok) throw new Error(await result.text());
  if (result.headers.get("content-type")?.startsWith("video/")) {
    await writeFile("tokyo.mp4", Buffer.from(await result.arrayBuffer()));
    break;
  }
  await new Promise(resolve => setTimeout(resolve, 10_000));
}
```

```bash cURL
QUEUE_ID=$(curl -s https://api.venice.ai/api/v1/video/queue \
  -H "Authorization: Bearer $VENICE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "minimax-h3-max-text-to-video",
    "prompt": "A slow tracking shot through a rain-soaked Tokyo street at night, neon reflecting in puddles, steam rising from a food cart",
    "duration": "5s",
    "resolution": "768P",
    "aspect_ratio": "16:9"
  }' | jq -r .queue_id)

while :; do
  STATUS=$(curl -s https://api.venice.ai/api/v1/video/retrieve \
    -H "Authorization: Bearer $VENICE_API_KEY" \
    -H "Content-Type: application/json" \
    -d "{\"model\": \"minimax-h3-max-text-to-video\", \"queue_id\": \"$QUEUE_ID\", \"delete_media_on_completion\": true}" \
    --output tokyo.mp4 --write-out '%{http_code} %{content_type}')
  case "$STATUS" in
    "200 video/"*) echo "Saved tokyo.mp4"; break ;;
    "200 "*) sleep 10 ;;
    *) cat tokyo.mp4; break ;;
  esac
done
```

A job can fail after it's queued, for example when a provider's content check rejects the prompt. `/video/retrieve` then returns the error instead of the video, which is why the examples stop on any response that isn't `200`. [Poll and download](#poll-and-download) covers what each one means.

A clip's price depends on its resolution, length and audio, so these are per second at each model's cheapest setting. [Video models](/models/video) lists every model, and [`/video/quote`](#quote-before-you-queue) prices an exact request.

## Choose the input

Each model starts from one kind of input, and accepts only the fields that input needs. `model_spec.constraints.model_type` in [`GET /models?type=video`](/api-reference/endpoint/models/list) says which kind, and so does the end of the model ID.

| Start from | Send | Models |
|---|---|---|
| A prompt | `prompt` | IDs ending in `-text-to-video` |
| An image | `image_url`, and a `prompt` describing the motion | IDs ending in `-image-to-video`. The clip takes the image's shape, so most reject `aspect_ratio`. |
| A first and a last frame | `image_url` and `end_image_url` | Transition models, such as `pixverse-v5.6-transition`, need both. Some image-to-video models take an end frame too. |
| Reference images, clips or audio | `reference_image_urls`, `reference_video_urls`, `reference_audio_urls` | IDs ending in `-reference-to-video`. See [Reference to video](/guides/media/reference-to-video). |
| A clip to edit | `video_url` | Video-to-video models, such as `seedance-2-5-flash-edit-video-basic` |
| A clip to upscale | `video_url`, and `upscale_factor` of `1`, `2` or `4` | `topaz-video-upscale`. See [Video upscaling](/guides/media/video-upscaling). |

Media fields take a public `https://` URL or a `data:` URL. Inlined files count toward the request's size limit, so host large ones rather than risk a `413`.

```json
{
  "model": "kling-v4-image-to-video",
  "prompt": "The camera slowly pushes in as lanterns flicker on the water",
  "image_url": "https://example.com/canal-at-dusk.jpg",
  "duration": "5s"
}
```

### Length, size and sound

Each model lists the exact values it takes in `durations`, `resolutions` and `aspect_ratios`, and they're case-sensitive: MiniMax models use `768P` where most use `720p`. Leaving `resolution` out uses the model's default. `aspect_ratio` is required when the model lists ratios and rejected when it lists none. Any field a model doesn't support returns `400` rather than being ignored.

Models with `audio_configurable: true` generate sound by default and take `audio: false` to skip it. Models with `audio_input: true` take an `audio_url` to build the clip around, as a WAV or MP3 of up to about 30 seconds and 15 MB.

Prompts can run to 2,500 characters, unless the model sets its own `prompt_character_limit`, which ranges from 1,000 to 20,000.

## Quote before you queue

`/video/quote` takes the fields that set the price and returns it in USD, without charging or starting anything:

```bash
curl https://api.venice.ai/api/v1/video/quote \
  -H "Content-Type: application/json" \
  -d '{
    "model": "kling-v4-text-to-video",
    "duration": "10s",
    "resolution": "1080p",
    "aspect_ratio": "16:9"
  }'
```

```json
{ "quote": 2.94 }
```

- No API key is needed, except to price `topaz-video-upscale`, which also needs the `video_url` it will measure.
- Send the `duration`, `resolution`, `aspect_ratio` and `audio` you'll queue. For reference-to-video, add `reference_video_total_duration`, the combined length of your reference clips in seconds, or the quote leaves them out. It's a quote-only field: `/video/queue` rejects it.
- A quote ignores fields the model doesn't take, so a successful quote doesn't prove the queue request is valid. Build the queue request from the model's constraints.
- Quotes are point-in-time. To show fixed prices in your app, quote each option you offer, cache the results, and refresh them on a schedule.

## Poll and download

Send `/video/retrieve` the `model` and `queue_id` from the queue response. It answers in one of four ways:

| Response | Meaning | What to do |
|---|---|---|
| `200`, JSON with `"status": "PROCESSING"` | Still generating | Wait, then poll again. |
| `200`, `Content-Type: video/mp4` | Done | The body is the video. Save it. |
| `200`, JSON with `"status": "COMPLETED"` | Done, delivered by link | Download it from the queue response's `download_url`, as described below. |
| Anything else | The job failed, or the poll did | See the list below the example. |

While the job runs, the JSON carries `average_execution_time`, a typical total for this model, and `execution_duration`, the time so far, both in milliseconds:

```json
{ "status": "PROCESSING", "average_execution_time": 145000, "execution_duration": 53200 }
```

Poll every 5 to 10 seconds. Polling faster doesn't finish the job sooner, and uses up the limit of 120 retrieves a minute.

Failures arrive here, because content checks and the provider run after the job is queued:

- **`422`**: the provider rejected the request or couldn't make the video. `credits_refunded` in the body says whether you got the money back, which you normally do. Runway models keep the charge when their content policy rejects a prompt.
- **`500`**: final for this job. Revise the prompt or media, then queue it again.
- **`429`, `502` or `503`**: temporary. Back off and poll the same `queue_id` again.
- **`400`** with `"Request ID is invalid."`: the `queue_id` is unknown, belongs to another account, or is more than 24 hours old. **`404`** means the video expired or was already deleted.

No endpoint lists past jobs, so store each `queue_id`, and any `download_url`, when you queue. [Billing usage history](/api-reference/endpoint/billing/usage-history) shows what past jobs cost.

### Download links

Some models, currently the Grok Imagine models, return a `download_url` in the queue response, and `/video/retrieve` only ever reports their status. Check for the field rather than the model name, since the list can change. Once the status is `COMPLETED`:

1. `GET` the `download_url`, with no auth header. It lasts up to 24 hours and is meant for one download from one network, with a few retries if the transfer drops. Repeated or shared fetches get `429` or `410`.
2. Save the file to your own storage if you need to serve it again.
3. `DELETE` the same URL to revoke it, with no API key needed. Proxies outside Venice can log full URLs, so this narrows the window in which the link works.

```bash
curl -X DELETE "$DOWNLOAD_URL"
```

Grok Imagine Private models aren't billed when moderation rejects a job.

## Clean up

Delete Venice's copy once you've saved yours, in either of two ways:

- Send `"delete_media_on_completion": true` with `/video/retrieve`, as the first example does. The video is deleted once it's been returned.
- Call `/video/complete` with the same `model` and `queue_id` after saving the file. It returns `{"success": true}`, or `409` if the job hasn't finished.

## Adult content

`/video/queue` has no `safe_mode`. Whether adult content is allowed depends on the model: use one built for it, such as the MiniMax H3 Chili models or the Wan 2.7 Enhanced variants. Other models may reject the request as a content violation, with `422`.

## Errors

These come back from `/video/queue`, `/video/quote` and `/video/complete`. [Poll and download](#poll-and-download) covers the ones `/video/retrieve` returns.

| Status | Meaning | What to do |
|---|---|---|
| `400` | A field is invalid, or not supported by this model | Check the model's constraints. Unsupported fields fail rather than being ignored. |
| `401` | The API key is missing or invalid | Check the `Authorization: Bearer` header. |
| `402` | Not enough balance for this job, or the key reached its spend limit | Add credits at [venice.ai/settings/api](https://venice.ai/settings/api?utm_source=venice-api-documentation). |
| `403` | The key's privacy setting excludes this model, or it isn't available in your region | Use a private model, or a key that allows this one. |
| `404` | The model doesn't exist | Check the ID against `GET /models?type=video`. |
| `409` | `/video/complete` was called before the job finished | Retrieve until it's done, then complete. |
| `413` | The request is too large | Host the media and send its URL instead. |
| `429` | Rate limited, at 40 queued jobs a minute per account, or the model is overloaded | Retry with exponential backoff. |
| `503` | The model is offline or at capacity | Retry later, or choose another model. |

## Every queue field

<Accordion title="All fields for POST /video/queue">
| Field | Notes |
|---|---|
| `model` | Required. An ID from `GET /models?type=video`. |
| `prompt` | Required, except for upscaling and `minimax-h3-max-multi-angle`. |
| `negative_prompt` | What to avoid. Ignored by models that don't support it. |
| `duration` | Required, from the model's `durations`. Leave it out for upscaling and video-to-video, which measure the source. |
| `resolution` | From the model's `resolutions`. Defaults to the model's own. |
| `aspect_ratio` | Required when the model lists `aspect_ratios`, rejected when it doesn't. |
| `audio` | On models with configurable audio. Defaults to `true`. |
| `image_url` | The first frame, for image-to-video. |
| `end_image_url` | The last frame, on models that take one. |
| `audio_url` | Audio to build the clip around, on models with `audio_input`. |
| `video_url` | The clip to edit or upscale. |
| `upscale_factor` | `1`, `2` or `4`, on upscale models only. |
| `reference_image_urls`, `reference_video_urls`, `reference_audio_urls` | Reference media for reference-to-video. The caps differ by model. |
| `elements`, `scene_image_urls` | Character and scene references for the Kling O3 reference models. |
| `bitrate_mode` | `standard` or `high`, on Seedance 2.0 and 2.5. It doesn't change the price. |
| `anon_user_id` | An identifier for your end user, up to 128 printable ASCII characters. |
</Accordion>

[OpenCode](https://opencode.ai/) is an AI coding agent for the terminal. OpenCode already ships a Venice AI provider, so you connect with one command and pick a model from the full Venice catalog. No config file required.

## Prerequisites

- A Venice API key from [venice.ai/settings/api](https://venice.ai/settings/api?utm_source=venice-api-documentation)
- OpenCode installed and working on your machine

---

## Setup

<Steps>
  <Step title="Connect Venice AI">
    Launch OpenCode and run the connect command:

    ```txt
    /connect
    ```

    Search for **Venice AI** and select it.

    <Frame as="div">
      <img
        src="/images/guides/opencode/connect-venice.png"
        alt="OpenCode's /connect palette filtered to Venice AI"
      />
    </Frame>
  </Step>

  <Step title="Paste your Venice API key">
    Paste the key when prompted and press enter:

    ```txt
    ┌ API key
    │
    │
    └ enter
    ```

    OpenCode stores the credential in `~/.local/share/opencode/auth.json`, so it stays available in every project.
  </Step>

  <Step title="Pick a model">
    Run the model command and choose a Venice model:

    ```txt
    /models
    ```

    `z-ai-glm-5-3-flash` is a good default for coding: fast, inexpensive, and a 1M-token context window. See [Model IDs](#model-ids) for other options.

    OpenCode also lists its own hosted free tier under similar names, for example **GLM-5.3-Flash Free** from **OpenCode** next to **GLM 5.3 Flash** from **Venice AI**. The provider name in the right column distinguishes them, and the Venice AI row is the one that uses your key and credits.
  </Step>
</Steps>

Send a small task to confirm the round trip, for example:

```txt
Review the current file and suggest one safe improvement.
```

## Pin a default model

To choose the model OpenCode starts with, add it to `opencode.json` in your project root (or `~/.config/opencode/opencode.json` for a global default):

```json
{
  "$schema": "https://opencode.ai/config.json",
  "model": "venice/z-ai-glm-5-3-flash",
  "small_model": "venice/z-ai-glm-5-3-flash"
}
```

Model references use the `venice/<model-id>` form, and `small_model` sets the cheaper model for background tasks.

## Connect without `/connect`

If you prefer to keep the credential in the project instead of OpenCode's auth store, or you are on an OpenCode build that predates the bundled provider, configure Venice as an OpenAI-compatible provider directly. Export the key, then add the provider to `opencode.json`:

```bash
export VENICE_API_KEY="your-api-key"
```

```json
{
  "$schema": "https://opencode.ai/config.json",
  "model": "venice/z-ai-glm-5-3-flash",
  "small_model": "venice/z-ai-glm-5-3-flash",
  "provider": {
    "venice": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Venice AI",
      "options": {
        "baseURL": "https://api.venice.ai/api/v1",
        "apiKey": "{env:VENICE_API_KEY}"
      },
      "models": {
        "z-ai-glm-5-3-flash": {
          "name": "GLM 5.3 Flash"
        },
        "kimi-k2-6": {
          "name": "Kimi K2.6"
        },
        "minimax-m25": {
          "name": "MiniMax M2.5"
        }
      }
    }
  }
}
```

List the models you want inside `models`. OpenCode only shows entries declared here for this provider, so leave that key out to use the full catalog.

## Model IDs

A few Venice models that work well in a coding agent. The catalog changes, so use [`GET /models?type=text`](/api-reference/endpoint/models/list) for the current list.

| Model | Venice ID |
|-------|-----------|
| GLM 5.3 Flash | `z-ai-glm-5-3-flash` |
| GLM 5.3 | `z-ai-glm-5-3` |
| Kimi K2.6 | `kimi-k2-6` |
| MiniMax M2.5 | `minimax-m25` |
| DeepSeek V4.1 Flash | `deepseek-v4-1-flash` |

Open-weight models such as these run fully private. Routed models from Anthropic, OpenAI, and Google run anonymized, so the upstream lab never sees your identity.

## Config Notes

- Keep `baseURL` set to `https://api.venice.ai/api/v1` in the manual provider block. The bundled provider already points there.
- The provider ID is `venice`, so model references use the `venice/<model-id>` form in both paths.
- Run `/connect` again at any time to replace the stored Venice key.
- Broaden context when the model supports it: several Venice models accept 1M tokens.

## Troubleshooting

<AccordionGroup>
  <Accordion title="Venice AI is missing from /connect">
    Update OpenCode to the latest release. The Venice AI provider ships with current builds, so an older install may only offer the manual config path above.
  </Accordion>
  <Accordion title="Invalid API key or 401">
    Confirm the key comes from [venice.ai/settings/api](https://venice.ai/settings/api?utm_source=venice-api-documentation), then run `/connect`, select **Venice AI**, and paste it again. OpenCode reports an auth failure rather than reaching Venice when the stored key is stale.
  </Accordion>
  <Accordion title="Model not available">
    Copy the ID exactly from [Model IDs](#model-ids), the [text model catalog](/models/text), or `GET /models`, and confirm your Venice account has access to it.
  </Accordion>
</AccordionGroup>

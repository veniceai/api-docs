[Claude Code](https://code.claude.com/docs) is Anthropic's CLI tool for agentic coding. Venice serves Anthropic's Messages API, so Claude Code connects to Venice directly, with no proxy or router in between.

## Setup

<Steps>
  <Step title="Install or update Claude Code">
    ```bash
    npm install -g @anthropic-ai/claude-code@latest
    claude --version
    ```
  </Step>

  <Step title="Get your API key">
    Generate a key at [venice.ai/settings/api](https://venice.ai/settings/api?utm_source=venice-api-documentation).
  </Step>

  <Step title="Point Claude Code at Venice">
    ```bash
    export ANTHROPIC_BASE_URL=https://api.venice.ai/api
    export ANTHROPIC_AUTH_TOKEN=your-venice-api-key
    export ANTHROPIC_API_KEY=""
    ```

    `ANTHROPIC_API_KEY` is set to an empty string so an Anthropic key in your shell is not sent instead of your Venice key. To keep the settings for every session, put them in `~/.claude/settings.json`:

    ```json
    {
      "env": {
        "ANTHROPIC_BASE_URL": "https://api.venice.ai/api",
        "ANTHROPIC_AUTH_TOKEN": "your-venice-api-key",
        "ANTHROPIC_API_KEY": ""
      }
    }
    ```
  </Step>

  <Step title="Choose a model and start">
    ```bash
    claude --model claude-opus-5-5
    ```

    Claude Code also runs quick background tasks on a small model. To choose it, set `ANTHROPIC_DEFAULT_HAIKU_MODEL`, for example to `claude-haiku-5-5`.
  </Step>
</Steps>

If you used claude-code-router with Venice before, you can remove it.

## Claude models

Claude models are relayed to Anthropic unchanged apart from the fields Venice manages, so extended thinking, prompt caching, interleaved tool use and Claude Code's web search work as they do with Anthropic.

| Claude Fable 5.1 | `claude-fable-5-1` | 1M |
| Claude Fable 5 | `claude-fable-5` | 1M |

Anthropic's own model IDs, such as `claude-sonnet-4-5-20250929`, resolve to the matching Venice model. The catalog changes over time; use [`GET /models?type=text`](/api-reference/endpoint/models/list) for the current list and limits.

## Other models

Any Venice text model that supports function calling works with Claude Code:

```bash
claude --model kimi-k3-1-pro
```

Venice translates these requests through Chat Completions. Reasoning appears as Claude Code thinking, and the web search tool uses Venice web search. Claude Code does not know the context window of models other than Claude, so set it to compact before the model's limit:

```bash
export CLAUDE_CODE_MAX_CONTEXT_TOKENS=256000
```

<Info>
Claude Code is tuned for Claude models. Other models work, but the experience depends on how well each model follows Claude Code's tool instructions.
</Info>

## What is not available

- Anthropic's code execution tool, containers, the advisor tool and the MCP connector (`mcp_servers`). MCP servers that Claude Code runs locally work as usual.
- Files API references. Send files inline.
- Signing in with a Claude subscription. Use a Venice API key.

## Troubleshooting

<AccordionGroup>
  <Accordion title="401: This request carries an Anthropic credential">
    Claude Code sent an Anthropic key or a claude.ai login instead of your Venice key. Set `ANTHROPIC_AUTH_TOKEN` to your Venice API key and `ANTHROPIC_API_KEY` to an empty string, then start a new session.
  </Accordion>

  <Accordion title="Prompt is too long on models other than Claude">
    Claude Code compacts the conversation and retries when a model reports a full context. To compact earlier, set `CLAUDE_CODE_MAX_CONTEXT_TOKENS` to the model's context window from [`GET /models`](/api-reference/endpoint/models/list) and start a new session.
  </Accordion>

  <Accordion title="Checking which path served a request">
    Every response carries `request-id`. The `x-venice-messages-lane` header is `claude` for Claude models and `compat` for others, and `x-venice-messages-ignored` lists request fields a model other than Claude could not apply.
  </Accordion>
</AccordionGroup>

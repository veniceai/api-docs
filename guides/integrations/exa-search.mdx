[Exa](https://exa.ai) is a web search API built for AI agents. You send a natural-language query and get back ranked pages with the excerpts most relevant to it, the full page text, or a summary. The Exa SDKs include ready-made tools for OpenAI-style function calling, and since Venice uses the same Chat Completions format, those tools work with Venice models unchanged. Point the OpenAI SDK at Venice, pass it the Exa tools, and any Venice model that supports function calling can search the web and read the pages it finds.

Venice also has [built-in web search](/guides/tools/web-retrieval), which needs no second account and is the simpler choice when you only want current information in a response. Exa is worth adding when you want its search controls: category filters for news, research papers, companies, people, and financial reports, domain and date constraints, query-focused excerpts, and deep multi-step search modes.

## Prerequisites

- Python 3.10 or later, or Node.js 22 or later
- A [Venice API key](/guides/getting-started/generating-api-key)
- An Exa API key from the [Exa dashboard](https://dashboard.exa.ai/api-keys). New accounts start with free credits.
- A Venice model that supports [function calling](/guides/features/function-calling). The examples use `z-ai-glm-5-3-flash`.

Install the OpenAI SDK and the Exa SDK:

```

```

Set both keys in your environment. The Exa clients read `EXA_API_KEY` on their own:

```bash
export VENICE_API_KEY=your-venice-api-key
export EXA_API_KEY=your-exa-api-key
```

## Add Exa tools to a Venice agent

`exa.openai.web_search()` and `exa.openai.get_contents()` return tool definitions in the Chat Completions format, so they go straight into the `tools` array of a Venice request. When the model replies with tool calls, pass its message to `handle_tool_calls`, which runs each Exa call and returns the matching `tool` messages. Append both to the conversation and ask again, until the model answers in text.

<CodeGroup>
```python Python
import os

from exa_py import Exa
from openai import OpenAI

exa = Exa()  # reads EXA_API_KEY
venice = OpenAI(
    api_key=os.environ["VENICE_API_KEY"],
    base_url="https://api.venice.ai/api/v1",
)

MODEL = "z-ai-glm-5-3-flash"
SYSTEM_PROMPT = (
    "Search the web when a question depends on recent or specific facts. "
    "Cite the URL of every source you use."
)
tools = [
    exa.openai.web_search(),
    exa.openai.get_contents(text={"max_characters": 10000}),
]


def ask(question: str, max_rounds: int = 6) -> str:
    messages = [
        {"role": "system", "content": SYSTEM_PROMPT},
        {"role": "user", "content": question},
    ]
    for _ in range(max_rounds):
        completion = venice.chat.completions.create(
            model=MODEL,
            messages=messages,
            tools=tools,
            extra_body={"venice_parameters": {"include_venice_system_prompt": False}},
        )
        message = completion.choices[0].message
        if not message.tool_calls:
            return message.content
        messages.append(message)
        messages += exa.openai.handle_tool_calls(message)
    raise RuntimeError(f"No answer after {max_rounds} rounds")


print(ask("What changed in the latest stable release of Python?"))
```

```javascript Node.js
import Exa from "exa-js";
import OpenAI from "openai";

const exa = new Exa(); // reads EXA_API_KEY
const venice = new OpenAI({
  apiKey: process.env.VENICE_API_KEY,
  baseURL: "https://api.venice.ai/api/v1",
});

const MODEL = "z-ai-glm-5-3-flash";
const SYSTEM_PROMPT =
  "Search the web when a question depends on recent or specific facts. " +
  "Cite the URL of every source you use.";
const tools = [
  exa.openai.webSearch(),
  exa.openai.getContents({ text: { maxCharacters: 10000 } }),
];

async function ask(question, maxRounds = 6) {
  const messages = [
    { role: "system", content: SYSTEM_PROMPT },
    { role: "user", content: question },
  ];
  for (let round = 0; round < maxRounds; round++) {
    const completion = await venice.chat.completions.create({
      model: MODEL,
      messages,
      tools,
      venice_parameters: { include_venice_system_prompt: false },
    });
    const message = completion.choices[0].message;
    if (!message.tool_calls?.length) return message.content;
    messages.push(message, ...(await exa.openai.handleToolCalls(message)));
  }
  throw new Error(`No answer after ${maxRounds} rounds`);
}

console.log(await ask("What changed in the latest stable release of Python?"));
```
</CodeGroup>

The model only writes tool calls, and your code decides what runs. A few details in the loop are worth keeping when you adapt it:

- **Append the assistant message before its tool results.** Every `tool` message has to follow the assistant turn that requested it. Appending the message object itself also keeps fields such as `reasoning_content`, which reasoning models like GLM 5.3 Flash return, so the model keeps its reasoning across tool rounds.
- **Cap page text.** `exa-py` limits `get_contents` to 10,000 characters per page by default, but `exa-js` sends no limit and gets the full page back. A single long page can fill the context window, so the examples set the same cap in both languages.
- **Turn off the Venice system prompt.** `include_venice_system_prompt: false` makes your system prompt the only instruction the model gets, and trims input tokens from every round.
- **Bound the loop.** Each round is a Venice request plus whatever Exa calls the model makes, so `max_rounds` limits both latency and cost.

### What the model controls

`web_search` asks the model for two arguments: a `query` describing the ideal page, and an `objective` that says what the search is for, which sources should rank first, and which facts to pull out. `get_contents` asks for a list of `urls`, which can come from an earlier search or from the user. Everything else, including the search type, result count, filters, and content options, is fixed in your code when you create the tool. The model can't change what gets searched or crawled.

By default, `web_search` runs an `auto` search for 10 results and returns highlights, the excerpts from each page most relevant to the query, instead of full page text. That keeps tool results short, which matters because every result is sent back to Venice as input on the next round.

## Configure the tools

Keyword arguments to the tool factories are passed through to Exa's `search` and `get_contents` calls. Give each configuration its own `name` and you can offer the model several differently scoped tools at once. This set, which replaces `tools` in the example above, adds a research paper search next to general web search:

<CodeGroup>
```python Python
tools = [
    exa.openai.web_search(),
    exa.openai.web_search(
        name="search_papers",
        description="Search research papers, preprints, and journal articles.",
        category="publication",
        num_results=5,
    ),
    exa.openai.get_contents(text={"max_characters": 10000}),
]
```

```javascript Node.js
const tools = [
  exa.openai.webSearch(),
  exa.openai.webSearch({
    name: "search_papers",
    description: "Search research papers, preprints, and journal articles.",
    category: "publication",
    numResults: 5,
  }),
  exa.openai.getContents({ text: { maxCharacters: 10000 } }),
];
```
</CodeGroup>

`handle_tool_calls` routes each call by tool name, so `search_papers` runs with its own settings. These are the options you are most likely to set:

| Python | Node.js | What it does |
| --- | --- | --- |
| `num_results` | `numResults` | Results per search. Defaults to 10, and results above 10 are billed extra |
| `type` | `type` | `auto` by default. `lite` is cheaper and faster, and `deep-lite` or `deep` run multi-step research |
| `category` | `category` | `news`, `publication`, `company`, `people`, `financial report`, or `personal site` |
| `include_domains`, `exclude_domains` | `includeDomains`, `excludeDomains` | Keep or drop results from specific domains or path prefixes |
| `start_published_date`, `end_published_date` | `startPublishedDate`, `endPublishedDate` | Limit results to a publication date range, in ISO 8601 |
| `contents` | `contents` | Return full text or summaries instead of highlights |

Some combinations are rejected. `company` and `people` searches don't accept date filters, and `people` doesn't accept `exclude_domains` either. Inside the tool loop, a rejected search comes back to the model as an `Error:` tool result rather than an exception. See Exa's [search reference](https://exa.ai/docs/reference/search) for every option.

## Search first, then generate

Function calling lets the model decide when and what to search. When your code already knows what to search, you can skip the tool loop: run one Exa search, number the results, and ask Venice to answer from them. This works with any Venice text model, and because you keep the list of sources that went into the prompt, every citation in the answer maps back to a URL.

Using the clients from the first example:

<CodeGroup>
```python Python
question = "What are the main techniques for reducing LLM inference latency?"

results = exa.search(question, num_results=8, contents={"highlights": True})
sources = "\n\n".join(
    f"[{i}] {result.title}\n{result.url}\n" + "\n".join(result.highlights or [])
    for i, result in enumerate(results.results, start=1)
)

completion = venice.chat.completions.create(
    model=MODEL,
    messages=[
        {
            "role": "system",
            "content": "Answer only from the numbered sources. Cite each claim by number, like [2].",
        },
        {"role": "user", "content": f"Question: {question}\n\nSources:\n\n{sources}"},
    ],
    extra_body={"venice_parameters": {"include_venice_system_prompt": False}},
)

print(completion.choices[0].message.content)
for i, result in enumerate(results.results, start=1):
    print(f"[{i}] {result.url}")
```

```javascript Node.js
const question = "What are the main techniques for reducing LLM inference latency?";

const results = await exa.search(question, {
  numResults: 8,
  contents: { highlights: true },
});
const sources = results.results
  .map((r, i) => `[${i + 1}] ${r.title}\n${r.url}\n${(r.highlights ?? []).join("\n")}`)
  .join("\n\n");

const completion = await venice.chat.completions.create({
  model: MODEL,
  messages: [
    {
      role: "system",
      content: "Answer only from the numbered sources. Cite each claim by number, like [2].",
    },
    { role: "user", content: `Question: ${question}\n\nSources:\n\n${sources}` },
  ],
  venice_parameters: { include_venice_system_prompt: false },
});

console.log(completion.choices[0].message.content);
results.results.forEach((r, i) => console.log(`[${i + 1}] ${r.url}`));
```
</CodeGroup>

| Use case | Model | Why |
| --- | --- | --- |

| Default for tool use | `zai-org-glm-5-2` | Venice's current `function_calling_default` |
| Uncensored research | `venice-uncensored-1-2` | Function calling without content filtering |

Model IDs rotate. Resolve the current function-calling default at runtime with [`GET /models/traits`](/api-reference/endpoint/models/traits), or browse the [text models](/models/text) for others that support function calling.

## Privacy

Venice and Exa are separate services, and your application talks to each one directly. Exa requests don't pass through Venice.

**Venice** receives your prompts, the tool definitions, and every tool result, including Exa's search results and page text. Venice doesn't store prompt or response content, and the model's [privacy tier](/overview/privacy) decides what happens at the inference layer. Private models run on zero-data-retention infrastructure.

**Exa** receives the query and objective the model writes for each search, the URLs it asks to read, and the options set in your code. Those requests fall under Exa's terms, not Venice's. Exa offers [Zero Data Retention](https://exa.ai/docs/admin/security/zero-data-retention) on Enterprise plans.

The part that's easy to miss is that the model writes search queries from the conversation, so details from a prompt can end up in a query sent to Exa. If prompts may contain personal or confidential information, tell the model in your system prompt to keep those details out of searches, or use the [search-first pattern](#search-first-then-generate) so your own code writes every query. If you set Exa's `user_identifier` to attribute usage to your end users, use an opaque ID: Exa keeps it even with Zero Data Retention enabled.

## Costs

Exa bills each search and page read to your Exa account at [Exa's rates](https://exa.ai/docs/admin/pricing), and Venice bills tokens as usual. Tool results go back to Venice as input on the next round, so the size of Exa's output shows up on your Venice bill too. A few habits keep both down:

- Stick with highlights unless the model needs whole pages, and keep a cap on page text.
- Lower `num_results` when a handful of sources is enough.
- Use the `lite` search type for high-volume or latency-sensitive search. It costs less than `auto`, serves only cached pages, and accepts fewer options.
- Keep `max_rounds` low. Each extra round can add searches as well as tokens.

<Tip>
Agents with a crypto wallet can skip both API keys. Venice accepts [x402 wallet payments](/guides/integrations/x402-venice-api) from a prepaid USDC balance, and Exa accepts [x402 payments per request](https://exa.ai/docs/integrations/payments/x402/quickstart) on its search and contents endpoints. The Exa SDK tools on this page need an API key, so an x402 agent calls Exa's REST API through an x402 client instead.
</Tip>

## Troubleshooting

<AccordionGroup>
  <Accordion title="401 Unauthorized or missing credentials">
    Confirm `VENICE_API_KEY` is set in the process that runs your code. Without it, Python raises `KeyError: 'VENICE_API_KEY'`, and the Node.js OpenAI SDK falls back to `OPENAI_API_KEY`. If that's unset too, you get a `Missing credentials` error. If it's set, the SDK sends your OpenAI key to Venice, which rejects it with `401`. A `401` with `VENICE_API_KEY` set means Venice rejected the key itself, so check it for typos or [generate a new one](/guides/getting-started/generating-api-key).
  </Accordion>

  <Accordion title="API key must be provided">
    `Exa()` and `new Exa()` throw this when `EXA_API_KEY` isn't set in the process running your code. Export it in the same shell, or pass the key directly with `Exa(api_key=...)` or `new Exa(apiKey)`.
  </Accordion>

  <Accordion title="The model says it couldn't search">
    `handle_tool_calls` doesn't raise when an Exa request fails. The error goes back to the model as the tool result instead, so it shows up in the answer rather than as an exception. Print the tool messages to see it. An invalid key returns `INVALID_API_KEY` (`401`), an empty balance returns `NO_MORE_CREDITS` (`402`), and too many requests return `RATE_LIMIT_EXCEEDED` (`429`).
  </Accordion>

  <Accordion title="'Exa' object has no attribute 'openai'">
    Your Exa SDK is older than this page needs. `exa.openai` arrived in 2.19.0, `get_contents` in 2.20.0, and the search tool's `objective` argument in 2.24.0. Upgrade with `pip install -U exa-py` or `npm install exa-js@latest`.
  </Accordion>

  <Accordion title="400 from Venice after a tool round">
    Each tool call needs a matching `tool` message, placed after the assistant message that made the call. `handle_tool_calls` answers every call in the message, and calls to tools it doesn't know get `Error: unknown tool "<name>"`. If you mix your own tools with Exa's, replace those outputs with your own results before the next request.
  </Accordion>

  <Accordion title="The model answers without searching">
    Check that the model supports function calling, and say when to search in the system prompt. Models often skip the tool when they think they can answer from memory, unless you tell them to search for recent or specific facts.
  </Accordion>
</AccordionGroup>

[Xcode](https://developer.apple.com/xcode/) includes a coding assistant that can answer questions about your project, write and refactor code, and fix errors. Besides its built-in providers, Xcode accepts any chat provider that supports the Chat Completions API, so you can add Venice in Xcode's Intelligence settings and use Venice models in coding assistant conversations.

## Prerequisites

- Xcode 26.3 or later. Earlier Xcode 26 releases can lose custom chat providers when Xcode relaunches.
- macOS Tahoe 26 or later. Xcode 27 requires macOS Tahoe 26.6 or later and an Apple silicon Mac.
- A Venice API key from [venice.ai/settings/api](https://venice.ai/settings/api?utm_source=venice-api-documentation)

## Setup

<Steps>
  <Step title="Get your Venice API key">
    Generate a key from [venice.ai/settings/api](https://venice.ai/settings/api?utm_source=venice-api-documentation). An **Inference Only** key is enough for Xcode.

    Consider creating a dedicated key with an **Epoch Consumption Limit**, so you can cap what Xcode spends and revoke the key without affecting other apps. See [Generating an API Key](/guides/getting-started/generating-api-key).
  </Step>

  <Step title="Open Intelligence settings">
    In Xcode, choose **Xcode > Settings** and select **Intelligence** in the sidebar.
  </Step>

  <Step title="Add Venice as a chat provider">
    Under **Chat**, click **Add a Chat Provider** and select **Internet Hosted**. Some Xcode 26 releases label the button **Add a Model Provider**.

    Enter the following values, then click **Add**:

    | Field | Value |
    | --- | --- |
    | URL | `https://api.venice.ai/api` |
    | API Key | `Bearer your-venice-api-key` |
    | API Key Header | `Authorization` |
    | Description | `Venice` |

    Keep the URL exactly as shown, with no `/v1` and no trailing slash. Xcode appends `/v1/models` and `/v1/chat/completions` to it, which produces Venice's standard endpoints under `https://api.venice.ai/api/v1`.

    Xcode sends the **API Key** field as the entire value of the `Authorization` header. Replace `your-venice-api-key` with your key and keep the `Bearer ` prefix.
  </Step>

  <Step title="Choose your models">
    Select the Venice provider under **Chat**. Xcode fetches the model list from Venice. Turn on the models you want to use, and star the ones you use most so they appear at the top of the model menu.

    The list includes every Venice text model, but the coding assistant only works with models that support tool calling. Check the [model requirements](#model-requirements) before you choose.
  </Step>

  <Step title="Start a conversation">
    Open a project, then click the **Coding Assistant** button or press **Command-0**. Click **New Conversation** and choose a Venice model under **Chat**. The placeholder text in the message field shows which model the conversation uses.

    Send a short prompt to test the connection:

    ```txt
    Summarize what this project does in three bullet points.
    ```
  </Step>
</Steps>

## Verify the setup

A full model list in Xcode doesn't confirm that your key works. Venice's `/models` endpoint returns the catalog with or without a valid key, so Xcode can load it even when the key or header is wrong. Venice checks the key when you send a message.

If messages fail, test the key outside Xcode. `GET /api_keys/rate_limits` requires a valid key and costs nothing:

```bash
curl https://api.venice.ai/api/v1/api_keys/rate_limits \
  -H "Authorization: Bearer $VENICE_API_KEY"
```

Then send a request to the same chat endpoint that Xcode uses:

```bash
curl https://api.venice.ai/api/v1/chat/completions \
  -H "Authorization: Bearer $VENICE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "z-ai-glm-5-3-flash",
    "messages": [{"role": "user", "content": "Reply with OK"}]
  }'
```

If both requests succeed but Xcode still can't chat, compare the provider settings against [Troubleshooting](#troubleshooting).

## Model requirements

The model you select must support tool calling. In chat conversations, Xcode gives the model tools for searching and editing your project, so a model without tool calling can't handle the coding assistant's requests. The [text model catalog](/models/text) lists this capability as **Function Calling**, and most Venice text models support it.

Ideally, the model should also have a context window of 200K tokens or more. Xcode has no context-window setting for chat providers, and with **Project Context** on, a request can include a lot of project code on top of Xcode's tool definitions.

To list the Venice models that meet both requirements:

```bash
curl -s https://api.venice.ai/api/v1/models \
  | jq -r '.data[] | select(.model_spec.capabilities.supportsFunctionCalling and .model_spec.availableContextTokens >= 200000) | .id'
```

## Choosing a model

Among the models that meet these requirements, consider:

- **Coding strength.** The [text model catalog](/models/text) marks models optimized for code, and [`GET /models/traits?type=text`](/api-reference/endpoint/models/traits) returns Venice's current coding default as `default_code`.
- **Cost.** **Project Context** makes requests large, so input-token pricing matters more than usual. Compare prices in the [text model catalog](/models/text).
- **Vision.** To attach screenshots or design mockups with **Upload files**, choose a model that supports vision.

Venice retires and replaces models regularly. If a model stops working, check [Deprecations](/overview/deprecations) and switch to a current one.

## Agents

Chat providers power chat conversations only. Xcode's built-in agents, such as Claude Agent and Codex, and any agents you add over the Agent Client Protocol (ACP) are configured separately and don't send requests through a chat provider. Agents also get more of Xcode's capabilities than chat does, such as building and testing your app.

To run an agent on Venice models with access to your Xcode project, configure a terminal agent for Venice and connect it to the Model Context Protocol (MCP) server that Xcode 26.3 and later provide:

<Steps>
  <Step title="Allow external agents">
    In Xcode's Intelligence settings, under **Model Context Protocol**, turn on **Allow external agents to use Xcode tools**.
  </Step>

  <Step title="Set up the agent with Venice">
    Follow the [Codex CLI](/guides/integrations/codex-cli) or [Claude Code](/guides/integrations/claude-code) guide.
  </Step>

  <Step title="Connect the agent to Xcode">
    Register Xcode's MCP server with the agent:

    <CodeGroup>
    ```bash Codex CLI
    codex mcp add xcode -- xcrun mcpbridge
    ```

    ```bash Claude Code
    claude mcp add --transport stdio xcode -- xcrun mcpbridge
    ```
    </CodeGroup>
  </Step>

  <Step title="Prompt the agent">
    Open your project in Xcode first, then prompt the agent in Terminal. Xcode alerts you when the agent connects.
  </Step>
</Steps>

## Privacy

Xcode sends chat requests from your Mac directly to Venice. **Project Context** is on by default in chat conversations, so Xcode includes relevant code and other context from your project in each request. To limit what Xcode sends, turn off **Project Context** in the message field and reference files and symbols explicitly with `@`.

Venice does not store or log prompt and response content at its proxy. The model you choose determines the runtime privacy tier:

- **Private** models use zero-data-retention infrastructure.
- **Anonymized** models hide your identity from the upstream provider, but that provider can process your code.
- **TEE** models, with `e2ee-` model IDs, run inside a hardware enclave. Xcode can't encrypt prompts on your Mac, so these models run in TEE mode rather than end-to-end encrypted mode when you use them from Xcode.

Check each model's privacy label in the [text model catalog](/models/text) and read [Venice privacy](/overview/privacy) before sending proprietary code.

## Troubleshooting

<AccordionGroup>
  <Accordion title="Xcode can't load models or rejects the provider">
    Check that the URL is exactly `https://api.venice.ai/api`. A URL ending in `/v1` makes Xcode request `/api/v1/v1/models`, and a trailing slash produces `/api//v1/models`. Venice returns `404` for both. Add the provider again with the corrected URL.
  </Accordion>
  <Accordion title="Models load, but messages fail">
    Venice's model list is public, so it loads even when the key or header is wrong. Confirm that **API Key Header** is `Authorization` and that **API Key** starts with `Bearer `, then test the key with the commands in [Verify the setup](#verify-the-setup).
  </Accordion>
  <Accordion title="Endpoint errors when you send a message">
    Check that the conversation uses a model that supports tool calling and, ideally, has a context window of 200K tokens or more. Xcode sends tool definitions and project context with each request: a model without tool calling can't handle them, and a large project can overflow a smaller context window. Turn on a model that meets the [model requirements](#model-requirements), then start a new conversation with it.
  </Accordion>
  <Accordion title="402 or payment required error">
    Venice returns `402` in two cases:

    - The request reached Venice without an `Authorization` header. Venice ignores other headers, such as `x-api-key`, and answers with an x402 payment challenge. Set **API Key Header** to `Authorization`.
    - The key reached its spend limit, or your balance ran out. See [Troubleshooting spend limit errors](/guides/getting-started/generating-api-key#troubleshooting-spend-limit-errors).
  </Accordion>
  <Accordion title="The Venice provider disappears after relaunching Xcode">
    Update to Xcode 26.3 or later, which fixed custom model providers disappearing between launches.
  </Accordion>
  <Accordion title="Model not found">
    Venice may have retired the model. Check [Deprecations](/overview/deprecations), choose a current model from the provider's model list, and start a new conversation.
  </Accordion>
  <Accordion title="Agent conversations don't use Venice">
    This is expected. Chat providers only power chat conversations. Start a conversation under **Chat**, or connect a Venice-configured agent as described in [Agents](#agents).
  </Accordion>
  <Accordion title="Intelligence settings or the coding assistant are missing">
    Coding intelligence in Xcode 26 requires macOS Tahoe 26. On a Mac managed by your organization, a device management profile can turn off the coding assistant with the `CodingAssistantAllowExternalIntegrations` key.
  </Accordion>
</AccordionGroup>

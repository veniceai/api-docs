Der [Venice MCP Server](https://github.com/veniceai/venice-mcp-server) ist der offizielle [Model Context Protocol](https://modelcontextprotocol.io/)-Server für Venice. Er stellt die Venice-API (Chat, Image, Video, Audio, Musik, Embeddings, Web Augment, Characters, Crypto-RPC und TEE-Attestierung) sowie Konto-Operationen (Abrechnung und API-Schlüssel) als **45 Tools** bereit, die jeder MCP-kompatible Agent aufrufen kann.

## Schnellstart

<Steps>
  <Step title="Venice API-Schlüssel besorgen">
    Erzeuge einen unter [venice.ai/settings/api](https://venice.ai/settings/api?utm_source=venice-api-documentation). Schritt-für-Schritt-Anleitung im [API-Key-Guide](/guides/getting-started/generating-api-key).
  </Step>

  <Step title="Venice zur MCP-Host-Konfiguration hinzufügen">
    Diesen Block in die Konfigurationsdatei deines MCP-Hosts einfügen:

    ```json
    {
      "mcpServers": {
        "venice": {
          "command": "npx",
          "args": ["-y", "@veniceai/mcp-server@0.3.0"],
          "env": { "VENICE_API_KEY": "<your-venice-api-key>" }
        }
      }
    }
    ```

    Übliche Konfigurationspfade:

    | Host | Pfad |
    |---|---|
    | Claude Desktop (macOS) | `~/Library/Application Support/Claude/claude_desktop_config.json` |
    | Claude Desktop (Windows) | `%APPDATA%\Claude\claude_desktop_config.json` |
    | Cursor | `~/.cursor/mcp.json` |
    | LM Studio | `mcp.json` (über die MCP-Einstellungen der App) |
  </Step>

  <Step title="MCP-Host neu starten">
    Dein Agent hat jetzt Chat, Image, Video, Musik, TTS, ASR, Abrechnung, API-Schlüssel und 39 weitere Venice-Tools zur Verfügung.
  </Step>
</Steps>

<Note>
Die meisten MCP-Hosts geben nur Umgebungsvariablen weiter, die **explizit** im `env`-Block aufgeführt sind. System-Env-Vars werden nicht geerbt. Wenn du trotz gesetztem API-Schlüssel 402-Fehler erhältst, prüfe, ob `VENICE_API_KEY` innerhalb von `env` in deiner Konfiguration steht.
</Note>

## Was du bekommst

**45 Tools** für jede Venice-Modalität plus Konto-Operationen, **3 Ressourcen** (`venice://models`, `venice://styles`, `venice://voices`) und **3 Prompt-Templates** (uneingeschränkte Recherche, NSFW-Creative-Writing, Image-Style-Explorer).

Jedes Tool deklariert explizite `readOnlyHint`-, `destructiveHint`-, `idempotentHint`- und `openWorldHint`-Annotations. So können Hosts Lookups ohne Rückfrage ausführen und vor destruktiven Aktionen – etwa Medien-Cleanup oder einem Crypto-Relay – nachfragen.

### Chat & Embeddings

| Tool | Beschreibung |
|---|---|
| `venice_chat` | OpenAI-kompatible Chat-Completion gegen Venices vollständigen LLM-Katalog, mit Text-/Bild-/Audio-/Video-/Datei-Blöcken, strukturierten Ausgaben, Function Tools, Prompt-Caching und Reasoning-Steuerung. Aufrufe sind Klartext und nicht gestreamt. |
| `venice_responses` | Alpha, zustandslose, OpenAI-kompatible Responses-API mit Text-/Bild-Input und Reasoning-Steuerung. E2EE-fähige Modelle und Tool-Felder werden nicht unterstützt. |
| `venice_embeddings` | Embeddings für Texteingabe berechnen. |
| `venice_chat_with_character` | Chat mit einem Venice-Character per Slug. |

### Image

|---|---|
| `venice_image_generate` | Bild generieren (Flux 2, Lustify SDXL, Anime/WAI, Qwen Image, GPT Image, Nano Banana Pro und mehr), mit Seitenverhältnis oder Breite/Höhe, Quality-Stufen, Prompt-Enhancement, Style-Referenzen, Web-Suche und Varianten. |
| `venice_image_edit` | Bild mit einem Prompt bearbeiten. |
| `venice_image_multi_edit` | Bis zu 8 Bilder gemeinsam mit einem Prompt bearbeiten (Komposition / Outpainting). |
| `venice_image_upscale` | Bild 2–4× hochskalieren, mit `creativity`-Steuerung. |
| `venice_image_remove_bg` | Bildhintergrund entfernen. |
| `venice_image_styles` | Bildstil-Presets auflisten. |

| Tool | Beschreibung |
|---|---|

Verifiziere den zurückgegebenen Nonce, den Debug-Modus und die Bindung des Signaturschlüssels selbst, bevor du einem TEE-Modell vertraust, und nutze für TEE-Modelle `venice_chat` (nie `venice_responses`). `enable_e2ee` wird von diesem Server abgelehnt.
</Warning>

</Note>

## Konfiguration

Der Server wird vollständig über Umgebungsvariablen konfiguriert.

### Modelle und Anfragen

| Env-Var | Default | Hinweise |
|---|---|---|
| `VENICE_API_KEY` | _(keine)_ | Dein Venice API-Schlüssel. Das einfachste Setup. |
| `VENICE_DEFAULT_CHAT_MODEL` | `deepseek-v4-flash-0731` | |
| `VENICE_DEFAULT_IMAGE_MODEL` | `flux-2-pro` | |
| `VENICE_DEFAULT_TTS_MODEL` | `tts-kokoro` | |
| `VENICE_DEFAULT_ASR_MODEL` | `openai/whisper-large-v3` | |
| `VENICE_DISABLE_NSFW` | `0` | Auf `1` setzen, um NSFW-Capability-Hinweise aus Tool-Beschreibungen zu entfernen. |
| `VENICE_HTTP_TIMEOUT_MS` | `60000` | |
| `VENICE_SIWX_TOKEN` | _(keiner)_ | x402-Wallet-Mode-Auth-Token. Siehe [x402 unten](#x402-wallet-modus). |

Wenn sowohl `VENICE_API_KEY` als auch `VENICE_SIWX_TOKEN` gesetzt sind, gewinnt der API-Schlüssel.

### Antwortgrößen-Limits

Generierte Medien werden gepuffert und als base64 in das MCP-Ergebnis eingebettet, daher hat jede Modalität eine Byte-Obergrenze.

| Env-Var | Default | Gilt für |
|---|---|---|
| `VENICE_MAX_IMAGE_RESPONSE_BYTES` | `33554432` (32 MiB) | `venice_image_generate`, `venice_image_edit`, `venice_image_multi_edit`, `venice_image_upscale`, `venice_image_remove_bg` |
| `VENICE_MAX_VIDEO_RESPONSE_BYTES` | `26214400` (25 MiB) | `venice_video_status` |
| `VENICE_MAX_AUDIO_RESPONSE_BYTES` | `33554432` (32 MiB) | `venice_tts`, `venice_music_status` |

Ein zu großes Bild- oder TTS-Ergebnis wird mit einem Fehler verworfen. Ein zu großes Video- oder Musik-Ergebnis bleibt in der Queue, sodass du das Status-Tool nach Anheben des Limits erneut mit derselben Queue-ID aufrufen kannst.

### HTTP-Server

Nur relevant beim [Streamable-HTTP-Deployment](#self-hosting-streamable-http).

| Env-Var | Default | Hinweise |
|---|---|---|
| `PORT` | `3333` | HTTP-Listener-Port. |
| `VENICE_MCP_HOST` | `127.0.0.1` | Bind-Adresse. Auf `0.0.0.0` setzen für LAN- oder Container-Exposition. |
| `VENICE_MCP_AUTH_TOKEN` | _(keiner)_ | Bearer-Token, das `/mcp` verlangt, wenn außerhalb von Loopback gebunden wird. |
| `VENICE_MCP_ALLOW_UNAUTHENTICATED_HTTP` | `0` | Notausgang für exponiertes unauthentifiziertes HTTP. Nur hinter einem vertrauenswürdigen authentifizierten Proxy verwenden. |
| `VENICE_MCP_MAX_SESSIONS` | `100` | Maximale aktive Streamable-HTTP-Sessions. |
| `VENICE_MCP_SESSION_TTL_MS` | `1800000` | Lebensdauer einer idle Session bis zum Cleanup. |

## Medienverhalten

- **Fertige Medien können Bytes oder eine URL sein.** Video- und Musik-Jobs liefern eingebettete MP4-/Audio-Ressourcen oder JSON mit einer `download_url`, die als Resource-Link zurückkommt. Lade zuerst diesen Link herunter und rufe dann `venice_video_complete` bzw. `venice_music_complete` auf; Medien-Cleanup wird nie auf ein `download_url`-Ergebnis angewendet, weil der Link nach dem Löschen nicht mehr funktioniert.
- **Manche Modelle liefern die URL nur beim Queue-Eintrag.** Bei VPS- und Grok-Imagine-Private-Modellen die von `venice_video_generate` zurückgegebene `download_url` sichern und in `venice_video_status` übergeben; ein `COMPLETED`-Retrieve ohne Inline-URL liefert trotzdem einen nutzbaren Link.
- **Prompt-Enhancement wird zurückgemeldet.** Wenn `enhance_prompt` angewendet wird, enthalten Bild-Generate-, Edit- und Multi-Edit-Ergebnisse den URL-dekodierten Prompt, den Venice zurückgibt.
- **ASR-Paging wird nur einmal berechnet.** Transkripte mit Zeitstempeln oder mehr als 8000 Zeichen liefern ein `result_handle` mit der ersten Seite. Weitere Seiten mit diesem Handle anfordern. Handles liegen im Speicher pro MCP-Session für 10 Minuten; nur die 16 neuesten bleiben erhalten.
- **Seedance-Consent ist kein Policy-Bypass.** Aktuelle öffentliche Seedance-Modelle können Medien mit erkennbaren Personen grundsätzlich ablehnen. Wird eine `needs_consent`-Antwort zurückgegeben, sind die drei `consents.seedance`-Flags rechtliche Bestätigungen: Setze sie nur auf `true`, nachdem der Nutzer jede Aussage explizit bestätigt hat.

## x402 Wallet-Modus

Venice unterstützt – zusätzlich zum normalen API-Key-Flow – die Authentifizierung mit einem [Sign-In-With-X-Wallet-Token](/guides/integrations/x402-venice-api), der durch Prepaid-USDC-Guthaben auf Base oder Solana gedeckt ist. Keine E-Mail, kein Telefon, kein KYC erforderlich: Deine Wallet ist die einzige Identität.

```json
{
  "mcpServers": {
    "venice": {
      "command": "npx",
      "args": ["-y", "@veniceai/mcp-server@0.3.0"],
      "env": { "VENICE_SIWX_TOKEN": "<base64 Sign-In-With-X payload>" }
    }
  }
}
```

Der MCP-Server leitet `VENICE_SIWX_TOKEN` bei jedem Venice-API-Aufruf im `SIGN-IN-WITH-X`-Header weiter. Der Server sieht nie deinen Private Key. Wallet-Signatur und USDC-Top-up-Autorisierungen erfolgen in deiner eigenen Wallet.

| Flow | Was passiert |
|---|---|
| **Einmalige Einrichtung** | Sign-In-With-X-Nachricht in deiner Wallet signieren → erzeugt einen SIWX-Token (base64 JSON). |
| **Top-up** | `POST /api/v1/x402/top-up` liefert 402 + Zahlungsanforderungen. Eine USDC-Zahlung für eine der zurückgegebenen Base- oder Solana-Optionen signieren, erneut senden, und Venice schreibt deinem Guthaben gut. |
| **Jeder Inferenz-Aufruf** | MCP-Server sendet `SIGN-IN-WITH-X: <SIWX>`; Venice belastet dein Prepaid-Guthaben. |

Der Mindest-Top-up beträgt **\$5 USD**. Das Mindest-Guthaben zum Inferenz-Aufruf beträgt **\$0,10**. Nach dem Top-up dauern Aufrufe unter 100 ms, weil die Verrechnung off-chain auf einem schnellen Credit-Konto stattfindet.

<Tip>
Wallets, die mit einem Venice-Konto mit gestaktem DIEM verknüpft sind, verbrauchen aus dem Staking-Guthaben statt aus USDC-Credits — kein Top-up nötig.
</Tip>

Venice akzeptiert keine Zahlungs-Header auf Inferenz-Routen, daher sendet dieser Server nie einen. `PAYMENT-SIGNATURE` gehört ausschließlich zu `/x402/top-up`, und der Top-up-Helfer ermittelt die Anforderungen, ohne eine Zahlung zu übermitteln.

### Abdeckung der Auth-Modi

Manche Endpunkte akzeptieren nur einen Auth-Modus:

| Tool | API-Schlüssel | x402 |
|---|---|---|
| Inferenz, Medien, Web Augment, Crypto-RPC, Character-Chat | ✓ | ✓ |
| `venice_list_characters`, `venice_get_character`, `venice_character_reviews` | ✓ | ✗ |
| `venice_billing_*`, `venice_list_api_keys`, `venice_get_api_key`, `venice_api_key_rate_limit_logs` | ✓ (Admin) | ✗ |
| `venice_api_key_rate_limits` | ✓ (beliebiger Key) | ✗ |
| `venice_x402_balance`, `venice_x402_transactions` | ✗ | ✓ |
| `venice_x402_top_up_info` | ✓ | ✓ |

Sind beide Credentials gesetzt, gewinnt der API-Schlüssel bei jedem Aufruf. Die SIWX-only-Helfer (`venice_x402_balance`, `venice_x402_transactions`) funktionieren daher nur, wenn das Wallet-Token dein einziges Credential ist.

## Self-Hosting (Streamable HTTP)

Für Team- oder Workspace-Deployments läuft der MCP-Server über HTTP statt stdio:

```bash
docker run -p 3333:3333 \
  -e VENICE_API_KEY=<your-venice-api-key> \
  -e VENICE_MCP_AUTH_TOKEN=<choose-a-long-random-token> \
  ghcr.io/veniceai/venice-mcp-server:latest
```

Der Server ist nun unter `http://localhost:3333/mcp` erreichbar. HTTP-Clients müssen `Authorization: Bearer <VENICE_MCP_AUTH_TOKEN>` senden und sollten neue Sessions ohne `mcp-session-id`-Header anlegen und danach die vom Server ausgegebene Session-ID wiederverwenden.

<Warning>
`/mcp` ist ein credential-gestützter Tool-Ausführungs-Endpoint: Aufrufer können den konfigurierten Venice API-Schlüssel oder x402-Guthaben verbrauchen. Wenn der HTTP-Modus außerhalb von Loopback bindet, schlägt der Start fehl, sofern `VENICE_MCP_AUTH_TOKEN` nicht gesetzt ist oder `VENICE_MCP_ALLOW_UNAUTHENTICATED_HTTP=1` hinter einem vertrauenswürdigen authentifizierten Proxy gesetzt wurde. Im Produktivbetrieb das npm-Paket explizit auf eine Version pinnen, statt auf `latest` zu vertrauen.
</Warning>

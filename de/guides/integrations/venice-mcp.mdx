Der [Venice MCP Server](https://github.com/veniceai/venice-mcp-server) ist der offizielle [Model Context Protocol](https://modelcontextprotocol.io/)-Server für Venice. Er stellt die Venice-API (Chat, Image, Video, Audio, Music, Embeddings, Web Augment, Characters, Crypto-RPC und TEE-Attestation) sowie Kontofunktionen (Abrechnung und API-Schlüssel) als **45 Tools** bereit, die jeder MCP-kompatible Agent aufrufen kann.

## Schnellstart

<Steps>
  <Step title="Venice API-Schlüssel besorgen">
    Erstelle einen unter [venice.ai/settings/api](https://venice.ai/settings/api?utm_source=venice-api-documentation). Schritt-für-Schritt-Anleitung im [API-Schlüssel-Guide](/de/guides/getting-started/generating-api-key).
  </Step>

  <Step title="Venice zur MCP-Host-Konfiguration hinzufügen">
    Füge dies in die Konfigurationsdatei deines MCP-Hosts ein:

    ```json
    {
      "mcpServers": {
        "venice": {
          "command": "npx",
          "args": ["-y", "@veniceai/mcp-server@0.3.0"],
          "env": { "VENICE_API_KEY": "<your-venice-api-key>" }
        }
      }
    }
    ```

    Übliche Konfigurationspfade:

    | Host | Pfad |
    |---|---|
    | Claude Desktop (macOS) | `~/Library/Application Support/Claude/claude_desktop_config.json` |
    | Claude Desktop (Windows) | `%APPDATA%\Claude\claude_desktop_config.json` |
    | Cursor | `~/.cursor/mcp.json` |
    | LM Studio | `mcp.json` (aus den MCP-Einstellungen der App) |
  </Step>

  <Step title="MCP-Host neu starten">
    Dein Agent hat jetzt Chat, Image, Video, Music, TTS, ASR und 39 weitere Venice-Tools verfügbar.
  </Step>
</Steps>

<Note>
Die meisten MCP-Hosts geben nur Umgebungsvariablen weiter, die **explizit** im `env`-Block aufgeführt sind. System-Env-Vars werden nicht geerbt. Wenn du trotz gesetztem API-Schlüssel 402-Fehler erhältst, prüfe, ob `VENICE_API_KEY` innerhalb von `env` in deiner Konfiguration steht.
</Note>

## Was du bekommst

**45 Tools** für jede Venice-Modalität plus Kontofunktionen, **3 Ressourcen** (`venice://models`, `venice://styles`, `venice://voices`) und **3 Prompt-Templates** (unzensierte Recherche, kreatives NSFW-Schreiben, Bildstil-Explorer).

Jedes Tool deklariert explizite Annotationen `readOnlyHint`, `destructiveHint`, `idempotentHint` und `openWorldHint`. So können Hosts Abfragen ohne Rückfrage ausführen und vor allem Destruktiven, etwa dem Löschen von Medien oder einem Crypto-Relay, um Bestätigung bitten.

### Chat & Embeddings

| Tool | Beschreibung |
|---|---|
| `venice_chat` | OpenAI-kompatible Chat-Completion gegen Venices vollständigen LLM-Katalog, mit Text-/Bild-/Audio-/Video-/Datei-Blöcken, Structured Outputs, Function-Tools, Prompt-Caching und Reasoning-Steuerung. Aufrufe erfolgen im Klartext und ohne Streaming. |
| `venice_responses` | Zustandslose, OpenAI-kompatible [Responses-API](/de/guides/features/responses-api) (Beta) mit Text-/Bild-Eingabe und Reasoning-Steuerung. Dieses Tool stellt keine Tool-Calling-Felder bereit, und E2EE-Modelle werden nicht unterstützt. |
| `venice_embeddings` | Embeddings für Texteingabe berechnen. |
| `venice_chat_with_character` | Chat mit einem Venice-Character per Slug. |

### Image

| Tool | Beschreibung |
|---|---|
| `venice_image_generate` | Bild generieren (Flux 2, Lustify SDXL, Anime/WAI, Qwen Image, GPT Image, Nano Banana Pro und mehr), mit Seitenverhältnis oder Breite/Höhe, Qualitätsstufen, Prompt-Verbesserung, Stilreferenzen, Websuche und Varianten. |
| `venice_image_edit` | Bild mit einem Prompt bearbeiten. |
| `venice_image_multi_edit` | Bis zu 8 Bilder zusammen mit einem Prompt bearbeiten (Komposition / Outpainting). |
| `venice_image_upscale` | Bild um das 2- bis 4-Fache hochskalieren, mit `creativity`-Steuerung. |
| `venice_image_remove_bg` | Bildhintergrund entfernen. |
| `venice_image_styles` | Bildstil-Presets auflisten. |

### Video

| Tool | Beschreibung |
|---|---|
| `venice_video_generate` | Video-Generierungsjob in die Queue stellen (Sora 2, Veo 3.1, Kling, Wan, LTX 2, Seedance, Runway Gen-4 und mehr), mit Bild-, Video-, Audio-, Referenz- und Element-Eingaben. |
| `venice_video_status` | Status eines Video-Jobs in der Queue prüfen (`POST /video/retrieve`). |
| `venice_video_complete` | Fertiges Video als heruntergeladen markieren und die serverseitigen Medien löschen. Meldet die Löschung nur, wenn Venice sie bestätigt. |
| `venice_video_quote` | Preis-Quote vor dem Queue-Eintrag bekommen. |

### Audio (TTS / ASR)

| Tool | Beschreibung |
|---|---|
| `venice_tts` | Text-to-Speech mit geklonten Stimmen, Temperature und Emotions-Tags. Streaming wird zu einem vollständigen Audio-Ergebnis gepuffert. |
| `venice_asr` | Audio von einer URL transkribieren, optional mit Zeitstempeln pro Wort oder Zeichen. Große Transkripte werden über ein Session-Handle seitenweise ausgeliefert. |
| `venice_voice_clone` | Aktuelle modellspezifische Stimmen auflisten oder eine Stimme aus einer Sample-URL klonen (liefert ein `vv_<id>`-Handle für `venice_tts`). |
| `venice_audio_quote` | Preis-Quote für Musikgenerierung bekommen. |

### TEE-Attestation

| Tool | Beschreibung |
|---|---|
| `venice_tee_attestation` | Hardware-Attestation-Nachweise (Intel-TDX-Quote, optionale NVIDIA-Nachweise, Signing-Key) für ein TEE-fähiges Textmodell abrufen, mit deiner eigenen 32-Byte-Nonce. |

<Warning>
Beide TEE-Tools liefern nur die Nachweise des Anbieters: Sie verifizieren diese nicht und verschlüsseln keinen Chat. Prüfe die zurückgegebene Nonce, den Debug-Modus-Status und die Bindung des Signing-Keys selbst, bevor du einem TEE-Modell vertraust; siehe [TEE-Attestation verifizieren](/de/guides/features/tee-e2ee-models#tee-attestation-verifizieren). `enable_e2ee` wird von diesem Server abgelehnt.
</Warning>

### Crypto

| Tool | Beschreibung |
|---|---|
| `venice_crypto_networks` | Die aktuellen Netzwerk-Slugs auflisten, die der RPC-Proxy akzeptiert. |
| `venice_crypto_rpc` | Eine JSON-RPC-Anfrage oder einen Batch von bis zu 100 Anfragen an Ethereum, Base, Arbitrum, Optimism, Polygon, Solana, Starknet, zkSync, Linea, BSC, Avalanche, Blast und mehr proxien. |

Transaktions-Broadcasts (`eth_sendRawTransaction`, `eth_sendUserOperation`, Solana `sendTransaction`, Starknet-Schreibvorgänge) müssen als Einzelanfragen mit einem `idempotency_key` gesendet werden, und bei einem erneuten Versuch muss derselbe Schlüssel wiederverwendet werden.

</Note>

## Konfiguration

Der Server wird vollständig über Umgebungsvariablen konfiguriert.

### Modelle und Anfragen

| Env-Var | Default | Hinweise |
|---|---|---|
| `VENICE_API_KEY` | _(keiner)_ | Dein Venice API-Schlüssel. Das einfachste Setup. |
| `VENICE_DEFAULT_CHAT_MODEL` | `deepseek-v4-flash-0731` | |
| `VENICE_DEFAULT_IMAGE_MODEL` | `flux-2-pro` | |
| `VENICE_DEFAULT_TTS_MODEL` | `tts-kokoro` | |
| `VENICE_DEFAULT_ASR_MODEL` | `openai/whisper-large-v3` | |
| `VENICE_DISABLE_NSFW` | `0` | Auf `1` setzen, um NSFW-Capability-Hinweise aus Tool-Beschreibungen zu entfernen. |
| `VENICE_HTTP_TIMEOUT_MS` | `60000` | |
| `VENICE_SIWX_TOKEN` | _(keiner)_ | x402-Wallet-Mode-Auth-Token. Siehe [x402 unten](#x402-wallet-modus). |

Wenn sowohl `VENICE_API_KEY` als auch `VENICE_SIWX_TOKEN` gesetzt sind, gewinnt bei den meisten Aufrufen der API-Schlüssel; die Ausnahmen findest du unter [Abdeckung der Auth-Modi](#abdeckung-der-auth-modi).

### Größenlimits für Antworten

Generierte Medien werden gepuffert und als base64 in das MCP-Ergebnis eingebettet, daher gibt es pro Modalität eine Byte-Obergrenze.

| Env-Var | Default | Gilt für |
|---|---|---|
| `VENICE_MAX_IMAGE_RESPONSE_BYTES` | `33554432` (32 MiB) | `venice_image_generate`, `venice_image_edit`, `venice_image_multi_edit`, `venice_image_upscale`, `venice_image_remove_bg` |
| `VENICE_MAX_VIDEO_RESPONSE_BYTES` | `26214400` (25 MiB) | `venice_video_status` |
| `VENICE_MAX_AUDIO_RESPONSE_BYTES` | `33554432` (32 MiB) | `venice_tts`, `venice_music_status` |

Ein zu großes Bild- oder TTS-Ergebnis wird mit einem Fehler verworfen. Ein zu großes Video- oder Musik-Ergebnis bleibt in der Queue, sodass du das Status-Tool nach dem Anheben des Limits erneut mit derselben Queue-ID aufrufen kannst.

### HTTP-Server

Nur relevant beim [Streamable-HTTP-Deployment](#self-hosting-streamable-http).

| Env-Var | Default | Hinweise |
|---|---|---|
| `PORT` | `3333` | Port des HTTP-Listeners. |
| `VENICE_MCP_HOST` | `127.0.0.1` | Bind-Adresse. Auf `0.0.0.0` setzen, um den Server im LAN oder aus einem Container erreichbar zu machen. |
| `VENICE_MCP_AUTH_TOKEN` | _(keiner)_ | Bearer-Token für `/mcp`. Erforderlich, wenn außerhalb von Loopback gebunden wird; dann muss er mindestens 16 Zeichen lang sein. Sobald er gesetzt ist, wird er auch auf Loopback erzwungen. |
| `VENICE_MCP_ALLOW_UNAUTHENTICATED_HTTP` | `0` | Notausgang für erreichbares, nicht authentifiziertes HTTP. Nur hinter einem vertrauenswürdigen, authentifizierten Proxy verwenden. |
| `VENICE_MCP_MAX_SESSIONS` | `100` | Maximale Anzahl aktiver Streamable-HTTP-Sessions. |
| `VENICE_MCP_SESSION_TTL_MS` | `1800000` | Lebensdauer inaktiver Sessions bis zur Bereinigung. |

## Verhalten bei der Mediengenerierung

- **Fertige Medien können Bytes oder eine URL sein.** Video- und Musik-Jobs liefern eingebettete MP4-/Audio-Ressourcen oder JSON mit einer `download_url`, die als Ressourcen-Link zurückkommt. Lade diesen Link zuerst herunter und rufe dann `venice_video_complete` oder `venice_music_complete` auf; bei einem `download_url`-Ergebnis werden Medien nie bereinigt, weil der Link nach dem Löschen der Datei nicht mehr funktioniert.
- **Manche Modelle liefern nur beim Queue-Eintrag eine URL.** Bei VPS- und Grok-Imagine-Private-Modellen speicherst du die von `venice_video_generate` zurückgegebene `download_url` und übergibst sie an `venice_video_status`; ein `COMPLETED`-Abruf ohne Inline-URL liefert so trotzdem einen nutzbaren Link.
- **Prompt-Verbesserung wird zurückgemeldet.** Wenn `enhance_prompt` angewendet wird, enthalten die Ergebnisse von Bildgenerierung, Bearbeitung und Multi-Bearbeitung den URL-dekodierten Prompt, den Venice zurückgegeben hat.
- **ASR-Paginierung wird nur einmal berechnet.** Transkripte mit mehr als 8.000 Zeichen oder mit mehr Zeitstempeln, als auf eine Seite passen (standardmäßig 200 pro Array, bis zu 500 mit `timestamp_limit`), liefern mit der ersten Seite ein `result_handle`. Weitere Seiten forderst du mit diesem Handle an. Handles bleiben pro MCP-Session 10 Minuten im Speicher, und nur die 16 neuesten werden aufbewahrt.
- **Die Seedance-Einwilligung umgeht keine Richtlinien.** Aktuelle öffentliche Seedance-Modelle können Medien mit erkennbaren Personen direkt ablehnen. Wenn eine `needs_consent`-Antwort zurückkommt, sind die drei `consents.seedance`-Flags rechtliche Erklärungen: Setze sie nur auf `true`, nachdem der Nutzer jede Aussage ausdrücklich bestätigt hat.

## x402 Wallet-Modus

Venice unterstützt zusätzlich zum normalen API-Key-Flow die Authentifizierung mit einem [Sign-In-With-X-Wallet-Token](/de/guides/integrations/x402-venice-api), der durch Prepaid-USDC-Guthaben auf Base oder Solana gedeckt ist. Keine E-Mail, kein Telefon, kein KYC erforderlich: Deine Wallet ist die einzige Identität.

```json
{
  "mcpServers": {
    "venice": {
      "command": "npx",
      "args": ["-y", "@veniceai/mcp-server@0.3.0"],
      "env": { "VENICE_SIWX_TOKEN": "<base64 Sign-In-With-X payload>" }
    }
  }
}
```

Der MCP-Server leitet `VENICE_SIWX_TOKEN` bei jedem Venice-API-Aufruf im `SIGN-IN-WITH-X`-Header weiter. Der Server sieht nie deinen Private Key. Wallet-Signatur und USDC-Top-up-Autorisierungen erfolgen in deiner eigenen Wallet.

| Flow | Was passiert |
|---|---|
| **Einmalige Einrichtung** | Sign-In-With-X-Nachricht in deiner Wallet signieren → erzeugt einen SIWX-Token (base64 JSON). |
| **Top-up** | `POST /api/v1/x402/top-up` liefert 402 + Zahlungsanforderungen. Eine USDC-Zahlung für eine der zurückgegebenen Base- oder Solana-Optionen signieren, erneut senden, und Venice schreibt deinem Guthaben gut. |
| **Jeder Inferenz-Aufruf** | MCP-Server sendet `SIGN-IN-WITH-X: <SIWX>`; Venice belastet dein Prepaid-Guthaben. |

Der Mindest-Top-up beträgt **\$5 USD**. Das Mindest-Guthaben zum Inferenz-Aufruf beträgt **\$0.10**. Nach dem Top-up dauern Aufrufe unter 100 ms, weil die Verrechnung off-chain auf einem schnellen Credit-Konto stattfindet.

<Tip>
Wallets, die mit einem Venice-Konto mit gestaktem DIEM verknüpft sind, verbrauchen aus dem Staking-Guthaben statt aus USDC-Credits, daher ist kein Top-up nötig.
</Tip>

Venice akzeptiert auf Inferenz-Routen keine Payment-Header, daher sendet dieser Server nie einen. `PAYMENT-SIGNATURE` gehört ausschließlich zu `/x402/top-up`, und der Top-up-Helfer ermittelt die Anforderungen, ohne eine Zahlung zu übermitteln.

### Abdeckung der Auth-Modi

Manche Endpoints akzeptieren nur einen Auth-Modus:

| Tool | API-Schlüssel | x402 |
|---|---|---|
| Inferenz, Medien, Web Augment, Crypto-RPC, Character-Chat | ✓ | ✓ |
| `venice_list_characters`, `venice_get_character`, `venice_character_reviews` | ✓ | ✗ |
| `venice_billing_*`, `venice_list_api_keys`, `venice_get_api_key`, `venice_api_key_rate_limit_logs` | ✓ (Admin) | ✗ |
| `venice_api_key_rate_limits` | ✓ (beliebiger Schlüssel) | ✗ |
| `venice_x402_balance`, `venice_x402_transactions` | ✗ | ✓ |
| `venice_x402_top_up_info` | ✓ | ✓ |

Wenn beide Zugangsdaten gesetzt sind, wird der API-Schlüssel für jeden authentifizierten Aufruf verwendet, außer für `venice_x402_balance` und `venice_x402_transactions`, die immer den Wallet-Token senden.

## Self-Hosting (Streamable HTTP)

Für Team- oder Workspace-Deployments läuft der MCP-Server über HTTP statt stdio:

```bash
docker run -p 3333:3333 \
  -e VENICE_API_KEY=<your-venice-api-key> \
  -e VENICE_MCP_AUTH_TOKEN=<choose-a-long-random-token> \
  ghcr.io/veniceai/venice-mcp-server:latest
```

Der Server ist nun unter `http://localhost:3333/mcp` erreichbar. HTTP-Clients müssen `Authorization: Bearer <VENICE_MCP_AUTH_TOKEN>` senden und sollten neue Sessions ohne `mcp-session-id`-Header erstellen und anschließend die vom Server vergebene Session-ID wiederverwenden.

<Warning>
`/mcp` ist ein credential-gestützter Tool-Ausführungs-Endpoint: Aufrufer können den konfigurierten Venice API-Schlüssel oder x402-Guthaben verbrauchen. Wenn der HTTP-Modus außerhalb von Loopback bindet, schlägt der Start fehl, sofern weder `VENICE_MCP_AUTH_TOKEN` gesetzt ist noch `VENICE_MCP_ALLOW_UNAUTHENTICATED_HTTP=1` hinter einem vertrauenswürdigen, authentifizierten Proxy gesetzt ist. Im Produktivbetrieb das npm-Paket explizit auf eine Version pinnen, statt auf `latest` zu vertrauen.
</Warning>

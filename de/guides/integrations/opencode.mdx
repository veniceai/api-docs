[OpenCode](https://opencode.ai/) ist ein KI-Coding-Agent für das Terminal. OpenCode bringt bereits einen Venice-AI-Provider mit, sodass Sie sich mit einem einzigen Befehl verbinden und ein Modell aus dem gesamten Venice-Katalog wählen. Eine Konfigurationsdatei ist nicht nötig.

<Note>
  Diese Anleitung bezieht sich auf OpenCode 1, das der Standard-Installer einrichtet. OpenCode 2 enthält Venice AI ebenfalls, mit einigen geänderten Bezeichnungen. Siehe [OpenCode 2](#opencode-2).
</Note>

## Voraussetzungen {#prerequisites}

- Ein Venice API-Schlüssel von [venice.ai/settings/api](https://venice.ai/settings/api?utm_source=venice-api-documentation)
- OpenCode installiert und einsatzbereit auf Ihrem Rechner

---

## Einrichtung {#setup}

<Steps>
  <Step title="Venice AI verbinden">
    Starten Sie OpenCode und führen Sie den Connect-Befehl aus:

    ```txt
    /connect
    ```

    Suchen Sie nach **Venice AI** und wählen Sie es aus.

    <Frame as="div">
      <img
        src="/images/guides/opencode/connect-venice.png"
        alt="Die /connect-Palette von OpenCode, gefiltert auf Venice AI"
      />
    </Frame>
  </Step>

  <Step title="Venice-API-Key einfügen">
    Fügen Sie den Key in das Feld **API key** ein und drücken Sie die Eingabetaste.

    OpenCode speichert die Zugangsdaten in `~/.local/share/opencode/auth.json`, sodass sie in jedem Projekt verfügbar bleiben.
  </Step>

  <Step title="Modell auswählen">
    Führen Sie den Modelle-Befehl aus und wählen Sie ein Venice-Modell:

    ```txt
    /models
    ```

    `z-ai-glm-5-3-flash` ist eine gute Standardwahl fürs Programmieren: schnell, günstig und mit einem Kontextfenster von 1M Tokens. Weitere Optionen finden Sie unter [Modell-IDs](#model-ids).

    OpenCode listet auch sein eigenes gehostetes Gratis-Angebot unter ähnlichen Namen auf, zum Beispiel **GLM-5.3-Flash Free** von **OpenCode** neben **GLM 5.3 Flash** von **Venice AI**. Der Provider-Name in der rechten Spalte unterscheidet sie, und die Zeile von Venice AI ist diejenige, die Ihren Key und Ihr Guthaben nutzt.
  </Step>
</Steps>

Senden Sie eine kleine Aufgabe, um den gesamten Ablauf zu bestätigen, zum Beispiel:

```txt
Review the current file and suggest one safe improvement.
```

## Standardmodell festlegen {#pin-a-default-model}

Nach dem Verbinden startet OpenCode neue Sitzungen möglicherweise mit einem gerouteten Modell wie Claude Sonnet 4.6, das mehr kostet als die Modelle unter [Modell-IDs](#model-ids). Um das Startmodell von OpenCode festzulegen, tragen Sie es in `opencode.json` im Projektstamm ein (oder in `~/.config/opencode/opencode.json` für einen globalen Standard):

```json
{
  "$schema": "https://opencode.ai/config.json",
  "model": "venice/z-ai-glm-5-3-flash",
  "small_model": "venice/z-ai-glm-5-3-flash"
}
```

Modellverweise verwenden die Form `venice/<model-id>`, und `small_model` legt das günstigere Modell für Hintergrundaufgaben fest.

## Ohne `/connect` verbinden {#connect-without-/connect}

Der mitgelieferte Provider liest `VENICE_API_KEY` auch aus der Umgebung. Exportieren Sie die Variable vor dem Start von OpenCode, dann erscheinen Venice-AI-Modelle in `/models`, ohne dass Sie `/connect` ausführen:

```bash
export VENICE_API_KEY="your-api-key"
```

Bei einem OpenCode-Build, der älter ist als der mitgelieferte Provider, oder um die Liste der angezeigten Modelle festzulegen, konfigurieren Sie Venice als OpenAI-kompatiblen Provider in `opencode.json`. Lassen Sie `VENICE_API_KEY` exportiert:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "model": "venice/z-ai-glm-5-3-flash",
  "small_model": "venice/z-ai-glm-5-3-flash",
  "provider": {
    "venice": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Venice AI",
      "options": {
        "baseURL": "https://api.venice.ai/api/v1",
        "apiKey": "{env:VENICE_API_KEY}"
      },
      "models": {
        "z-ai-glm-5-3-flash": {
          "name": "GLM 5.3 Flash"
        },
        "kimi-k2-6": {
          "name": "Kimi K2.6"
        },
        "minimax-m25": {
          "name": "MiniMax M2.5"
        }
      }
    }
  }
}
```

Führen Sie unter `models` die gewünschten Modelle auf. OpenCode zeigt für diesen Provider nur die hier deklarierten Einträge an. Bei Builds mit dem mitgelieferten Provider liefert die Umgebungsvariable allein bereits den gesamten Katalog.

## OpenCode 2 {#opencode-2}

OpenCode 2 ist eine eigene Release-Linie mit eigenem Installer:

```bash
curl -fsSL https://opencode.ai/v2/install | bash
```

Es bringt einen nativen Venice-AI-Provider mit, und die obige Einrichtung funktioniert mit einigen Unterschieden:

- Der `/connect`-Dialog heißt **Connect an integration**. Suchen Sie unter **Services** nach **Venice AI** und fügen Sie Ihren Key dann im Dialog **Connect Venice AI** ein.
- Wenn Sie `VENICE_API_KEY` vor dem Start exportieren, wird der Provider auch ohne `/connect` aktiviert.
- Ohne festgelegtes Modell kann OpenCode 2 auch mit einem gerouteten Modell starten, etwa Claude Fable 5.2.
- Die `opencode.json`-Beispiele auf dieser Seite funktionieren weiterhin, weil OpenCode 2 das Konfigurationsformat von OpenCode 1 weiterhin liest. In der nativen OpenCode-2-Konfiguration legen Sie das Hintergrundmodell mit `agents.title.model` statt `small_model` fest. Den Rest des nativen Formats finden Sie im [Migrationsleitfaden](https://opencode.ai/docs/migrate-v1) von OpenCode.

## Modell-IDs {#model-ids}

Einige Venice-Modelle, die sich gut für einen Coding-Agenten eignen. Der Katalog ändert sich, nutzen Sie daher [`GET /models?type=text`](/de/api-reference/endpoint/models/list) für die aktuelle Liste.

| Modell | Venice-ID |
|-------|-----------|
| GLM 5.3 Flash | `z-ai-glm-5-3-flash` |
| GLM 5.3 | `z-ai-glm-5-3` |
| Kimi K2.6 | `kimi-k2-6` |
| MiniMax M2.5 | `minimax-m25` |
| DeepSeek V4.1 Flash | `deepseek-v4-1-flash` |

Open-Weight-Modelle wie diese laufen vollständig privat. Geroutete Modelle von Anthropic, OpenAI und Google laufen anonymisiert, sodass das Ursprungslabor Ihre Identität nie sieht.

## Konfigurations-Hinweise {#config-notes}

- Lassen Sie `baseURL` im manuellen Provider-Block auf `https://api.venice.ai/api/v1` gesetzt. Der mitgelieferte Provider zeigt bereits dorthin.
- Die Provider-ID ist `venice`, daher verwenden Modellverweise in beiden Varianten die Form `venice/<model-id>`.
- Führen Sie `/connect` jederzeit erneut aus, um den gespeicherten Venice-Key zu ersetzen.
- Erweitern Sie den Kontext, wenn das Modell es unterstützt: Mehrere Venice-Modelle akzeptieren 1M Tokens.

## Fehlerbehebung {#troubleshooting}

<AccordionGroup>
  <Accordion title="Venice AI fehlt in /connect">
    Aktualisieren Sie OpenCode mit `opencode upgrade` auf das neueste 1.x-Release. Der Venice-AI-Provider ist in aktuellen Builds enthalten, daher bietet eine ältere Installation möglicherweise nur den oben beschriebenen manuellen Konfigurationsweg.
  </Accordion>
  <Accordion title="Ungültiger API-Key oder 401">
    Prüfen Sie, dass der Key von [venice.ai/settings/api](https://venice.ai/settings/api?utm_source=venice-api-documentation) stammt, führen Sie dann `/connect` aus, wählen Sie **Venice AI** und fügen Sie ihn erneut ein. Ist der gespeicherte Key veraltet, meldet OpenCode einen Authentifizierungsfehler, statt Venice zu erreichen.
  </Accordion>
  <Accordion title="Modell nicht verfügbar">
    Kopieren Sie die ID exakt aus [Modell-IDs](#model-ids), dem [Textmodell-Katalog](/de/models/text) oder `GET /models`, und prüfen Sie, ob Ihr Venice-Konto Zugriff darauf hat.
  </Accordion>
</AccordionGroup>

Die Image-API von Venice kann Bilder mit echtem Alphakanal zurückgeben, statt eines aufgemalten weißen oder karierten Hintergrunds. Das Modell komponiert das Motiv von Anfang an mit Transparenz, sodass Kanten, Schatten und halbtransparente Bereiche (Glas, Haare, Rauch) einen Alpha-Wert pro Pixel tragen statt einer harten Maske.

Das unterscheidet sich von `/image/background-remove`, das ein fertiges, opakes Bild nimmt und den Vordergrund nachträglich segmentiert. Nutze native Transparenz, wenn du das Asset ohnehin generierst oder bearbeitest; nutze die Hintergrundentfernung, wenn du nur das opake Bild hast.

## Was du brauchst

| Voraussetzung | Detail |
|---|---|
| Modell | Eines mit `supportsTransparentBackground: true` in den Constraints von `GET /models`. Aktuell `gpt-image-1-5`, `gpt-image-2-5-flare` und `gpt-image-2-5-sunburst` (plus ihre `-edit`-Varianten für die Edit-Endpoints) |
| Ausgabeformat | `png` oder `webp`. JPEG hat keinen Alphakanal, daher wird `jpeg` abgelehnt |
| Parameter | `transparent_background: true` auf `/image/generate`, `/image/edit`, `/image/multi-edit`. `background: "transparent"` auf `/images/generations` |

Alles andere liefert `400`, bevor die Inferenz läuft – abgelehnte Requests werden dir also nicht berechnet.

## Schritt 1: Ein transparentes Bild generieren

`/image/generate` ist der native Endpoint. Setze `format` auf `png` oder `webp` und `transparent_background` auf `true`.

```bash
curl https://api.venice.ai/api/v1/image/generate \
  -H "Authorization: Bearer $VENICE_API_KEY" \
  -H "Content-Type: application/json" \
  -o sticker.png \
  -d '{
    "model": "gpt-image-2-5-flare",
    "prompt": "A die-cut sticker of a cartoon rocket ship, bold outlines, flat colors, no background",
    "format": "png",
    "transparent_background": true,
    "quality": "low",
    "return_binary": true
  }'
```

Die Antwort hat `content-type: image/png` mit einem RGBA-Pixel-Layout. Ohne `return_binary` erhältst du den üblichen JSON-Envelope mit einem Base64-String in `images[0]`.

`format` ist standardmäßig `webp`, was ebenfalls Alpha unterstützt – du kannst `format` also weglassen. Nur ein explizites `"format": "jpeg"` schlägt fehl.

<Tip>
Schreib zusätzlich zum Flag auch „no background" oder „isolated on transparent background" in den Prompt. Das Flag garantiert einen Alphakanal; der Prompt hält das Modell davon ab, einen Boden, Tisch oder Hintergrund zu zeichnen, der innerhalb der Bounding Box des Motivs opak bleiben würde.
</Tip>

## Schritt 2: Den Alphakanal prüfen

Verlass dich nicht auf die Dateiendung. Prüfe den Pixelmodus und sieh dir die Alpha-Verteilung an, um sicherzustellen, dass der Hintergrund tatsächlich transparent ist und keine abgeflachte weiße Füllung.

```python
from PIL import Image

im = Image.open("sticker.png")
print(im.format, im.mode, im.size)  # PNG RGBA (1024, 1024)

alpha = im.getchannel("A")
hist = alpha.histogram()
total = sum(hist)
print(f"fully transparent: {100 * hist[0] / total:.1f}%")
print(f"partially transparent: {100 * sum(hist[1:255]) / total:.1f}%")
print("subject bbox:", alpha.getbbox())
```

Ein korrektes Ergebnis hat einen großen Anteil an Pixeln mit Alpha `0` (der Hintergrund), einen Streifen partieller Werte entlang der Kanten (Anti-Aliasing und weiche Schatten) und eine Bounding Box des Motivs, die kleiner als die Leinwand ist. Ist `im.mode` gleich `RGB` oder liegt der transparente Anteil bei `0%`, ist der Alphakanal irgendwo in deiner Pipeline verloren gegangen – meist durch einen Resize- oder Re-Encode-Schritt, der ihn verworfen hat.

<Note>
Die GPT-Image-Modelle liefern den opaken Bereich aktuell mit Alpha `252`–`254` statt `255`. Visuell ist das nicht zu unterscheiden, aber wenn du auf `== 255` thresholdest, um das Motiv zu finden, erhältst du eine leere Maske. Nutze stattdessen `> 0` oder `>= 250` als Schwellenwert.
</Note>

## Schritt 3: Den OpenAI-kompatiblen Endpoint nutzen

Wenn du bereits das OpenAI SDK verwendest, akzeptiert `/images/generations` denselben `background`-Parameter wie OpenAI. Setze ihn auf `"transparent"` und wähle `png` oder `webp` als `output_format`.

```python
import base64
import os
from openai import OpenAI

client = OpenAI(
    base_url="https://api.venice.ai/api/v1",
    api_key=os.environ["VENICE_API_KEY"],
)

result = client.images.generate(
    model="gpt-image-2-5-flare",
    prompt="A flat vector icon of a paper airplane, isolated, no background",
    output_format="webp",
    background="transparent",
)

with open("icon.webp", "wb") as f:
    f.write(base64.b64decode(result.data[0].b64_json))
```

`background` akzeptiert `transparent`, `opaque` oder `auto`. `opaque`, `auto` und `null` behalten alle das Standardverhalten des Modells bei – der einzige Wert, der etwas ändert, ist also `transparent`. `output_format` ist auf diesem Endpoint standardmäßig `png`, du kannst es also weglassen.

<Note>
`/images/generations` akzeptiert `quality`, `style`, `output_compression` und `size` aus Gründen der OpenAI-Kompatibilität, ignoriert sie aber. Bei den GPT-Image-Modellen, die diese Seite behandelt, hat `size` keine Wirkung. Die Ausgabe bleibt beim Standard-Seitenverhältnis und der Standardauflösung des Modells. Neben `model` und `prompt` beeinflussen nur `background`, `output_format` und `moderation` das Bild; `response_format` wählt nur zwischen Base64 und einer Data-URL. `resolution` und `aspect_ratio` sind keine Felder, und das Schema ist strikt, daher liefert das Senden eines der beiden `400`. Lass `quality` hier weg; nutze den nativen Endpoint `/image/generate`, wenn du die Stufe steuern willst (siehe Preise unten).
</Note>

## Schritt 4: Mit Transparenz bearbeiten

Auch `/image/edit` und `/image/multi-edit` akzeptieren `transparent_background`. Das Quellbild muss nicht transparent sein; du kannst ein opakes Foto übergeben und das Modell bitten, das Motiv beim Bearbeiten freizustellen.

```bash
curl https://api.venice.ai/api/v1/image/edit \
  -H "Authorization: Bearer $VENICE_API_KEY" \
  -F "model=gpt-image-2-5-flare-edit" \
  -F "prompt=Make the apple green and remove the background" \
  -F "image=@apple.jpg" \
  -F "transparent_background=true" \
  -o apple-green.png
```

Auf den Edit-Endpoints wird `output_format` bei Weglassen abgeleitet: normalerweise PNG für 1K-Edits und JPEG für 2K/4K. Ist `transparent_background` jedoch `true`, wird bei jeder Auflösung PNG abgeleitet. Du musst `output_format` also nur explizit senden, wenn du WebP willst.

`/image/multi-edit` nimmt dieselben Felder mit zwei Unterschieden: Sende jedes Eingabebild als wiederholten `images`-Part, und gib das Modell mit `modelId` statt `model` an. Es eignet sich ideal, um ein Produktfoto in eine neue Szene zu komponieren und das Ergebnis als Freisteller zurückzubekommen, den du in dein eigenes Layout einsetzen kannst.

```bash
curl https://api.venice.ai/api/v1/image/multi-edit \
  -H "Authorization: Bearer $VENICE_API_KEY" \
  -F "modelId=gpt-image-2-5-flare-edit" \
  -F "prompt=Put the sunglasses from the second image on the person in the first, and remove the background" \
  -F "images=@person.jpg" \
  -F "images=@sunglasses.jpg" \
  -F "transparent_background=true" \
  -o person-sunglasses.png
```

## Preise

Transparenz kostet keinen Aufpreis. Du zahlst den normalen Preis pro Bild des Modells.

Die beiden Routen rechnen unterschiedlich ab:

| Endpoint | Stufensteuerung | Was dir berechnet wird |
|---|---|---|
| `POST /image/generate` (nativ) | `resolution` und `quality` bei `gpt-image-2-5-*`; `gpt-image-1-5` hat einen einzigen Festpreis ohne Stufen | Die gewählte Stufe. Eine `1K`-`low`-Generierung auf `gpt-image-2-5-flare` ist der günstigste Weg, an einem Sticker oder Icon zu iterieren, bevor du für `high` oder `4K` zahlst |
| `POST /images/generations` (OpenAI-kompatibel) | Keine. `quality` wird ignoriert und es gibt kein `resolution`-Feld | Die Standardstufe des Modells. Bei `gpt-image-2-5-*` ist das `1K` mit `high`, die teuerste Qualitätsstufe. Weder `quality: "low"` noch `size` senkt also den Preis |

Wenn du die Kosten pro Bild steuern willst, nutze den nativen Endpoint. Die aktuelle Preistabelle findest du unter [Image-Modelle](/de/models/image).

## Fehler

Die Validierung läuft, bevor das Modell aufgerufen wird. Beide Meldungen nennen die Lösung.

| Request | Status | Body |
|---|---|---|
| `transparent_background: true` mit `format` / `output_format` `jpeg` | `400` | `Transparent background requires png or webp output format.` |
| `transparent_background: true` auf einem Modell ohne das Flag | `400` | `Transparent background is not supported by model 'flux-2-pro'. Use a model with "supportsTransparentBackground": true in its constraints (see GET /api/v1/models).` |
| `background: "transparent"` mit `output_format: "jpeg"` auf `/images/generations` | `400` | `Transparent background requires png or webp output format.` |

`transparent_background: false` mit `jpeg` ist in Ordnung und liefert ein normales opakes JPEG.

## Unterstützte Modelle zur Laufzeit ermitteln

Modell-IDs ändern sich. Statt die obige Liste hart zu codieren, filtere `GET /models` nach dem Constraint-Flag. Der Key ist nur bei Modellen vorhanden, die es unterstützen, und dann `true`.

```bash
curl -s "https://api.venice.ai/api/v1/models?type=image" \
  | jq -r '.data[] | select(.model_spec.constraints.supportsTransparentBackground == true) | .id'
```

Verwende `type=inpaint` für die Edit-Endpoints; damit erhältst du die `-edit`-Modell-IDs.

## Wann dies und wann `/image/background-remove`?

| | `transparent_background` | `/image/background-remove` |
|---|---|---|
| Input | Ein Prompt (und optional ein Quellbild zum Bearbeiten) | Ein bestehendes opakes Bild |
| Wie Alpha entsteht | Das Modell komponiert von Anfang an mit Transparenz | Ein Segmentierungsmodell maskiert den Vordergrund nachträglich |
| Schatten und Spiegelungen | Bleiben mit partiellem Alpha erhalten, weil das Modell sie als Teil des Motivs gerendert hat | Werden zusammen mit dem Hintergrund entfernt, da sie nicht zum Vordergrund gehören |
| Modellwahl | Nur GPT Image 1.5 / 2.5 | Festes internes Modell, kein `model`-Feld |
| Kosten | Normaler Generierungs- oder Edit-Preis des Modells | Pauschaler Preis für Hintergrundentfernung |

Wenn du das Asset ohnehin generierst, fordere Transparenz direkt an und spar dir den zweiten Aufruf. Greif zu `/image/background-remove`, wenn das opake Bild bereits existiert und du es nicht neu generieren willst.

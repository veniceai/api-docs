Die Bildbearbeitung auf Venice ist synchron. Sende dein Quellbild an `/image/edit` oder `/image/multi-edit`, und das bearbeitete Ergebnis kommt in derselben Antwort als Bilddatei zurück. Für Freisteller liefert `/image/background-remove` ein transparentes PNG.

<Warning>
Die Image-Edit-Endpoints sind experimentell, und modellspezifisches Verhalten kann sich im Laufe der Zeit ändern.
</Warning>

## Endpoints

| Endpoint | Zweck | Geeignet für |
|---|---|---|
| `POST /image/edit` | Ein Bild mit einem Prompt bearbeiten | Allgemeine Edits und Prompt-getriebenes Inpainting |
| `POST /image/multi-edit` | Bearbeitung mit mehreren Referenzbildern (Limit variiert je nach Modell) | Compositing und Edits mit mehreren Referenzen |
| `POST /image/background-remove` | Hintergrund eines Bildes entfernen | Transparente Freisteller für Produkte, Porträts und Assets |

## Wann welcher Endpoint?

- `/image/edit` verwenden, wenn du ein Quellbild hast und einen Teil davon per Prompt verändern, entfernen oder umstilen willst.
- `/image/multi-edit` verwenden, wenn du den Edit zusätzlich an weiteren Referenzbildern ausrichten willst.
- `/image/background-remove` verwenden, wenn du nur ein sauberes Vordergrundmotiv mit Transparenz brauchst.

<Note>
Für Inpainting `/image/edit` oder `/image/multi-edit` verwenden. Der alte `inpaint`-Parameter auf `/image/generate` ist deprecated.
</Note>

<Tip>
Setze `enhance_prompt: true` auf einem der Edit-Endpoints, damit ein Vision-fähiger Enhancer das Eingabebild oder die Eingabebilder analysiert und deine Anweisung vor der Bearbeitung umschreibt. Siehe [Prompt-Enhancement](/de/guides/media/prompt-enhancement) für Verhalten, Preise und Details zu Response-Headern.
</Tip>

## Schritt 1: Ein einzelnes Bild bearbeiten

Single-Image-Edit ist der einfachste Inpainting-Flow. Sende ein Bild plus einen kurzen Prompt wie „remove the sign", „change the sky to sunrise" oder „replace the background with a studio backdrop".

**Request:**
```bash
POST https://api.venice.ai/api/v1/image/edit
Authorization: Bearer $VENICE_API_KEY
Content-Type: application/json

{
  "model": "firered-image-edit",
  "prompt": "Replace the cloudy sky with a warm sunrise while preserving the buildings and canal",
  "image": "https://example.com/venice-canal.jpg"
}
```

**Antwort (200):**
Der Response-Body sind rohe Bild-Binärdaten. Speichere sie direkt in eine Datei. Das Format ist PNG bei 1K-Edits und JPEG bei 2K- und 4K-Edits bzw. PNG bei jeder Auflösung, wenn `transparent_background` auf `true` steht. Setze `output_format` auf `jpeg`, `png` oder `webp`, um das Format explizit festzulegen.

<CodeGroup>
```python Python
import base64
import os
import requests

with open("input.jpg", "rb") as f:
    image_base64 = base64.b64encode(f.read()).decode("utf-8")

response = requests.post(
    "https://api.venice.ai/api/v1/image/edit",
    headers={
        "Authorization": f"Bearer {os.environ['VENICE_API_KEY']}",
        "Content-Type": "application/json",
    },
    json={
        "model": "firered-image-edit",
        "prompt": "Remove the tourist crowd from the square and keep the architecture intact",
        "image": image_base64,
    },
)

with open("edited.png", "wb") as f:
    f.write(response.content)
```

```javascript Node.js
import fs from "fs";

const imageBase64 = fs.readFileSync("input.jpg").toString("base64");

const response = await fetch("https://api.venice.ai/api/v1/image/edit", {
  method: "POST",
  headers: {
    Authorization: `Bearer ${process.env.VENICE_API_KEY}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    model: "firered-image-edit",
    prompt: "Remove the tourist crowd from the square and keep the architecture intact",
    image: imageBase64,
  }),
});

const editedImage = Buffer.from(await response.arrayBuffer());
fs.writeFileSync("edited.png", editedImage);
```

```bash cURL
curl https://api.venice.ai/api/v1/image/edit \
  -H "Authorization: Bearer $VENICE_API_KEY" \
  -H "Content-Type: application/json" \
  -o edited.png \
  -d '{
    "model": "firered-image-edit",
    "prompt": "Colorize this black and white portrait naturally",
    "image": "https://example.com/portrait-bw.jpg"
  }'
```
</CodeGroup>

## Schritt 2: Multi-Edit mit Referenzbildern nutzen

`/image/multi-edit` akzeptiert mehrere Bilder, und die Obergrenze ist modellspezifisch. Lies `model_spec.constraints.maxInputImages` aus `GET /models?type=inpaint`, um die Obergrenze für ein bestimmtes Modell zu erhalten. Fehlt das Feld, liegt die Obergrenze bei 3 bzw. bei 1, wenn `combineImages` auf `false` steht.

Das erste Bild ist das Basis-Bild. Die weiteren Bilder sind zusätzliche Referenzen, die den Edit konditionieren.

<Note>
Der öffentliche Endpoint hat keinen Masken-Kanal. Zusätzliche Bilder wirken als Referenzen über das gesamte Bild, nicht als Regionskarten. Es gibt keinen `mask`-Parameter, und das Senden eines solchen gibt einen `400` zurück. Prompte präzise, um einzugrenzen, wo der Edit landet.
</Note>

Das ist die bessere Wahl, wenn du:

- eine bestehende Komposition mit einem zusätzlichen Referenzbild kombinieren willst
- dem Modell Beispiele für den Stil, das Objekt oder die Textur geben willst, die angewendet werden sollen
- den Edit enger einschränken willst, als es ein Single-Image-Prompt erlaubt

**JSON-Request:**
```json
{
  "modelId": "firered-image-edit",
  "prompt": "Replace the blank billboard area with a glowing Venice film festival poster while preserving lighting and perspective",
  "images": [
    "https://example.com/street-scene.png",
    "https://example.com/billboard-reference.png"
  ]
}
```

**Multipart-Request:**
```bash
curl https://api.venice.ai/api/v1/image/multi-edit \
  -H "Authorization: Bearer $VENICE_API_KEY" \
  -F "modelId=firered-image-edit" \
  -F "prompt=Replace the blank billboard area with a glowing Venice film festival poster while preserving lighting and perspective" \
  -F "images=@street-scene.png" \
  -F "images=@billboard-reference.png" \
  -o multi-edited.png
```

Wie bei `/image/edit` sind die Response-Body rohe Bilddaten, und das Ausgabeformat folgt denselben Regeln.

<Note>
`/image/multi-edit` verwendet im Request-Schema derzeit das Feld `modelId` statt `model`.
</Note>

## Inpainting-Tipps

Prompt-basiertes Inpainting funktioniert am besten, wenn die Anweisung kurz und lokal ist:

- `remove the tree`
- `change the sky to sunset`
- `replace the logo with a blank sign`
- `restore the torn corner of the photo`

Für umfangreichere Szenenänderungen beschreibe, was unverändert bleiben soll:

```text
Replace the background with a modern photo studio backdrop while preserving the subject pose, facial features, and clothing.
```

Wenn der Edit ständig den falschen Bereich trifft, wechsle von `/image/edit` zu `/image/multi-edit`, übergib ein zusätzliches Referenzbild, das das gewünschte Ergebnis zeigt, und beschreibe die beabsichtigte Änderung präzise im Prompt.

## Schritt 3: Hintergrund entfernen

Verwende `/image/background-remove`, wenn du das Vordergrundmotiv auf transparentem Hintergrund isoliert haben willst. Dieser Endpoint liefert ein PNG mit Alpha-Transparenz.

**Per Bild-URL:**
```bash
curl https://api.venice.ai/api/v1/image/background-remove \
  -H "Authorization: Bearer $VENICE_API_KEY" \
  -H "Content-Type: application/json" \
  -o cutout.png \
  -d '{
    "image_url": "https://example.com/product-photo.jpg"
  }'
```

**Per lokalem Datei-Upload:**
```bash
curl https://api.venice.ai/api/v1/image/background-remove \
  -H "Authorization: Bearer $VENICE_API_KEY" \
  -F "image=@product-photo.jpg" \
  -o cutout.png
```

Hintergrundentfernung eignet sich für:

- E-Commerce-Produktfotos
- Profilbilder und Porträts
- Assets, die du auf einen neuen Hintergrund legen willst

Wenn du das Bild ohnehin generierst oder bearbeitest, kannst du dir diesen zweiten Aufruf sparen: `/image/generate`, `/image/edit` und `/image/multi-edit` akzeptieren bei unterstützten Modellen `transparent_background: true` und liefern den Alphakanal direkt mit. Siehe [Bilder mit transparentem Hintergrund](/de/guides/media/transparent-backgrounds) für den Vergleich.

## Request-Parameter

### `/image/edit`

| Parameter | Typ | Pflicht | Default | Beschreibung |
|---|---|---|---|---|
| `image` | Datei, Base64-String oder URL | Ja | - | Zu bearbeitendes Quellbild |
| `prompt` | string | Ja | - | Text-Anweisungen für den Edit |
| `model` | string | Nein | `firered-image-edit` | Edit-Modell-ID |
| `aspect_ratio` | string | Nein | Modell-Default | Output-Ratio bei Modellen, die das unterstützen |
| `resolution` | string | Nein | `1K` | Auflösungsstufe für das Ausgabebild, z. B. `1K`, `2K` oder `4K`. Unterstützte Werte variieren je nach Modell |
| `output_format` | string | Nein | abgeleitet | `jpeg`, `png` oder `webp`. Bei Weglassen PNG für 1K-Edits und JPEG für 2K- und 4K-Edits bzw. PNG bei jeder Auflösung, wenn `transparent_background` auf `true` steht |
| `enhance_prompt` | boolean | Nein | `false` | Eingabebild analysieren und die Edit-Anweisung vor der Inferenz umschreiben |
| `disable_prompt_optimization_thinking` | boolean | Nein | Modell-Default | Den Prompt-Optimierungs-Thinking-Schritt des Modells für schnellere Generierung überspringen. Nur von Modellen mit `supportsOptimizePromptThinking` unterstützt; andere ignorieren es |
| `safe_mode` | boolean | Nein | `true` | Anstößige Inhalte im bearbeiteten Ergebnis unscharf machen. Auf `false` setzen, um die Unschärfe zu deaktivieren. |
| `transparent_background` | boolean | Nein | `false` | Den Edit mit echtem Alphakanal zurückgeben. Erfordert ein Modell mit `supportsTransparentBackground: true` und `output_format` `png` oder `webp` (wird bei Weglassen als PNG abgeleitet). Siehe [Bilder mit transparentem Hintergrund](/de/guides/media/transparent-backgrounds) |
| `modelId` | string | Deprecated | - | Deprecated-Alias für `model` |

### `/image/multi-edit`

| Parameter | Typ | Pflicht | Default | Beschreibung |
|---|---|---|---|---|
| `images` | Array aus Dateien, Base64-Strings oder URLs | Ja | - | Erstes Bild ist das Basis-Bild; weitere sind zusätzliche Referenzen. Maximum ist modellspezifisch – siehe `model_spec.constraints.maxInputImages` |
| `prompt` | string | Ja | - | Text-Anweisungen, wie die Bilder kombiniert oder bearbeitet werden |
| `modelId` | string | Nein | `firered-image-edit` | Edit-Modell-ID |
| `resolution` | string | Nein | `1K` | Auflösungsstufe für das Ausgabebild, z. B. `1K`, `2K` oder `4K`. Unterstützte Werte variieren je nach Modell |
| `quality` | string | Nein | Modell-Default | `low`, `medium` oder `high` bei Modellen, die in `model_spec.constraints` `qualities` auflisten. Höhere Werte können die Request-Kosten erhöhen |
| `output_format` | string | Nein | abgeleitet | `jpeg`, `png` oder `webp`. Gleiche Ableitungsregeln wie bei `/image/edit` |
| `enhance_prompt` | boolean | Nein | `false` | Eingabebilder analysieren und die Edit-Anweisung vor der Inferenz umschreiben |
| `disable_prompt_optimization_thinking` | boolean | Nein | Modell-Default | Den Prompt-Optimierungs-Thinking-Schritt des Modells für schnellere Generierung überspringen. Nur von Modellen mit `supportsOptimizePromptThinking` unterstützt; andere ignorieren es |
| `safe_mode` | boolean | Nein | `true` | Anstößige Inhalte im bearbeiteten Ergebnis unscharf machen. Auf `false` setzen, um die Unschärfe zu deaktivieren. |
| `transparent_background` | boolean | Nein | `false` | Das komponierte Ergebnis mit echtem Alphakanal zurückgeben. Gleiche Modell- und Formatregeln wie bei `/image/edit` |

### `/image/background-remove`

| Parameter | Typ | Pflicht | Beschreibung |
|---|---|---|---|
| `image` | Datei oder Base64-String | Eines von `image` oder `image_url` | Quellbild zum Freistellen |
| `image_url` | string | Eines von `image` oder `image_url` | Öffentliche Bild-URL zum Freistellen |

<Note>
`/image/background-remove` verwendet ein festes internes Modell. Es akzeptiert kein `model`-Feld. Wird eines gesendet (zum Beispiel `"model": "bria-bg-remover"`), gibt es `400` zurück, weil `model` kein erkanntes Feld ist.
</Note>

### Adult-Inhalte und Safe Mode

Sowohl `/image/edit` als auch `/image/multi-edit` akzeptieren `safe_mode` (Default: `true`). Wenn aktiviert, werden Adult-Inhalte in der bearbeiteten Ausgabe unscharf gemacht. Setze `safe_mode: false`, um die Ausgabe ohne Unschärfe zu erhalten:

```json
{
  "model": "qwen-edit-uncensored",
  "prompt": "…",
  "image": "…",
  "safe_mode": false
}
```

Nicht unscharfe Adult-Ausgaben (NSFW) stehen allen API-Nutzern zur Verfügung. Du brauchst kein Pro-Abo, und die Einstellung für den Filter für Inhalte für Erwachsene in der Venice-App hat keinen Einfluss auf Bildanfragen über die API.

Die Inhaltsrichtlinien variieren je nach Edit-Modell und gelten unabhängig von `safe_mode`. Für unzensiertes Editing nutze `qwen-edit-uncensored`.

Der Unterschied im Namen des Moderations-Feldes zwischen den Endpoints stiftet oft Verwirrung:

| Endpoint | Feld zum Deaktivieren der Unschärfe |
|---|---|
| `POST /image/edit`, `POST /image/multi-edit` | `safe_mode: false` |
| `POST /image/generate` (native Generierung) | `safe_mode: false` |
| `POST /images/generations` (OpenAI-kompatible Generierung) | `moderation: "low"` |

Wird `safe_mode` an `/images/generations` übergeben, gibt es einen `400` mit `Unrecognized key(s) in object: 'safe_mode'`.

## Unterstützte Eingabeformate

| Endpoint | JSON-Input | Multipart-Input | Output |
|---|---|---|---|
| `/image/edit` | Base64-String oder URL | Datei-Upload | `image/png`, `image/jpeg` oder `image/webp` |
| `/image/multi-edit` | Base64-Strings oder URLs | Datei-Uploads | `image/png`, `image/jpeg` oder `image/webp` |
| `/image/background-remove` | Base64-String oder URL | Datei-Upload | `image/png` |

Für Edit-Endpoints müssen Bilder mindestens 256×256 Pixel groß sein, und die Gesamtpixelzahl darf 33.177.600 (8K-Auflösung) nicht überschreiten. Hochgeladene Dateien müssen kleiner als `25MB` sein.

Das Default-Edit-Modell ist `firered-image-edit`, **\$0,04 pro Edit**. Andere edit-fähige Modelle können andere Preise und Einschränkungen haben. Prompt-Enhancement erhöht den Edit-Preis um **\$0,04 pro angewendetem Rewrite**.

## Fehler

| Status | Bedeutung | Aktion |
|---|---|---|
| `400` | Ungültige Request-Parameter | Bildanzahl, Feldnamen und Input-Format prüfen |
| `401` | Authentifizierung fehlgeschlagen | API-Schlüssel prüfen |
| `402` | Unzureichendes Guthaben | Credits unter [venice.ai/settings/api](https://venice.ai/settings/api?utm_source=venice-api-documentation) aufladen |
| `413` | Datei zu groß | Hochgeladene Dateien unter 25 MB halten |
| `415` | Ungültiger Content-Type (nur `/image/multi-edit`; die anderen Endpoints geben `400` zurück) | JSON oder Multipart-Form-Data korrekt nutzen |
| `422` | Verstoß gegen Content-Policy oder Eingabebild zu groß | Prompt anpassen oder Bilddimensionen verringern |
| `429` | Rate-Limit überschritten oder Modell überlastet | Mit Backoff erneut versuchen; `Retry-After`-Header beachten |
| `500` | Inferenz-Verarbeitung fehlgeschlagen | Request wiederholen |
| `503` | Modell ausgelastet | Nach kurzer Verzögerung erneut versuchen |

<Note>
Einige Edit-Modelle haben strengere Content-Policies als Image-Generation-Modelle. Anfragen, die gegen die Richtlinie des gewählten Modells verstoßen, werden mit `422` abgelehnt.
</Note>

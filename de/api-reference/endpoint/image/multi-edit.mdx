## Limits für Input-Bilder

Die maximale Anzahl an Input-Bildern ist modellspezifisch. Lesen Sie `model_spec.constraints.maxInputImages` aus [`GET /models?type=inpaint`](/de/api-reference/endpoint/models/list) aus. Fehlt das Feld, liegt das Limit bei 3 bzw. bei 1, wenn `combineImages` auf `false` steht.

## Qualitätsstufen

Einige Multi-Edit-Modelle akzeptieren einen optionalen Parameter `quality` (`low`, `medium`, `high`), der visuelle Qualität gegen Kosten abwägt. Modelle, die in `model_spec.constraints` aus [`GET /models?type=inpaint`](/de/api-reference/endpoint/models/list) `qualities` auflisten, akzeptieren nur diese Werte, und manche unterstützen nur eine Teilmenge wie `low` und `medium`. Andere Modelle ignorieren den Parameter.

```json
{
  "modelId": "gpt-image-2-edit",
  "images": ["iVBORw0KGgo...", "iVBORw0KGgo..."],
  "prompt": "blend the two scenes into one cinematic frame",
  "resolution": "2K",
  "quality": "medium"
}
```

Wenn Sie `quality` weglassen, verwendet das Modell seine Standardstufe (`high` für `gpt-image-2-edit`). Preise pro Stufe (1K/2K/4K × low/medium/high) finden Sie unter `model_spec.pricing.quality` im [Models-Endpoint](/de/api-reference/endpoint/models/list) und in der [Preisübersicht](/de/overview/pricing).

<Info>
Qualitätsabhängige Preise sind der Standard für alle API- und SDK-Aufrufer — kein Opt-in-Header erforderlich. Anfragen, bei denen `quality` weggelassen wird, werden mit der Standardstufe des Modells abgerechnet (`high` für `gpt-image-2-edit`).
</Info>

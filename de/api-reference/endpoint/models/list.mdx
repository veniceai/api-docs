Wenn du den Query-Parameter `type` weglässt, enthält die Antwort nur Textmodelle. Übergib `type=all`, um den vollständigen Modellkatalog zurückzugeben.

## Einen Modelleintrag lesen {#reading-a-model-entry}

Senden Sie die `id` eines Modells als `model`-Parameter. Das meiste, wonach Sie filtern, steht unter `model_spec`:

| Feld | Was es Ihnen sagt |
| --- | --- |
| `type` | Welchen Endpunkt das Modell bedient: `text` für Chat Completions oder `image`, `video`, `tts`, `asr`, `embedding` usw. |
| `model_spec.capabilities` | Was ein Textmodell unterstützt, z. B. `supportsFunctionCalling`, `supportsVision`, `supportsReasoning`, `supportsResponseSchema`, `supportsWebSearch` und `supportsE2EE` |
| `model_spec.availableContextTokens` | Das Kontextfenster in Tokens |
| `model_spec.pricing` | Preise in USD und DIEM: pro 1M Tokens für Textmodelle, pro Einheit für Medienmodelle |
| `model_spec.privacy` | `private` oder `anonymized`. E2EE- und TEE-Modelle sind `private` und setzen `supportsE2EE` oder `supportsTeeAttestation` |
| `model_spec.constraints` | Die Parameterwerte, die das Modell akzeptiert, z. B. Seitenverhältnisse, Videodauern und Qualitätsstufen |
| `model_spec.traits` | Rollen, die das Modell innehat, z. B. `default` oder `fastest` |
| `model_spec.deprecation` | Vorhanden, wenn das Modell eingestellt wird, mit dem Entfernungsdatum und, falls vorhanden, seiner `replacementModelId` |

Um ein Modell nach Rolle statt nach ID auszuwählen, rufen Sie [`GET /models/traits`](/de/api-reference/endpoint/models/traits) auf. Zum Durchsuchen und Vergleichen von Modellen siehe die Seiten unter [Modelle](/de/models/overview).

## Preise nach Qualitätsstufe

Für Bildmodelle, die den optionalen Parameter `quality` akzeptieren, enthält die Antwort eine Preismatrix pro Qualitätsstufe unter `model_spec.pricing.quality`. Jeder Top-Level-Schlüssel ist eine Auflösungsstufe (`1K`, `2K`, `4K`), und jeder verschachtelte Schlüssel ist eine Qualitätsstufe (`low`, `medium`, `high`) mit ihrem eigenen Preis in `usd` und `diem`:

```json
"pricing": {
  "resolutions": {
    "1K": { "usd": 0.27, "diem": 0.27 },
    "2K": { "usd": 0.51, "diem": 0.51 },
    "4K": { "usd": 0.84, "diem": 0.84 }
  },
  "quality": {
    "1K": {
      "low":    { "usd": 0.02, "diem": 0.02 },
      "medium": { "usd": 0.07, "diem": 0.07 },
      "high":   { "usd": 0.26, "diem": 0.26 }
    },
    "2K": {
      "low":    { "usd": 0.03, "diem": 0.03 },
      "medium": { "usd": 0.13, "diem": 0.13 },
      "high":   { "usd": 0.50, "diem": 0.50 }
    },
    "4K": {
      "low":    { "usd": 0.05, "diem": 0.05 },
      "medium": { "usd": 0.21, "diem": 0.21 },
      "high":   { "usd": 0.83, "diem": 0.83 }
    }
  }
}
```

`pricing.resolutions` ist der ältere Preisplan pro Bild, der aus Gründen der Abwärtskompatibilität beibehalten wird. `pricing.quality` ist die Matrix pro (Auflösung, Qualität), die immer dann angewendet wird, wenn der Parameter `quality` unterstützt wird. Beide Felder sind in der Antwort enthalten, damit Clients die Qualitätsunterstützung erkennen und die Matrix in ihren eigenen UIs anzeigen können.

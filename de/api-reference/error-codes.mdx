Wenn ein Fehler auftritt, gibt die Venice API einen HTTP-Statuscode und eine beschreibende Nachricht zurück. Einige Fehler enthalten zusätzliche Felder, wie z. B. Erstattungsstatus, vorgeschlagene Wiederholungsmodelle, Validierungsdetails oder Request-IDs.

## Fehlerantwortformat

Die meisten Fehler geben ein `error`-Feld mit einer menschenlesbaren Nachricht zurück:

```json
{
  "error": "Invalid request parameters"
}
```

Einige Endpoints enthalten zusätzliche Felder, die spezifisch für den Endpoint sind. Beispielsweise können Video-Moderationsfehler enthalten, ob Credits erstattet wurden:

```json
{
  "error": "Your generation was blocked due to the model provider's content policies. Credits have been refunded.",
  "credits_refunded": true
}
```

Validierungsfehler können `details`- und `issues`-Felder mit feldbezogenen Validierungsinformationen enthalten:

```json
{
  "error": "Invalid request parameters",
  "details": {
    "_errors": [],
    "field": {
      "_errors": ["Field is required"]
    }
  },
  "issues": []
}
```

Einige OpenAI-kompatible Endpoints geben für bestimmte Fälle möglicherweise OpenAI-artige Fehlerobjekte zurück, z. B. bei Fehlern wegen Kontextlänge:

```json
{
  "error": {
    "message": "Your request exceeds the model's maximum context. Please reduce your prompt or completion length.",
    "type": "invalid_request_error",
    "param": "messages",
    "code": "context_length_exceeded"
  }
}
```

## Fehlende Anmeldedaten

Eine Anfrage ohne Anmeldedaten gibt `402 Payment Required` zurück, nicht `401`. Jede kostenpflichtige Route akzeptiert auch die [x402-Wallet-Authentifizierung](/de/guides/integrations/x402-venice-api), daher ist die Antwort eine Zahlungsaufforderung: Sie enthält einen `PAYMENT-REQUIRED`-Header und einen Body, der beide Authentifizierungswege beschreibt.

```json
{
  "x402Version": 2,
  "error": "Authentication required",
  "accepts": [ ... ],
  "authOptions": {
    "apiKey": {
      "header": "Authorization: Bearer YOUR_API_KEY",
      "getKey": "https://venice.ai/settings/api"
    },
    "x402Wallet": {
      "header": "SIGN-IN-WITH-X",
      "topUp": "POST /api/v1/x402/top-up"
    }
  }
}
```

Wenn du einen API-Schlüssel verwenden wolltest, prüfe, ob der Header `Authorization: Bearer` gesetzt ist. Ein vorhandener, aber ungültiger Schlüssel gibt `401` zurück.

## Fehler im Anfrageformat

Diese Fehler entstehen beim Lesen des Request-Bodys, bevor eine endpunktspezifische Validierung ausgeführt wird.

| HTTP-Status | Message | Ursache |
| --- | --- | --- |
| 400 | `'Content-Type' must be 'application/json'` | Ein `POST`-, `PUT`- oder `PATCH`-Body, der ohne `Content-Type: application/json` gesendet wurde. Endpunkte, die Datei-Uploads entgegennehmen, akzeptieren auch `multipart/form-data` |
| 400 | `Invalid JSON request` | Der Body ist kein gültiges JSON |
| 400 | `Invalid multipart request: malformed part header` | Ein `multipart/form-data`-Body, der nicht geparst werden kann |
| 413 | `Request body exceeds the maximum allowed size.` | Der Request-Body ist zu groß |
| 415 | `Request encoding is not supported` | Ein `Content-Encoding` oder Zeichensatz, den die API nicht dekodieren kann |

Ein falscher `Content-Type` gibt `400` zurück, nicht `415`. Antworten mit `413` wegen Größenüberschreitung enthalten außerdem ein `code`-Feld:

```json
{
  "code": "PAYLOAD_TOO_LARGE",
  "error": "Request body exceeds the maximum allowed size."
}
```

## Weitere Fehler

Die obige Tabelle ist nicht vollständig. Manche Fehler werden ohne einen aufgeführten Code zurückgegeben, und Meldungen können je nach Modell und Endpunkt variieren. Verzweige daher anhand des HTTP-Status und nicht anhand des Meldungstexts. Fehler, die dir begegnen können und nicht in der Tabelle stehen:

| HTTP-Status | Wann er auftritt |
| --- | --- |
| 400 | Eine Bildeingabe in einer Chat- oder Responses-Anfrage hat ein nicht unterstütztes Format |
| 400 | Die angeforderte Stimme ist für das Text-to-Speech-Modell nicht verfügbar |
| 403 | Die Anfrage stammt von einer IP-Adresse, die nicht auf der Allowlist des API-Schlüssels steht |
| 403 | Das angeforderte Modell ist durch die Datenschutzeinstellung des API-Schlüssels nicht erlaubt |
| 403 | Der Zugriff auf das angeforderte Modell ist eingeschränkt. Wende dich an support@venice.ai |
| 409 | Ein Video-, Musik- oder Voice-Changer-Ergebnis wird noch hochgeladen, wenn du es abrufst. Versuche es in Kürze erneut |
| 410 | Der Endpunkt wurde eingestellt |
| 422 | Audio ist zu lang oder zu kurz (Voice Cloning, Voice Changer und Audio-Jobs) |
| 422 | Das Eingabebild einer Videoanfrage hat ein Seitenverhältnis außerhalb des Bereichs, den das Modell akzeptiert |
| 422 | Die Eingabe einer Videoanfrage wurde von der Inhaltsmoderation blockiert |
| 500 | Die Video- oder Voice-Changer-Generierung ist fehlgeschlagen |
| 502 | Die Sprachsynthese ist upstream fehlgeschlagen, oder ein generiertes Video konnte nicht abgerufen werden. Wiederhole die Anfrage |

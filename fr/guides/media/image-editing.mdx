L'édition d'images sur Venice est synchrone. Envoyez votre image source à `/image/edit` ou `/image/multi-edit` et le résultat édité revient dans la même réponse sous forme de fichier image. Pour les détourages, `/image/background-remove` renvoie un PNG transparent.

<Warning>
Les endpoints d'édition d'images sont expérimentaux et le comportement spécifique au modèle peut évoluer au fil du temps.
</Warning>

## Endpoints

| Endpoint | Objectif | Idéal pour |
|---|---|---|
| `POST /image/edit` | Éditer une seule image avec un prompt | Éditions générales et inpainting piloté par prompt |
| `POST /image/multi-edit` | Éditer en utilisant plusieurs images de référence (la limite varie selon le modèle) | Composition et éditions multi-références |
| `POST /image/background-remove` | Supprimer l'arrière-plan d'une image | Détourages transparents pour produits, portraits et assets |

<Note>
Venice ne propose pas d'endpoint `/images/edits` compatible OpenAI, donc les appels du SDK OpenAI tels que `client.images.edit()` renvoient `404`. Envoyez plutôt vos éditions à `/image/edit`.
</Note>

## Quand utiliser quel endpoint

- Utilisez `/image/edit` lorsque vous avez une image source et souhaitez modifier, supprimer ou restyler une partie de celle-ci avec un prompt.
- Utilisez `/image/multi-edit` lorsque vous avez besoin de conditionner l'édition à des images de référence supplémentaires.
- Utilisez `/image/background-remove` lorsque vous souhaitez uniquement un sujet de premier plan propre avec transparence.

<Note>
Pour l'inpainting, utilisez `/image/edit` ou `/image/multi-edit`. L'ancien paramètre `inpaint` sur `/image/generate` est déprécié.
</Note>

<Tip>
Définissez `enhance_prompt: true` sur l'un ou l'autre des endpoints d'édition pour qu'un enhancer conscient de l'image analyse l'image ou les images d'entrée et réécrive votre instruction avant l'édition. Voir [Amélioration de prompt](/fr/guides/media/prompt-enhancement) pour le comportement, la tarification et les détails de l'en-tête de réponse.
</Tip>

## Étape 1 : Éditer une seule image

L'édition d'une seule image est le flux d'inpainting le plus simple. Envoyez une image et un prompt court tel que « remove the sign », « change the sky to sunrise » ou « replace the background with a studio backdrop ».

**Requête :**
```http
POST https://api.venice.ai/api/v1/image/edit
Authorization: Bearer $VENICE_API_KEY
Content-Type: application/json

{
  "model": "firered-image-edit",
  "prompt": "Replace the cloudy sky with a warm sunrise while preserving the buildings and canal",
  "image": "https://example.com/venice-canal.jpg"
}
```

**Réponse (200) :**
Le corps de la réponse est constitué de données binaires brutes d'image. Enregistrez-les directement dans un fichier. Le format est PNG pour les éditions 1K et JPEG pour les éditions 2K et 4K, ou PNG à toute résolution lorsque `transparent_background` vaut `true`. Définissez `output_format` sur `jpeg`, `png` ou `webp` pour le choisir explicitement.

Les endpoints d'édition n'ont pas de paramètre `response_format` et ne peuvent donc pas renvoyer l'image en JSON base64. Si vous avez besoin du base64, encodez vous-même les octets de la réponse.

<CodeGroup>
```python Python
import base64
import os
import requests

with open("input.jpg", "rb") as f:
    image_base64 = base64.b64encode(f.read()).decode("utf-8")

response = requests.post(
    "https://api.venice.ai/api/v1/image/edit",
    headers={
        "Authorization": f"Bearer {os.environ['VENICE_API_KEY']}",
        "Content-Type": "application/json",
    },
    json={
        "model": "firered-image-edit",
        "prompt": "Remove the tourist crowd from the square and keep the architecture intact",
        "image": image_base64,
    },
)

with open("edited.png", "wb") as f:
    f.write(response.content)
```

```javascript Node.js
import fs from "fs";

const imageBase64 = fs.readFileSync("input.jpg").toString("base64");

const response = await fetch("https://api.venice.ai/api/v1/image/edit", {
  method: "POST",
  headers: {
    Authorization: `Bearer ${process.env.VENICE_API_KEY}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    model: "firered-image-edit",
    prompt: "Remove the tourist crowd from the square and keep the architecture intact",
    image: imageBase64,
  }),
});

const editedImage = Buffer.from(await response.arrayBuffer());
fs.writeFileSync("edited.png", editedImage);
```

```bash cURL
curl https://api.venice.ai/api/v1/image/edit \
  -H "Authorization: Bearer $VENICE_API_KEY" \
  -H "Content-Type: application/json" \
  -o edited.png \
  -d '{
    "model": "firered-image-edit",
    "prompt": "Colorize this black and white portrait naturally",
    "image": "https://example.com/portrait-bw.jpg"
  }'
```
</CodeGroup>

## Étape 2 : Utiliser multi-edit avec des images de référence

`/image/multi-edit` accepte plusieurs images, et le plafond est spécifique au modèle. Lisez `model_spec.constraints.maxInputImages` depuis `GET /models?type=inpaint` pour obtenir le plafond d'un modèle donné. Lorsque le champ est absent, le plafond est de 3, ou de 1 lorsque `combineImages` vaut `false`.

La première image est l'image de base. Les images restantes sont des références supplémentaires qui conditionnent l'édition.

<Note>
L'endpoint public n'a pas de canal de masque. Les images supplémentaires agissent comme des références sur l'ensemble de l'image, pas comme des cartes de régions. Il n'existe pas de paramètre `mask`, et en envoyer un renvoie un `400`. Rédigez un prompt précis pour délimiter la zone où l'édition s'applique.
</Note>

C'est le meilleur choix lorsque vous souhaitez :

- combiner une composition existante avec une image de référence supplémentaire
- fournir au modèle des exemples du style, de l'objet ou de la texture à appliquer
- contraindre l'édition plus étroitement qu'un prompt sur une seule image ne peut le faire

**Requête JSON :**
```json
{
  "modelId": "firered-image-edit",
  "prompt": "Replace the blank billboard area with a glowing Venice film festival poster while preserving lighting and perspective",
  "images": [
    "https://example.com/street-scene.png",
    "https://example.com/billboard-reference.png"
  ]
}
```

**Requête multipart :**
```bash
curl https://api.venice.ai/api/v1/image/multi-edit \
  -H "Authorization: Bearer $VENICE_API_KEY" \
  -F "modelId=firered-image-edit" \
  -F "prompt=Replace the blank billboard area with a glowing Venice film festival poster while preserving lighting and perspective" \
  -F "images=@street-scene.png" \
  -F "images=@billboard-reference.png" \
  -o multi-edited.png
```

Comme pour `/image/edit`, le corps de la réponse est constitué de données d'image brutes, et le format de sortie suit les mêmes règles.

<Note>
`/image/multi-edit` utilise actuellement le champ `modelId` plutôt que `model` dans le schéma de requête.
</Note>

## Conseils d'inpainting

L'inpainting basé sur prompt fonctionne mieux lorsque l'instruction est courte et locale :

- `remove the tree`
- `change the sky to sunset`
- `replace the logo with a blank sign`
- `restore the torn corner of the photo`

Pour des changements de scène plus larges, décrivez ce qui doit rester identique :

```text
Replace the background with a modern photo studio backdrop while preserving the subject pose, facial features, and clothing.
```

Si l'édition continue d'affecter la mauvaise zone, passez de `/image/edit` à `/image/multi-edit` et fournissez une image de référence supplémentaire montrant le résultat souhaité, puis décrivez précisément la modification voulue dans le prompt.

## Étape 3 : Supprimer l'arrière-plan

Utilisez `/image/background-remove` lorsque vous souhaitez isoler le sujet de premier plan sur un arrière-plan transparent. Cet endpoint renvoie un PNG avec transparence alpha.

**En utilisant une URL d'image :**
```bash
curl https://api.venice.ai/api/v1/image/background-remove \
  -H "Authorization: Bearer $VENICE_API_KEY" \
  -H "Content-Type: application/json" \
  -o cutout.png \
  -d '{
    "image_url": "https://example.com/product-photo.jpg"
  }'
```

**En utilisant un téléversement de fichier local :**
```bash
curl https://api.venice.ai/api/v1/image/background-remove \
  -H "Authorization: Bearer $VENICE_API_KEY" \
  -F "image=@product-photo.jpg" \
  -o cutout.png
```

Utilisez la suppression d'arrière-plan pour :

- les photos de produits e-commerce
- les photos de profil et les portraits
- les assets que vous prévoyez de placer sur un nouvel arrière-plan

Si vous générez ou éditez l'image de toute façon, vous pouvez éviter ce second appel : `/image/generate`, `/image/edit` et `/image/multi-edit` acceptent `transparent_background: true` sur les modèles compatibles et renvoient directement le canal alpha. Voir [Images à arrière-plan transparent](/fr/guides/media/transparent-backgrounds) pour la comparaison.

## Paramètres de la requête

### `/image/edit`

| Paramètre | Type | Requis | Par défaut | Description |
|---|---|---|---|---|
| `image` | fichier, chaîne base64 ou URL | Oui | - | Image source à éditer |
| `prompt` | string | Oui | - | Instructions textuelles pour l'édition |
| `model` | string | Non | `firered-image-edit` | Identifiant du modèle d'édition |
| `aspect_ratio` | string | Non | valeur par défaut du modèle | Ratio de sortie pour les modèles qui le prennent en charge |
| `resolution` | string | Non | `1K` | Niveau de résolution de l'image de sortie, par exemple `1K`, `2K` ou `4K`. Les valeurs prises en charge varient selon le modèle |
| `output_format` | string | Non | déduit | `jpeg`, `png` ou `webp`. S'il est omis, PNG pour les éditions 1K et JPEG pour les éditions 2K et 4K, ou PNG à toute résolution lorsque `transparent_background` vaut `true` |
| `enhance_prompt` | boolean | Non | `false` | Analyser l'image d'entrée et réécrire l'instruction d'édition avant l'inférence |
| `disable_prompt_optimization_thinking` | boolean | Non | valeur par défaut du modèle | Ignorer l'étape de réflexion d'optimisation du prompt du modèle pour une génération plus rapide. Pris en charge uniquement par les modèles avec `supportsOptimizePromptThinking` ; ignoré par les autres |
| `safe_mode` | boolean | Non | `true` | Floute le contenu pour adultes dans le résultat modifié. Définir sur false pour désactiver le flou. |
| `transparent_background` | boolean | Non | `false` | Renvoyer l'image éditée avec un véritable canal alpha. Nécessite un modèle avec `supportsTransparentBackground: true` et un `output_format` `png` ou `webp` (déduit comme PNG s'il est omis). Voir [Images à arrière-plan transparent](/fr/guides/media/transparent-backgrounds) |
| `modelId` | string | Déprécié | - | Alias déprécié de `model` |

### `/image/multi-edit`

| Paramètre | Type | Requis | Par défaut | Description |
|---|---|---|---|---|
| `images` | tableau de fichiers, chaînes base64 ou URL | Oui | - | La première image est l'image de base ; les autres sont des références supplémentaires. Le maximum est spécifique au modèle — voir `model_spec.constraints.maxInputImages` |
| `prompt` | string | Oui | - | Instructions textuelles pour combiner ou éditer les images |
| `modelId` | string | Non | `firered-image-edit` | Identifiant du modèle d'édition |
| `resolution` | string | Non | `1K` | Niveau de résolution de l'image de sortie, par exemple `1K`, `2K` ou `4K`. Les valeurs prises en charge varient selon le modèle |
| `quality` | string | Non | valeur par défaut du modèle | `low`, `medium` ou `high` sur les modèles qui listent `qualities` dans `model_spec.constraints`. Des valeurs plus élevées peuvent augmenter le coût de la requête |
| `output_format` | string | Non | déduit | `jpeg`, `png` ou `webp`. Mêmes règles de déduction que pour `/image/edit` |
| `enhance_prompt` | boolean | Non | `false` | Analyser les images d'entrée et réécrire l'instruction d'édition avant l'inférence |
| `disable_prompt_optimization_thinking` | boolean | Non | valeur par défaut du modèle | Ignorer l'étape de réflexion d'optimisation du prompt du modèle pour une génération plus rapide. Pris en charge uniquement par les modèles avec `supportsOptimizePromptThinking` ; ignoré par les autres |
| `safe_mode` | boolean | Non | `true` | Floute le contenu pour adultes dans le résultat modifié. Définir sur false pour désactiver le flou. |
| `transparent_background` | boolean | Non | `false` | Renvoyer le résultat composé avec un véritable canal alpha. Mêmes règles de modèle et de format que pour `/image/edit` |

### `/image/background-remove`

| Paramètre | Type | Requis | Description |
|---|---|---|---|
| `image` | fichier ou chaîne base64 | L'un de `image` ou `image_url` | Image source à détourer |
| `image_url` | string | L'un de `image` ou `image_url` | URL publique de l'image à détourer |

<Note>
`/image/background-remove` utilise un modèle interne fixe. Il n'accepte pas de champ `model`. Son envoi (par exemple `"model": "bria-bg-remover"`) renvoie `400`, car `model` n'est pas un champ reconnu.
</Note>

### Contenu adulte et mode sûr

`/image/edit` et `/image/multi-edit` acceptent tous deux `safe_mode` (par défaut : `true`). Lorsqu'il est activé, le contenu adulte dans le résultat édité est flouté ; envoyez donc `safe_mode: false` pour recevoir une sortie non floutée :

```json
{
  "model": "qwen-edit-uncensored",
  "prompt": "…",
  "image": "…",
  "safe_mode": false
}
```

La sortie pour adultes (NSFW) non floutée est disponible pour tous les utilisateurs de l'API. Vous n'avez pas besoin d'un abonnement Pro, et le paramètre de filtre de contenu mature dans l'application Venice n'affecte pas les requêtes d'image effectuées via l'API.

Les politiques de contenu varient selon le modèle d'édition et s'appliquent indépendamment de `safe_mode`. Pour une édition non censurée, utilisez `qwen-edit-uncensored`.

La différence de nom du paramètre de modération entre les endpoints prête à confusion :

| Endpoint | Champ pour désactiver le flou |
|---|---|
| `POST /image/edit`, `POST /image/multi-edit` | `safe_mode: false` |
| `POST /image/generate` (génération native) | `safe_mode: false` |
| `POST /images/generations` (génération compatible OpenAI) | `moderation: "low"` |

Passer `safe_mode` à `/images/generations` renvoie une erreur `400` avec `Unrecognized key(s) in object: 'safe_mode'`.

## Formats d'entrée pris en charge

| Endpoint | Entrée JSON | Entrée multipart | Sortie |
|---|---|---|---|
| `/image/edit` | Chaîne base64 ou URL | Téléversement de fichier | `image/png`, `image/jpeg` ou `image/webp` |
| `/image/multi-edit` | Chaînes base64 ou URL | Téléversements de fichiers | `image/png`, `image/jpeg` ou `image/webp` |
| `/image/background-remove` | Chaîne base64 ou URL | Téléversement de fichier | `image/png` |

Pour les endpoints d'édition, les images doivent faire au moins 256×256 pixels, et le nombre total de pixels ne doit pas dépasser 33 177 600 (résolution 8K). Les fichiers téléversés doivent faire moins de `25MB`.

## Modèles et tarification

Le modèle d'édition par défaut est `firered-image-edit`, au tarif de **0,04 $ par édition**. D'autres modèles capables d'édition peuvent avoir des tarifs et des contraintes différents. L'amélioration de prompt ajoute **0,04 $ par réécriture appliquée** au prix de l'édition.

Voir :

- [Tarification des images](/fr/overview/pricing)
- [API Models](/fr/api-reference/endpoint/models/list) avec `type=inpaint`

## Erreurs

| Statut | Signification | Action |
|---|---|---|
| `400` | Paramètres de requête invalides | Vérifiez le nombre d'images, les noms de champs et le format d'entrée |
| `401` | Échec d'authentification | Vérifiez votre clé API |
| `402` | Solde insuffisant | Ajoutez des crédits sur [venice.ai/settings/api](https://venice.ai/settings/api?utm_source=venice-api-documentation) |
| `413` | Fichier trop volumineux | Gardez les fichiers téléversés sous 25 MB |
| `415` | Type de contenu invalide (`/image/multi-edit` uniquement ; les autres endpoints renvoient `400`) | Utilisez correctement JSON ou multipart form-data |
| `422` | Violation de la politique de contenu ou image d'entrée trop grande | Ajustez le prompt ou réduisez les dimensions de l'image |
| `429` | Limite de débit dépassée ou modèle surchargé | Réessayez avec un backoff ; vérifiez l'en-tête `Retry-After` |
| `500` | Échec du traitement d'inférence | Réessayez la requête |
| `503` | Modèle à pleine capacité | Réessayez après un court délai |

<Note>
Certains modèles d'édition ont des politiques de contenu plus strictes que les modèles de génération d'images. Les requêtes qui enfreignent la politique du modèle sélectionné sont rejetées avec `422`.
</Note>

Venice fournit des API distinctes pour découvrir des pages web et en extraire le contenu :

- **Web Search** renvoie des résultats structurés comprenant titres, URL, extraits et dates.
- **Web Scrape** convertit une page publique sélectionnée en Markdown.

Utilisez-les ensemble lorsque votre application a besoin d'un matériau source actuel et inspectable avant l'inférence.

## Rechercher sur le web

Envoyez une requête à l'API Search :

```bash
curl https://api.venice.ai/api/v1/augment/search \
  -H "Authorization: Bearer $VENICE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"query":"latest developments in decentralized AI"}'
```

Brave est le fournisseur par défaut et offre une non-conservation des données (Zero Data Retention). Google est également disponible avec des requêtes anonymisées transitant par Venice, et [Exa](/fr/guides/integrations/exa-search) est disponible avec la non-conservation des données (Zero Data Retention). Consultez la [référence de l'API Web Search](/api-reference/endpoint/augment/search) pour la sélection du fournisseur et le schéma de réponse complet.

## Choisir un fournisseur {#choosing-a-provider}

Chaque fournisseur accepte la même requête et coûte le même prix par recherche, donc changer de fournisseur revient à modifier un seul champ. La différence tient à ce qui est renvoyé :

| Fournisseur | Résultats | Idéal pour |
|---|---|---|
| `brave` (par défaut) | Courts extraits correspondant à la requête | Actualités et recherches courantes, et pipelines qui scrapent les pages qu'ils sélectionnent |
| `google` | 5 résultats, surtout le texte complet de la page depuis son début, ou seulement l'extrait lorsqu'un site bloque le scraping | Lire le texte de la page sans scraping séparé |
| `exa` | Courts extraits correspondant à la requête, et les résultats les plus pertinents de notre benchmark | Questions de code et de recherche, et résultats envoyés directement dans un prompt |

Les résultats plus longs deviennent des tokens d'entrée quand vous les transmettez à un modèle : ils coûtent donc plus cher et prennent plus de temps à traiter. Si les résultats vont directement dans un prompt, limitez leur nombre et la quantité de texte que chacun apporte. Avec `google`, conservez les passages qui correspondent à la requête plutôt que le début de chaque résultat, qui contient souvent la navigation ou un bandeau de cookies.

Pour comparer les fournisseurs en pertinence, précision des réponses, latence et coût en tokens, lisez [Benchmark des fournisseurs de recherche web](/fr/learn/search-provider-benchmark). L'article renvoie vers le harness du benchmark, pour que vous puissiez relancer la comparaison sur vos propres questions.

## Extraire une page

Après avoir sélectionné un résultat, envoyez son URL publique à l'API Scrape :

```bash
curl https://api.venice.ai/api/v1/augment/scrape \
  -H "Authorization: Bearer $VENICE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"url":"https://example.com/article"}'
```

Le point de terminaison renvoie le contenu de la page au format Markdown. Il demande d'abord la représentation Markdown native du site lorsqu'elle est disponible et, à défaut, utilise une extraction basée sur un navigateur.

## Flux Search-to-Scrape

<Steps>
  <Step title="Rechercher">
    Soumettez une requête ciblée et collectez les résultats structurés.
  </Step>
  <Step title="Sélectionner les sources">
    Filtrez les résultats par pertinence, domaine et date avant de récupérer le contenu des pages.
  </Step>
  <Step title="Extraire">
    Extrayez le Markdown uniquement des pages que votre application a l'intention d'utiliser.
  </Step>
  <Step title="Utiliser ou stocker le contenu">
    Incluez le Markdown dans un prompt, créez des embeddings, mettez-le en cache ou conservez les URL sources pour les citations.
  </Step>
</Steps>

Web Search et Web Scrape ont chacun une limite de requêtes par minute et par compte. Les requêtes au-delà de la limite renvoient `429` ; réessayez-les avec un backoff exponentiel et limitez le scraping parallèle à un pool réduit.

## API de recherche autonome ou recherche web du modèle ?

Utilisez les API autonomes lorsque votre application a besoin de contrôler la sélection des sources ou souhaite réutiliser le contenu récupéré. Activez la recherche web sur une requête de modèle lorsque vous souhaitez que Venice gère la récupération dans le cadre d'une seule requête d'inférence.

| Besoin | Approche |
|---|---|
| Inspecter ou filtrer les résultats avant l'inférence | Web Search autonome |
| Extraire une URL spécifique et connue | Web Scrape autonome |
| Mettre en cache ou réutiliser le contenu récupéré | API autonomes |
| Laisser le modèle récupérer automatiquement le contexte actuel | Recherche web du modèle |

<Warning>
Web Search et Web Scrape sont des API expérimentales. Leurs formats de requête et de réponse peuvent changer sans préavis. Web Scrape n'accepte que les pages accessibles publiquement, et les sites qui bloquent l'accès automatisé peuvent être rejetés.
</Warning>

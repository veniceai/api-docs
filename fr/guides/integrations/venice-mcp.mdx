Le [serveur Venice MCP](https://github.com/veniceai/venice-mcp-server) est le serveur officiel [Model Context Protocol](https://modelcontextprotocol.io/) pour Venice. Il expose l'API Venice (chat, image, vidéo, audio, musique, embeddings, web augment, personnages, RPC crypto et attestation TEE) ainsi que les opérations de compte (facturation et clés API) sous la forme de **45 outils** que tout agent compatible MCP peut appeler.

## Démarrage rapide

<Steps>
  <Step title="Obtenez une clé API Venice">
    Générez-en une sur [venice.ai/settings/api](https://venice.ai/settings/api?utm_source=venice-api-documentation). Voir le [guide des clés API](/guides/getting-started/generating-api-key) pour la procédure pas à pas.
  </Step>

  <Step title="Ajoutez Venice à la configuration de votre hôte MCP">
    Collez ceci dans le fichier de configuration de votre hôte MCP :

    ```json
    {
      "mcpServers": {
        "venice": {
          "command": "npx",
          "args": ["-y", "@veniceai/mcp-server@0.3.0"],
          "env": { "VENICE_API_KEY": "<your-venice-api-key>" }
        }
      }
    }
    ```

    Chemins de configuration courants :

    | Hôte | Chemin |
    |---|---|
    | Claude Desktop (macOS) | `~/Library/Application Support/Claude/claude_desktop_config.json` |
    | Claude Desktop (Windows) | `%APPDATA%\Claude\claude_desktop_config.json` |
    | Cursor | `~/.cursor/mcp.json` |
    | LM Studio | `mcp.json` (depuis les réglages MCP de l'application) |
  </Step>

  <Step title="Redémarrez votre hôte MCP">
    Votre agent dispose désormais du chat, de l'image, de la vidéo, de la musique, du TTS, de l'ASR, de la facturation, des clés API et de 39 autres outils Venice.
  </Step>
</Steps>

<Note>
La plupart des hôtes MCP ne transmettent que les variables d'environnement **explicitement** listées dans le bloc `env`. Les variables système ne sont pas héritées. Si vous voyez des erreurs 402 alors qu'une clé API est définie, vérifiez que `VENICE_API_KEY` se trouve bien dans `env` dans votre configuration.
</Note>

## Ce que vous obtenez

**45 outils** couvrant chaque modalité Venice plus les opérations de compte, **3 ressources** (`venice://models`, `venice://styles`, `venice://voices`) et **3 modèles de prompts** (recherche sans censure, écriture créative NSFW, explorateur de styles d'image).

Chaque outil déclare des annotations explicites `readOnlyHint`, `destructiveHint`, `idempotentHint` et `openWorldHint`. Les hôtes peuvent donc exécuter les lookups sans demander, et demander confirmation avant toute action destructive, comme le nettoyage de médias ou un relais crypto.

### Chat et embeddings

| Outil | Description |
|---|---|
| `venice_chat` | Chat completion compatible OpenAI sur tout le catalogue de LLM de Venice, avec blocs texte/image/audio/vidéo/fichier, sorties structurées, function tools, prompt caching et contrôle du raisonnement. Les appels sont en clair et sans streaming. |
| `venice_responses` | API Responses alpha, sans état et compatible OpenAI, avec entrée texte/image et contrôle du raisonnement. Les modèles compatibles E2EE et les champs d'outils ne sont pas pris en charge. |
| `venice_embeddings` | Calcule des embeddings pour du texte. |
| `venice_chat_with_character` | Discute avec un personnage Venice par slug. |

### Image

| Outil | Description |
|---|---|
| `venice_image_generate` | Génère une image (Flux 2, Lustify SDXL, Anime/WAI, Qwen Image, GPT Image, Nano Banana Pro et plus), avec ratio d'aspect ou largeur/hauteur, paliers de qualité, amélioration de prompt, références de style, recherche web et variantes. |
| `venice_image_edit` | Modifie une image avec un prompt. |
| `venice_image_multi_edit` | Modifie jusqu'à 8 images ensemble avec un seul prompt (composition / outpainting). |
| `venice_image_upscale` | Agrandit une image de 2 à 4×, avec un contrôle `creativity`. |
| `venice_image_remove_bg` | Supprime l'arrière-plan d'une image. |
| `venice_image_styles` | Liste les presets de style d'image. |

### Vidéo

| Outil | Description |
|---|---|
| `venice_video_generate` | Met en file une génération vidéo (Sora 2, Veo 3.1, Kling, Wan, LTX 2, Seedance, Runway Gen-4 et plus) avec entrées image, vidéo, audio, références et éléments. |
| `venice_video_status` | Vérifie l'état d'un job vidéo (`POST /video/retrieve`). |
| `venice_video_complete` | Marque une vidéo terminée comme téléchargée ; ne supprime les médias côté serveur que lorsque Venice le confirme. |
| `venice_video_quote` | Obtient un devis avant la mise en file. |

### Audio (TTS / ASR)

| Outil | Description |
|---|---|
| `venice_tts` | Synthèse vocale avec voix clonées, température et tags d'émotion. Le streaming est regroupé en un seul résultat audio complet. |
| `venice_asr` | Transcrit un audio depuis une URL, avec horodatages optionnels par mot/caractère. Les transcriptions volumineuses sont paginées via un handle de session. |
| `venice_voice_clone` | Liste les voix live par modèle, ou clone une voix depuis une URL d'échantillon (renvoie un handle `vv_<id>` pour `venice_tts`). |
| `venice_audio_quote` | Obtient un devis pour la génération de musique. |

### Musique

| Outil | Description |
|---|---|
| `venice_music_generate` | Met en file une génération musicale (`ace-step-15`, `elevenlabs-music`, `minimax-music-v2/v25/v26`, `stable-audio-25`, `mmaudio-v2-text-to-audio`, `elevenlabs-sound-effects-v2`) avec contrôles de paroles, instrumental, boucle, voix, langue, vitesse et durée. |
| `venice_music_status` | Vérifie l'état d'un job musical. |
| `venice_music_complete` | Marque un job musical terminé comme téléchargé. |

### Web augment

| Outil | Description |
|---|---|
| `venice_web_search` | Recherche sur le web avec Brave (par défaut, Zero Data Retention) ou Google (proxifié et anonymisé par Venice). |
| `venice_web_scrape` | Scrape une URL en markdown. |
| `venice_text_parser` | Extrait le texte de PDF/DOCX/EPUB/PPTX/XLSX. |

### Catalogue et personnages

| Outil | Description |
|---|---|
| `venice_list_models` | Parcourt le catalogue de modèles live de tous types, avec résumés compacts, prix et flags de capacités. |
| `venice_model_details` | Obtient la ligne catalogue complète d'un modèle exact : contraintes `model_spec`, capacités et tarifs. |
| `venice_model_traits` | Associe les noms de traits (`default`, `most_uncensored`, …) aux IDs de modèles actuels. |
| `venice_model_compatibility_mapping` | Associe les noms de modèles compatibles aux IDs de modèles Venice. |
| `venice_list_characters` | Liste les personnages publics de Venice avec filtres de recherche, tag, modèle et tri. **Clé API uniquement.** |
| `venice_get_character` | Obtient un personnage public par slug. **Clé API uniquement.** |
| `venice_character_reviews` | Liste les avis publics d'un personnage, paginés. **Clé API uniquement.** |

### Attestation TEE

| Outil | Description |
|---|---|
| `venice_tee_attestation` | Obtient les preuves d'attestation matérielle (quote Intel TDX, preuves NVIDIA optionnelles, clé de signature) pour un modèle texte compatible TEE, avec votre propre nonce de 32 octets. |
| `venice_tee_signature` | Obtient la payload de signature de l'enclave pour l'ID d'une requête de chat TEE terminée. |

<Warning>
Les deux outils TEE ne renvoient que les preuves du fournisseur : ils ne les vérifient pas et ne chiffrent pas le chat. Vérifiez vous-même le nonce renvoyé, l'état du mode debug et la liaison de la clé de signature avant de faire confiance à un modèle TEE, et utilisez `venice_chat` (jamais `venice_responses`) pour les modèles TEE. Ce serveur rejette `enable_e2ee`.
</Warning>

### Crypto

| Outil | Description |
|---|---|
| `venice_crypto_networks` | Liste les slugs de réseau live acceptés par le proxy RPC. |
| `venice_crypto_rpc` | Proxifie une requête JSON-RPC, ou un lot de 100 maximum, vers Ethereum, Base, Arbitrum, Optimism, Polygon, Solana, Starknet, zkSync, Linea, BSC, Avalanche, Blast et plus. |

Les diffusions de transactions (`eth_sendRawTransaction`, `eth_sendUserOperation`, `sendTransaction` de Solana, écritures Starknet) doivent être envoyées en requêtes individuelles avec `idempotency_key`, et la même clé doit être réutilisée lors d'un nouvel essai.

### Facturation (clés admin)

| Outil | Description |
|---|---|
| `venice_billing_balance` | Disponibilité actuelle en USD, DIEM et crédits inclus. |
| `venice_billing_usage_analytics` | Usage agrégé en bêta par date, modèle et clé API (lookback ou plage personnalisée). |
| `venice_billing_usage_history` | Usage détaillé avec pagination par curseur et sortie JSON ou CSV. |

<Note>
Les outils de facturation exigent une clé API **ADMIN**. Les clés d'inférence ne peuvent pas appeler ces endpoints, et le serveur échoue localement au lieu de se rabattre sur un token de wallet. La route obsolète `/billing/usage` n'est pas couverte.
</Note>

### Clés API

| Outil | Description |
|---|---|
| `venice_list_api_keys` | Liste les métadonnées des clés actives, en incluant uniquement les six derniers caractères. Clé admin uniquement. |
| `venice_get_api_key` | Obtient les métadonnées, l'usage, les soldes et les rate limits d'une clé par ID. Clé admin uniquement. |
| `venice_api_key_rate_limits` | Soldes actuels, statut d'accès, tier, expiration et rate limits par modèle. Clé d'inférence ou admin. |
| `venice_api_key_rate_limit_logs` | Les 50 derniers dépassements de rate limit (expérimental). Clé admin uniquement. |

### Helpers wallet x402

Utiles uniquement si vous vous authentifiez avec un wallet via [x402](/guides/integrations/x402-venice-api) au lieu d'une clé API.

| Outil | Description |
|---|---|
| `venice_x402_balance` | Vérifie le solde de crédit x402 prépayé d'une adresse wallet EVM ou Solana. |
| `venice_x402_top_up_info` | Obtient les exigences de recharge (réseau, token USDC, destinataire, montant minimum). Ne prend aucun argument. |
| `venice_x402_transactions` | Liste les recharges et débits x402 récents d'une adresse wallet EVM ou Solana. |

## Configuration

Le serveur se configure entièrement via des variables d'environnement.

### Modèles et requêtes

| Variable | Défaut | Notes |
|---|---|---|
| `VENICE_API_KEY` | _(aucun)_ | Votre clé API Venice. La configuration la plus simple. |
| `VENICE_DEFAULT_CHAT_MODEL` | `deepseek-v4-flash-0731` | |
| `VENICE_DEFAULT_IMAGE_MODEL` | `flux-2-pro` | |
| `VENICE_DEFAULT_TTS_MODEL` | `tts-kokoro` | |
| `VENICE_DEFAULT_ASR_MODEL` | `openai/whisper-large-v3` | |
| `VENICE_DISABLE_NSFW` | `0` | Mettez `1` pour retirer les notes de capacité NSFW des descriptions d'outils. |
| `VENICE_HTTP_TIMEOUT_MS` | `60000` | |
| `VENICE_SIWX_TOKEN` | _(aucun)_ | Token d'authentification en mode wallet x402. Voir [x402 ci-dessous](#mode-wallet-x402). |

Si `VENICE_API_KEY` et `VENICE_SIWX_TOKEN` sont tous deux définis, la clé API l'emporte.

### Limites de taille des réponses

Les médias générés sont mis en mémoire tampon et intégrés en base64 dans le résultat MCP : chaque modalité a donc un plafond en octets.

| Variable | Défaut | S'applique à |
|---|---|---|
| `VENICE_MAX_IMAGE_RESPONSE_BYTES` | `33554432` (32 MiB) | `venice_image_generate`, `venice_image_edit`, `venice_image_multi_edit`, `venice_image_upscale`, `venice_image_remove_bg` |
| `VENICE_MAX_VIDEO_RESPONSE_BYTES` | `26214400` (25 MiB) | `venice_video_status` |
| `VENICE_MAX_AUDIO_RESPONSE_BYTES` | `33554432` (32 MiB) | `venice_tts`, `venice_music_status` |

Une image ou un résultat TTS trop volumineux est écarté avec une erreur. Une vidéo ou une musique trop volumineuse reste en file : vous pouvez rappeler l'outil de statut avec le même queue ID après avoir relevé la limite.

### Serveur HTTP

Utile uniquement pour le [déploiement Streamable HTTP](#auto-hébergement-streamable-http).

| Variable | Défaut | Notes |
|---|---|---|
| `PORT` | `3333` | Port d'écoute HTTP. |
| `VENICE_MCP_HOST` | `127.0.0.1` | Adresse de bind. Mettez `0.0.0.0` pour exposer sur le LAN ou dans un conteneur. |
| `VENICE_MCP_AUTH_TOKEN` | _(aucun)_ | Token bearer exigé par `/mcp` lorsque le bind sort de la loopback. |
| `VENICE_MCP_ALLOW_UNAUTHENTICATED_HTTP` | `0` | Échappatoire pour un HTTP exposé sans authentification. À utiliser uniquement derrière un proxy authentifié de confiance. |
| `VENICE_MCP_MAX_SESSIONS` | `100` | Nombre maximal de sessions Streamable HTTP actives. |
| `VENICE_MCP_SESSION_TTL_MS` | `1800000` | Durée de vie d'une session inactive avant nettoyage. |

## Comportement de génération de médias

- **Un média terminé peut être des octets ou une URL.** Les jobs vidéo et musique renvoient des ressources MP4/audio intégrées, ou du JSON avec une `download_url` renvoyée comme resource link. Téléchargez ce lien d'abord, puis appelez `venice_video_complete` ou `venice_music_complete` ; le nettoyage des médias ne s'applique jamais à un résultat `download_url`, car le lien cesse de fonctionner une fois le fichier supprimé.
- **Certains modèles ne renvoient l'URL qu'à la mise en file.** Pour les modèles VPS et Grok Imagine Private, conservez la `download_url` renvoyée par `venice_video_generate` et passez-la à `venice_video_status` ; un retrieve `COMPLETED` sans URL intégrée fournit tout de même un lien exploitable.
- **L'amélioration de prompt est renvoyée.** Lorsque `enhance_prompt` est appliqué, les résultats de génération, d'édition et de multi-édition d'image incluent le prompt URL-décodé renvoyé par Venice.
- **La pagination ASR n'est facturée qu'une fois.** Les transcriptions avec horodatages ou de plus de 8000 caractères renvoient un `result_handle` avec la première page. Demandez les pages suivantes avec ce handle. Les handles vivent en mémoire par session MCP pendant 10 minutes, et seuls les 16 plus récents sont conservés.
- **Le consentement Seedance n'est pas un contournement de politique.** Les modèles Seedance publics actuels peuvent refuser d'emblée les médias contenant des personnes détectables. Lorsqu'une réponse `needs_consent` est renvoyée, les trois flags `consents.seedance` sont des attestations légales : ne les passez à `true` qu'après confirmation explicite de chaque déclaration par l'utilisateur.

## Mode wallet x402

Venice prend en charge l'authentification avec un [token wallet Sign-In-With-X](/guides/integrations/x402-venice-api) adossé à du crédit USDC prépayé sur Base ou Solana, en plus du flux normal par clé API. Sans e-mail, téléphone ni KYC : votre wallet est la seule identité.

```json
{
  "mcpServers": {
    "venice": {
      "command": "npx",
      "args": ["-y", "@veniceai/mcp-server@0.3.0"],
      "env": { "VENICE_SIWX_TOKEN": "<base64 Sign-In-With-X payload>" }
    }
  }
}
```

Le serveur MCP transmet `VENICE_SIWX_TOKEN` dans l'en-tête `SIGN-IN-WITH-X` à chaque appel de l'API Venice. Le serveur ne voit jamais votre clé privée. La signature du wallet et les autorisations de recharge USDC se font dans votre propre wallet.

| Flux | Ce qui se passe |
|---|---|
| **Configuration initiale** | Vous signez un message Sign-In-With-X dans votre wallet → produit un token SIWX (JSON en base64). |
| **Recharge** | `POST /api/v1/x402/top-up` renvoie 402 + les exigences de paiement. Signez un paiement USDC pour l'une des options Base ou Solana renvoyées, renvoyez la requête, et Venice crédite votre solde. |
| **Chaque appel d'inférence** | Le serveur MCP envoie `SIGN-IN-WITH-X: <SIWX>` ; Venice débite votre solde prépayé. |

La recharge minimale est de **\$5 USD**. Le solde minimum pour appeler l'inférence est de **\$0.10**. Une fois rechargé, les appels prennent moins de 100 ms, car le règlement se fait off-chain sur un compte de crédit rapide.

<Tip>
Les wallets liés à un compte Venice avec du DIEM staké consomment le solde de staking au lieu des crédits USDC : aucune recharge n'est nécessaire.
</Tip>

Venice n'accepte pas d'en-têtes de paiement sur les routes d'inférence, donc ce serveur n'en envoie jamais. `PAYMENT-SIGNATURE` ne concerne que `/x402/top-up`, et le helper de recharge découvre les exigences sans soumettre de paiement.

### Couverture des modes d'authentification

Certains endpoints n'acceptent qu'un seul mode d'authentification :

| Outil | Clé API | x402 |
|---|---|---|
| Inférence, médias, web augment, RPC crypto, chat avec personnage | ✓ | ✓ |
| `venice_list_characters`, `venice_get_character`, `venice_character_reviews` | ✓ | ✗ |
| `venice_billing_*`, `venice_list_api_keys`, `venice_get_api_key`, `venice_api_key_rate_limit_logs` | ✓ (admin) | ✗ |
| `venice_api_key_rate_limits` | ✓ (n'importe quelle clé) | ✗ |
| `venice_x402_balance`, `venice_x402_transactions` | ✗ | ✓ |
| `venice_x402_top_up_info` | ✓ | ✓ |

Si les deux identifiants sont définis, la clé API l'emporte sur tous les appels : les helpers réservés à SIWX (`venice_x402_balance`, `venice_x402_transactions`) ne fonctionnent donc que lorsque le token wallet est votre unique identifiant.

## Auto-hébergement (Streamable HTTP)

Pour les déploiements d'équipe ou de workspace, exécutez le serveur MCP en HTTP plutôt qu'en stdio :

```bash
docker run -p 3333:3333 \
  -e VENICE_API_KEY=<your-venice-api-key> \
  -e VENICE_MCP_AUTH_TOKEN=<choose-a-long-random-token> \
  ghcr.io/veniceai/venice-mcp-server:latest
```

Le serveur est désormais disponible sur `http://localhost:3333/mcp`. Les clients HTTP doivent envoyer `Authorization: Bearer <VENICE_MCP_AUTH_TOKEN>` et créer de nouvelles sessions sans en-tête `mcp-session-id`, puis réutiliser l'ID de session émis par le serveur.

<Warning>
`/mcp` est un endpoint d'exécution d'outils adossé à des identifiants : les appelants peuvent dépenser la clé API Venice configurée ou le solde x402. Lorsque le mode HTTP se lie hors de la loopback, le démarrage échoue sauf si `VENICE_MCP_AUTH_TOKEN` est défini, ou si `VENICE_MCP_ALLOW_UNAUTHENTICATED_HTTP=1` est configuré derrière un proxy authentifié de confiance. En production, épinglez explicitement la version du paquet npm au lieu de vous fier à `latest`.
</Warning>

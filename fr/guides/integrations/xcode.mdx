[Xcode](https://developer.apple.com/xcode/) inclut un assistant de codage capable de répondre à des questions sur votre projet, d'écrire et de refactoriser du code, et de corriger des erreurs. En plus de ses fournisseurs intégrés, Xcode accepte tout fournisseur de chat prenant en charge l'API Chat Completions : vous pouvez donc ajouter Venice dans les réglages Intelligence de Xcode et utiliser les modèles Venice dans les conversations de l'assistant de codage.

## Prérequis

- Une clé API Venice depuis [venice.ai/settings/api](https://venice.ai/settings/api?utm_source=venice-api-documentation)
- [Xcode](https://developer.apple.com/xcode/) 26.3 ou version ultérieure (les versions antérieures de Xcode 26 peuvent perdre les fournisseurs de chat personnalisés au redémarrage de Xcode)
- macOS Tahoe 26 ou version ultérieure (Xcode 27 nécessite macOS Tahoe 26.6 ou version ultérieure et un Mac équipé d'une puce Apple)

## Configuration

<Steps>
  <Step title="Obtenez votre clé API Venice">
    Générez une clé depuis [venice.ai/settings/api](https://venice.ai/settings/api?utm_source=venice-api-documentation). Une clé **Inference Only** suffit pour Xcode.

    Envisagez de créer une clé dédiée avec une **Epoch Consumption Limit**, afin de plafonner les dépenses de Xcode et de pouvoir révoquer la clé sans affecter les autres applications. Consultez [Générer une clé API](/fr/guides/getting-started/generating-api-key).
  </Step>

  <Step title="Ouvrez les réglages Intelligence">
    Dans Xcode, choisissez **Xcode > Settings** et sélectionnez **Intelligence** dans la barre latérale.
  </Step>

  <Step title="Ajoutez Venice comme fournisseur de chat">
    Sous **Chat**, cliquez sur **Add a Chat Provider** et sélectionnez **Internet Hosted**. Certaines versions de Xcode 26 nomment ce bouton **Add a Model Provider**.

    Saisissez les valeurs suivantes, puis cliquez sur **Add** :

    | Champ | Valeur |
    | --- | --- |
    | URL | `https://api.venice.ai/api` |
    | API Key | `Bearer your-venice-api-key` |
    | API Key Header | `Authorization` |
    | Description | `Venice` |

    Conservez l'URL exactement telle qu'indiquée, sans `/v1` ni barre oblique finale. Xcode y ajoute `/v1/models` et `/v1/chat/completions`, ce qui donne les endpoints standard de Venice sous `https://api.venice.ai/api/v1`.

    Xcode envoie le champ **API Key** comme valeur complète de l'en-tête `Authorization`. Remplacez `your-venice-api-key` par votre clé et conservez le préfixe `Bearer `.
  </Step>

  <Step title="Choisissez vos modèles">
    Sélectionnez le fournisseur Venice sous **Chat**. Xcode récupère la liste des modèles auprès de Venice. Activez les modèles que vous souhaitez utiliser, et ajoutez une étoile à ceux que vous utilisez le plus pour qu'ils apparaissent en haut du menu des modèles.

    La liste inclut tous les modèles de texte Venice, mais l'assistant de codage ne fonctionne qu'avec les modèles qui prennent en charge l'appel d'outils. Consultez les [exigences relatives aux modèles](#exigences-relatives-aux-modèles) avant de choisir, ou commencez avec `z-ai-glm-5-3-flash`.
  </Step>

  <Step title="Démarrez une conversation">
    Ouvrez un projet, puis cliquez sur le bouton **Coding Assistant** ou appuyez sur **Command-0**. Cliquez sur **New Conversation** et choisissez un modèle Venice sous **Chat**. Le texte indicatif du champ de message indique quel modèle la conversation utilise.

    Envoyez un prompt court pour tester la connexion :

    ```txt
    Summarize what this project does in three bullet points.
    ```
  </Step>
</Steps>

## Vérifier la configuration

L'envoi du prompt de test constitue la véritable vérification. Une liste complète de modèles dans Xcode ne prouve pas que votre clé fonctionne, car l'endpoint `GET /models` de Venice renvoie le catalogue avec ou sans clé valide. Venice ne vérifie la clé que lorsque vous envoyez un message.

Si le prompt échoue, vérifiez votre clé API en dehors de Xcode :

```bash
curl https://api.venice.ai/api/v1/api_keys/rate_limits \
  -H "Authorization: Bearer $VENICE_API_KEY"
```

Cet endpoint nécessite une clé valide : une erreur `401` ici désigne donc la clé plutôt que la configuration de Xcode. Si la clé fonctionne, comparez les réglages du fournisseur avec la section [Dépannage](#dépannage).

## Exigences relatives aux modèles

<Warning>
**Le modèle doit prendre en charge l'appel d'outils.** Dans les conversations de chat, Xcode fournit au modèle des outils pour rechercher et modifier votre projet : un modèle sans appel d'outils ne peut donc pas traiter les requêtes de l'assistant de codage.
</Warning>

Le [catalogue de modèles de texte](/fr/models/text) indique cette capacité sous le nom **Function Calling**, et la plupart des modèles de texte Venice la prennent en charge.

Idéalement, le modèle doit aussi disposer d'une fenêtre de contexte de 200K tokens ou plus. Xcode ne propose aucun réglage de fenêtre de contexte pour les fournisseurs de chat, et avec **Project Context** activé, une requête peut inclure beaucoup de code du projet en plus des définitions d'outils de Xcode.

Pour lister les modèles Venice qui répondent aux deux exigences :

```bash
curl -s https://api.venice.ai/api/v1/models \
  | jq -r '.data[] | select(.model_spec.capabilities.supportsFunctionCalling and .model_spec.availableContextTokens >= 200000) | .id'
```

## Choisir les modèles

Ces modèles répondent aux deux exigences :

| Cas d'usage | Exemple d'ID de modèle |
| --- | --- |
| Codage | `deepseek-v4-pro-0813` |
| Coût réduit | `z-ai-glm-5-3-flash` |
| Tâches les plus difficiles | `grok-4-7` |
| Captures d'écran et maquettes avec **Upload files** | `qwen-3-8-27b` |

Lorsque vous comparez d'autres modèles :

- [`GET /models/traits?type=text`](/fr/api-reference/endpoint/models/traits) renvoie les choix actuels de Venice, comme `default_code` pour le codage.
- **Project Context** rend les requêtes volumineuses, donc la tarification des tokens d'entrée compte plus que d'habitude. Comparez les prix dans le [catalogue de modèles de texte](/fr/models/text).

Venice retire et remplace régulièrement des modèles. Si un modèle cesse de fonctionner, consultez les [Dépréciations](/fr/overview/deprecations) et passez à un modèle actuel.

## Agents

Les fournisseurs de chat alimentent uniquement les conversations de chat. Les agents intégrés de Xcode, comme Claude Agent et Codex, ainsi que tous les agents que vous ajoutez via l'Agent Client Protocol (ACP), sont configurés séparément et n'envoient pas de requêtes via un fournisseur de chat. Les agents ont également accès à davantage de capacités de Xcode que le chat, comme la compilation et le test de votre application.

Pour exécuter un agent sur les modèles Venice avec accès à votre projet Xcode, configurez un agent de terminal pour Venice et connectez-le au serveur Model Context Protocol (MCP) fourni par Xcode 26.3 et versions ultérieures :

<Steps>
  <Step title="Autorisez les agents externes">
    Dans les réglages Intelligence de Xcode, sous **Model Context Protocol**, activez **Allow external agents to use Xcode tools**.
  </Step>

  <Step title="Configurez l'agent avec Venice">
    Suivez le guide [Codex CLI](/fr/guides/integrations/codex-cli) ou [Claude Code](/fr/guides/integrations/claude-code).
  </Step>

  <Step title="Connectez l'agent à Xcode">
    Enregistrez le serveur MCP de Xcode auprès de l'agent :

    <CodeGroup>
    ```bash Codex CLI
    codex mcp add xcode -- xcrun mcpbridge
    ```

    ```bash Claude Code
    claude mcp add --transport stdio xcode -- xcrun mcpbridge
    ```
    </CodeGroup>
  </Step>

  <Step title="Envoyez un prompt à l'agent">
    Ouvrez d'abord votre projet dans Xcode, puis envoyez un prompt à l'agent dans le Terminal. Xcode vous avertit lorsque l'agent se connecte.
  </Step>
</Steps>

## Confidentialité

Xcode envoie les requêtes de chat directement de votre Mac vers Venice. **Project Context** est activé par défaut dans les conversations de chat : Xcode inclut donc du code pertinent et d'autres éléments de contexte de votre projet dans chaque requête. Pour limiter ce que Xcode envoie, désactivez **Project Context** dans le champ de message et référencez explicitement les fichiers et symboles avec `@`.

Venice ne stocke ni ne journalise le contenu des prompts et des réponses au niveau de son proxy. Le modèle que vous choisissez détermine le niveau de confidentialité à l'exécution :

- Les modèles **Private** utilisent une infrastructure sans conservation des données.
- Les modèles **Anonymized** masquent votre identité auprès du fournisseur en amont, mais ce fournisseur peut traiter votre code.
- Les modèles **TEE**, avec des ID de modèles `e2ee-`, s'exécutent dans une enclave matérielle. Xcode ne peut pas chiffrer les prompts sur votre Mac : ces modèles fonctionnent donc en mode TEE plutôt qu'en mode chiffré de bout en bout lorsque vous les utilisez depuis Xcode.

Vérifiez le label de confidentialité de chaque modèle dans le [catalogue de modèles de texte](/fr/models/text) et lisez [Confidentialité Venice](/fr/overview/privacy) avant d'envoyer du code propriétaire.

## Dépannage

<AccordionGroup>
  <Accordion title="Erreur 401 ou d'authentification">
    Vérifiez que le champ **API Key** contient `Bearer ` suivi d'une clé Venice obtenue sur [venice.ai/settings/api](https://venice.ai/settings/api?utm_source=venice-api-documentation), sans espaces superflus. Xcode charge la liste des modèles même avec une clé incorrecte, car cette liste est publique : les erreurs d'authentification n'apparaissent donc que lorsque vous envoyez un message. Testez la clé avec la commande de la section [Vérifier la configuration](#vérifier-la-configuration).
  </Accordion>
  <Accordion title="Xcode ne parvient pas à charger les modèles ou rejette le fournisseur">
    Vérifiez que l'URL est exactement `https://api.venice.ai/api`. Une URL se terminant par `/v1` amène Xcode à requêter `/api/v1/v1/models`, et une barre oblique finale produit `/api//v1/models`. Venice renvoie `404` dans les deux cas. Ajoutez à nouveau le fournisseur avec l'URL corrigée.
  </Accordion>
  <Accordion title="Erreurs d'endpoint lors de l'envoi d'un message">
    Vérifiez que la conversation utilise un modèle qui prend en charge l'appel d'outils et qui dispose, idéalement, d'une fenêtre de contexte de 200K tokens ou plus. Xcode envoie des définitions d'outils et le contexte du projet avec chaque requête : un modèle sans appel d'outils ne peut pas les traiter, et un projet volumineux peut dépasser une fenêtre de contexte plus petite. Activez un modèle qui répond aux [exigences relatives aux modèles](#exigences-relatives-aux-modèles), puis démarrez une nouvelle conversation avec celui-ci.
  </Accordion>
  <Accordion title="Erreur 402 ou paiement requis">
    Venice renvoie `402` dans deux cas :

    - La requête a atteint Venice sans en-tête `Authorization`. Venice ignore les autres en-têtes, comme `x-api-key`, et répond par un challenge de paiement x402. Définissez **API Key Header** sur `Authorization`.
    - La clé a atteint sa limite de dépenses, ou votre solde est épuisé. Consultez [Dépannage des erreurs de limite de dépenses](/fr/guides/getting-started/generating-api-key#résolution-des-erreurs-de-limite-de-dépense).
  </Accordion>
  <Accordion title="Modèle introuvable">
    Venice a peut-être retiré le modèle. Consultez les [Dépréciations](/fr/overview/deprecations), choisissez un modèle actuel dans la liste des modèles du fournisseur et démarrez une nouvelle conversation.
  </Accordion>
</AccordionGroup>

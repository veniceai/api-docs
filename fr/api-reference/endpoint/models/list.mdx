Si vous omettez le paramètre de requête `type`, la réponse inclut uniquement les modèles de texte. Passez `type=all` pour renvoyer le catalogue complet des modèles.

## Lire une entrée de modèle {#reading-a-model-entry}

Envoyez l'`id` d'un modèle comme paramètre `model`. La plupart des champs sur lesquels vous filtrez se trouvent sous `model_spec` :

| Champ | Ce qu'il indique |
| --- | --- |
| `type` | L'endpoint servi par le modèle : `text` pour les chat completions, ou `image`, `video`, `tts`, `asr`, `embedding`, etc. |
| `model_spec.capabilities` | Ce que prend en charge un modèle de texte, comme `supportsFunctionCalling`, `supportsVision`, `supportsReasoning`, `supportsResponseSchema`, `supportsWebSearch` et `supportsE2EE` |
| `model_spec.availableContextTokens` | La fenêtre de contexte, en tokens |
| `model_spec.pricing` | Prix en USD et en DIEM : par 1M de tokens pour les modèles de texte, par unité pour les modèles multimédias |
| `model_spec.privacy` | `private` ou `anonymized`. Les modèles E2EE et TEE sont `private` et définissent `supportsE2EE` ou `supportsTeeAttestation` |
| `model_spec.constraints` | Les valeurs de paramètres acceptées par le modèle, comme les formats d'image, les durées de vidéo et les niveaux de qualité |
| `model_spec.traits` | Rôles attribués au modèle, comme `default` ou `fastest` |
| `model_spec.deprecation` | Présent lorsque le modèle est en cours de retrait, avec sa date de suppression et, le cas échéant, son `replacementModelId` |

Pour choisir un modèle par rôle plutôt que par ID, appelez [`GET /models/traits`](/fr/api-reference/endpoint/models/traits). Pour parcourir et comparer les modèles, consultez les pages [Modèles](/fr/models/overview).

## Tarification par niveau de qualité

Pour les modèles d'image qui acceptent le paramètre `quality` optionnel, la réponse expose une matrice de prix par qualité sous `model_spec.pricing.quality`. Chaque clé de premier niveau est un niveau de résolution (`1K`, `2K`, `4K`) et chaque clé imbriquée est un niveau de qualité (`low`, `medium`, `high`) avec son propre prix `usd` et `diem` :

```json
"pricing": {
  "resolutions": {
    "1K": { "usd": 0.27, "diem": 0.27 },
    "2K": { "usd": 0.51, "diem": 0.51 },
    "4K": { "usd": 0.84, "diem": 0.84 }
  },
  "quality": {
    "1K": {
      "low":    { "usd": 0.02, "diem": 0.02 },
      "medium": { "usd": 0.07, "diem": 0.07 },
      "high":   { "usd": 0.26, "diem": 0.26 }
    },
    "2K": {
      "low":    { "usd": 0.03, "diem": 0.03 },
      "medium": { "usd": 0.13, "diem": 0.13 },
      "high":   { "usd": 0.50, "diem": 0.50 }
    },
    "4K": {
      "low":    { "usd": 0.05, "diem": 0.05 },
      "medium": { "usd": 0.21, "diem": 0.21 },
      "high":   { "usd": 0.83, "diem": 0.83 }
    }
  }
}
```

`pricing.resolutions` est la grille de prix par image héritée, conservée pour la compatibilité ascendante. `pricing.quality` est la matrice par (résolution, qualité) qui s'applique chaque fois que le paramètre `quality` est pris en charge. Les deux champs sont conservés dans la réponse afin que les clients puissent détecter la prise en charge de la qualité et exposer la matrice dans leurs propres interfaces.

## Limites d'images d'entrée

Le nombre maximal d'images d'entrée dépend du modèle. Lisez `model_spec.constraints.maxInputImages` depuis [`GET /models?type=inpaint`](/fr/api-reference/endpoint/models/list). Lorsque ce champ est absent, la limite est de 3, ou de 1 lorsque `combineImages` vaut `false`.

## Niveaux de qualité

Certains modèles d'édition multi-images acceptent un paramètre `quality` optionnel (`low`, `medium`, `high`) qui arbitre entre fidélité visuelle et coût. Les modèles qui listent `qualities` dans `model_spec.constraints` de [`GET /models?type=inpaint`](/fr/api-reference/endpoint/models/list) n'acceptent que ces valeurs, et certains ne prennent en charge qu'un sous-ensemble comme `low` et `medium`. Les autres modèles ignorent ce paramètre.

```json
{
  "modelId": "gpt-image-2-edit",
  "images": ["iVBORw0KGgo...", "iVBORw0KGgo..."],
  "prompt": "blend the two scenes into one cinematic frame",
  "resolution": "2K",
  "quality": "medium"
}
```

Lorsque vous omettez `quality`, le modèle utilise son niveau par défaut (`high` pour `gpt-image-2-edit`). Les prix par niveau (1K/2K/4K × low/medium/high) se trouvent sous `model_spec.pricing.quality` dans l'[endpoint Models](/fr/api-reference/endpoint/models/list) et sont listés dans l'[aperçu de la tarification](/fr/overview/pricing).

<Info>
La tarification consciente de la qualité est la valeur par défaut pour tous les appelants de l'API et du SDK — aucun en-tête d'opt-in requis. Les requêtes qui omettent `quality` sont facturées au niveau par défaut du modèle (`high` pour `gpt-image-2-edit`).
</Info>

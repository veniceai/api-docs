## الحدود حسب نوع النموذج

### نماذج النصوص والـ Embedding والصور

لكل نموذج من نماذج النصوص والـ Embedding والصور (بما في ذلك upscale وinpaint) حدوده الخاصة. في استجابة `/api_keys/rate_limits`، يحتوي `data.rateLimits` على إدخال واحد لكل نموذج، ويسرد الحقل `rateLimits` في كل إدخال قيمة `amount` لكل `type` من أنواع الحدود: `RPM` (طلبات في الدقيقة)، أو `TPM` (رموز في الدقيقة)، أو `RPD` (طلبات في اليوم). للتحقق من نموذج واحد:

```bash
curl -s https://api.venice.ai/api/v1/api_keys/rate_limits \
  -H "Authorization: Bearer $VENICE_API_KEY" \
  | jq '.data.rateLimits[] | select(.apiModelId == "venice-uncensored-1-2")'
```

قد تتغير الحدود، لذا اقرأها من الـ API بدلاً من تثبيتها في الكود. تتضمن استجابات الاستدلال أيضاً الحد المطبَّق وسعتك المتبقية في [رؤوس الاستجابة](#رؤوس-الاستجابة) `x-ratelimit-*`.

### نماذج الكلام والنسخ

يسمح كل نموذج من نماذج الكلام والنسخ بـ 60 طلباً في الدقيقة، أو 120 باستخدام مفتاح شريك.

### نماذج الفيديو والموسيقى

تخضع طلبات الإدراج في قائمة الانتظار والاسترجاع للفيديو والموسيقى وتغيير الصوت لحدود طلبات لكل حساب. تعامل مع استجابات `429` باستخدام backoff، واستعلم endpoints الاسترجاع على فترات معتدلة بدلًا من حلقة متقاربة. تُحتسب فوترة المهام لكل عملية توليد من رصيدك، لذا قم بتسعير المهمة أولًا باستخدام [`POST /video/quote`](/ar/api-reference/endpoint/video/quote) أو [`POST /audio/quote`](/ar/api-reference/endpoint/audio/quote) أو [`POST /audio/voice-changer/quote`](/ar/api-reference/endpoint/audio/voice-changer/quote).

## التعامل مع الأخطاء

يجب إعادة محاولة الطلبات الفاشلة (500، 503، 429) باستخدام exponential backoff.

بالنسبة لأخطاء 429 على endpoints الاستدلال، يعطي header `x-ratelimit-reset-requests` أقصى وقت، كطابع Unix زمني بالميلي ثانية، تكون فيه نافذة الطلبات قد خلت تمامًا. الانتظار حتى ذلك الوقت آمن دائمًا؛ وقد تنجح إعادة المحاولة قبله أيضًا.

```javascript
const reset = Number(response.headers.get('x-ratelimit-reset-requests'));
const waitMs = Math.max(0, reset - Date.now());
await new Promise((resolve) => setTimeout(resolve, waitMs));
```

### ميزانيات الأخطاء

يحمي حدّان إضافيان الـ API من العملاء الذين يستمرون في إعادة المحاولة دون جدوى. يُحسب كلاهما لكل نموذج ولكل مفتاح API، ويعيد كلاهما `429`. تُحسب الطلبات الفاشلة في نوافذ ثابتة مدتها 30 ثانية:

| الميزانية | العتبة | ينطبق على |
|:-------|----------:|:-----------|
| الطلبات الفاشلة | 50 لكل 30 ثانية | جميع الـ endpoints |
| طلبات الميزات غير المدعومة | 200 لكل 30 ثانية | `/chat/completions`، `/responses` |

تحسب الميزانية الثانية الطلبات التي تطلب من نموذج ميزة لا يدعمها. على سبيل المثال، طلب الرؤية أو استدعاء الأدوات من نموذج لا يمتلك تلك القدرة. يظهر تجاوز أي من الميزانيتين في [سجلات حدود المعدل](/ar/api-reference/endpoint/api_keys/rate_limit_logs) باسم `FAILED_REQUESTS` أو `UNSUPPORTED_FEATURE_REQUESTS`.

يحدد الحقل `error` في جسم الاستجابة العتبة التي تم تجاوزها. بالنسبة لميزانية الطلبات الفاشلة يكون نصه:

```
Too many failed attempts (> 50) resulting in a non-success status code. Please wait 30 seconds and try again. See https://docs.venice.ai/api-reference/rate-limiting for more information.
```

## رؤوس الاستجابة

تتضمن استجابات الاستدلال (chat completions وresponses والصور والصوت والـ embeddings) هذه الرؤوس. لا تُرسَل على مسارات النماذج أو مفاتيح API أو الفوترة أو x402، وينطبق الأمر نفسه على رؤوس `x-venice-balance-*`.

| Header | الوصف |
|:-------|:------------|
| `x-ratelimit-limit-requests` | الحد الأقصى للطلبات المسموح بها في النافذة الحالية |
| `x-ratelimit-remaining-requests` | الطلبات المتبقية في النافذة الحالية |
| `x-ratelimit-reset-requests` | طابع Unix الزمني بالميلي ثانية الذي تكون فيه النافذة الحالية قد خلت تمامًا (وقت الطلب مضافًا إليه طول النافذة الكامل، بغض النظر عن الاستخدام) |
| `x-ratelimit-limit-tokens` | الحد الأقصى لـ tokens المسموح به في الدقيقة |
| `x-ratelimit-remaining-tokens` | الـ tokens المتبقية في الدقيقة الحالية |
| `x-ratelimit-reset-tokens` | طابع Unix الزمني بالميلي ثانية عند إعادة تعيين حد الـ tokens |

لميزانية الطلبات الفاشلة رؤوسها الخاصة، وتُرسَل في كل استجابة لطلب مُرسَل بمفتاح API، بما في ذلك استجابات `401`:

| Header | الوصف |
|:-------|:------------|
| `x-ratelimit-remaining` | الطلبات الفاشلة المتبقية في النافذة الحالية ومدتها 30 ثانية |
| `x-ratelimit-resets` | طابع Unix الزمني بالميلي ثانية عند إعادة تعيين النافذة الحالية ومدتها 30 ثانية |

يستخدم endpoint `/crypto/rpc/{network}` حدوده الخاصة ورؤوسه الخاصة `X-RateLimit-Limit` و`X-RateLimit-Remaining` و`X-RateLimit-Reset`، والتي تُعيَّن فقط في استجابات 429. على عكس رؤوس الميلي ثانية أعلاه، فإن `X-RateLimit-Reset` طابع Unix زمني بالثواني. راجع [Crypto RPC](/ar/api-reference/endpoint/crypto/rpc) لمزيد من التفاصيل.

## مستوى الشريك

لمفاتيح الشريك حدودها الخاصة لكل نموذج. استدعِ `GET /api_keys/rate_limits` باستخدام مفتاح شريك للاطلاع عليها.

إذا كنت تصل باستمرار إلى حدود المعدل وتُظهِر أنماط استخدامك **طلبًا مستمرًا عبر الزمن**، تواصل لمناقشة الوصول كشريك: [support@venice.ai](mailto:support@venice.ai).

يمكن تعديل حدود مستوى الشريك بناءً على احتياجاتك المحددة.

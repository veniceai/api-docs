تتم مصادقة طلبات Venice API باستخدام مفاتيح Bearer API. يوضّح هذا الدليل كيفية إنشاء مفتاح من لوحة تحكم Venice، وتخزينه بشكل آمن، والتحقق من أنه يعمل.

<Note>
  إذا كنت تبني وكيلاً مستقلاً (autonomous agent) يحتاج إلى إصدار مفتاحه الخاص باستخدام محفظة، فاستخدم دليل [إنشاء مفتاح API للوكيل المستقل](/guides/integrations/generating-api-key-agent) بدلاً من ذلك.
</Note>

## قبل أن تبدأ {#before-you-start}

* سجّل الدخول إلى حساب Venice الخاص بك.
* تأكّد من أن الحساب يمتلك رصيداً قابلاً للإنفاق قبل استدعاء نقاط النهاية المدفوعة. يمكنك إنشاء مفتاح قبل تمويل الحساب، لكن طلبات النماذج لن تنجح حتى يصبح بإمكان الحساب استهلاك DIEM أو الأرصدة المجمّعة أو USD.

<Steps>
  <Step title="افتح إعدادات API">
    قم بزيارة [https://venice.ai/settings/api](https://venice.ai/settings/api?utm_source=venice-api-documentation). يمكنك أيضاً فتح هذه الصفحة من تطبيق Venice عبر اختيار **API** في إعداداتك.

    تعرض لوحة إعدادات API أرصدتك، ومستوى API الخاص بك، والاستخدام، ومفاتيح API الحالية.
  </Step>

  <Step title="ابدأ إنشاء مفتاح جديد">
    اختر **Generate New API Key**، ثم قم بتهيئة المفتاح:

    * **Description:** استخدم اسماً قصيراً يحدّد التطبيق أو البيئة أو التكامل الذي سيستخدم هذا المفتاح.
    * **API Key Type:** استخدم **Inference Only** لطلبات النماذج العادية. استخدم **Admin** فقط عندما يكون المفتاح بحاجة إلى إدارة مفاتيح API برمجياً.
    * **Expires at:** يمكنك اختيارياً تحديد تاريخ انتهاء صلاحية. إذا تركت هذا الحقل فارغاً، فلن تنتهي صلاحية المفتاح تلقائياً.
    * **Epoch Consumption Limits:** يمكنك اختيارياً تحديد سقف لمقدار DIEM أو USD الذي يستطيع هذا المفتاح إنفاقه خلال حقبة (epoch) مدتها 24 ساعة. إذا تركت هذا الحقل فارغاً، فسيتمكن المفتاح من استخدام الرصيد المتاح للحساب وفقاً لحدود حسابك.
  </Step>

  <Step title="أنشئ المفتاح وانسخه">
    انقر على **Generate**. ستعرض Venice مفتاح API الكامل مرة واحدة فقط.

    <Warning>
      انسخ المفتاح فوراً وخزّنه في مكان آمن. بعد إغلاق مربع الحوار، لن تعرض Venice سوى البيانات الوصفية التعريفية مثل وصف المفتاح والأحرف الأخيرة منه. إذا فقدت القيمة السرية، فاحذف المفتاح وأنشئ مفتاحاً جديداً.
    </Warning>

    الصق المفتاح تماماً كما صدر. استخدم زر النسخ في مربع الحوار بدلاً من تحديد النص يدوياً، حتى لا تقطع الحرف الأول أو الأخير أو تلتقط سطراً جديداً زائداً في النهاية. عندما تطلب منك أداة ما إدخال المفتاح في حقل نموذج، أدخل المفتاح وحده: بدون البادئة `Bearer`، وبدون علامات اقتباس حوله، وبدون مسافات في بدايته أو نهايته. ولأن لوحة التحكم لا تعرض سوى الأحرف الأخيرة القليلة بعد إغلاق مربع الحوار، فلا تحاول أبداً إعادة بناء مفتاح مفقود بإعادة كتابة تلك القيمة المُقنّعة.

    أضف المفتاح إلى بيئتك المحلية أو إلى مدير الأسرار الخاص بك:

    ```bash
    export VENICE_API_KEY=your-api-key-here
    ```
  </Step>

  <Step title="تحقّق من المفتاح">
    أرسل طلباً منخفض المخاطر للتأكد من أن المصادقة تعمل. نقطة النهاية [حدود المعدل والأرصدة](/ar/api-reference/endpoint/api_keys/rate_limits) مجانية وتقبل أيّاً من نوعي المفاتيح. استخدمها بدلاً من `GET /models`، التي تُرجع كتالوج النماذج سواء أُرسل مفتاح أم لا، وبالتالي تنجح حتى عندما يكون مفتاحك خاطئاً:

    ```bash
    curl --request GET \
      --url https://api.venice.ai/api/v1/api_keys/rate_limits \
      --header "Authorization: Bearer $VENICE_API_KEY"
    ```

    تُرجع الاستجابة الناجحة فئة API الخاصة بك وأرصدتك وحدود المعدل، ويُشير الحقل `data.accessPermitted` إلى ما إذا كان المفتاح مسموحاً له باستخدام نقاط نهاية الاستدلال.

    يعني الخطأ `401` مع `AUTHENTICATION_FAILED` أن المفتاح نفسه قد رُفض. اطبع القيمة المخزّنة وقارنها بالأحرف الأخيرة المعروضة في لوحة التحكم: الأسباب المعتادة هي النسخ الجزئي، أو التقاط البادئة `Bearer` أو علامات الاقتباس داخل القيمة نفسها، أو وجود مسافة أو سطر جديد زائد في أيٍّ من الطرفين. تأكّد أيضاً من أن الترويسة تتكوّن من `Bearer`، ثم مسافة واحدة، ثم المفتاح نفسه، على سبيل المثال `Authorization: Bearer $VENICE_API_KEY` في سطر الأوامر.
  </Step>
</Steps>

<Warning>
  تعطيل الإنفاق بالدولار الأمريكي (USD) أثناء إنشاء مفتاح API في تطبيق Venice يضبط حد الإنفاق بالدولار الأمريكي على صفر لمفتاح API المحدد. قد تفشل استدعاءات API مع خطأ رصيد غير كافٍ عندما لا يستطيع رصيدك المتاح من DIEM أو الأرصدة المجمّعة تغطية الطلب، حتى لو كان لدى حسابك رصيد بالدولار الأمريكي.
</Warning>

## تنسيق المفتاح {#key-format}

تبدأ المفاتيح الجديدة ببادئة تحدد النوع، تليها 42 حرفاً آمناً للاستخدام في عناوين URL:

| البادئة | نوع المفتاح |
| --- | --- |
| `VENICE_INFERENCE_KEY_` | Inference Only |
| `VENICE_ADMIN_KEY_` | Admin |

تظل المفاتيح الأقدم تعمل كما صدرت: يستخدم بعضها الشرطات في البادئة (`VENICE-INFERENCE-KEY-`، `VENICE-ADMIN-KEY-`)، وأقدمها بلا بادئة.

استخدم المفتاح تماماً كما صدر. تتحقق API من السلسلة كاملة، لذا فإن المفتاح الذي حوّلته أداة إلى أحرف صغيرة، أو غيّرت علامات الترقيم فيه، أو أزالت بادئته، أو أعطته بادئة مختلفة، يفشل مع `401` و`Authentication failed`. تذكر بعض صفحات المجتمع أن مفاتيح Venice تبدأ بـ `vapi_`. هذا غير صحيح، وإضافة `vapi_` إلى المفتاح تعطّله.

تحدد البادئة نوع المفتاح. يعمل مفتاح Admin أيضاً على نقاط نهاية النماذج لأنه النوع الأوسع. أما مفتاح Inference Only على نقطة نهاية إدارية، مثل سرد المفاتيح أو إنشائها أو قراءة الرصيد، فيفشل مع `401` و`Admin API key required`. تقبل `GET /api_keys/rate_limits` أياً من النوعين.

## استكشاف أخطاء حدود الإنفاق وإصلاحها {#troubleshooting-spend-limit-errors}

حدود الإنفاق لكل مفتاح مستقلة عن رصيد حسابك. يمكن حظر مفتاح من الإنفاق حتى عندما يظل حسابك يمتلك رصيداً ممولاً بالدولار الأمريكي (USD) أو DIEM أو أرصدة مجمّعة. إذا أرجع طلب ما رمز الحالة 402 مع أحد الرموز التالية، فإن السبب هو الحد الخاص بالمفتاح نفسه وليس رصيد حسابك:

* `API_KEY_USD_SPEND_LIMIT_EXCEEDED` — حد الإنفاق بالدولار الأمريكي للمفتاح مضبوط على صفر (تم تعطيل الإنفاق بالدولار الأمريكي عند الإنشاء) أو أن الحقبة (epoch) الحالية قد بلغت سقفها بالدولار الأمريكي.
* `API_KEY_DIEM_SPEND_LIMIT_EXCEEDED` — بلغ المفتاح سقف DIEM الخاص به للحقبة الحالية التي مدتها 24 ساعة.

للتحقق من الحالة الحالية لمفتاح ما، استدعِ [Get API Key Rate Limits and Balances](/ar/api-reference/endpoint/api_keys/rate_limits) وافحص `data.accessPermitted` و`data.balances`. لمعرفة الحدود المُهيّأة للمفتاح، استدعِ [Get API Key](/ar/api-reference/endpoint/api_keys/get) باستخدام مفتاح Admin واقرأ `consumptionLimits`.

لحلّ الخطأ، إما ارفع حدود الاستهلاك حسب الحقبة (Epoch Consumption Limits) للمفتاح أو أزلها من [venice.ai/settings/api](https://venice.ai/settings/api?utm_source=venice-api-documentation)، أو استدعِ [Update API Key](/ar/api-reference/endpoint/api_keys/update) مع كائن `consumptionLimit` جديد. حقل الطلب بصيغة المفرد، رغم أن استجابات مفاتيح API تُرجع `consumptionLimits`. أرصدة الحساب (USD وDIEM والأرصدة المجمّعة) هي مصادر دفع مستقلة تُستهلك تلقائياً حسب توفّرها؛ لست بحاجة إلى اختيار واحد منها وقت الطلب.

راجع [رموز الأخطاء](/api-reference/error-codes) للاطلاع على القائمة الكاملة للاستجابات المتعلقة بالفوترة.

## أفضل الممارسات {#best-practices}

* أنشئ مفاتيح منفصلة لبيئات التطوير والاختبار (staging) والإنتاج.
* فضّل مفاتيح **Inference Only** للتطبيقات التي تستدعي نقاط نهاية النماذج فقط.
* اجعل مفاتيح **Admin** نادرة، ومحدودة النطاق بدقة، ومخزّنة فقط في بيئات موثوقة على جانب الخادم.
* لا ترفع مفاتيح API أبداً إلى نظام التحكم في الإصدارات ولا تكشفها في الكود الذي يعمل على جانب العميل.
* حدّد تواريخ انتهاء صلاحية وحدود استهلاك للمفاتيح المستخدمة في البيئات المؤقتة أو المشتركة أو الأعلى مخاطرة.
* احذف المفاتيح غير المستخدمة، وقم بتدوير أي مفتاح قد يكون تعرّض للكشف.

## الاستدعاء من المتصفح {#calling-from-a-browser}

ترسل API الترويسة `access-control-allow-origin: *`، لذا يمكن للمتصفح استدعاؤها مباشرة. لكن المفتاح سيكون حينها داخل حزمة تطبيقك ويصبح علنياً. ضع وكيلاً (proxy) صغيراً أمامها واحتفظ بالمفتاح على الخادم.

الوكيل وحده لا يكفي. لا تقوم `access-control-allow-origin` بأي مصادقة: يتجاهل `curl` والخوادم الأخرى CORS تماماً، واسم مضيف Worker علني. الوكيل الذي يكتفي بحقن المفتاح هو صنبور مفتوح على رصيدك. يجب على المستدعي أيضاً إثبات هويته.

هناك مستويان، ومن المهم معرفة أيهما تبني:

- **السر المشترك** يضبط الإنفاق. يحمل كل زائر القيمة نفسها، لذا يمنع الاستخدام المجهول لـ Worker الخاص بك لكنه لا يمنع زائراً من تمريره إلى غيره. مناسب للنماذج الأولية.
- **الرمز المميز لكل مستخدم** يحدد هوية المستدعي. يصادق المتصفح لدى الواجهة الخلفية الخاصة بك، التي تصدر رمزاً قصير العمر، ويتحقق Worker منه. هذا هو الشكل المناسب للإنتاج.

يحتفظ المثالان أدناه بمفتاح Venice على الخادم. وتنطبق قاعدة ثالثة على كليهما: **استخدم مفتاح inference-only**، لأن مفتاح admin الذي يمر عبر وكيل عام يمكنه استدعاء `POST /api_keys` وقراءة السر الجديد مباشرة من الاستجابة الممرَّرة.

### المستوى 1: سر مشترك {#level-1-a-shared-secret}

يحتفظ Worker بمفتاح Venice وبسر، ويرفض أي طلب لا يحمل السر. أبقِ السر بعيداً عن المتصفح: اجعل واجهتك الخلفية تضيفه عند استدعاء Worker، بحيث لا يتواصل المتصفح إلا مع واجهتك الخلفية.

```js index.js
// Only the paths you need. Add deliberately: an inference key still reads
// balances through GET /api_keys/rate_limits.
const ALLOWED = new Set(['/chat/completions', '/image/generate']);

export default {
  async fetch(request, env) {
    if (request.method === 'OPTIONS') {
      return new Response(null, { headers: cors() });
    }
    if (!ALLOWED.has(new URL(request.url).pathname)) {
      return json(404, { error: 'Not found' });
    }
    if (request.method !== 'POST') {
      return json(405, { error: 'Method not allowed' });
    }
    if (request.headers.get('x-proxy-key') !== env.PROXY_SECRET) {
      return json(401, { error: 'Proxy secret required' });
    }
    return forward(request, env);
  },
};

async function forward(request, env) {
  const path = new URL(request.url).pathname;
  const upstream = await fetch(`${env.VENICE_BASE_URL}/api/v1${path}`, {
    method: 'POST',
    headers: { 'content-type': 'application/json', authorization: `Bearer ${env.VENICE_API_KEY}` },
    body: await request.text(),
  });
  return new Response(upstream.body, {
    status: upstream.status,
    headers: { ...cors(), 'content-type': upstream.headers.get('content-type') ?? 'application/json' },
  });
}

const cors = () => ({
  'access-control-allow-origin': 'https://your-site.example',
  'access-control-allow-headers': 'content-type,x-proxy-key',
  'access-control-allow-methods': 'POST,OPTIONS',
});

const json = (status, body) =>
  new Response(JSON.stringify(body), { status, headers: { ...cors(), 'content-type': 'application/json' } });
```

```bash Deploy
npx wrangler deploy index.js --name venice-proxy
npx wrangler secret put VENICE_API_KEY      # an inference-only key
npx wrangler secret put PROXY_SECRET        # any long random value
npx wrangler secret put VENICE_BASE_URL     # https://api.venice.ai
```

استدعِه من واجهتك الخلفية، حيث يبقى السر:

```js Server
await fetch('https://venice-proxy.<account>.workers.dev/chat/completions', {
  method: 'POST',
  headers: { 'content-type': 'application/json', 'x-proxy-key': process.env.PROXY_SECRET },
  body: JSON.stringify({ model: 'venice-uncensored-1-2', messages: [{ role: 'user', content: 'Hi' }] }),
});
```

تُلحق المسارات مباشرة، لذا يصل `/chat/completions` إلى `/api/v1/chat/completions` في الخادم الأصلي. لا تضمّن `/v1` في عنوان URL الأساسي لأي عميل OpenAI توجّهه إلى هنا.

يظل السر المشترك بيانات اعتماد مشتركة: قيّد معدل الطلبات على المسار باستخدام قواعد تحديد المعدل في Cloudflare قبل أن يستقبل حركة مرور عامة.

### المستوى 2: رمز مميز لكل مستخدم {#level-2-a-per-user-token}

عندما يجب على المتصفح استدعاء Worker مباشرة، ضع المصادقة الخاصة بك أمامه. تتحقق واجهتك الخلفية من الجلسة الموجودة لديها وتوقّع رمزاً قصير العمر، ويتحقق Worker من هذا الرمز بدلاً من قيمة مشتركة. ويعيد استخدام `ALLOWED` و`forward` و`cors` و`json` من Worker المستوى 1:

```js index.js
export default {
  async fetch(request, env) {
    if (request.method === 'OPTIONS') {
      return new Response(null, { headers: cors() });
    }
    if (!ALLOWED.has(new URL(request.url).pathname) || request.method !== 'POST') {
      return json(404, { error: 'Not found' });
    }
    if (!(await validToken(request.headers.get('authorization')?.replace(/^Bearer /, ''), env))) {
      return json(401, { error: 'Token required' });
    }
    return forward(request, env);
  },
};

// Verify a token issued by your backend: its signature, expiry and subject.
// Any HMAC over `sub.exp` works; this is the shape, not a full implementation.
async function validToken(token, env) {
  if (!token) return false;
  // The payload itself contains a dot, so split on the last one only.
  const cut = token.lastIndexOf('.');
  if (cut < 1) return false;
  const payload = token.slice(0, cut);
  const key = await crypto.subtle.importKey(
    'raw', new TextEncoder().encode(env.PROXY_SIGNING_KEY),
    { name: 'HMAC', hash: 'SHA-256' }, false, ['verify'],
  );
  const ok = await crypto.subtle.verify('HMAC', key, hexToBytes(token.slice(cut + 1)), new TextEncoder().encode(payload));
  return ok && Number(payload.slice(payload.lastIndexOf('.') + 1)) > Date.now();
}

const hexToBytes = (hex) => new Uint8Array(hex.match(/../g).map((b) => parseInt(b, 16)));
```

أصدر الرمز في الواجهة الخلفية بعد التحقق من الجلسة بنفسك، حتى لا يحتفظ Worker أبداً بحالة المستخدم. يمنحك ذلك حدوداً للمعدل لكل مستخدم، وإمكانية الإلغاء، وفاتورة يمكن نسبتها إلى صاحبها.

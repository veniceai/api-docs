يخزّن prompt caching الـ input tokens المعالجة بحيث يمكن للطلبات اللاحقة ذات البادئات المتطابقة إعادة استخدامها بدلًا من إعادة معالجتها. هذا يقلل زمن الاستجابة للـ prompts الطويلة ويخفض التكاليف: تُحاسَب قراءات الذاكرة المؤقتة بجزء من سعر الإدخال، غالبًا 10% أو أقل.

تتعامل Venice مع التخزين المؤقت تلقائيًا للنماذج المدعومة، لكن فهم كيفية تنفيذ كل مزود للتخزين المؤقت يساعدك على زيادة معدلات إصابات الذاكرة المؤقتة وتقليل التكاليف.

## كيف يعمل التخزين المؤقت {#how-caching-works}

يعمل التخزين المؤقت على **مطابقة البادئات**: يخزن النظام الـ tokens المعالجة ويعيد استخدامها عندما تبدأ الطلبات اللاحقة بنفس المحتوى.

ضع في اعتبارك chatbot بـ system prompt مكون من 2,000 token:

<Steps>
  <Step title="الطلب 1">
    System prompt (2,000 token) + رسالة المستخدم (50 token)
    
    **معالجة**: 2,050 token · **من الذاكرة المؤقتة**: 0 token
    
    البادئة مكتوبة في الذاكرة المؤقتة.
  </Step>
  <Step title="الطلب 2">
    System prompt (2,000 token) + رسالة المستخدم (80 token)
    
    **معالجة**: 80 token · **من الذاكرة المؤقتة**: 2,000 token
  </Step>
  <Step title="الطلب 3">
    System prompt (2,000 token) + رسالة المستخدم (120 token)
    
    **معالجة**: 120 token · **من الذاكرة المؤقتة**: 2,000 token
  </Step>
</Steps>

**الإجمالي بدون تخزين مؤقت**: 2,050 + 2,080 + 2,120 = 6,250 token بالسعر الكامل

**الإجمالي مع التخزين المؤقت**: 2,050 + 80 + 120 = 2,250 token بالسعر الكامل، و 4,000 token بسعر مخفض

<Warning>
يعمل التخزين المؤقت فقط على **البادئة**. أي تغيير في بداية الـ prompt الخاص بك يبطل الذاكرة المؤقتة لكل ما يليه. ضع دائمًا المحتوى الثابت (system prompt، المستندات، الأمثلة) قبل المحتوى الديناميكي (رسائل المستخدم).
</Warning>

## التسعير {#pricing}

تدعم معظم النماذج النصية التخزين المؤقت. تجد أسعار قراءة الذاكرة المؤقتة وكتابتها لكل نموذج في صفحته ضمن [نماذج النصوص](/ar/models/text)، وفي `model_spec.pricing.cache_input` و`model_spec.pricing.cache_write` ضمن استجابة [سرد النماذج](/ar/api-reference/endpoint/models/list).

<Note>
تفرض بعض النماذج، ومنها Claude وGPT-5.6 والإصدارات الأحدث، سعرًا أعلى لكتابات الذاكرة المؤقتة مقارنةً بالإدخال العادي. الطلب الأول الذي يملأ الذاكرة المؤقتة يكلف أكثر، ثم تُحاسَب إصابات الذاكرة المؤقتة اللاحقة بسعر القراءة الأرخص.
</Note>

النماذج التي تسعّر [عمليات كتابة الذاكرة المؤقتة لمدة ساعة](#one-hour-cache-lifetime) بشكل منفصل تُدرج أيضًا `model_spec.pricing.cache_write_1h`. في هذه النماذج، يغطي `cache_write` عمليات الكتابة لمدة خمس دقائق، ويغطي `cache_write_1h` عمليات الكتابة لمدة ساعة.

## السلوك الخاص بكل مزود {#provider-specific-behavior}

تُطبّع Venice التخزين المؤقت عبر المزودين. بالنسبة لمعظم النماذج، التخزين المؤقت تلقائي. فقط أرسل طلباتك وتحقق من الاستجابة للحصول على إحصائيات الذاكرة المؤقتة. بعض المزودين لا يخزّنون إلا المحتوى المُعلَّم بـ `cache_control`، وتضيف Venice هذه العلامات نيابةً عنك.

سلوك التخزين المؤقت يتم التحكم فيه في النهاية من قبل كل مزود وقد يتغير، لذا تحقق من مستندات المزود للحصول على آخر التفاصيل.

| النماذج | من يضع علامات الذاكرة المؤقتة | كتابات الذاكرة المؤقتة |
|--------|--------------------------|--------------|
| Claude | Venice، تلقائيًا. يمكنك إضافة علاماتك الخاصة. | 1.25x سعر الإدخال للكتابات لمدة خمس دقائق، و2x للكتابات لمدة ساعة |
| Qwen 3.6 Plus وQwen 3.7 Plus وQwen 3.7 Max وQwen 3.8 Max وQwen 4 Max وGemini 3.x | Venice، تلقائيًا | بسعر `cache_write` الخاص بالنموذج عندما يُدرج سعرًا له |
| GPT-5.6 والإصدارات الأحدث، بما في ذلك GPT-6 | OpenAI، في نهاية أحدث رسالة | 1.25x سعر الإدخال. تبقى الإدخالات 30 دقيقة على الأقل. |
| نماذج GPT الأقدم | لا حاجة لها | لا تُحاسَب |
| جميع النماذج الأخرى | لا حاجة لها. يخزّن المزود تلقائيًا. | لا تُحاسَب ما لم يُدرج النموذج `cache_write` |

تختلف أسعار قراءة الذاكرة المؤقتة حسب النموذج، من نسبة مئوية صغيرة من سعر الإدخال إلى نحو نصفه. راجع `model_spec.pricing.cache_input` للنموذج الذي تستخدمه.

### Claude (Anthropic) {#claude-anthropic}

يتطلب Claude نقاط فاصلة صريحة للذاكرة المؤقتة على مستوى البروتوكول. تتعامل Venice مع هذا تلقائيًا:

- **System prompt**: تضع Venice علامة على نهاية الـ system prompt. تُرسَل رسائل `developer` الأولى إلى Claude كجزء من الـ system prompt، لذا تُخزَّن معه.
- **تاريخ المحادثة**: تضع Venice علامة على ردّ المساعد السابق، بحيث يُقرأ كل ما يسبق أحدث رسالة مستخدم من الذاكرة المؤقتة.
- **حلقات الأدوات**: عندما ينتهي الطلب بنتائج أدوات، تضع Venice العلامة على أحدث نتيجة أداة بدلًا من ذلك. تُكتب كل جولة في الذاكرة المؤقتة مرة واحدة وتُقرأ في الجولة التالية.

هذا يعني أن تاريخ المحادثة الخاص بك يُقرأ من الذاكرة المؤقتة، ويتم معالجة آخر دور فقط كإدخال جديد:

| الدور | Prompt Tokens | قراءة الذاكرة المؤقتة | كتابة الذاكرة المؤقتة | التوفير |
|------|---------------|------------|-------------|---------|
| 1 | 10,979 | 0 | 10,938 | أول كتابة |
| 2 | 11,031 | 10,938 | 31 | 99.7% مخزَّن |
| 3 | 11,062 | 10,969 | 52 | 99.5% مخزَّن |

**تفاصيل إضافية:**

- **حتى 4 نقاط فاصلة لكل طلب**: يستخدم النظام أطول بادئة متطابقة
- **مفتاح الذاكرة المؤقتة دقيق بايتيًا**: تغييرات المسافات البيضاء، أو ترميزات الصور المختلفة، أو إعادة ترتيب الأدوات يكسر إصابات الذاكرة المؤقتة
- **كتابات الذاكرة المؤقتة أغلى من الإدخال**: 1.25x سعر الإدخال للكتابات لمدة خمس دقائق و2x للكتابات لمدة ساعة. تكلف قراءات الذاكرة المؤقتة 10% من سعر الإدخال في معظم نماذج Claude، و5% في Claude Opus 5.5 وSonnet 5.5، و2.5% في Claude Fable 5.1 و5.2.

#### التحكم اليدوي بالذاكرة المؤقتة {#manual-cache-control}

للحالات الخاصة مثل تخزين مستند كبير في الدور الأول، يمكنك إضافة نقاط فاصلة صريحة:

```json
{
  "messages": [
    {
      "role": "system",
      "content": [{
        "type": "text",
        "text": "You are a legal assistant...",
        "cache_control": { "type": "ephemeral" }
      }]
    },
    {
      "role": "user", 
      "content": [{
        "type": "text",
        "text": "[Long contract document...]",
        "cache_control": { "type": "ephemeral" }
      }]
    },
    { "role": "assistant", "content": "I've reviewed the contract." },
    { "role": "user", "content": "What are the termination clauses?" }
  ]
}
```

هذا يضمن تخزين كل من system prompt والمستند من الطلب الأول. للمحادثات النموذجية، لا تحتاج إلى علامات يدوية.

#### كيف تتجمع علاماتك مع علامات Venice {#how-your-markers-combine-with-venice’s}

- يمكن أن يحتوي الطلب على أربع نقاط فاصلة للذاكرة المؤقتة كحد أقصى. إذا أرسلت أكثر، تحتفظ Venice بآخر أربع، وهي التي تغطي أطول البادئات.
- تضيف Venice علاماتها التلقائية فقط في الخانات التي تتركها فارغة، ولا تضيف علامة إلى system prompt سبق أن وضعت عليه علامة.
- تحتفظ Venice بـ `cache_control` على كتل محتوى النظام والمستخدم، وعلى رسائل الأدوات (على الرسالة نفسها أو داخل محتواها)، وعلى كتل `tool_result` بأسلوب Anthropic.
- يقبل Claude قيمتَي `ttl` التاليتين: `"5m"` (الافتراضية) و`"1h"`، ويشترط أن تأتي الكتل ذات الساعة الواحدة قبل الكتل ذات الخمس دقائق، بدءًا من الـ system prompt. تتبع العلامات التلقائية من Venice قيم TTL الخاصة بك، وتحذف Venice العلامات الموجودة على نتائج الأدوات التي تخالف أيًا من القاعدتين. أما الكتل الأخرى التي تخالفهما فتجعل Claude يرفض الطلب.

#### مدة ذاكرة مؤقتة لساعة واحدة {#one-hour-cache-lifetime}

افتراضيًا، تستمر إدخالات ذاكرة Claude المؤقتة خمس دقائق. للإبقاء على كتلة مخزّنة مؤقتًا لمدة ساعة، اضبط `ttl` على `"1h"` في كائن `cache_control` الخاص بها:

```json
{
  "type": "text",
  "text": "[Long contract document...]",
  "cache_control": { "type": "ephemeral", "ttl": "1h" }
}
```

يقبل `ttl` القيمة `"5m"` (الافتراضية) أو `"1h"`. تُحتسب عمليات الكتابة لمدة ساعة بسعر `cache_write_1h` الخاص بالنموذج عندما تتضمنه أسعاره (تفرض Anthropic ضعفي سعر الإدخال). تُبلغ الاستجابة عنها في `prompt_tokens_details.cache_creation_1h_input_tokens`.

### Qwen وGemini 3.x {#qwen-and-gemini-3-x}

تضع Venice علامة على نهاية الـ system prompt وعلى الرسالة التي تسبق أحدث رسالة مستخدم، وهي عادةً ردّ المساعد السابق. في نماذج Qwen التي تستضيفها Alibaba، تضع Venice العلامة على أحدث نتيجة أداة في حلقات الأدوات. تُمرَّر العلامات التي تضيفها داخل محتوى رسائل النظام أو المستخدم أو المساعد كما هي؛ أما العلامات على رسائل الأدوات فلا تُمرَّر.

### جميع النماذج الأخرى {#all-other-models}

التخزين المؤقت **تلقائي**، ولا تحتاج إلى `cache_control`. تضع نماذج GPT-5.6 والإصدارات الأحدث من OpenAI نقطة فاصلة خاصة بها في نهاية أحدث رسالة وتحتفظ بإدخالات الذاكرة المؤقتة 30 دقيقة على الأقل. أبقِ الـ prompts أطول من [الحد الأدنى للطول](#meet-minimum-token-thresholds) واستخدم `prompt_cache_key` للتوجيه المتسق.

## معاملات الطلب {#request-parameters}

| المعامل | النوع | النماذج | الوصف |
|-----------|------|--------|-------------|
| `prompt_cache_key` | string | الكل | تلميح توجيه لتقارب الذاكرة المؤقتة. تُبقي Venice الطلبات ذات المفتاح نفسه لدى المزود نفسه وتمرر المفتاح إلى المزودين الذين يستخدمونه لتوجيه الذاكرة المؤقتة. |
| `prompt_cache_retention` | string | نماذج GPT الأقدم | تُبقي القيمة `"extended"` أو `"24h"` البادئات المخزّنة حتى 24 ساعة في النماذج التي تدعم الاحتفاظ الممتد، مثل GPT-5.2 وGPT-5.4 وGPT-5.5. |
| `cache_control` | object | Claude | تحدد كتل المحتوى للتخزين المؤقت. انظر [Claude](#claude-anthropic). |

### `prompt_cache_key` {#prompt_cache_key}

للمحادثات أو سير عمل الوكلاء، استخدم `prompt_cache_key` متسق لتحسين معدلات إصابات الذاكرة المؤقتة:

```json
{
  "model": "claude-sonnet-5-5",
  "prompt_cache_key": "session-abc-123",
  "messages": [...]
}
```

تُبقي Venice الطلبات التي تتشارك المفتاح نفسه لدى المزود نفسه وتمرر المفتاح إلى المزودين الذين يستخدمونه للتوجيه إلى ذاكرة مؤقتة دافئة، مثل OpenAI. إذا لم ترسل مفتاحًا، توجّه Venice الطلبات حسب أول رسالة مستخدم وترسل إلى المزودين مفتاحًا مبنيًا على حسابك. لذا عيّن مفتاحك الخاص عندما تشغّل محادثات كثيرة بالتوازي أو تعيد كتابة رسائل سابقة بين الأدوار. استخدم معرف جلسة أو معرف محادثة كمفتاح.

## حقول الاستجابة {#response-fields}

يتضمن كائن `usage` في الاستجابة إحصائيات الذاكرة المؤقتة:

```json
{
  "usage": {
    "prompt_tokens": 5500,
    "completion_tokens": 200,
    "total_tokens": 5700,
    "prompt_tokens_details": {
      "cached_tokens": 5000
    }
  }
}
```

| الحقل | الوصف |
|-------|-------------|
| `prompt_tokens` | إجمالي input tokens، بما في ذلك الـ tokens المقروءة من الذاكرة المؤقتة والمكتوبة فيها |
| `prompt_tokens_details.cached_tokens` | Tokens المقدَّمة من الذاكرة المؤقتة (تُفوتر بسعر مخفض) |
| `prompt_tokens_details.cache_creation_input_tokens` | Tokens المكتوبة في الذاكرة المؤقتة، تُفوتر بسعر كتابة الذاكرة المؤقتة للنموذج (أعلى من الإدخال في Claude وGPT-5.6 والإصدارات الأحدث) |
| `prompt_tokens_details.cache_write_tokens` | القيمة نفسها لـ `cache_creation_input_tokens`، تحت اسم الحقل الذي تقرؤه العملاء المتوافقة مع OpenRouter |
| `prompt_tokens_details.cache_creation_5m_input_tokens` | توكنات كتابة الذاكرة المؤقتة المخزّنة بمدة TTL تبلغ خمس دقائق. يظهر عندما يُبلغ المزوّد عن عمليات الكتابة حسب TTL. |
| `prompt_tokens_details.cache_creation_1h_input_tokens` | توكنات كتابة الذاكرة المؤقتة المخزّنة بمدة TTL تبلغ ساعة واحدة (`"ttl": "1h"`). يظهر عندما يُبلغ المزوّد عن عمليات الكتابة حسب TTL. |

لا تظهر حقول كتابة الذاكرة المؤقتة إلا عندما يكتب الطلب في الذاكرة المؤقتة.

**تفصيل الفوترة** (باستخدام Claude Sonnet 5.5 كمثال):
- 5000 token مخزَّن × \$0.10/1M = \$0.0005
- 500 token غير مخزَّن × \$2.00/1M = \$0.001
- الإجمالي: \$0.0015 (مقابل \$0.011 بدون تخزين مؤقت، توفير 86%)

## أفضل الممارسات {#best-practices}

### هيكلة الـ prompts للتخزين المؤقت {#structure-prompts-for-caching}

ضع المحتوى الثابت في البداية، والمحتوى الديناميكي في النهاية.

**هيكلة جيدة**

| الموضع | المحتوى | مخزَّن؟ |
|----------|---------|---------|
| 1 | تعليمات النظام | نعم |
| 2 | المستندات المرجعية | نعم |
| 3 | أمثلة Few-shot | نعم |
| 4 | استعلام المستخدم | لا |

**هيكلة سيئة**

| الموضع | المحتوى | مخزَّن؟ |
|----------|---------|---------|
| 1 | الطابع الزمني الحالي | لا (يبطل كل شيء بعده) |
| 2 | تعليمات النظام | لا |
| 3 | استعلام المستخدم | لا |

### حافظ على البادئات متطابقة بايتيًا {#keep-prefixes-byte-identical}

تُحسب مفاتيح الذاكرة المؤقتة من تسلسلات بايتات دقيقة. حتى الاختلافات التافهة تكسر إصابات الذاكرة المؤقتة:

- مسافات بيضاء أو أسطر جديدة مختلفة
- طوابع زمنية أو معرفات طلب في الـ prompts
- ترتيب عشوائي لأمثلة few-shot
- تنسيقات مختلفة لنفس المحتوى

### اجتز عتبات الحد الأدنى من الـ tokens {#meet-minimum-token-thresholds}

لكل نموذج حد أدنى لطول البادئة لا يُخزَّن أي شيء دونه، ولا يُعاد أي خطأ. في Claude يبلغ 512 token لـ Opus 5.5 وOpus 5 وSonnet 5.5 وFable 5 وFable 5.1 وFable 5.2 وHaiku 5.5، و1,024 لـ Opus 4.8 وSonnet 5 وSonnet 4.6، و2,048 لـ Opus 4.7، و4,096 لـ Opus 4.6 وOpus 4.5. تحتاج نماذج OpenAI إلى 1,024 token، ويحتاج المزودون الآخرون عادةً إلى نحو 1,024. للـ prompts الصغيرة، فكر في:

- إضافة المزيد من السياق أو الأمثلة للوصول إلى العتبة
- تجميع طلبات صغيرة متعددة في prompts مجمعة
- قبول أن التخزين المؤقت لن يطبَّق للاستعلامات البسيطة

### استخدم `prompt_cache_key` للمحادثات {#use-prompt_cache_key-for-conversations}

للمحادثات الجارية، عيّن `prompt_cache_key` متسق:

```json
// الدور 1
{ "prompt_cache_key": "conv-xyz", "messages": [...] }

// الدور 2
{ "prompt_cache_key": "conv-xyz", "messages": [...] }

// الدور 3
{ "prompt_cache_key": "conv-xyz", "messages": [...] }
```

هذا يحسن احتمال أن جميع الأدوار تصيب نفس الخادم بذاكرة مؤقتة دافئة.

### راقب أداء الذاكرة المؤقتة {#monitor-cache-performance}

تتبع هذه المقاييس:
- **معدل إصابة الذاكرة المؤقتة**: `cached_tokens / prompt_tokens`
- **توفير التكلفة**: قارن التكلفة الفعلية بالتكلفة دون تخزين مؤقت
- **تقليل زمن الاستجابة**: الوقت حتى أول token مع إصابات الذاكرة المؤقتة مقابل بدونها

إذا كان `cached_tokens` صفرًا باستمرار:
1. قد تكون الـ prompts أقل من الحد الأدنى لعدد الـ tokens
2. قد تتغير الـ prompts بين الطلبات
3. قد تصيب الطلبات خوادم مختلفة (استخدم `prompt_cache_key`)
4. قد تكون الذاكرة المؤقتة قد انتهت صلاحيتها (الطلبات نادرة جدًا)

### ضع في الاعتبار اقتصاديات الذاكرة المؤقتة {#consider-cache-economics}

**كتابات الذاكرة المؤقتة في Claude**: تكلف الكتابة لمدة خمس دقائق 25% أكثر من الإدخال العادي، وتكلف الكتابة لمدة ساعة الضعف. بعد ذلك تكلف القراءات 10% من سعر الإدخال أو أقل.

| السيناريو | هل تستحق علاوة كتابة الذاكرة المؤقتة؟ |
|----------|-------------------------------|
| طلب واحد بهذا الـ prompt | لا (تدفع علاوة الكتابة ولا تقرأها أبدًا) |
| 2+ طلبات بنفس البادئة خلال خمس دقائق | نعم (تسترد الكتابة لمدة خمس دقائق تكلفتها عند الطلب الثاني) |
| طلبات بنفس البادئة موزعة على مدى ساعة | استخدم `"ttl": "1h"` (تسترد الكتابة لمدة ساعة تكلفتها عند الطلب الثالث) |
| Prompts تتغير بسرعة | لا (تكاليف كتابة ثابتة) |
| system prompt مستقر، استعلامات كثيرة | نعم (مُستهلَك عبر قراءات كثيرة) |

## عمر الذاكرة المؤقتة {#cache-lifetime}

تنتهي صلاحية الذاكرات المؤقتة بعد فترة من عدم النشاط (عادةً 5-10 دقائق). هذا يعني:

| نمط حركة المرور | فائدة التخزين المؤقت |
|-----------------|-----------------|
| طلبات مستمرة (< 5 دقائق فجوات) | عالية: الذاكرة المؤقتة تبقى دافئة |
| حركة مرور متقطعة (فجوات > 10 دقائق) | محدودة: الذاكرة المؤقتة تنتهي بين الموجات |
| طلبات متفرقة (ساعات بينها) | لا شيء: الذاكرة المؤقتة دائمًا باردة |

في Claude، يمكنك تمديد إدخال الذاكرة المؤقتة إلى ساعة واحدة باستخدام [مدة ذاكرة مؤقتة لساعة واحدة](#one-hour-cache-lifetime). يحتفظ GPT-5.6 والإصدارات الأحدث من OpenAI بالإدخالات 30 دقيقة على الأقل. في نماذج GPT الأقدم التي تدعم الاحتفاظ الممتد، عيّن `prompt_cache_retention` إلى `"24h"` للاحتفاظ بالإدخالات حتى 24 ساعة.

## التخزين المؤقت مع الأدوات والوظائف {#caching-with-tools-and-functions}

يمكن تخزين تعريفات الوظائف مع system prompts:

```json
{
  "model": "claude-sonnet-5-5",
  "tools": [
    {
      "type": "function",
      "function": {
        "name": "search_database",
        "description": "Search the product database",
        "parameters": { ... }
      }
    }
  ],
  "messages": [
    {
      "role": "system",
      "content": [
        {
          "type": "text",
          "text": "You are a shopping assistant...",
          "cache_control": { "type": "ephemeral" }
        }
      ]
    },
    ...
  ]
}
```

تصبح تعريفات الأدوات جزءًا من البادئة المخزَّنة. إذا كان لديك أدوات كثيرة، يمكن أن يقلل هذا بشكل كبير من التكاليف لكل طلب.

### حلقات الأدوات {#tool-loops}

في الحلقة الوكيلية، ينتهي كل طلب بنتائج استدعاءات الأدوات السابقة. في Claude، وفي نماذج Qwen التي تستضيفها Alibaba، تضع Venice العلامة التلقائية على أحدث نتيجة أداة، بحيث تُكتب كل جولة في الذاكرة المؤقتة مرة واحدة وتقرؤها الجولة التالية. لا تحتاج إلى علامات خاصة بك.

لوضع علامة على نتيجة أداة بنفسك في Claude، عيّن `cache_control` على رسالة الأداة أو داخل محتواها:

```json
{
  "role": "tool",
  "tool_call_id": "call_1",
  "content": [
    {
      "type": "text",
      "text": "[Large file contents...]",
      "cache_control": { "type": "ephemeral" }
    }
  ]
}
```

تحتفظ كتل `tool_result` بأسلوب Anthropic داخل رسالة المستخدم أيضًا بـ `cache_control` الخاص بها.

## التخزين المؤقت مع الصور والمستندات {#caching-with-images-and-documents}

لنماذج الرؤية، يمكن تضمين الصور في المحتوى المخزَّن:

```json
{
  "model": "claude-sonnet-5-5",
  "messages": [
    {
      "role": "user",
      "content": [
        {
          "type": "image_url",
          "image_url": { "url": "data:image/png;base64,..." }
        },
        {
          "type": "text",
          "text": "This is the floor plan. I'll ask several questions about it.",
          "cache_control": { "type": "ephemeral" }
        }
      ]
    },
    {
      "role": "assistant",
      "content": "I can see the floor plan. What would you like to know?"
    },
    {
      "role": "user",
      "content": "How many bedrooms are there?"
    }
  ]
}
```

يتم تخزين الصورة والسياق الأولي، لذا فإن الأسئلة المتابعة حول نفس الصورة لا تعيد معالجتها.

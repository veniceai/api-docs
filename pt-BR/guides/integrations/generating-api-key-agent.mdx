Um agente de IA que controla uma carteira na Base pode gerar sua própria chave de API de inferência Venice sem nenhum humano no processo. O agente adquire VVV, faz stake, solicita uma requisição de chave de curta duração para sua carteira, assina a mensagem legível da requisição e envia a assinatura de volta para receber uma nova chave de API vinculada à carteira de stake.

Este guia percorre o fluxo completo de ponta a ponta e cobre as opções de financiamento para efetivamente pagar pela inferência depois que a chave é gerada.

## Pré-requisitos {#prerequisites}

* Uma carteira EVM na Base controlada pelo agente (chave privada em uma variável de ambiente ou gerenciador de segredos).
* Uma pequena quantidade de ETH na Base para gás (o staking são duas transações: `approve` e depois `stake`).
* Qualquer quantidade diferente de zero de VVV para fazer stake. O endpoint de geração exige apenas que a carteira tenha saldo de sVVV diferente de zero, então 1 VVV é suficiente para gerar uma chave. Veja [Pagando pela inferência](#paying-for-inference) para saber o que você precisa para realmente chamar endpoints pagos.

<Tip>
  Use uma carteira de agente dedicada em vez de uma carteira de tesouraria. A chave privada da carteira assina cada requisição de token Venice, portanto seu raio de impacto deve ser pequeno.
</Tip>

## Passos {#steps}

<Steps>
  <Step title="Adquira VVV">
    Envie VVV para a carteira do agente, ou faça com que o agente realize um swap em uma DEX como [Aerodrome](https://aerodrome.finance/swap?from=eth\&to=0xacfe6019ed1a7dc6f7b508c02d1b04ec88cc21bf\&chain0=8453\&chain1=8453) ou [Uniswap](https://app.uniswap.org/swap?chain=base\&inputCurrency=NATIVE\&outputCurrency=0xacfe6019ed1a7dc6f7b508c02d1b04ec88cc21bf).

    Contrato do token VVV na Base: `0xacfE6019Ed1A7Dc6f7B508C02d1b04ec88cC21bf`
  </Step>

  <Step title="Faça stake de VVV na Venice">
    Faça stake do VVV no [Smart Contract de Staking da Venice](https://basescan.org/address/0x321b7ff75154472b18edb199033ff4d116f340ff#code) em `0x321b7ff75154472B18EDb199033fF4D116F340Ff`. São duas transações:

    1. `approve(spender, amount)` no token VVV, onde `spender` é o contrato de staking.
    2. `stake(amount)` no contrato de staking.

    <Frame as="div">
      <img src="/images/guides/SC-Stake.png" alt="Staking no Smart Contract" />
    </Frame>

    Quando a segunda transação for confirmada, o saldo de VVV da carteira diminui e o saldo de sVVV aumenta na mesma quantia. O endpoint de geração lê o saldo de sVVV para confirmar que a carteira está com stake.
  </Step>

  <Step title="Solicite uma requisição de chave para a carteira">
    Chame `GET /api/v1/api_keys/generate_web3_key` com o endereço da carteira de stake. O endpoint não exige autenticação.

    ```bash
    curl --request GET \
      --url 'https://api.venice.ai/api/v1/api_keys/generate_web3_key?address=<wallet address>'
    ```

    A resposta contém dois campos:

    - `token`, um token assinado pela Venice e vinculado a essa carteira. Ele expira 15 minutos após sua emissão, então assine e envie bem antes disso.
    - `message`, o texto legível que a carteira assina. Ele identifica a carteira, o tipo de chave (`INFERENCE`), o emissor, a chain, um nonce de uso único e os horários de emissão e expiração:

    ```text
    Venice API key request

    Sign this only if you are creating a Venice inference API key for this wallet. The key spends from this wallet's Venice account.

    Wallet: <wallet address>
    Key type: INFERENCE
    Issued by: api.venice.ai
    Chain ID: 8453
    Nonce: <random hex>
    Issued At: <ISO 8601 time>
    Expiration Time: <ISO 8601 time>
    ```
  </Step>

  <Step title="Assine a mensagem com a carteira de stake">
    Assine exatamente a string `message` com a carteira que detém o VVV em stake. Esse é um `personal_sign` padrão (EIP-191). Tanto `ethers.Wallet.signMessage(message)` quanto `account.signMessage({ message })` do `viem` produzem a assinatura correta. Não modifique a mensagem: a Venice a reconstrói a partir do token, e a assinatura precisa corresponder a ela exatamente.
  </Step>

  <Step title="Gere a chave de API">
    Faça `POST` com o endereço, a assinatura e o token para o mesmo endpoint.

    ```bash
    curl --request POST \
      --url https://api.venice.ai/api/v1/api_keys/generate_web3_key \
      --header 'Content-Type: application/json' \
      --data '{
        "address": "<wallet address>",
        "signature": "<signature of message>",
        "token": "<token>",
        "apiKeyType": "INFERENCE",
        "description": "Agent key minted on <date>"
      }'
    ```

    Campos obrigatórios: `address`, `signature`, `token`, `apiKeyType`. `apiKeyType` deve ser `INFERENCE`: a geração assinada pela carteira não cria chaves ADMIN. Crie chaves ADMIN nas [configurações de API](https://venice.ai/settings/api?utm_source=venice-api-documentation).

    Campos opcionais:

    - `description`, `expiresAt`
    - `consumptionLimit` — o teto de gasto dessa chave, denominado em `usd` ou `diem` (`vcu` está obsoleto; use `diem` no lugar)
    - `limitPeriod` — a janela em que o teto é medido: `EPOCH` (redefine a cada dia UTC), `MONTH` (redefine no dia 1º de cada mês UTC) ou `LIFETIME` (nunca redefine, então o teto é permanente)
    - `modelPrivacy` — quais modelos a chave pode chamar, por nível de privacidade: `ALL`, `PRIVATE_TEXT` ou `PRIVATE_ONLY`
    - `ipAllowlist` — endereços IPv4 ou IPv6 e sub-redes CIDR autorizados a usar a chave (até 100 entradas); uma lista vazia permite qualquer endereço IP

    <Warning>
    `limitPeriod` assume `EPOCH` como padrão quando omitido, o que significa que o teto **redefine todos os dias** em vez de ser um total vitalício. Uma chave criada com `consumptionLimit: {"usd": 50}` e sem `limitPeriod` pode gastar $50 por dia. Para uma chave de agente sem supervisão, defina `limitPeriod: "LIFETIME"` explicitamente para que o limite seja um teto permanente.
    </Warning>

    Em caso de sucesso, a resposta contém a string `apiKey` gerada. Armazene-a no cofre de segredos do agente e use-a como um Bearer token normal (`Authorization: Bearer <key>`).
  </Step>
</Steps>

## Exemplo de ponta a ponta {#end-to-end-example}

O exemplo abaixo usa uma carteira real obtida de uma variável de ambiente, em vez de uma gerada aleatoriamente. Uma carteira aleatória não tem VVV em stake e a geração será rejeitada com o erro `Wallet 0x… has no staked VVV on Base`.

```typescript
import { ethers } from "ethers"

const wallet = new ethers.Wallet(process.env.WALLET_PRIVATE_KEY!)
const address = wallet.address

const tokenResponse = await fetch(
  `https://api.venice.ai/api/v1/api_keys/generate_web3_key?address=${address}`,
)
const { data: { token, message } } = await tokenResponse.json()

const signature = await wallet.signMessage(message)

const mintResponse = await fetch("https://api.venice.ai/api/v1/api_keys/generate_web3_key", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({
    address,
    signature,
    token,
    apiKeyType: "INFERENCE",
    description: "Agent key",
    // A permanent $50 ceiling. Without limitPeriod this would reset daily.
    consumptionLimit: { usd: 50 },
    limitPeriod: "LIFETIME",
  }),
})

const result = await mintResponse.json()
if (!mintResponse.ok) {
  throw new Error(`Mint failed: ${result.error}`)
}

console.log("Minted key:", result.data.apiKey)
```

## Referência de erros {#error-reference}

O endpoint retorna mensagens de erro específicas e acionáveis. Mapeie-as no agente para que ele possa decidir se deve tentar novamente, solicitar um novo token ou parar.

| Status | A mensagem de erro contém | O que significa | O que fazer |
| --- | --- | --- | --- |
| `400` | `Invalid wallet address` | O parâmetro de consulta ou o campo `address` não é um endereço EVM válido. | Corrija o endereço e reenvie. |
| `400` | `creates INFERENCE keys only` | `apiKeyType` era `ADMIN`. | Defina `apiKeyType` como `INFERENCE` ou crie uma chave ADMIN pelo painel. |
| `400` | `issued for a different wallet` | O token foi solicitado para um `address` diferente do que está no corpo do `POST`. | Solicite um token com `?address=` definido para a carteira que assina. |
| `400` | `JWT has expired` | O token de validação expirou antes de você assiná-lo e enviá-lo. | Solicite um novo token, assine-o e envie imediatamente. |
| `400` | `JWT signature is invalid` | O token não foi assinado pela Venice (provavelmente adulterado ou fabricado). | Sempre use um token novo do endpoint `GET`. |
| `400` | `JWT claims are invalid` | O emissor ou audiência do token não corresponde ao que a Venice espera. | Use o token sem modificações retornado pelo endpoint `GET`. |
| `400` | `JWT is malformed` | O `token` enviado não é um JWT. | Garanta que você está enviando exatamente a string `token` retornada pelo endpoint `GET`. |
| `400` | `Wallet signature does not match` | A `signature` não é a assinatura da carteira `address` sobre a `message` do token. | Assine exatamente a `message` retornada com o token, usando a carteira proprietária de `address`. |
| `400` | `Tokens without a wallet address are no longer accepted` | O token foi solicitado sem `?address=`. Esses tokens legados deixam de funcionar em 26 de dezembro de 2026. | Solicite um token com `?address=` e assine sua `message`. |
| `400` | `Could not verify wallet signature` | A chamada RPC para verificar a assinatura falhou (transitório). | Tente novamente com backoff. |
| `400` | `has no staked VVV` | A carteira tem saldo de sVVV zero. A mensagem completa é `Wallet 0x… has no staked VVV on Base`, com o endereço da sua carteira no lugar de `0x…`, seguida de um link, então faça a correspondência com `has no staked VVV` em vez do texto completo. | Faça stake de VVV primeiro e tente novamente. |

## Tokens legados {#legacy-tokens}

Antes de novembro de 2026, o endpoint emitia tokens sem endereço de carteira, e a carteira assinava a string bruta do token. Esses tokens ainda geram chaves até **26 de dezembro de 2026, 00:00 UTC**, e as respostas para eles trazem os cabeçalhos `Deprecation`, `Sunset` e `Link`. Depois dessa data, o `POST` os rejeita. Mude para `?address=` e assine `message` antes disso.

## Pagando pela inferência {#paying-for-inference}

Gerar uma chave e ser capaz de chamar endpoints pagos com ela são duas coisas separadas. Uma chave recém-gerada autentica corretamente, mas não pode chamar endpoints pagos (como `/chat/completions`) até que a conta da carteira tenha um saldo gastável.

A chave gerada pode gastar a partir da conta do usuário nesta ordem de prioridade: DIEM, depois créditos ganhos, depois créditos agrupados, depois USD.

| Fonte de financiamento | Autônoma? | Como |
| --- | --- | --- |
| **DIEM a partir de staking de VVV** | Sim | A alocação diária de DIEM da carteira é proporcional à sua participação no pool de staking. A conta precisa de pelo menos 0,1 DIEM em stake para que qualquer DIEM seja gastável. Stakes maiores ganham proporcionalmente mais DIEM diariamente, renovado a cada época (00:00 UTC). |
| **USD via Stripe** | Não (navegador) | Faça login em venice.ai com a mesma carteira (Sign-In-With-Ethereum). O dashboard encontra o registro de usuário existente. Adicione créditos em Settings, API. |
| **Assinatura cripto Coinbase** | Não (navegador) | Mesmo login com carteira, depois assine pelo dashboard. O fluxo redireciona para o Coinbase Commerce para o pagamento, então não pode ser conduzido por script. |
| **Onramp Coinbase** | Não (navegador) | Mesmo login com carteira, depois use o widget de onramp no dashboard. Hospedado na UI da Coinbase. |

Se o agente precisar de um caminho de financiamento totalmente cripto-nativo e headless, as opções mais limpas são:

1. **Fazer stake de mais VVV** para que a alocação diária de DIEM cubra o gasto do agente. A chave gerada usa isso automaticamente.
2. **Usar o [fluxo de carteira x402](/pt-BR/guides/integrations/x402-venice-api) em vez da chave de API.** Com o x402 o agente assina uma mensagem Sign-In-With-X por requisição, faz recarga diretamente com USDC na Base ou Solana via `POST /api/v1/x402/top-up` e paga por requisição. O saldo de USDC do x402 é vinculado à carteira, não ao usuário, portanto não aparece como saldo para a chave Bearer gerada, mas permite que a mesma carteira pague pela inferência programaticamente.

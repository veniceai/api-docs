As requisições à API Venice são autenticadas com chaves de API do tipo Bearer. Este guia mostra como criar uma chave a partir do painel da Venice, armazená-la com segurança e verificar se ela está funcionando.

<Note>
  Se você está construindo um agente autônomo que precisa criar sua própria chave com uma carteira, use o guia [Criação de chave de API por agente autônomo](/guides/integrations/generating-api-key-agent) em vez deste.
</Note>

## Antes de começar {#before-you-start}

* Faça login na sua conta Venice.
* Certifique-se de que a conta tenha um saldo disponível antes de chamar endpoints pagos. Você pode criar uma chave antes de adicionar fundos à conta, mas as requisições aos modelos não terão sucesso até que a conta possa consumir DIEM, créditos incluídos ou USD.

<Steps>
  <Step title="Abra as configurações da API">
    Acesse [https://venice.ai/settings/api](https://venice.ai/settings/api?utm_source=venice-api-documentation). Você também pode abrir essa página pelo app da Venice selecionando **API** nas configurações.

    O painel de configurações da API mostra seus saldos, o seu tier de API, o uso e as chaves de API existentes.
  </Step>

  <Step title="Inicie uma nova chave">
    Selecione **Generate New API Key** (Gerar nova chave de API) e configure a chave:

    * **Description:** Use um nome curto que identifique o aplicativo, o ambiente ou a integração que usará essa chave.
    * **API Key Type:** Use **Inference Only** para requisições normais aos modelos. Use **Admin** apenas quando a chave precisar gerenciar chaves de API de forma programática.
    * **Expires at:** Opcionalmente, defina uma data de expiração. Se você deixar em branco, a chave não expira automaticamente.
    * **Epoch Consumption Limits:** Opcionalmente, limite quanto de DIEM ou USD essa chave pode gastar durante uma época de 24 horas. Se você deixar em branco, a chave poderá usar o saldo disponível da conta, sujeito aos limites da sua conta.
  </Step>

  <Step title="Gere e copie a chave">
    Clique em **Generate**. A Venice exibirá a chave de API completa uma única vez.

    <Warning>
      Copie a chave imediatamente e armazene-a em um local seguro. Depois que você fechar a caixa de diálogo, a Venice mostrará apenas metadados de identificação, como a descrição da chave e os últimos caracteres. Se você perder o valor secreto, exclua a chave e crie uma nova.
    </Warning>

    Cole a chave exatamente como ela foi emitida. Use o botão de copiar da caixa de diálogo em vez de selecionar o texto manualmente, para não cortar o primeiro ou o último caractere nem capturar uma quebra de linha no final. Quando uma ferramenta pedir a chave em um campo de formulário, insira apenas a chave: sem o prefixo `Bearer`, sem aspas ao redor e sem espaços no início ou no fim. Como o painel mostra apenas os últimos caracteres depois que a caixa de diálogo é fechada, nunca tente reconstruir uma chave perdida redigitando esse valor mascarado.

    Adicione a chave ao seu ambiente local ou gerenciador de segredos:

    ```bash
    export VENICE_API_KEY=your-api-key-here
    ```
  </Step>

  <Step title="Verifique a chave">
    Faça uma requisição de baixo risco para confirmar que a autenticação está funcionando. [Get API Key Rate Limits and Balances](/pt-BR/api-reference/endpoint/api_keys/rate_limits) não tem custo e aceita qualquer um dos tipos de chave. Use-o em vez de `GET /models`, que retorna o catálogo de modelos com ou sem chave e, portanto, funciona mesmo quando a sua chave está errada:

    ```bash
    curl --request GET \
      --url https://api.venice.ai/api/v1/api_keys/rate_limits \
      --header "Authorization: Bearer $VENICE_API_KEY"
    ```

    Uma resposta bem-sucedida retorna o seu nível de API, saldos e limites de taxa, e `data.accessPermitted` informa se a chave pode consumir os endpoints de inferência.

    Um `401` com `AUTHENTICATION_FAILED` significa que a própria chave foi rejeitada. Exiba o valor armazenado e compare-o com os últimos caracteres mostrados no painel: as causas comuns são uma cópia parcial, um prefixo `Bearer` ou aspas capturados no próprio valor, ou um espaço ou quebra de linha extra em qualquer uma das pontas. Confirme também que o cabeçalho é `Bearer`, um espaço e depois a própria chave, por exemplo `Authorization: Bearer $VENICE_API_KEY` em um shell.
  </Step>
</Steps>

<Warning>
  Desativar os gastos em USD durante a criação da chave de API no aplicativo Venice define o seu limite de gasto em USD como zero para essa chave de API. As chamadas de API podem falhar com um erro de saldo insuficiente quando o seu DIEM disponível ou os créditos agrupados não conseguirem cobrir a solicitação, mesmo que sua conta tenha saldo em USD.
</Warning>

## Formato da chave {#key-format}

Chaves novas começam com um prefixo de tipo seguido de 42 caracteres seguros para URL:

| Prefixo | Tipo de chave |
| --- | --- |
| `VENICE_INFERENCE_KEY_` | Inference Only |
| `VENICE_ADMIN_KEY_` | Admin |

Chaves mais antigas continuam funcionando como foram emitidas: algumas usam hifens no prefixo (`VENICE-INFERENCE-KEY-`, `VENICE-ADMIN-KEY-`), e as mais antigas não têm prefixo.

Use a chave exatamente como foi emitida. A API verifica a string inteira, então uma chave que uma ferramenta converteu para minúsculas, repontuou, da qual removeu o prefixo ou à qual deu outro prefixo falha com `401` e `Authentication failed`. Algumas páginas da comunidade dizem que as chaves da Venice começam com `vapi_`. Não começam, e adicionar `vapi_` a uma chave a invalida.

O prefixo identifica o tipo de chave. Uma chave Admin também funciona nos endpoints de modelos, porque é o tipo mais amplo. Uma chave Inference Only em um endpoint de administração, como listar ou criar chaves ou consultar o saldo, falha com `401` e `Admin API key required`. `GET /api_keys/rate_limits` aceita qualquer um dos tipos.

## Solução de problemas com erros de limite de gasto {#troubleshooting-spend-limit-errors}

Os limites de gasto por chave são independentes do saldo da sua conta. Uma chave pode ficar impedida de gastar mesmo quando a sua conta ainda tem créditos em USD, DIEM ou créditos incluídos disponíveis. Se uma requisição retornar um 402 com um destes códigos, a causa é o próprio limite da chave e não o saldo da conta:

* `API_KEY_USD_SPEND_LIMIT_EXCEEDED` — o limite de gasto em USD da chave está definido como zero (o gasto em USD foi desativado na criação) ou a época atual atingiu o seu teto em USD.
* `API_KEY_DIEM_SPEND_LIMIT_EXCEEDED` — a chave atingiu o seu teto de DIEM para a época atual de 24 horas.

Para confirmar o estado atual de uma chave, chame [Get API Key Rate Limits and Balances](/pt-BR/api-reference/endpoint/api_keys/rate_limits) e inspecione `data.accessPermitted` e `data.balances`. Para ver os limites configurados da chave, chame [Get API Key](/pt-BR/api-reference/endpoint/api_keys/get) com uma chave Admin e leia `consumptionLimits`.

Para resolver o erro, aumente ou remova os Epoch Consumption Limits da chave em [venice.ai/settings/api](https://venice.ai/settings/api?utm_source=venice-api-documentation), ou chame [Update API Key](/pt-BR/api-reference/endpoint/api_keys/update) com um novo objeto `consumptionLimit`. O campo da requisição é singular, embora as respostas de chave de API retornem `consumptionLimits`. Os saldos da conta (USD, DIEM e créditos incluídos) são fontes de pagamento independentes e são consumidos automaticamente conforme a disponibilidade; você não precisa escolher uma delas no momento da requisição.

Consulte [Códigos de erro](/api-reference/error-codes) para a lista completa de respostas relacionadas a cobrança.

## Boas práticas {#best-practices}

* Crie chaves separadas para desenvolvimento, staging e produção.
* Prefira chaves **Inference Only** para aplicações que apenas chamam endpoints de modelos.
* Mantenha chaves **Admin** raras, com escopo restrito e armazenadas apenas em ambientes confiáveis do lado do servidor.
* Nunca faça commit de chaves de API no controle de versão nem as exponha em código do lado do cliente.
* Defina datas de expiração e limites de consumo para chaves usadas em ambientes temporários, compartilhados ou de maior risco.
* Exclua chaves não utilizadas e faça a rotação de qualquer chave que possa ter sido exposta.

## Chamadas a partir de um navegador {#calling-from-a-browser}

A API envia `access-control-allow-origin: *`, então um navegador pode chamá-la diretamente. Mas aí a chave fica no seu bundle e se torna pública. Coloque um pequeno proxy na frente e mantenha a chave no servidor.

Um proxy sozinho não basta. `access-control-allow-origin` não autentica nada: `curl` e outros servidores ignoram CORS completamente, e o hostname do Worker é público. Um proxy que só injeta a chave é uma torneira aberta para o seu saldo. Quem chama também precisa se identificar.

Há dois níveis, e importa qual deles você está construindo:

- **Um segredo compartilhado** controla os gastos. Todo visitante tem o mesmo valor, então ele impede o uso anônimo do seu Worker, mas não que um visitante o repasse. Bom para um protótipo.
- **Um token por usuário** identifica quem chama. O navegador se autentica no seu próprio backend, que emite um token de curta duração, e o Worker o valida. Esse é o formato para produção.

Os dois exemplos abaixo mantêm a chave da Venice no servidor. Uma terceira regra vale para ambos: **use uma chave inference-only**, porque uma chave admin roteada por um proxy público pode fazer `POST /api_keys` e ler o novo segredo direto na resposta do proxy.

### Nível 1: um segredo compartilhado {#level-1-a-shared-secret}

O Worker guarda a chave da Venice e um segredo, e rejeita tudo o que não tiver o segredo. Mantenha o segredo fora do navegador: faça seu backend anexá-lo ao chamar o Worker, para que o navegador só converse com o seu backend.

```js index.js
// Only the paths you need. Add deliberately: an inference key still reads
// balances through GET /api_keys/rate_limits.
const ALLOWED = new Set(['/chat/completions', '/image/generate']);

export default {
  async fetch(request, env) {
    if (request.method === 'OPTIONS') {
      return new Response(null, { headers: cors() });
    }
    if (!ALLOWED.has(new URL(request.url).pathname)) {
      return json(404, { error: 'Not found' });
    }
    if (request.method !== 'POST') {
      return json(405, { error: 'Method not allowed' });
    }
    if (request.headers.get('x-proxy-key') !== env.PROXY_SECRET) {
      return json(401, { error: 'Proxy secret required' });
    }
    return forward(request, env);
  },
};

async function forward(request, env) {
  const path = new URL(request.url).pathname;
  const upstream = await fetch(`${env.VENICE_BASE_URL}/api/v1${path}`, {
    method: 'POST',
    headers: { 'content-type': 'application/json', authorization: `Bearer ${env.VENICE_API_KEY}` },
    body: await request.text(),
  });
  return new Response(upstream.body, {
    status: upstream.status,
    headers: { ...cors(), 'content-type': upstream.headers.get('content-type') ?? 'application/json' },
  });
}

const cors = () => ({
  'access-control-allow-origin': 'https://your-site.example',
  'access-control-allow-headers': 'content-type,x-proxy-key',
  'access-control-allow-methods': 'POST,OPTIONS',
});

const json = (status, body) =>
  new Response(JSON.stringify(body), { status, headers: { ...cors(), 'content-type': 'application/json' } });
```

```bash Deploy
npx wrangler deploy index.js --name venice-proxy
npx wrangler secret put VENICE_API_KEY      # an inference-only key
npx wrangler secret put PROXY_SECRET        # any long random value
npx wrangler secret put VENICE_BASE_URL     # https://api.venice.ai
```

Chame-o a partir do seu backend, onde o segredo fica:

```js Server
await fetch('https://venice-proxy.<account>.workers.dev/chat/completions', {
  method: 'POST',
  headers: { 'content-type': 'application/json', 'x-proxy-key': process.env.PROXY_SECRET },
  body: JSON.stringify({ model: 'venice-uncensored-1-2', messages: [{ role: 'user', content: 'Hi' }] }),
});
```

Os caminhos são anexados diretamente, então `/chat/completions` chega a `/api/v1/chat/completions` no upstream. Deixe `/v1` fora da URL base de qualquer cliente OpenAI que você apontar para cá.

Um segredo compartilhado continua sendo uma credencial compartilhada: limite a taxa da rota com as regras de rate limiting da Cloudflare antes que ela receba tráfego público.

### Nível 2: um token por usuário {#level-2-a-per-user-token}

Quando o navegador precisar chamar o Worker diretamente, coloque sua própria autenticação na frente. Seu backend verifica a sessão que já tem e assina um token de curta duração, e o Worker verifica esse token em vez de um valor compartilhado. Ele reutiliza `ALLOWED`, `forward`, `cors` e `json` do Worker do Nível 1:

```js index.js
export default {
  async fetch(request, env) {
    if (request.method === 'OPTIONS') {
      return new Response(null, { headers: cors() });
    }
    if (!ALLOWED.has(new URL(request.url).pathname) || request.method !== 'POST') {
      return json(404, { error: 'Not found' });
    }
    if (!(await validToken(request.headers.get('authorization')?.replace(/^Bearer /, ''), env))) {
      return json(401, { error: 'Token required' });
    }
    return forward(request, env);
  },
};

// Verify a token issued by your backend: its signature, expiry and subject.
// Any HMAC over `sub.exp` works; this is the shape, not a full implementation.
async function validToken(token, env) {
  if (!token) return false;
  // The payload itself contains a dot, so split on the last one only.
  const cut = token.lastIndexOf('.');
  if (cut < 1) return false;
  const payload = token.slice(0, cut);
  const key = await crypto.subtle.importKey(
    'raw', new TextEncoder().encode(env.PROXY_SIGNING_KEY),
    { name: 'HMAC', hash: 'SHA-256' }, false, ['verify'],
  );
  const ok = await crypto.subtle.verify('HMAC', key, hexToBytes(token.slice(cut + 1)), new TextEncoder().encode(payload));
  return ok && Number(payload.slice(payload.lastIndexOf('.') + 1)) > Date.now();
}

const hexToBytes = (hex) => new Uint8Array(hex.match(/../g).map((b) => parseInt(b, 16)));
```

Emita o token no backend depois da sua própria verificação de sessão, para que o Worker nunca guarde estado de usuário. Isso dá a você limites de taxa por usuário, revogação e uma cobrança atribuível.

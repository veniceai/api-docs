If you omit the `type` query parameter, the response includes only text models. Pass `type=all` to return the full model catalog.

## Reading a Model Entry

Send a model's `id` as the `model` parameter. Most of what you filter on is under `model_spec`:

| Field | What it tells you |
| --- | --- |
| `type` | Which endpoint the model serves: `text` for chat completions, or `image`, `video`, `tts`, `asr`, `embedding`, and so on |
| `model_spec.capabilities` | What a text model supports, such as `supportsFunctionCalling`, `supportsVision`, `supportsReasoning`, `supportsResponseSchema`, `supportsWebSearch`, and `supportsE2EE` |
| `model_spec.availableContextTokens` | The context window, in tokens |
| `model_spec.pricing` | Prices in USD and DIEM: per 1M tokens for text models, per unit for media models |
| `model_spec.privacy` | `private` or `anonymized`. E2EE and TEE models are `private` and set `supportsE2EE` or `supportsTeeAttestation` |
| `model_spec.constraints` | The parameter values the model accepts, such as aspect ratios, video durations, and quality tiers |
| `model_spec.traits` | Roles the model holds, such as `default` or `fastest` |
| `model_spec.deprecation` | Present when the model is retiring, with its removal date and, when there is one, its `replacementModelId` |

To pick a model by role instead of by ID, call [`GET /models/traits`](/api-reference/endpoint/models/traits). To browse and compare models, see the [Models](/models/overview) pages.

## Quality-Tier Pricing

For image models that accept the optional `quality` parameter, the response exposes a per-quality price matrix under `model_spec.pricing.quality`. Each top-level key is a resolution tier (`1K`, `2K`, `4K`) and each nested key is a quality level (`low`, `medium`, `high`) carrying its own `usd` and `diem` price:

```json
"pricing": {
  "resolutions": {
    "1K": { "usd": 0.27, "diem": 0.27 },
    "2K": { "usd": 0.51, "diem": 0.51 },
    "4K": { "usd": 0.84, "diem": 0.84 }
  },
  "quality": {
    "1K": {
      "low":    { "usd": 0.02, "diem": 0.02 },
      "medium": { "usd": 0.07, "diem": 0.07 },
      "high":   { "usd": 0.26, "diem": 0.26 }
    },
    "2K": {
      "low":    { "usd": 0.03, "diem": 0.03 },
      "medium": { "usd": 0.13, "diem": 0.13 },
      "high":   { "usd": 0.50, "diem": 0.50 }
    },
    "4K": {
      "low":    { "usd": 0.05, "diem": 0.05 },
      "medium": { "usd": 0.21, "diem": 0.21 },
      "high":   { "usd": 0.83, "diem": 0.83 }
    }
  }
}
```

`pricing.resolutions` is the legacy per-image schedule kept for backward compatibility. `pricing.quality` is the per-(resolution, quality) matrix that applies whenever the `quality` parameter is supported. Both fields are kept in the response so clients can detect quality support and surface the matrix in their own UIs.
